# 微信聊天记录推送接口说明

## 1. 接口地址

当前局域网访问地址：

```text
POST http://192.168.1.64:9888/api/wechat-chat/push
```

请求头：

```text
Content-Type: application/json
```

说明：

- 该地址适合同一局域网内机器访问。
- 如果调用方不在当前局域网，需要先配置公网域名、端口映射或内网穿透，再把上面的 `http://192.168.1.64:9888` 替换成公网地址。
- 当前接口未加鉴权；如开放到公网，建议后续增加 `token` 或网关鉴权。

## 2. 请求体格式

接口支持一次推送多条消息。

```json
{
  "merchant_no": "202308240010699",
  "pushed_at": "2026-07-03 11:40:26",
  "messages": [
    {
      "msg_key": "m1",
      "group_name": "测试群",
      "group_serial_no": "g1",
      "sender_name": "张三",
      "sender_serial_no": "s1",
      "cite_content": "引用内容",
      "msg_time": "2026-07-03 12:00:00",
      "send_time": "2026-07-03 12:00:00",
      "message_time": "2026-07-03 12:00:00",
      "content": "你好",
      "msg_content": "你好",
      "msg_content_decoded": "你好",
      "raw_msg_content": "5L2g5aW9",
      "file": {
        "file_serial_no": "78f15602ba0e4d2cba6e748c7f771f30",
        "file_name": "fe88d7999d98489eb192a290010a8fbc.jpg",
        "file_url": "http://kfpt-file.oss-cn-hangzhou.aliyuncs.com/test.jpg"
      },
      "msg_type": 2033
    }
  ]
}
```

## 3. 字段说明

顶层字段：

| 字段 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| `merchant_no` | string | 建议传 | 商户号或推送方标识，用于区分来源 |
| `pushed_at` | string | 建议传 | 本次推送时间，格式建议 `YYYY-MM-DD HH:mm:ss` |
| `messages` | array | 必填 | 消息数组，可一次推多条 |

`messages[]` 字段：

| 字段 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| `msg_key` | string | 建议传 | 消息唯一标识，用于去重 |
| `group_name` | string | 必填 | 群名称，例如 `测试群` |
| `group_serial_no` | string | 强烈建议传 | 群唯一编号。没有时会用群名兜底，但不如编号稳定 |
| `sender_name` | string | 必填 | 发送人名称 |
| `sender_serial_no` | string | 建议传 | 发送人唯一编号 |
| `cite_content` | string | 可选 | 引用消息内容 |
| `message_time` | string | 建议传 | 消息时间，优先使用该字段 |
| `send_time` | string | 可选 | 发送时间，`message_time` 为空时使用 |
| `msg_time` | string | 可选 | 消息时间兜底字段 |
| `msg_content_decoded` | string | 建议传 | 解码后的消息正文，优先使用 |
| `msg_content` | string | 可选 | 消息正文，`msg_content_decoded` 为空时使用 |
| `content` | string | 可选 | 消息正文兜底字段 |
| `raw_msg_content` | string | 可选 | 原始 Base64 内容，当前系统仅作为最后兜底尝试解码 |
| `file` | object | 可选 | 附件信息 |
| `msg_type` | number/string | 可选 | 消息类型 |

`file` 字段：

| 字段 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| `file_serial_no` | string | 可选 | 文件唯一编号 |
| `file_name` | string | 可选 | 文件名 |
| `file_url` | string | 可选 | 文件下载地址，建议传纯 URL |

消息正文优先级：

```text
msg_content_decoded > msg_content > content > raw_msg_content
```

消息时间优先级：

```text
message_time > send_time > msg_time > pushed_at
```

```json
{
  "received": 1,
  "stored": 1,
  "groups": 1,
  "candidates": 1,
  "written_candidates": 1,
  "candidate_file": "/home/linzx/project-discovery/data/wechat_chat_candidates.jsonl",
  "group_candidate_files": [
    "/home/linzx/project-discovery/data/wechat_chat_candidates_by_group/2026-07-03/group_001.jsonl"
  ],
  "message_files": [
    "/home/linzx/project-discovery/data/wechat_chat_messages/2026-07-03/group_001.jsonl"
  ],
  "items": [
    {
      "source": "wechat_chat",
      "source_group": "微信群聊",
      "group_name": "投研项目群",
      "sender_name": "李四",
      "key_message_time": "2026-07-03 12:03:00",
      "attention_score": 65,
      "decision_label": "保留观察",
      "title": "群聊线索｜星河机器人正在做具身智能仓储机器人"
    }
  ]
}
```

返回字段说明：

| 字段 | 说明 |
| --- | --- |
| `received` | 本次收到的消息数 |
| `stored` | 新写入的原始消息数；重复消息不会重复写入 |
| `groups` | 本次涉及的群数量 |
| `candidates` | 本次重新挖掘出的群聊候选数 |
| `written_candidates` | 新增写入的候选线索数 |
| `candidate_file` | 全局微信群聊候选线索文件 |
| `group_candidate_files` | 本次涉及群的隔离候选线索文件，每个群每天一份 |
| `message_files` | 本次涉及群的原始消息文件，每个群每天一份 |
| `items` | 本次识别出的前 50 条候选线索 |

## 6.1 每个微信群的隔离方式

系统会按“日期 + 群编号”隔离存储和分析。

原始消息隔离路径：

```text
data/wechat_chat_messages/YYYY-MM-DD/{group_serial_no}.jsonl
```

候选线索隔离路径：

```text
data/wechat_chat_candidates_by_group/YYYY-MM-DD/{group_serial_no}.jsonl
```

同时，系统也会维护一个全局候选文件，供前端统一展示：

```text
data/wechat_chat_candidates.jsonl
```

隔离规则：

- 每次接收消息后，只分析本次涉及的群。
- 计算聊天前后文时，只读取同一天、同一个群的消息。
- 不同微信群之间不会互相混入上下文。
- 如果同一次推送包含多个群，会分别入库、分别分析、分别生成候选文件。
- 如果没有 `group_serial_no`，系统会用 `group_name` 做兜底，但建议必须传稳定的 `group_serial_no`。

## 7. 线索识别逻辑

系统会保存所有有效消息，但只有消息本身命中投资相关信号时，才会生成候选线索。

常见触发词包括：

```text
融资、天使轮、种子轮、Pre-A、A轮、B轮、估值、BP、商业计划书、
路演、项目、尽调、推荐项目、投资人、创始人、创业公司、未上市、
客户、订单、量产、专利、临床、注册证、样机、芯片、机器人、
人工智能、大模型、生物医药、医疗器械、新材料、新能源
```

生成候选线索后，系统会自动带上：

- 哪个群提出：`group_name`
- 谁提出：`sender_name`
- 什么时间：`message_time/send_time/msg_time`
- 关键信息原文
- 前后文聊天记录
- 附件信息
- 一级市场评分
- 项目画像字段：轮次、估值、机构、行业、核心亮点、风险提示、人员构成、联系方式等

## 8. 查询已接收消息

查询某天全部群聊消息：

```text
GET http://192.168.1.64:9888/api/wechat-chat/messages?date=2026-07-03
```

按群名查询：

```text
GET http://192.168.1.64:9888/api/wechat-chat/messages?date=2026-07-03&group_name=投研项目群
```

按群编号查询：

```text
GET http://192.168.1.64:9888/api/wechat-chat/messages?date=2026-07-03&group_serial_no=group_001
```

查询某天有哪些群，以及每个群消息数、候选线索数：

```text
GET http://192.168.1.64:9888/api/wechat-chat/groups?date=2026-07-03
```

## 9. 前端查看

浏览器访问：

```text
http://192.168.1.64:9888/
```

在来源筛选里选择：

```text
微信群聊
```

即可查看由聊天记录挖掘出的投资线索。
