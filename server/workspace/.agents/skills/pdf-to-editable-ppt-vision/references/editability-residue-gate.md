# 扁平化页面可编辑残留门禁

## 目录

- 适用条件
- 文字残留门禁
- 图形残留门禁
- 前景独立性门禁
- 交付判定

## 适用条件

用户要求“所有文字可编辑”“图标、线条、箭头也可编辑”“元素级可编辑”或
指出移动对象后会露出旧内容时，必须执行本门禁。仅统计新增文本框或运行
画布溢出检查不构成可编辑性验收。

## 文字残留门禁

对最终使用的每张去字背景再次运行 OCR，而不是复用首次 OCR 结果。

1. 使用与转换阶段相同或更高质量的 OCR 后端。
2. 输出每页残留文字、置信度和边界框。
3. 将残留分为：
   - 已有可编辑文字下方的重复像素；
   - 首次 OCR 漏识别的有效文字；
   - 图标、装饰或噪声误识别；
   - 经确认保留为栅格的截图、论文页或照片内部文字。
4. 前两类必须清除旧像素；第二类还必须补建可编辑文本框。
5. 未在交付说明中明确豁免的有效文字残留数量必须为零。

不能以“文字上方已经覆盖了文本框”为通过理由。移动或删除文本框后仍出现
旧文字即为失败。

## 图形残留门禁

对用户要求可编辑的流程图、架构图、信息图和图标区域建立对象清单，至少包括：

- 容器、节点框、圆环和胶囊框；
- 分隔线、连接线、箭头和端点；
- 业务图标、状态图标和流程小图标；
- 节点标签和图例；
- 数据驱动图表或表格。

简单图形使用 PowerPoint 原生形状；复杂线性图标使用独立 SVG。只把新图标
覆盖在旧图标上不算重建，必须同步清除背景中的旧图标像素。

照片、复杂插画、山水纹理和无法可靠矢量化的装饰可以保留为栅格，但不得把
承担业务语义的图标、箭头或流程节点归入“装饰”。

## 前景独立性门禁

生成一份仅用于 QA 的前景版 PPTX：删除对象名以
`ocr-clean-background-` 开头的整页背景图片，保留其他对象。

逐页渲染前景版并检查：

- 所有要求可编辑的文字仍然可见；
- 所有要求可编辑的图标、线条、箭头和节点仍然可见；
- 多行正文仍为同一文本框中的多行；
- 不存在只在背景像素中出现的业务标签；
- 不存在依赖背景图片才能看懂的关键流程关系。

对每页记录 `requiredObjectCount`、`foregroundObjectCount`、
`residualTextCount` 和 `unresolvedGraphicRegions`。用户要求全元素可编辑时，
任何未豁免的未解决区域都必须阻止交付。

`requiredObjectCount` 必须来自本次用户范围，而不是笼统地把整页所有视觉像素
都视为必需对象。例如用户明确要求“全部文字和功能图标可编辑”时，所有文本框
和功能图标均应纳入，装饰底纹、照片和卡片底板可以作为已披露的非目标背景；
如果用户要求“所有元素”或“流程关系也能重排”，则容器、节点、圆环、箭头和
连接线也必须纳入，不能用范围说明规避重建。

运行 `scripts/build_editability_residue_report.py` 对最终背景 OCR 结果进行正式
分类并生成 `editability-residue-report.json`，不得只保留未分类的 OCR 原始数组。

## 交付判定

只有同时满足以下条件时，才能声明为“语义重建版”或
`readyForContentReplacement=true`：

- 去字背景二次 OCR 的未豁免有效残留为零；
- 前景版渲染包含全部要求可编辑的业务信息；
- 目标图标、线条、箭头和节点已出现在对象清单中；
- 移动或删除抽查对象后不会露出旧像素；
- 复杂栅格豁免区域已逐页列明。

若仍有业务文字或业务图标只存在于整页背景中，应标记为未完成，不得以
“OCR 可编辑版”代替用户要求的“全元素可编辑版”。
