## 重建模型

使用 96 DPI 的幻灯片坐标系，并根据实际页面尺寸计算缩放比例：
`scale = target_slide_width / pdf_page_width`。对于 `1280 × 720 px`
的幻灯片，`960 × 540 pt` 的 PDF 缩放比例为 `4/3`，
`1920 × 1080 pt` 的 PDF 缩放比例为 `2/3`。

在文字、绘图和图片之间保留 PDF 显示列表的序列号。对象应按以下方式表示：

- 矩形使用 PowerPoint 原生矩形；
- 直线路径和多边形使用 PowerPoint 原生自定义形状；
- 曲线使用嵌入式 SVG 矢量对象；
- 简单图标使用一个或多个 PowerPoint 原生形状，复杂图标使用独立 SVG；
- 文字使用独立文本框，并保留源字体家族、字号、字重、颜色、旋转角度，
  同时将内边距设为零；
- 栅格资源作为独立图片放置在其 PDF 边界框对应的位置。

## PDF 常见陷阱

### 跨行文字片段

`page.get_texttrace()` 可能返回一个跨越多行的同字体片段。不得把该片段
直接拼接到一个自动换行文本框中。应在字符投影基线变化时拆分字符，
再为每一条原始文本行创建一个文字对象。这样可以避免信息密集页发生重叠。

### 可搜索但不可见的水印

即使 Poppler 不会渲染，WPS 仍可能在内容流中留下低透明度的斜向水印文字。
如果某文字片段透明度极低、覆盖页面的大块对角区域，或匹配已知的裁切水印
短语，应忽略该片段。移除前必须对照 Poppler 页面渲染结果确认。

可见水印也可能具有 `0.20–0.45` 的透明度，并以大字号斜向覆盖全部页面。
不得只依赖某一个固定短语或 `opacity < 0.20` 的单一规则。安全识别应综合
跨页重复比例、旋转角度、透明度、字号、覆盖面积和水印词库。用户通过
`--watermark-text` 明确指定的短语可以直接移除；其他不确定对象应保留。

### 被识别为图片的软蒙版

PyMuPDF 可能把一张图片及其 `/SMask` 辅助位图识别为两个独立图片块。
如果两者都插入，蒙版可能显示成不透明色块。应将父级 xref 与其蒙版合成，
并跳过位于其内部、xref 为零的辅助图片块。对于少量有问题的图标，
可直接从 Poppler 源页面渲染图中裁出正确外观。

### 字体替换

即使 Microsoft PowerPoint 内部已经包含源字体，LibreOffice 或 pdftoppm
预览仍可能使用替代字体。PPTX 中应保留正确的源字体；如果可以使用
PowerPoint，应先在其中验证，再决定是否为了预览器中的字体替换而调整字号
或位置。

### 整页图片

如果一页只有一张覆盖全页的图片，则源文件属于扁平化文件。
这种文件可以精确恢复视觉外观，但无法自动恢复对象级可编辑性，
不得向用户暗示相反情况。

如果用户要求文字可编辑，应使用 OCR 并移除原文字。如果用户要求图表或
表格可编辑，应人工核对并录入数据，重建为 PowerPoint 原生对象，
且必须先覆盖扁平化原图对应区域。

### 富对象页面中的内嵌流程图

`object-rich` 只说明页面存在可提取对象，不代表所有可见内容都已元素化。
一张大图片可能封装完整流程图、架构图、表格或产品矩阵，而页面标题和正文
仍是独立文字。必须检查图片资源本身：如果图片内部包含多个节点、箭头、
标签或单元格，用户又要求这些内容可编辑，应按
[embedded-diagram-workflow.md](embedded-diagram-workflow.md) 覆盖旧图并
重建为原生对象。

不得只在图片上叠加少量文本框。目标节点、容器、连接线和标签都应分别出现在
PPTX inspect 结果中；移动新对象后不得露出旧像素图形。

### OCR 文字移除

不得直接在未修改的栅格文字上叠加可编辑文本。应从背景中移除识别到的文字，
或使用匹配的填充完整覆盖文字区域。以原始尺寸检查抗锯齿残边和纹理背景。

OCR 置信度不等于语义正确。常见错误包括：把图标字形识别为字母、
把 `AI` 识别成 `Al`，以及把中文词语替换成形近字。重要文案必须人工修正；
如果密集截图的识别准确性无法确认，应将其排除。

对于带底色矩形组成的文字矩阵，应逐单元格清除文字并保留原始填充色，
不要对整张图做大范围修复。窄竖排中文需要检查字符是否保持正向；整块旋转
后汉字侧倒属于失败。最终 inspect 结果必须包含每个目标单元格对应的独立
文本框，且原图片已通过 `imageReplacements` 在正确图层原位替换。

### 扇形与裁剪填充

饼图扇区、圆角渐变块和弧形装饰可能由 `fill-shade` 与独立描边路径共同
组成。若转换后出现矩形色块、弧线与填充分离、扇区未闭合或圆心错位，检查：

- `get_bboxlog()` 是否把对象标记为 `fill-shade`；
- 是否存在边界相同、序号紧邻的曲线描边路径；
- shade 图片是否为单一纯色；
- 纯色是否已融合进曲线路径且矩形图片已跳过；
- 曲线首尾是否通过圆心或边界线闭合；
- 白色扇区分隔线的宽度、连接处和层级是否与源 PDF 一致。

至少以原始尺寸检查圆心、四个象限边界和最小扇区。只看缩略图不足以发现
一像素缺口、曲线切线不连续和描边覆盖顺序错误。

### 扁平化图标分离

不得只在扁平化背景上叠加一个新图标，否则移动新图标后会露出旧图标。
应先用匹配的纯色形状或背景修补图覆盖旧图标，再添加独立图标对象。

简单图标优先用原生形状重建。多部件图标应保留为多个可分别选择的形状，
并采用稳定、易识别的对象名称。复杂图标使用 SVG；交付时说明需要在
PowerPoint 中“转换为形状”后才能编辑内部路径。只有无法可靠矢量化时，
才保留为独立栅格图片。

## 水印识别与验证

富对象 PDF 默认生成 `watermark-report.json`。至少检查：

- 被移除的文字内容与用户目标一致；
- 页码覆盖范围符合水印实际出现范围；
- 识别理由包含跨页重复、旋转、低透明度、常见短语或用户指定短语；
- 没有把正常页眉、页脚、公司名、章节标题或 Logo 文字误删；
- PPTX 解包后的 `ppt/slides/slide*.xml` 中不再包含目标水印文字；
- 最终逐页渲染中没有残余水印、异常空洞或覆盖色块。

如果 `watermark-report.json` 的移除数量为零，但源渲染仍有水印，应检查水印
是否为矢量路径、图片或整页栅格像素。路径或独立图片需要精确定位并删除对应
对象；烧录水印需要背景修补或图像修复。任何自动修复都必须与源页面逐页
比较，确保没有损伤正文、图表、照片或纹理。

交付前必须运行 `scripts/validate_watermark_handoff.py --mode strict`。该脚本
除扫描 PPTX 包内文字外，还会从最终渲染图提取浅灰色低饱和像素，并在
原角度及 `±30°/±45°` 方向执行 OCR，以捕获普通 OCR 容易遗漏的斜向灰色
水印。只检查 `watermark-report.json` 或只搜索 XML 都不构成完成验收。

## 视觉对比

以完全相同的尺寸渲染源文件和转换结果，并检查：

- 标题和正文基线；
- 密集分栏中的换行；
- 蒙版和透明 Logo；
- 图标的尺寸、描边、填充、部件层级和背景修补区域；
- 内嵌流程图的节点、连接线、标签和高亮框均可分别选择；
- 图片与形状交叉处的层级顺序；
- 表格、图表、箭头和时间线；
- 可编辑 OCR 文字下方不存在重复的栅格文字；
- 文字矩阵的检测单元格数与人工盘点一致，`unrecognized_cell_count` 为 0；
- 竖排文字内容、字符顺序和朝向均与源文件一致；
- 扇形和弧形填充没有矩形外溢，所有扇区共享正确圆心和外轮廓；
- 目标水印已消失，且没有误删正常内容或留下修补痕迹；
- 页面边缘、页脚和页码。

像素差异指标只能用于定位可疑页面。即使页面视觉上正确，细微的字体抗锯齿
差异也可能造成较高的数值误差。必须人工检查高差异页面。

## PowerPoint 验证

优先在最终使用文件的平台验证。Windows 使用 PowerShell COM，macOS
使用 AppleScript。Linux 没有 Microsoft PowerPoint，应使用 Presentations
技能渲染器和 LibreOffice 做双重兼容性检查，并在交付时说明限制。完整命令见
[cross-platform.md](cross-platform.md)。

在已安装 Microsoft PowerPoint 的 macOS 上，可以使用 AppleScript 导出
验证 PDF：

```applescript
on run argv
  set inputPath to item 1 of argv
  set outputPath to item 2 of argv
  tell application "Microsoft PowerPoint"
    activate
    open POSIX file inputPath
    delay 2
    save active presentation in POSIX file outputPath as save as PDF
    close active presentation saving no
  end tell
end run
```

使用 Poppler 渲染验证 PDF，并与原始 PDF 对比。这样可以发现
LibreOffice 渲染器中没有暴露、但会在 PowerPoint 中出现的问题。

macOS PowerPoint 首次写入新目录时可能弹出文件夹访问授权。不得绕过系统
权限提示；改为写入已授权目录，或由用户确认授权。

## 交付表述

必须准确说明可编辑范围：

- 文字、图片和简单形状是彼此独立的可编辑对象；
- 原生形状图标可直接修改，复合图标的组成部件可分别选择；
- 独立 SVG 图标可移动缩放，并可在 PowerPoint 中转换为形状后修改路径；
- 独立栅格图标只能移动、缩放、裁剪和替换，内部路径不可编辑；
- 曲线是 SVG 矢量对象，可在 PowerPoint 中转换为形状；
- 复杂照片或扁平化插画仍为栅格图片；
- 为避免 OCR 错误，被排除的截图或技术论文页面仍为栅格图片；
- 明确重建的图标、图表和表格是原生可编辑对象；
- 文件已经完成打开、渲染和画布溢出检查。
