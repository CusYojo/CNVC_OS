# 证据检索与缓存流程

## 默认顺序

1. **本地项目资料库优先**：先检索当前项目的上传原件、知识片段、访谈或会议材料、项目档案和用户补充输入。
2. **缓存公开证据复用**：继续检索项目资料库中此前保存的 `public_web`、`public_web_official` 或等价公开来源缓存。缓存符合本次资料截止日、主体和问题口径时直接复用。
3. **关键缺口识别**：只列出会改变当前阶段判断、下一步推进或暂缓/归档建议的缺口，例如主体身份、股权与治理、创始人与团队、产品状态、知识产权、融资与估值、客户验证、财务和交易安排。
4. **进程内候选发现**：只围绕上述缺口检索具体公司、项目、人员、产品或事件，发现候选 URL。优先使用公司、研发或合作机构、政府或监管部门、投资方、客户、专利和论文等一手来源。
5. **LLM Gateway 页面核验**：实际打开候选页面，核验当前项目主体、正文、发布主体、发布时间和资料截止日，只提炼与缺口直接相关的有限证据。
6. **缓存写回与复用**：只将页面核验通过的补全结果保存回当前项目资料库，后续任务先读缓存再决定是否联网。

## 联网边界

- 除非用户明确要求只联网搜索，否则不得跳过本地项目资料库。
- 不得以宽泛赛道词、行业趋势或政策主题作为第一步全网检索。
- 不调用或依赖 SearXNG；只使用运行环境已提供且获授权的其他联网能力。
- 进程内检索摘要、搜索结果页、聚合摘要、无法打开的 URL、主体不匹配或晚于资料截止日的页面只能作为被拒绝的线索，不得进入 Evidence、正文或缓存。
- 本地证据已经足以支持判断时停止检索，不为增加篇幅而联网。
- 网络信息只能补充项目资料，不能覆盖与项目原件冲突的事实；冲突必须标为待核验。
- 联网不可用、超时、无结果或缓存写入失败时记录审计告警并跳过联网，继续使用本地资料与已有缓存；不得因此中止主文档生成。

## 缓存要求

每条网络补全结果至少保存：

- 项目 ID 和规范化主体名称。
- 查询目的或待补字段。
- 来源标题、发布主体、原始 URL。
- 发布日期或版本、访问时间、资料截止日。
- 支持判断的必要摘录和内容哈希。
- 来源类型、核验状态及其支持的报告字段。

以规范化 URL 与内容哈希去重。以下情形才刷新缓存：

- 缓存晚于本次资料截止日而不可使用。
- 融资、人员、产品、客户、监管状态等时效性事实可能已变化。
- 原始页面更新、失效或与其他来源冲突。
- 缓存不能回答本次具体缺口。

## 用户明确要求只联网搜索

用户明确要求“只联网搜索”“不要使用项目资料库”或同等含义时，按用户要求切换为网络优先。仍须围绕具体主体由主服务进程内公开检索器发现候选来源、由 LLM Gateway 核验页面，只记录和缓存核验通过的来源；不得因此生成泛行业研究报告。
