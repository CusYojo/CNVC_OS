# 模板分析数据规范

## 数据职责

`template_analysis` 是模板文件与生成文档之间的稳定契约。它只描述格式、结构和内容规则，不保存可被误用为当前项目事实的模板示例正文。

## 顶层字段

| 字段 | 要求 |
| --- | --- |
| `schemaVersion` | 分析数据结构版本，当前为 `1.0` |
| `analysisVersion` | 规范化分析数据的 SHA-256 版本 |
| `format` | `docx` 或 `pptx` |
| `fileName` | 经服务端清洗后的原模板文件名 |
| `formatProfile` | 格式画像 |
| `structures` | 按原模板顺序排列的结构数组 |
| `summary` | 不含模板示例事实的分析摘要 |

## 格式画像

必须尽可能提取：

- 字体：字体集合、正文字体、标题字体。
- 字号：文档标题、章节标题、正文。
- 段落：行间距、段前段后、对齐方式。
- 页面：页面或画布尺寸、方向、页边距或文本框布局。
- 视觉：主要颜色、页眉、页脚、页码。
- 元素：表格数量、图片或媒体数量。

未显式声明的属性必须标记为“按模板继承”或 `null`，不得猜测为确定值。

## 结构数组

每个结构包含：

| 字段 | 要求 |
| --- | --- |
| `order` | 从 1 开始的原模板顺序 |
| `title` | 章节标题或幻灯片标题 |
| `level` | 文档标题层级；PPTX 默认一级 |
| `contentPurpose` | 该结构承担的业务作用 |
| `contentSummary` | 对示例内容特征的抽象描述，不复制敏感事实 |
| `contentRequirements` | 当前项目生成该结构时必须满足的规则 |

## 版本计算

1. 对不含 `analysisVersion` 的分析对象做稳定 JSON 序列化。
2. 计算 SHA-256。
3. 保存为 `sha256-` 加前 12 位十六进制字符。
4. 原模板 SHA-256 与分析版本分别保存，二者不得混用。

同一模板重新分析时生成新的分析版本；历史任务继续关联创建时使用的版本。
