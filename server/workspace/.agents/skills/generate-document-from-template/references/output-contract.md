# 文档生成与质量规范

## 输入

- 当前用户、项目和会话。
- 原模板文件及其 SHA-256。
- 指定版本的 `template_analysis`。
- 资料截止日、用户参数、本地项目资料库证据、已缓存公开证据、必要的定向网络补全、项目档案和用户补充输入。

## 内容生成

1. 以投资中台资深投资经理身份撰写供投资团队、投资总监和投委会内部审阅的投资材料，结论先行，避免内部过程描述和空泛套话。
2. 保持分析数据中的内部结构槽顺序和层级，但重新拟定全部可见章节标题。
3. 对封面、目录、正文、附录和引用页使用与当前项目及具体线索匹配的全新内容。
4. 正文事实优先来自本地项目资料库、项目档案和用户补充输入；只对关键缺口先由 Flue 发现候选来源，再由 LLM Gateway 联网证据服务实际打开并核验页面，并优先复用项目资料库中的已核验公开证据缓存。模板示例正文、Flue 搜索摘要、搜索结果页和未通过主体或日期核验的页面不得进入输出。
5. 文档标题必须包含当前项目、公司或线索主体并重新生成，不得使用上传文件名或原文档标题。
6. 报告必须围绕当前项目的主体、股权与治理、团队、产品与技术、市场与客户、商业模式、财务、融资与估值、交易方案、风险和可核验来源展开；没有具体主体支撑的行业、政策或市场描述应删除或压缩为与主体直接相关的背景。
7. 单项目报告在证据能够支持时，应结合当前阶段用自然语言给出推进、继续观察、暂缓或归档方向；批量报告按证据分别给出各主体方向。证据不足时可以暂不下阶段结论，不得为了命中固定阶段词或固定字段硬造内容。
8. 阶段方向、判断依据、关键风险、前置条件和下一步动作应按阅读逻辑写入连贯段落，可以拆分、合并或省略重复内容，不要求全部出现在同一句或同一段；不使用“阶段与推进建议：”“判断依据：”“关键风险：”等“标签：内容”的冒号式短句。
9. 数字注明期间、单位和口径；证据状态与来源索引保留在内部审计结构，但客户可见文字不得出现“【资料记载】”“【待核验】”“【AI推断】”、Markdown 粗体状态词或状态徽标。
10. 不输出“资料缺口”状态、标题、清单或占位文案；经过缓存复用和定向网络补全仍未覆盖的事项只在自然段中形成简洁的核验边界。
11. 同一事实只在一个主结构完整陈述，其他位置只允许简短交叉引用。
12. 文末或最后一页只列正文实际使用的来源，并包含责任声明。
13. Flue、LLM Gateway、单个页面访问、模型或内容 Reviewer 异常时删除无依据内容，保留相应结构并留空或写成简洁待核验边界；不得复制相邻结构内容，不得把技术报错写入客户文档，也不得阻塞主文档生成。

## 格式生成

### DOCX

- 使用分析数据中的页面尺寸、方向、页边距、字体、字号、行距、段距和对齐方式。
- 正文、标题、表格、页眉页脚和页码保持可编辑。
- 保持结构层级，避免将整页内容栅格化。

### PPTX

- 使用分析数据中的画布比例、主题字体、字号、颜色和幻灯片顺序。
- 文字、表格、基础图表和形状保持可编辑。
- 背景、照片和复杂装饰可作为图片使用，但不得把核心业务内容整体图片化。

## 交付前检查

- 文件可由 Microsoft Office 和 WPS 打开，无修复提示。
- 中文无乱码，字体缺失时使用安全替代字体。
- 格式画像的关键令牌已应用。
- 结构完整且顺序一致。
- 报告角色为投资中台资深投资经理，正文不呈现为泛行业研究报告。
- 证据能够支持时，每个被分析主体均有与当前阶段匹配的推进、继续观察、暂缓或归档方向及具体理由；证据不足时明确不下阶段结论。
- 项目主体、股权与治理、团队、产品与技术、客户、财务、融资、交易或风险判断可追溯至实际来源。
- 建议不声称已经改变项目阶段，阶段流转以 OA 审批结果为准。
- 本地项目资料与网络补全来源区分清楚；审计记录可区分 Flue 候选发现与 LLM Gateway 页面核验，只有核验通过的页面已去重并可缓存复用。
- 无大段重复内容或连续重复句。
- 引用可定位到实际使用的项目资料。
- 交付物不含“资料缺口”标签或占位文案。
- 交付物不含“阶段与推进建议：”等冒号式标签，不含“【资料记载】”“【待核验】”“【AI推断】”或同类可见状态标记；正文以完整自然段呈现。
- 模板原文档标题、可见章节标题、页眉页脚、示例项目名称、人员、客户和数字没有泄漏到交付物。
- 可选预览或伴生转换失败不影响已通过格式、中文编码和可打开性检查的主 DOCX/PPTX 交付。
