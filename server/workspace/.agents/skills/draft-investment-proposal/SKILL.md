# 起草正式投资提案

## 默认产物

直接生成一份可编辑DOCX，并由冻结后的DOCX原生导出一份同内容PDF；两份文件使用相同主文件名，内容和语气接近内置九份赛智投资提案，而不是输出分析过程。

- 默认篇幅4—9页；材料特别丰富时可适度增加。
- 默认定位为提交投资决策委员会审议的正式提案。
- 只给公司名称时，先读取当前项目资料并定向检索公开信息，形成正式提案初稿；不得因私有数据缺失把全文改写成核验清单。
- 已有交易方案时写明投资主体、金额、方式、估值和股比；没有交易方案时不得编造，只在交易章节用一段话简要说明尚未确定的项目。
- 除非用户明确要求，不生成独立尽调报告、风险审查稿、谈判授权稿、Manifest、评分报告或计算日志。

## 工作流

### 1. 读取资料

- 逐份读取当前项目内与目标公司有关的材料。
- 只给公司名称或需要更新公开事实时，定向检索公司官网、工商/监管、投资机构、合作方和可靠媒体。
- 内部区分工商或交易文件、公司披露、管理层预测、公开线索和分析判断；最终正文不显示内部状态标签。

### 2. 统一口径

建立简短的内部数据表，至少复核：

- 公司全称、投资主体、实际控制人和日期；
- 收入、成本、毛利、毛利率和净利润；
- 历史轮次、本轮金额、投前/投后估值和投后股比；
- 增资、老股、SPV和完全稀释口径；
- 预测年度、实际值A和预测值E；
- 可比公司数据时点和单位。

任何数字进入正文前必须勾稽。冲突无法消除时并列说明口径，不擅自选择更有利数字。

### 3. 选择案例结构

默认使用资料包最常见的简明结构，不强制固定节数：

1. 公司基本情况简介；
2. 本次交易方案或交易条件；
3. 公司业务计划；
4. 项目亮点总结；
5. 仅在材料已有明确风险分析或用户要求时增加风险提示；
6. 仅在扩展型提案中增加独立结论。

二级标题按材料实际存在的内容选用。没有股权表、历史融资、预测或可比数据时，省略相应表格或小节，不为补齐结构制造长篇缺口说明。

### 4. 写成案例语体

- 开篇沿用正式请示语，直接说明投资主体、目标公司、投资方式和提请审议事项。
- 公司、团队、产品、客户、财务和交易事实直接陈述；公司自述可用“公司披露”“公司预计”等自然限定。
- 每段围绕一个中心意思，优先使用案例中的机构书面语。
- 风险控制章节只摘要实际已谈或明确拟议的交易条款。没有条款时不得自行设计回购率、清算倍数、董事席位或终止条件。
- 项目亮点用三至四点概括，每点由事实支持；不得把亮点改写为核验任务。
- 正文不反复出现“应核验、应取得、未满足则终止、交易响应”等尽调工作语言。

### 5. 表格与计算

- 财务、融资、交易、预测和可比估值优先使用原生表格。
- 毛利必须等于收入减成本；毛利率必须与毛利/收入一致。
- 持股比例必须说明按本轮全部融资完成后还是单笔交割计算；增资与老股相加时按交割后完全稀释股本复核。
- 投前、投后、综合入股成本和老股定价必须分别命名，不混用“公司估值”。
- 只有材料已有退出预测或用户明确要求时才计算MOIC/IRR；不得为通过门禁强制创造情景模型。

### 6. Word生成、PDF导出与验收

- 唯一默认版式权威为`assets/primary-layout-authority.docx`，源自佳量脑科学案例；从工作副本生成，保留其A4页面、页边距、页眉页码、样式和中文自动编号。
- 主标题宋体16pt加粗、居中、段后6pt；称谓仿宋12pt加粗、顶格，并同时清除首行缩进和左缩进；普通正文仿宋12pt、首行缩进480 DXA，使用模板1.5倍行距。
- 一级标题使用黑体和`一、`编号，二级标题使用楷体和`（一）`编号；二级标题在每个一级标题下重新从`（一）`开始。
- 一级标题统一增加12pt段前距、段后0；不插入空白段落，也不复制蓝成应急约49pt的大空白。
- 表格采用佳量式`C0C0C0`灰色表头和黑色0.5pt全框线，表格文字10.5—11pt，数字右对齐。
- 文末公司署名和日期各占一段，仿宋12pt，清除缩进并右对齐到正文右边界；不得做成正文左侧缩进。
- 只有用户明确指定另一案例时才切换对应表格或页面样式。
- 根据实际内容生成3—6个一级标题和必要的二级标题，不再强制6个一级标题、11个二级标题或17节。
- 运行：

```bash
python scripts/validate_jialiang_style_fidelity.py final.docx
python scripts/validate_proposal.py final.docx --render-dir render
```

- 逐页检查标题、表格、分页、空白、数字和落款。若需修复，只修改DOCX并重新运行全部门禁。
- DOCX冻结后，优先使用WPS文字原生PDF引擎；当前环境没有WPS时，使用Microsoft Word原生PDF引擎，并以最终PDF逐页视觉检查为准：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/export_pdf_word.ps1 -InputDocx final.docx -OutputPdf final.pdf
```

- 当前环境没有WPS或Microsoft Word时，才使用文档技能提供的LibreOffice转换工具；不得单独排版、编辑或修补PDF。
- DOCX与PDF必须位于同一交付目录、主文件名完全一致；PDF必须由最终冻结的DOCX重新导出。
- 将最终交付PDF渲染为逐页图片，检查全部页面；然后运行：

```bash
python scripts/validate_pdf_pair.py final.docx final.pdf --render-dir pdf-render
```

- 任一PDF页存在溢出、空白页、截断、字体替换或编号异常时，回到DOCX修复、重新校验、重新导出PDF；最终只交付这一对DOCX和PDF。

## 禁止状态

- 将公司名称输入自动扩写为以问题、待办和终止条件为主的风险审查稿；
- 强制要求所有项目都有三情景MOIC/IRR、可比公司表或三张财务报表；
- 把公开线索写成已核验事实，或编造交易金额、估值、股比和保护条款；
- 同一缺口在多个章节反复出现；
- 大段复制交易协议或尽调清单；
- 交付Manifest、JSON、日志、渲染图、多份候选DOCX或额外PDF；
- 从未冻结或未通过门禁的DOCX导出PDF，或让DOCX与PDF内容、主文件名不一致。

## 交付

只交付一份正式投资提案DOCX和一份由该DOCX原生导出的PDF，两者主文件名相同；并用一句话说明提案采用的投资方案和数据截止日。若关键交易信息尚未提供，可说明该文件为正式提案初稿，但正文仍保持案例提案体例。
