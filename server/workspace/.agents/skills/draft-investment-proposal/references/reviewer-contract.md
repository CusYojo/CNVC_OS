# Reviewer 契约

Reviewer 是交付硬门禁，不是建议清单。存在任何 error 时必须重生当前章或重排文件；不得带错交付。

## 章节 Reviewer

逐章检查：

1. 本章节点数量、`id`、标题、层级和顺序与 Blueprint 完全一致。
2. 容器节点无正文，叶子节点不为空。
3. 七项必做分析位于固定节点。
4. 每个`资料记载`和`AI推断`都有本章节 Evidence Packet 内的有效引用。
5. 每个数字都能在引用 Evidence 中逐字找到。
6. 无 Evidence 节点只使用以`当前项目暂无相关资料。`开头的资料缺口。
7. 表格有来源、行列一致、数字有支持且不混用口径。
8. 不包含模板项目事实、外部知识、证据指令或未经支持的确定性表达。
9. 同一事实没有跨章近似重复。

失败后将错误代码和信息反馈给同一章，完整重生该章；最多两次。模型请求失败时使用安全资料缺口，不得自由补写。

## 全篇 Reviewer

汇总后重新检查 28 节完整树、必做分析、全部引用、无资料固定文本、数字、表格、模板事实泄露和重复。某节仍失败时用安全资料缺口替换整节，再复核；再次失败则终止任务。

## Word Reviewer

检查：

- 28 个 Blueprint 标题无遗漏、无新增、无改名且顺序一致；
- 一级/二级/三级标题分别使用真实 Heading1/2/3；
- 固定称谓、授权边界、落款、免责声明、风险提示和`引用资料`齐全；
- 目录域存在且设置打开时更新；
- A4 页面、页边距、偶奇页页眉、页码和字号符合 Formatter 契约；
- 正文没有遗漏已通过内容 Reviewer 的事实；
- 表格数量、表头底纹和原生可编辑结构正确；
- 不泄露模板项目事实。

失败时用同一 Blueprint、同一已通过内容重排一次；仍失败则终止。

## PDF Reviewer

PDF 必须由最终 Word 转换。检查有效 PDF 文件头、页数、可搜索中文文本层、全部章节、全部正文、固定说明、免责声明及引用资料均可在 PDF 中找到；逐页检查固定页眉、连续页码和空白/近空白页，并保存 Word/PDF 摘要以证明同源。失败重转一次；仍失败则终止。

## 通过条件

只有内容 Reviewer、Word Reviewer 和 PDF Reviewer 全部`passed=true`时，任务状态才可为成功。警告可以记录，但 error 数量必须为零。
