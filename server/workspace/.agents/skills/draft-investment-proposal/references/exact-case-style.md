| 角色 | 精确实现 |

必须复用上述真实样式。禁止用Title、Heading 1、Heading 2、Normal或系统近似字体重建同名视觉。

## 全框线表

- 适用于股权、融资、交易、风险和产品比较。
- 表头填充`C0C0C0`；全部外边框与内部线为黑色single、`sz=4`。
- 单元格边距：上0、左108、下0、右108 DXA；垂直居中。
- 表头重复；行高只用`atLeast`，基准454 DXA；不允许固定行高。
- 列宽按案例正文宽度分配，内容角色不同不得等宽。

## 财务三线表

- 适用于财务和回报情景，组件源自第二权威第3页。
- 白底，无左、右和内部竖线。
- 表头顶线黑色single、`sz=12`；表头下线`sz=4`；末行底线`sz=12`。
- 表头及行标签宋体10.5pt加粗；数字宋体10.5pt右对齐；单元格固定12pt行距。
- 单元格边距同全框线表。
- 不得直接把辅案例中的数字样式ID复制到主案例。不同DOCX内同一ID可能指向不同类型；必须把辅案例的真实表格样式导入为唯一新ID，并确认`tblStyle`解析到`w:type="table"`。
- 导入时保留辅案例表格样式的段落、字体和单元格属性，但移除第二个默认表格标记；生成表格采用固定布局和已规划列宽，防止渲染器按内容重排后压缩叙述列。

## 执行门禁

1. 生成任务本地`artifact.md`，记录参考路径、指纹、全部精确参数、槽位和保留部件。
2. 生成DOCX后运行`python scripts/validate_case_style_fidelity.py final.docx`。
3. 任一版式错误都必须回到生成器修复；不得在校验器里放宽标准。
4. 再运行提案内容/结构校验并渲染全部页面。
5. 只有版式错误0、内容错误0、逐页视觉缺陷0时才能冻结交付。

“完全一样”按样式身份与可观察版式定义：页面、字体、字号、段落节奏、页眉页脚、标题层级和表格组件与案例一致；项目文字不同导致的自然换行和页数变化不算版式偏差。
