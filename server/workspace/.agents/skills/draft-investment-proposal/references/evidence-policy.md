# 当前项目资料库 Evidence 契约

## 来源优先级与边界

只使用当前任务、当前 `projectId` 且不晚于 `sourceCutoffDate` 的授权资料和可核验公开来源。默认按以下优先级组织，不得静默覆盖：

1. 当前项目知识库中的原始文件、授权档案和经确认记录；
2. 当前项目结构化字段；
3. 用户在本次任务中明确给出的项目数据和事实，来源名为`用户补充输入`；
4. 当前项目中已核验、未失效的网络补全缓存；
5. 针对明确证据缺口新取得并完成来源核验的网络补全；
6. 基于以上证据形成的审慎分析。

模板只提供结构、格式和风格，不能进入 Evidence。其他项目、模型训练知识、未经核验的搜索摘要和未写入当前项目 Evidence Packet 的网络结果不得补齐当前项目事实。缓存或新取得的公开网页证据只作为`待核验`线索，不能替代工商底档、合同、审计报告、股权名册、交易文件等原始证据。

进入 RAG 前排除模板文件、非当前项目资料、越期资料、重复/测试/占位/损坏片段、主体无法对应当前项目的孤立事实。保留文件名、片段定位和资料日期；`待核验`占位值本身不是证据。

## 默认检索与缓存流程

| 阶段 | 输入 | 产出 | 失败处理 |
|---|---|---|---|
| Local Project Retrieval | 当前项目资料库、项目档案、用户输入 | 清洗后的本地证据 | 登记本地证据缺口 |
| Network Cache Retrieval | 当前项目、实体、章节主题、资料截止日 | 可复用网络补全缓存 | 未命中则进入缺口分析 |
| Evidence Gap Analysis | 17 节职责、本地与缓存证据 | 影响判断的具体证据缺口 | 无关键缺口则跳过联网 |
| Flue Candidate Discovery | 具体项目、实体、缺口、资料截止日 | 候选 URL 与检索线索 | 能力不可用或无结果则继续本地生成 |
| LLM Gateway Page Verification | 候选 URL、当前项目、本地证据、资料截止日 | 已打开、主体匹配且日期合规的页面证据 | 单页或服务失败时丢弃该来源 |
| Network Cache Writeback | 已通过页面核验的网络结果及来源元数据 | 当前项目可复用缓存 | 写入失败保留审计告警 |
| Chapter Evidence | 本地、缓存和本次补全证据 | 独立 Evidence Packet | 无证据则固定资料缺口 |

默认顺序固定为：本地项目资料库 → 当前项目网络补全缓存 → 章节证据缺口分析 → 定向网络补全 → 缓存写回。不得一开始就进行宽泛的全网搜索。只有用户明确要求“只联网搜索”或同义指令时，才允许跳过本地优先顺序；仍须限定具体项目和待核验事项，并优先复用相同查询、URL 或内容指纹的缓存。

定向网络补全只允许围绕当前项目的公司主体、股东与治理、团队成员、产品与技术、客户或合作公告、知识产权、融资事件、估值或交易事项、司法监管事件、行业政策和具名可比项目展开。Flue 只负责发现候选 URL；LLM Gateway 联网证据服务必须实际读取页面并核验当前项目主体、发布主体、发布时间和资料截止日。不得为了填满章节而检索泛行业材料，不得将 Flue 搜索摘要、无明确主体的市场宣传、聚合摘要、搜索结果页或不可访问页面加入 Evidence。

网络补全优先使用政府、监管、司法、登记机关、公司、研发或合作机构官网及融资机构公告，其次使用可追溯的专业媒体。网页只提供线索时必须标记`待核验`；工商、财务、合同、股权和交易条款仍须回到一手文件复核。

不恢复或依赖 SearXNG。Flue 或 LLM Gateway 任一不可用、超时、无结果或页面核验未通过时，跳过对应来源并继续使用本地和缓存证据生成受限初稿，不得阻塞整个任务。

## 网络缓存契约

联网前先按当前项目、规范化实体名称、章节主题、查询意图、规范化 URL 和内容指纹检索缓存。来源元数据完整、内容未失效且不晚于 `sourceCutoffDate` 时直接复用；存在过期、缺字段、主体不匹配、内容冲突或明确更新信号时才重新获取。

每条有效网络补全结果至少缓存：

- 当前 `projectId`、规范化实体名称、适用章节和查询意图；
- 页面标题、规范化 URL、发布主体和页面类型；
- 发布日期或更新时间、访问时间和资料截止日；
- 与证据缺口直接相关的有限摘要；
- 内容指纹、缓存写入时间和核验状态。

同一规范化 URL 或相同内容指纹只保留一个有效版本。网络结果与本地资料冲突时不得覆盖本地记录，应同时进入对应 Evidence Packet，披露来源、时点与口径并标记`待核验`。

## 章节 Evidence Packet

为 14 个叶子节点独立评分并选取最多六个片段，同一来源最多三个片段。表格章节优先使用结构化财务、融资、估值、股权或预测资料。

每个 Packet 保留：

- 全局 source index；
- source name/type/id；
- 片段 locator；
- 版本或日期；
- 用于生成的原文；
- 章节覆盖状态。

一个事实只能引用当前节点 Packet 中的来源。亮点、风险和结论可以综合前文证据，但仍需在自身 Packet 中显式提供相应来源。

进入 Packet 前必须删除网页界面与来源审计噪声：`...展开`、`…展开`、`查看更多`等折叠态文本不能作为证据句；`原文链接`、`来源网址`、页面标题、访问日期、内容指纹等只保留在来源元数据。若同一页面同时存在折叠简介和完整工商字段，应舍弃折叠简介，优先保留完整法律主体、成立时间、注册资本、地址和经营范围。证据减载只能在完整句、分号或换行边界结束，不得制造新的截断文本。

## 事实、数字与分析

- 直接事实需有证据明确支持主体、动作、时点和口径。
- 证据事实数字必须逐字存在于引用原文。允许把已核验输入写入 Calculation Ledger 后机械推导持股比例、投前/投后估值、综合入股估值、增长率、MOIC 和 IRR；每项必须保存公式、输入、单位、来源和结果，并由 Reviewer 独立重算。允许明确标注的基础、审慎、乐观情景假设，但不得把情景值写成公司事实、管理层预测或市场共识。
- 分析只能说明已引事实的含义、条件、影响和约束，用户可见状态为`分析判断`。
- 仅由缓存或本次定向补全的`public_web`证据支持的正文和表格一律标记`待核验`，不得升级为`资料记载`或`分析判断`。
- 公司自述、管理层预测、意向订单、框架协议、未审计财务和拟议条款应标记`待核验`或条件性`分析判断`。
- 竞争优势需有专利、客户、性能、成本、交付或第三方验证等项目证据，不得把自述升级为客观领先。
- 融资用途不得从融资金额反推；风险不得虚构已发生事件。

## 冲突与缺口

来源冲突时并列披露双方口径、日期和来源，标记`待核验`，并说明需要核对的原始文件。不得私自选取更有利的数据。

完成本地检索、缓存复用和允许的定向网络补全后，某章节仍没有证据时，允许在受限初稿中保留`资料缺口`内部状态。正文应直接写明尚未明确的具体事实、判断影响、所需原始资料和人工复核要求，不得使用统一的无资料判定前缀，也不得用模板事实、未经核验的网络结果、模型常识、无来源行业平均值或“合理假设”代替。
