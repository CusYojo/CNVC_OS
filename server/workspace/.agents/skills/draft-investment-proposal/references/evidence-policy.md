# 当前项目 Evidence 与 RAG 契约

## 检索边界

只检索当前 `projectId` 的项目档案和项目知识库，且资料时间不得晚于`sourceCutoffDate`。不得检索其他项目、公共互联网或模板正文来补齐当前项目事实。

进入 RAG 前排除：

- 模板文件及名称带有投资提案模板特征的内容；
- 非当前项目 scope/refId 的内容；
- 越过资料截止日的内容；
- 重复、测试、占位、损坏或无可读正文的片段；
- 主体无法对应当前项目的孤立事实。

项目结构化档案只有字段实际包含相关信息时，才能进入对应章节 Evidence。`待核验`占位值不是证据。

## 章节 Evidence Packet

为每个叶子节点独立评分并选取最多六个证据片段，同一文件最多三个片段。优先使用章节关键词命中的当前项目资料；表格章节优先结构化财务、融资、估值、股权或预测资料。

一个事实只能引用当前节点 Packet 中的来源。投资逻辑、亮点、风险及结论可以综合前文项目证据，但仍必须通过其自身 Packet 显式提供来源。

Packet 必须保留：

- 全局 source index；
- source name/type/id；
- 知识片段 locator；
- 版本或日期；
- 用于生成的原文；
- 章节覆盖状态。

## 事实与分析

- 直接事实需要证据原文明确包含其主体、动作和口径。
- 数字必须逐字存在于引用原文；不允许模型暗算派生比例、复合增长率、IRR、MOIC 或估值。
- 分析只能基于已引事实，以条件性语言说明含义、约束或需核验事项。
- 市场空间不得用行业常识或外部市场报告补齐；当前项目没有市场数据时明确无资料。
- 竞争优势不得把公司自述直接升级为客观领先；必须有专利、客户、性能、成本、交付或第三方验证等项目证据。
- 融资用途不得从融资金额反推用途。
- 风险可以由项目证据中的缺口、冲突和条件形成，但不得虚构已发生事件。

## 冲突与不确定性

来源冲突时保留双方口径，标为`待核验`并说明需要核对的原始文件。不得私自选择更有利的数据。预测、未审计数据、意向订单、框架协议和拟议条款不得当作既成事实。

## 无资料

Evidence Packet 为空时，该叶子节点必须只输出一项资料缺口：

```json
{
  "text": "当前项目暂无相关资料。需补充该主题相关原始文件或经确认的项目记录后再行分析。",
  "status": "资料缺口",
  "sourceIndexes": []
}
```

不得用模板事实、外部常识、行业平均值或“合理假设”代替。
