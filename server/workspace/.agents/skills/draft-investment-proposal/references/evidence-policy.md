# 当前项目 Evidence 与 RAG 契约

## 来源优先级与边界

只使用当前任务、当前 `projectId` 且不晚于 `sourceCutoffDate` 的授权资料。冲突时按以下优先级组织，不得静默覆盖：

1. 用户在本次任务中明确给出的项目数据和事实，来源名为`用户补充输入`；
2. 当前项目结构化字段；
3. 当前项目授权档案和知识库；
4. 基于以上证据形成的审慎分析。

模板只提供结构、格式和风格，不能进入 Evidence。其他项目、公共互联网和模型训练知识均不得补齐当前项目事实。

进入 RAG 前排除模板文件、非当前项目资料、越期资料、重复/测试/占位/损坏片段、主体无法对应当前项目的孤立事实。`待核验`占位值本身不是证据。

## 章节 Evidence Packet

为 14 个叶子节点独立评分并选取最多六个片段，同一来源最多三个片段。表格章节优先使用结构化财务、融资、估值、股权或预测资料。

每个 Packet 保留：

- 全局 source index；
- source name/type/id；
- 片段 locator；
- 版本或日期；
- 用于生成的原文；
- 章节覆盖状态。

一个事实只能引用当前节点 Packet 中的来源。亮点、风险和结论可以综合前文证据，但仍需在自身 Packet 中显式提供相应来源。

## 事实、数字与分析

- 直接事实需有证据明确支持主体、动作、时点和口径。
- 数字必须逐字存在于引用原文；不得擅自计算 IRR、MOIC、增长率、比例、市场规模、估值或预测。
- 分析只能说明已引事实的含义、条件、影响和约束，用户可见状态为`分析判断`。
- 公司自述、管理层预测、意向订单、框架协议、未审计财务和拟议条款应标记`待核验`或条件性`分析判断`。
- 竞争优势需有专利、客户、性能、成本、交付或第三方验证等项目证据，不得把自述升级为客观领先。
- 融资用途不得从融资金额反推；风险不得虚构已发生事件。

## 冲突与缺口

来源冲突时并列披露双方口径、日期和来源，标记`待核验`，并说明需要核对的原始文件。不得私自选取更有利的数据。

Evidence Packet 为空时，该叶子节点只输出一项安全缺口：

```json
{
  "text": "当前项目暂无相关资料。需补充该主题相关原始文件或经确认的项目记录后再行分析。",
  "status": "资料缺口",
  "sourceIndexes": []
}
```

不得用模板事实、外部常识、行业平均值或“合理假设”代替。
