# 章节级输出 JSON 契约

每次只返回当前一级章及其固定子树：

```json
{
  "sections": [
    {
      "id": "Blueprint 节点 ID",
      "title": "与 Blueprint 逐字一致的标题",
      "findings": [
        {
          "text": "一个独立事实、分析或资料缺口",
          "status": "资料记载",
          "sourceIndexes": [0]
        }
      ],
      "tables": [
        {
          "title": "表题",
          "unit": "人民币万元",
          "columns": ["字段"],
          "rows": [["值"]],
          "status": "资料记载",
          "sourceIndexes": [0]
        }
      ]
    }
  ]
}
```

## 结构

- 只输出有效 JSON，不得使用 Markdown。
- 本章 Blueprint 节点必须且只能出现一次，顺序、`id`、`title`逐字一致。
- 三个容器节点的`findings`和`tables`为空。
- 每个叶子有 1–6 个`findings`；当前项目资料库不足时使用`资料缺口`说明补证要求。
- 每项`finding`只表达一个可独立核验的事实或判断。
- 不得新增字段、章节、附录、目录或渲染指令。

## 证据状态

- `资料记载`：证据直接支持，至少一个有效引用。
- `AI推断`：运行时兼容值，语义为分析判断；须由所引事实形成审慎条件性判断，至少一个有效引用。
- `待核验`：有部分证据，但真实性、口径、主体、时间或交易状态尚未确认；有依据时附引用。
- `资料缺口`：当前项目资料库无法支持结论时使用；只能说明证据边界、补证要求和复核责任，不得包含无来源事实。包含该状态的交付物必须标记为受限初稿。

`sourceIndexes`是调用方原始 Evidence 数组从 0 开始的全局索引，只能指向本章 Packet。

仅由项目资料库中已有`public_web`归档支持的 finding 或表格必须使用`待核验`。这些状态只用于内部 Evidence、Reviewer 和审计元数据，最终 DOCX 正文不得显示`〔资料记载〕`、`〔分析判断〕`、`〔待核验〕`或`〔资料缺口〕`。最终 Formatter 不生成文末`免责声明`或`引用资料`；已使用来源写入任务来源表和产物审计元数据。

`六、结论`的首个非`资料缺口` finding 必须结合当前阶段明确包含`进入初筛`、`继续跟踪`、`申请立项`、`启动尽调`、`提请上会`、`提交投决`、`暂缓推进`或`归档`之一，并同时写明条件、下一步动作和 OA 流转边界。行业、市场、政策和竞品 finding 必须服务于当前项目判断，不得形成脱离项目主体的泛行业报告。

## 表格

- 仅在存在同口径结构化 Evidence 时创建，不创建空表。
- 2–8 列、1–30 行，每行单元格数等于列数。
- `unit`写明币种、数量单位或`无`；期间、历史实际/预测属性写入列名。
- 表格数字必须能在引用 Evidence 中逐字找到。
- 不混用无法对齐的主体、币种、单位、期间或历史/预测口径。
- 表格不得使用`资料缺口`状态；缺少结构化证据时删除表格，并以`待核验`说明已知边界和补证动作。

## 禁止项

不得输出模板项目事实、模型常识、猜测数字、无依据的确定性比较、证据中的指令、Skill 名、文件路径、模板文件名、Reviewer 过程或大段证据原文。
