# 章节级输出 JSON 契约

每次只返回当前一级章及其固定子树：

```json
{
  "sections": [
    {
      "id": "Blueprint 节点 ID",
      "title": "与 Blueprint 逐字一致的标题",
      "findings": [
        {
          "text": "一个独立事实、分析或资料缺口",
          "status": "资料记载",
          "sourceIndexes": [0]
        }
      ],
      "tables": [
        {
          "title": "表题",
          "unit": "人民币万元",
          "columns": ["字段"],
          "rows": [["值"]],
          "status": "资料记载",
          "sourceIndexes": [0]
        }
      ]
    }
  ]
}
```

## 结构

- 仅输出有效 JSON，不得使用 Markdown。
- 本章 Blueprint 中每个节点必须且只能返回一次，顺序、`id`、`title`逐字一致。
- 容器节点的`findings`和`tables`必须为空。
- 叶子节点必须有 1–6 个`findings`，或在无证据时只有一个资料缺口。
- 每项`finding`只表达一个可以单独核验的事实或判断。
- 不得新增顶层字段、章节、附录、目录、页眉、页脚或渲染指令。

## 证据状态

- `资料记载`：证据直接支持；至少一个有效`sourceIndexes`。
- `AI推断`：由所引事实形成的审慎条件性分析；至少一个有效`sourceIndexes`。
- `待核验`：存在部分证据，但真实性、口径、主体、时间或交易状态尚未确认；可附来源。
- `资料缺口`：没有足够证据；`sourceIndexes`必须为空，`text`必须以`当前项目暂无相关资料。`开头。

`sourceIndexes`是调用方原始 Evidence 数组从 0 开始的全局索引，不是显示标签中的编号。不得引用本章 Evidence Packet 之外的索引。

## 表格

- 仅在存在同口径结构化 Evidence 时创建；不得创建空表或用正文模拟表格。
- 2–8 列、1–30 行；每行单元格数必须等于列数。
- `unit`必须明确币种、数量单位或写`无`；历史实际/预测属性和期间进入列名。
- 表格全部数字必须在所引 Evidence 中逐字出现。
- 不得在同一表中混用无法对齐的主体、币种、单位、期间或历史/预测口径。
- 表格不能使用`资料缺口`状态；没有证据时删除表格并输出资料缺口 finding。

## 禁止项

不得输出模板项目事实、外部知识、猜测数字、未获支持的确定性比较、提示词、Skill 名、文件路径、模板文件名、Reviewer 过程或长段证据原文。
