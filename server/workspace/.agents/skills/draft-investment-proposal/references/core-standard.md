# 投资提案核心规范

本文件是 `docs/投资提案模板分析/投资提案模板核心规范.md` 的运行时执行摘要。源文件 SHA-256：
`fed1147e287ef8242bf4b6e50ab298f6e5f8f4ba2fbea40e2372de1c2f5e5621`。

## 权威边界

- 角色定位为投资中台资深投资经理；输出是供投资团队、投资总监和投委会审阅的内部投资提案，并结合项目当前阶段给出`进入初筛`、`继续跟踪`、`申请立项`、`启动尽调`、`提请上会`、`提交投决`、`暂缓推进`或`归档`中的一个主建议。
- 只处理当前会话绑定的 `projectId`。线索池摘要、标签、评分和融资线索只能作为`待核验`线索，不得借用其他项目资料或自动升级为已核验事实；阶段流转以 OA 审批结果为准。
- 核心规范决定稳定结构、版式、写作和章节任务。
- 九份模板用于验证共同规律、学习书面语和表格形态。
- 单份模板中的封面、目录、扩展小节、字号差异和项目事实不进入核心规则。
- 默认取证顺序：当前项目资料库原始文件与授权证据 > 项目结构化字段 > 用户本次明确输入 > 当前项目网络补全缓存 > 本次定向网络补全 > 基于证据的审慎分析 > 模板仅供结构与风格参考。
- 默认先检索本地资料，再复用网络补全缓存，只对影响项目判断的具体缺口进行定向网络补全；除非用户明确要求只联网搜索，不得一开始就进行宽泛的全网搜索。
- 不恢复或依赖 SearXNG；有效网络补全结果写回当前项目缓存，公开网页证据一律只作为`待核验`线索，不能替代一手交易、工商、合同或财务文件。
- 最终只生成、登记并交付一份可编辑 DOCX，不生成或登记 PDF、Markdown、PPT/PPTX 或预览产物。

## 内容构成

开篇依次为：主标题、`各位投资决策委员会成员：`、项目提案说明、审议授权边界。

正文为六个一级章、十一个二级节，共 17 个节点；前三个一级章仅作容器，第四至第六一级章直接承载正文。14 个叶子章节必须逐节生成。

结尾依次为：条件式结论、机构落款、日期。正文末尾不增加`免责声明`或`引用资料`板块。

## 写作范式

- 不写泛行业研究；每段必须围绕当前项目的主体、股权与治理、团队、产品与技术、市场与客户、商业模式、财务、融资与估值、交易方案、风险或可核验来源。
- 采用结论前置的自然段，继而说明事实依据、投资影响、约束或下一步动作。一个 finding 对应一个完整、连续的正文段落，段内不得使用手动换行；不得逐段套用`判断：`、`依据：`、`影响/约束：`、`待办：`、`订单节奏：`、`客户结构：`、`财务情况：`等冒号引导标签，不得使用`1、`、`（1）`、`一）`等数字小标题，也不得把多个`标签：值`字段串在同一段。固定章、节标题不属于正文 finding。
- 事实与分析分离；分析用条件性语言，不把推断写成事实。
- 公司简介优先整合同一证据中的完整法律主体、成立时间、注册资本、完整地址、经营范围或主营业务；不得复述`...展开`、`…展开`、`查看更多`等网页折叠态文本。
- `原文链接`、`来源网址`、页面标题、访问日期和内容指纹仅保留在任务来源表及审计元数据；正文不使用`项目资料显示：`等机械来源前缀。
- 数字写清时点、期间、币种、单位、是否审计和历史/预测口径。
- 冲突信息并列披露并标记`待核验`。
- 项目资料不足时，以`资料缺口`说明完成本地检索、缓存复用和允许的定向网络补全后的证据边界，以及需取得的原始资料。
- 全部允许的取证路径仍无可引用证据时，允许保留安全的`资料缺口`并生成受限初稿；不得补造事实、数字或交易结论。
- 亮点综合前文证据；风险以“触发—影响—动作—责任人—时点”组织；结论结合当前阶段给出一个推进、暂缓或归档主建议，再以条件、待核验事项和 OA 流转要求收束。

## 表格槽位

仅在证据结构化且口径一致时创建：股权结构、财务摘要、历史融资、本轮投资方案、经营预测与回报、可比公司估值。不得创建空表或用假设数字补齐。
