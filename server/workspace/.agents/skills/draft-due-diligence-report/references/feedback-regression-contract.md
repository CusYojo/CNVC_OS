# 历次反馈回归契约

本文件把用户对历次报告的纠偏固化为新版技能的默认验收标准。它约束结构和质量，不提供任何目标公司事实。样例公司、人员、客户、金额、估值和结论永远不得复制到新项目。

## 1. 总体原则

- 输出必须是完整上会尽职调查报告，不得退化为投资提案、宣传稿或问题清单。
- 样例负责定义视觉角色、章节顺序、表格表意和内容颗粒度；目标项目资料负责提供全部事实。
- 先做`章节—表格—字段—证据`映射，再写正文。标题与内容必须同义，禁止为凑版式把无关事实填入既定表格。
- 用户指出一处问题后，必须横向扫描同类表格、同类字段和相邻章节，开放缺陷清零后再交付。
- 默认执行“试用—发现缺陷—修复—全量重测—逐页验收”闭环；只修改说明文件或只通过脚本退出码均不算完成。
- 字体与内容深度按`assets/style-profile.json`和`content-density-contract.md`执行；所有表格文字严格12pt，不得通过局部缩字号容纳堆叠内容。
- 表格版式按`assets/table-layout-profile.json`和`table-role-contract.md`执行；不得把所有第一行当表头或把所有行设为不可跨页。
- 表格行距按角色显式写入：标签/表头1.15倍，普通表体1.5倍，段前段后为0；只有配置列明的密集财务表体可使用1.15倍。表3和表5的叙述正文出现单倍行距属于发布阻断。
- 默认交付物是尽调完成后、用于投委会决策的`investment-recommendation`终稿。可见报告属于投资经理决策层，证据缺口、补件任务和核验过程属于内部审计层；不得把进行中的尽调语言带入终稿。

## 2. 封面与目录硬约束

### 封面

- 公司全称与`上会尽职调查报告`分成两个独立居中段落，使用参考报告同角色字体、字号和间距。
- 封面不得出现横线、段落边框、外框、装饰表格、文本框或形状。
- 团队与日期分别居中置于页面下部；不得借助空表格定位。
- 封面公司名、报告名、团队和日期之外不得残留样例事实或旧项目字段。

### 目录

- 目录必须由真实标题样式和Word TOC/PAGEREF域生成，显示点引导符和实际页码。
- 目录不得用表格模拟，不得出现全部为0的页码，不得手工录入页码。
- 正文冻结后更新全部域；若当前环境不能刷新，设置打开时更新域，并在Word/WPS最终导出前刷新。

### 目录后的结构闭合

- 目录后直接进入`1、投资概要`，并按样例进入`1.1 公司情况`；不得插入“报告基础与范围”“编制说明”“证据口径”或同义说明块。
- 内部证据编号仅用于工作底稿。交付正文、表格、脚注、尾注和附录出现`SRC-*`、`CLAIM-*`、工作路径或表后来源串，均为发布阻断错误。
- 表格之后只允许使用模板对应位置原有的正文槽位；模板未设置表后正文槽位时，下一可见块必须是既定标题或下一张表。不得在每张表后新增复述、来源说明或“行业判断/项目判断”。
- `行业判断`只可作为内部推理描述，不能成为样例外标题或固定段落标签；行业内容写入`1.3 行业概况`及第5章既有标题。

## 3. 内容颗粒度与语义契约

### 1.1 公司情况

固定语义字段为：`公司名称`、`成立时间`、`注册地址`、`实际经营地址`、`法定代表人/实际控制人`、`主营业务`、`发展阶段`、`核心判断`。

- 注册地址必须来自工商或公司登记材料。
- 实际经营地址必须来自办公、研发、租赁、访谈或现场材料。终稿直接写最终确认地址；地址字段只写地址，不得混入租赁面积、租期、租金或“同一园区”等说明。
- 发展阶段必须同时回答技术、产品、客户/收入和组织治理处于何种阶段，但只保留一项自然结论；`核心判断`保持一段简洁结论，不复制估值计算、现金流调整或风险控制过程。右栏不得以“中心判断：”或其他写作标签开头。

### 1.2 交易要点

- 只使用`transaction-register.json`中`current_round_id`的最新交易文件；上一轮金额、估值、投资人和条款不得进入本轮摘要。1.2、7.2和末章使用同一组`report_assertions`并通过旧条款禁入检查。
- 最后一行优先使用`主要权利与交割安排`，把保护性权利、付款、交割和工商变更写成具体交易事实。
- 禁止“交易实施按签署文件、付款安排与工商变更口径执行”及语义等价表述；“口径”只用于财务、估值和计算基础。

### 1.3 行业概况

固定行标签为：`行业所处发展阶段`、`市场环境`、`关键影响因素`。

- 每一行至少写2—3个自然段，以自然句完成“阶段/环境结论—关键驱动与约束—对目标公司的影响”，每行不少于180个非空白字符，不重复交易、客户收入计算或财务调整。不显示“中心判断”“事实基础”“投资影响”等推理标签。
- 颗粒度应覆盖技术演进、真实数据或供应链、基础模型/泛化、商业化生态、客户验收等与项目相关维度。
- 禁止只写宏观口号，也禁止为满足字符量堆叠重复论点；外部事实须有来源和日期，无法联网核验时不得编造。

### 1.5 投资价值与风险

固定行标签为：`投资价值`、`主要风险`。

- 投资价值从赛道/需求、技术路线、数据闭环、客户或收入验证、团队与生态、交易与估值中的适用维度选择3—5项展开。
- 每一点均须有标题和至少3个自然段；编号从`（1）`连续递增，不得出现孤立编号、空编号或跳号。投资价值单元格不少于650个非空白字符。
- 价值必须说明“事实—能力—商业/投资意义”，不能把产品模块清单或泛泛优势当作价值判断。
- 投资价值只写项目特定的正向逻辑及必要证据，不追加`但`、`仍需`、`取决于`、`建议核验`或`不能直接证明估值`等防御性尾句；风险集中写入`主要风险`行并使用闭环处置表达。
- 主要风险不重复财务章节中的净亏损、负现金流等原始金额；如其影响投资，仅写投入期属性、投资影响和已形成控制安排。

### 2.1 公司基本信息

- 注册资本只写截至报告日工商登记数；实缴资本、历次增资和投后资本分别归入历史沿革、财务或投资方案。
- 住所、经营范围、治理和资质字段只承载本字段事实，不把交易测算、估值口径或财务分析写入工商表。

### 2.4 核心团队

- 每名核心成员使用独立三级标题。
- 每人至少覆盖现任职责、教育背景、关键任职经历、代表项目/成果和与公司业务的匹配性；资料支持时补充任职期间、资格证书或产业资源。
- 禁止用一句话简介、仅列学校和职位、或把取证状态当作履历内容。

### 2.3.1 公司股东

- 固定使用`股东｜认缴注册资本（万元）｜持股比例`，呈现报告基准日已经生效的股东结构和实际控制关系。
- 已签署生效但尚未登记的历史融资可在表前用一句事实说明其状态；本轮拟实施交易完成后的投后结构必须移至`7.2 公司估值与投资方式`。
- 本节禁止使用`投后股东`、`模拟投后股东`、`模拟认缴注册资本`、`模拟持股比例`、`协议附件拟投后股东`、`管理层Cap Table模拟投后股东（两批融资全部完成）`等本轮交易或推演过程标题。

### 2.7 资质、认证及荣誉情况

- 使用`类别｜资质、认证或荣誉情况`表头，第一行灰底加粗；不得使用“核验结果”等审计过程语言。
- 数据行只列业务资质、体系/产品认证、政府或行业认定和荣誉。诉讼、处罚、失信、债权债务、房屋租赁、劳动社保、数据与测绘、环保消防移至法律分析或第8章风险。
- 第一列居中，第二列左对齐；长行允许跨页，跨页时重复真实表头。

### 2.5 组织架构

默认成果物为组织架构图，不再固定输出`部门｜人员配置｜主要职责`表。

- 优先复用资料中的清晰原图；原图不可用时根据已核实的部门、人员和汇报关系重绘。
- 图中节点文字使用与报告一致的中文字体并保持可读；层级过宽时使用横向页面，不缩小为难以辨认的图片。
- 图片替代文本写入全部已核实节点标签和汇报关系；校验器按用户/台账提供的`expected-org-label`逐项检查，只有一张无语义图片不能通过。
- 图下用2—4段说明经营管理层、核心部门职责、汇报关系和当前组织阶段。
- 人数、人员、劳动/社保/个税和访谈结果必须在内部完成勾稽；冲突未形成最终口径时阻断终稿，不把冲突处理过程写入可见报告。

### 2.6 关联公司及关联交易

- 表头使用：`关联主体或事项｜关联关系及投资相关情况`。
- 数据行按项目重大事实动态生成，写明关联主体、关系、控制/持股、重大往来及权利边界；不得为了凑固定行保留无实质内容的`关联往来`或`个人往来`。
- 涉及控制权、资金占用、利益输送、税务、竞业、知识产权或数据权属的事项不受金额限制；其他关联交易按金额与公司规模的重要性筛选。
- 单笔及累计均低于1万元、已结清且属于正常报销/临时垫付的个人往来，默认留在内部台账；存在持续余额、异常性质或治理冲突时仍应披露。
- 经营亏损、经营现金流、融资性现金流和估值调整不是关联关系事实，禁止写入本节。
- 右栏只写关联身份、控制/持股/任职事实、重大往来及已形成的离任、退出、权属或交易安排；不在关联事实后追加“避免/防范……冲突”、“相关不利后果由……承担”等目的性或风险解释。实质性竞业、权属或利益冲突只在第8章分析一次。

### 3.1 产品概念总览

必须分为两张语义独立的表：核心产品使用`核心产品｜产品定义/核心功能｜应用场景/目标客户｜商业化进展`；核心技术使用`核心技术｜技术描述/原理｜技术来源/权属｜技术门槛/产品作用`。不得把认证、资质或专利清单写成产品/技术描述，也不得在两表中复制同一段内容。

### 3.5 核心技术沿革

固定表头为：`年份｜代表成果｜对现有产品/技术的作用`。代表成果必须是已核实的论文、算法、产品、测试或工程里程碑；第三列解释其如何沉淀为公司当前路线，禁止改成`资料可核验进展｜成熟度判断`。

### 4.1 商业模式与销售策略

表头按目标公司的客户采购和交付语言选择，不再固定使用`商业验证`列。项目制技术/数据服务优先使用`业务板块｜主要产品/服务｜收入来源｜销售与交付方式`；软件平台可使用`产品/服务｜收费模式｜获客方式｜交付与续费`；硬件可使用`产品线｜销售模式｜交付方式｜收入构成`。合同、验收、开票、回款和复购集中归入`4.2 客户验证情况`，不在4.1重复。

### 6.1 业务拓展规划

固定表头为：`阶段｜研发目标｜商业目标｜组织目标`。规划、预测和管理层愿景必须与历史实际分开标识，不能写成已实现事实。

### 人员与收入预测表

- 人员预测表首列为`人员类别`，其后仅列资料支持的连续预测年度。
- 收入预测表首列为`营业收入构成`，其后仅列资料支持的连续预测年度。
- 期间与单位必须独立清晰；不得把日期、单位或预测性质藏入正文。

## 4. 27张表格角色契约

严格样例模式下，报告包含27张原生表格。首行角色依次为：

1. 公司名称（公司情况键值表）
2. 投资主体（交易要点键值表）
3. 行业所处发展阶段（行业概况键值表）
4. 商业路径（商业模式键值表）
5. 投资价值（投资价值与风险键值表）
6. 公司名称（公司基本信息键值表）
7. 时间｜事项｜注册资本/融资
8. 股东｜认缴注册资本（万元）｜持股比例
9. 主体｜上层持有人或合伙人｜穿透要点
10. 组织架构图成果物（可使用单元格容器保持模板位置，但不得呈现旧人员配置表）
11. 关联主体或事项｜关联关系及投资相关情况；数据行按重大事项动态生成
12. 类别｜资质、认证或荣誉情况
13. 核心产品｜产品定义/核心功能｜应用场景/目标客户｜商业化进展
14. 核心技术｜技术描述/原理｜技术来源/权属｜技术门槛/产品作用
15. 应用场景｜解决方案
16. 年份｜代表成果｜对现有产品/技术的作用
17. 知识产权类别｜权属及进展
18. 按业务适配的商业模式表，例如业务板块｜主要产品/服务｜收入来源｜销售与交付方式；不使用“商业验证”固定列
19. 主要成本项｜成本构成/采购情况
20. 细分市场｜近期机会｜中期空间
21. 阶段｜研发目标｜商业目标｜组织目标
22. 人员类别｜资料支持且至少有一项数据的预测年度
23. 单位：万元｜实际期间列；纵向分利润表、资产负债表、现金流量表
24. 营业收入构成｜资料支持且至少有一项数据的预测年度
25. 投资亮点｜业务基础｜投资价值
26. 退出路径｜实现条件
27. 风险类别｜具体风险描述｜风险控制安排

表格视觉角色保持稳定，业务表头按`table-semantic-contract.md`适配目标公司的业务语义。项目材料不支持某个业务表时，应合并、调整或删除不适用的数据行，不能用范围限制、证据状态、排除口径或不相干内容填充。

版式角色另按四类执行：表1/2/6为`key_value_short`，表3/4/5为`key_value_narrative`，表22—24为`financial`，其余为`matrix`。键值表没有表头行；叙述键值表右栏左对齐且允许长行跨页。表12为带真实表头的资质荣誉矩阵。普通矩阵表表头使用`D9D9D9`，财务表头使用`D7D7D7`。具体重复表头、列对齐、段落行距和拆分策略以`assets/table-layout-profile.json`为唯一机器权威。

## 5. 投资经理决策层契约

- 上会尽调终稿默认使用`investment-recommendation`。用户明确说明已经决定投资、确定投资、本轮要投或要求按已决定投资的投资经理视角写作时使用`final-investment-decision`；报告阶段不得改变交易文件真实的签署/生效状态。
- 交付DOCX/PDF只承载已经核实的事实、已经形成的分析判断、明确的投资影响和已经落实/接受的控制安排；来源定位、补件记录、待办任务和非重大覆盖限制只存在于事实台账、冲突表、`open_issues`和QA日志。
- 每个重大事项在内部台账中必须归入`已核实`、`已接受不利事实`、`已落实交易控制`、`明确投后责任`、`非投资逻辑/估值基础`或`不影响投资结论`。这些状态标签和排除理由不进入可见报告；可能反转投资结论且仍未闭环的事项直接阻断终稿。
- 已核实的不利事实不得删除，但应写成已经形成的投资判断和处置结果，不写成“建议补充”“仍需核验”或“未达标时再决定”的开放任务。
- 投资理由和综合评价禁止使用“公司所处赛道具有长期需求，但行业关注度、政策与同业融资不能直接证明公司份额和估值”及语义等价的泛化否定；必须直接说明目标公司的具体商业验证、能力与投资意义。

## 6. 投资结论及建议契约

- `investment-recommendation`的一级标题使用`投资结论及建议`；`final-investment-decision`仅在用户明确要求时使用`投资结论`。
- 默认结论严格使用三个自然段：第一段写公司与产品定位；第二段写行业机会、商业基础、团队和产业资源；第三段写本轮具体交易，包含主体/载体、金额或区间、当前来源支持的估值类型/区间、交易方式和投后权益或计算机制。
- 结论不使用“核心逻辑由…项事实构成”等提纲式语言，不复制风险表、交割条件或投后控制清单，不使用`本项目投资结论为同意……`或其他审批式表述。
- 对可控制问题，必须已经转化为交割条件、分期付款条件、投后责任、陈述保证、赔偿或保护性权利，并在投资方案和风险章节归位；结论不重复清单。
- 交易方案缺失、重大事实无法核验或存在未处置的实质性否决风险时，停止生成两种终稿；只有用户明确要求进行稿时才使用`dd-in-progress`，且不得伪装为最终报告。
- 结论不得引入正文未分析的新事实；估值、金额、主体和投后权益必须与投资概要和投资方案一致。
