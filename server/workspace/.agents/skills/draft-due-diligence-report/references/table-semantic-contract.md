# 表格语义与业务自适应契约

本契约解决“样例视觉结构”与“目标公司业务语义”的边界。参考报告定义页面、表格角色、灰度、边框、对齐、列宽和分页；目标公司资料定义表头、行项和全部项目事实。

## 一、生成前先判断业务类型

在章节规划前，先从资料中确定目标公司的主要收入形态和交付形态：

- 项目制技术服务/数据服务；
- 软件、工具链、SaaS或平台；
- 硬件、设备或软硬一体化产品；
- 算法、模型、知识产权授权或技术许可；
- 制造、生物医药、消费或其他项目特定形态。

同一公司兼有多种形态时，以报告期已形成的主营业务为主表，其他产品线在产品矩阵中分行展示。不以研发规划替代已经营业务。

## 二、固定语义与可适配语义

### 稳定表头

以下表头与工商、交易、财务或风险决策直接相关，默认保持稳定：

| 表格用途 | 默认表头 |
|---|---|
| 历史沿革 | `时间｜事项｜注册资本/融资` |
| 报告日股东结构（2.3.1） | `股东｜认缴注册资本（万元）｜持股比例` |
| 股权穿透 | `主体｜上层持有人或合伙人｜穿透要点` |
| 组织与人员 | 默认使用组织架构图；无可靠层级资料且用户允许时才降级为`部门｜人员配置｜主要职责` |
| 关联交易 | `关联主体或事项｜关联关系及投资相关情况`，数据行按重大主体/事项动态生成 |
| 资质、认证及荣誉 | `类别｜资质、认证或荣誉情况`；不承载诉讼、处罚、失信、债务、租赁、劳动、数据测绘或环保消防事项 |
| 风险 | `风险类别｜具体风险描述｜风险控制安排` |

2.3.1只呈现报告基准日已经生效的股东结构和实际控制关系；本轮投后权益移至7.2直接陈述，不使用“模拟投后”。如交易方案仍无法确定，应停止投资决策终稿，不通过表头增加不确定性。

### 业务自适应表头

产品、技术、场景、商业模式、成本和市场表格只固定表意角色，不固定单一字面表头。下列默认组合仅作选择范围：

| 表意角色 | 可选表头组合 |
|---|---|
| 核心产品 | `核心产品｜产品定义/核心功能｜应用场景/目标客户｜商业化进展` |
| 核心技术 | `核心技术｜技术描述/原理｜技术来源/权属｜技术门槛/产品作用` |
| 应用场景 | `应用场景｜客户需求｜解决方案｜商业进展`；窄表可用`应用场景｜解决方案` |
| 技术沿革 | `年份｜代表成果｜对现有产品/技术的作用` |
| 知识产权 | `知识产权类别｜权属及进展` |
| 商业模式 | 项目制技术/数据服务优先使用`业务板块｜主要产品/服务｜收入来源｜销售与交付方式`；软件平台可使用`产品/服务｜收费模式｜获客方式｜交付与续费`；硬件可使用`产品线｜销售模式｜交付方式｜收入构成` |
| 成本结构 | `主要成本项｜成本构成/采购情况` |
| 市场空间 | `细分市场｜近期机会｜中期空间` |
| 投资亮点 | `投资亮点｜业务基础｜投资价值` |

选择时优先使用公司的客户采购语言和交付语言。例如，项目制数据服务优先展示“产品/服务、目标客户、交付形式、商业进展”；硬件优先展示“产品、应用场景、交付形态、量产/销售进展”。

## 三、表头禁止元话语

交付终稿表头不得出现：

- `尽调证据`、`尽调材料人数/规划`、`资料可核验进展`；
- `模拟投后股东`、`模拟认缴注册资本`、`模拟持股比例`；
- `核验边界`、`证据状态`、`投资口径`、`基准判断`；
- 把文件名、报告日期、版本或来源机构写入表头。
- `核验结果`等审计过程表头；2.7使用`资质、认证或荣誉情况`。

表22和表24只保留至少有一个实质数值/文字的预测年度列；禁止空列、全横杠列和纯占位符列。表23按实际期间动态扩列，并用利润表、资产负债表、现金流量表分组行表达完整财务分类。

`2.6 关联公司及关联交易`不再使用`核验结果`作为默认表头，避免把取证过程带入投资经理终稿。

## 四、内容填充原则

- 表头与表体必须同义：“商业化进展”只写合同、交付、验收、回款、复购或可核实项目阶段，不写估值排除过程。
- 一张表只承载一个比较问题；不把产品阶段、财务口径、数据权属和估值判断挤入同一单元格。
- 同一事实只设置一个主要归属章节。亏损、负现金流和财务调整不得进入关联关系表、综合评估或投资结论；重大财务风险在财务/风险章节披露一次。
- 关联交易执行重大性筛选：控制权、资金占用、利益输送、税务、竞业、知识产权和数据权属事项不受金额限制；无持续余额且已结清的零星报销/临时垫付留在内部台账。
- 资料不支持某个可选业务字段时，调整表头、合并表格或改用对应正文槽位；不用“不纳入本次测算”“未取得”填满空行。
- 预测表只展示有明确预测输入的年度和行项。没有可采用预测时，保留历史与最新一期经营表，不制造连续年度空表。
- 交易摘要中的付款、交割和工商变更写具体安排，不使用“按……口径执行/办理”；“口径”只用于会计、估值或计算基础。
- 4.1不使用`商业验证`固定列；已形成的合同、验收、开票、回款和复购事实归入4.2客户验证章节。4.1只说明公司如何获客、收费、交付和形成收入。
- 2.6只写关联身份、控制/持股/任职事实、重大往来和已形成安排；不在表内追加“避免/防范冲突”、“相关不利后果”等风险评价。

## 五、生成后语义验收

逐表回答：

1. 表头是否是目标公司的业务语言，而不是取证或写作过程语言；
2. 各列是否承载可比较的同类事实；
3. 是否有某列在多数行只写估值排除、资料缺口或“不纳入测算”；
4. 产品阶段、客户验证、收入形态和交易事实是否在全文一致；
5. 移除内部来源定位后，表格是否仍能自然读懂。
6. 4.1是否只回答收费、获客、销售和交付，并与4.2的客户验证事实分工清晰。

任一表格头文不符、把取证过程当作业务字段、或靠否定性占位语填满时，退回章节—表格矩阵重新选择表头。
