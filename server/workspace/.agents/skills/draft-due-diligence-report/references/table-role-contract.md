# 表格、组织架构成果物与分页契约

本契约定义表格及组织架构成果物的版式角色，不提供任何目标公司事实，也不固定业务表头。权威配置为`assets/table-layout-profile.json`；表头与内容语义由`table-semantic-contract.md`约束。参考报告提供视觉基准，用户反馈提供已验证的纠偏规则。

## 一、禁止危险默认值

- 不得假定“所有表格第一行都是表头”。
- 不得默认给所有第一行加深灰底、加粗、居中或`w:tblHeader`。
- 不得默认给所有行添加`w:cantSplit`。
- 不得以`cell.text = ""`、`paragraph.clear()`或无样式新段落重建模板内容。
- 不得用统一颜色、对齐、行高或字号覆盖键值表、矩阵表和财务表的角色差异。
- 全部表格文字必须显式使用仿宋_GB2312 12pt；空间不足时拆表、续表或改用横向页面，不得缩字号。
- 段落行距不得依赖模板残留或生成器临时设置：标签/表头为1.15倍，普通表体为1.5倍，段前段后为0；配置明确列出的密集财务表体可使用1.15倍。不得用单倍行距压缩表3、表5或其他叙述内容。

## 二、四类角色

### `key_value_short`

适用表1、2、6。没有表头行：左列是浅灰`F2F2F2`标签、加粗、居中；右列白底/无填充、常规字、居中。短行可保持不跨页。

### `key_value_narrative`

适用表3、4、5。没有表头行：左列是浅灰`F2F2F2`标签、加粗、居中；右列白底/无填充、常规字、左对齐。长叙述行必须允许跨页。

### `matrix`

适用表7—21及25—27，但不含键值表和2.5组织架构图容器。第一行是实际列标题，使用深灰`D9D9D9`、加粗、居中；表体默认无填充、常规字。表8使用`股东｜认缴注册资本（万元）｜持股比例`，表12使用`类别｜资质、认证或荣誉情况`，表13/14分别固定为核心产品/核心技术。表11、12、15、16、20、26、27等叙述列按配置左对齐。第27表第三列固定为`风险控制安排`，不得回退为`风险控制建议`。只有配置中列明的长表才设置重复表头。

矩阵表的列数、列宽和业务表头必须服务目标公司的业务形态。表13/14的核心产品/核心技术语义固定分离；其他业务表可按目标公司采购和交付语言自适应。不得把`尽调证据`、`证据状态`、`模拟投后`或`核验边界`写成列标题。表18为4.1商业模式/经营管理表，采用`业务板块｜主要产品/服务｜收入来源｜销售与交付方式`或与目标公司业务同义的四列表头，不得设置独立`商业验证`列。

### `organization_chart`

适用2.5组织架构。可使用一格无边框容器维持模板位置，但可见成果必须是组织架构图而不是旧`部门｜人员配置｜主要职责`表。图中层级、部门、人员和汇报关系全部来自已核实事实；节点文字保持可读，过宽时使用横向页面；图片替代文本必须包含全部节点标签和汇报关系，以便`expected-org-label`语义门禁校验。

### `financial`

适用表22—24。使用财务表灰`D7D7D7`和白色表体，不能套用普通矩阵表`D9D9D9`。表22/24按有数据年度动态增删列。表23第一行是`单位：万元｜实际期间…`表头，利润表、资产负债表、现金流量表为灰色分组行；资产/负债分类与合计行不得缺失。财务表禁止固定行高，表体默认为常规字。

## 三、分页与重复表头

- 典型长叙述表3、4、5、12、15、20、27使用`allow_long_rows`；当数据行文本达到配置阈值时不得有`w:cantSplit`。
- 表8、15、20、23、24、27按配置重复真实表头；键值表不得出现`w:tblHeader`。
- `w:trHeight w:hRule="exact"`在严格模式下直接报错。需要最低高度时只允许`atLeast`，并须确认不会制造空白页。
- 逐页渲染若同时出现行拆分违规和异常稀疏页，追加`TABLE_PAGINATION_WASTE`并拒绝交付。

## 四、唯一写入接口

普通表格生成器必须导入`scripts/table_writer.py`，显式传入表号。组织架构图使用独立图形成果物写入，不得用`fill_table()`伪造层级：

```python
from table_writer import write_table

write_table(
    document.tables[2],
    rows,
    table_number=3,
)
```

单元格值可以是字符串，也可以是字符串序列；序列会生成多个真实Word段落，并复制模板原型的`w:pPr`和`w:rPr`。生成完成后可执行防御性归一化：

```bash
python scripts/table_writer.py draft.docx normalized.docx
```

归一化不能替代内容与证据复核，且不能用于掩盖错误表号、错误字段或缺失事实。

## 五、强制错误码

- `TABLE_ROLE_STYLE_MISMATCH`：标签/表头/表体的粗细或对齐不符合角色；
- `TABLE_FALSE_HEADER_ROW`：键值表或非表头行被标记为重复表头；
- `TABLE_REPEAT_HEADER`：配置要求的真实重复表头缺失；
- `TABLE_NARRATIVE_ALIGNMENT`：叙述性内容被居中；
- `TABLE_ROW_SPLIT_POLICY`：长叙述行被禁止跨页；
- `TABLE_FILL_COLOR_MISMATCH`：`F2F2F2`、`D9D9D9`、`D7D7D7`或白色表体错用；
- `TABLE_PARAGRAPH_FORMAT_LOSS`：单元格内容失去显式段落/run原型格式；
- `TABLE_PARAGRAPH_SPACING_MISMATCH`：标签、表头或表体的行距、段前或段后不符合角色配置；
- `TABLE_PAGINATION_WASTE`：错误跨页策略造成异常稀疏页；
- `FIXED_ROW_HEIGHT`：严格模式下出现固定行高。
- `ORG_CHART_MISSING`：2.5没有可读组织架构图；
- `TABLE_BODY_SIZE_INCONSISTENT`：任一表格正文不是12pt；
- `TABLE_LOCAL_FONT_OVERRIDE`：个别表格使用与全表不同的字体或字号。
- `BUSINESS_VALIDATION_COLUMN_DUPLICATION`：表18设置`商业验证`或`关键验证`列，导致客户证据与4.2重复；
- `ASSOCIATION_RISK_NARRATIVE_SPILL`：表11在关联事实之后附加“避免/防范冲突”或“不利后果”等风险解释。

## 六、回归测试

以一份已通过严格门禁的真实报告为正向样例，运行：

```bash
python scripts/test_table_layout_regressions.py accepted.docx \
  --target-company 目标公司全称 \
  --forbid-term 样例公司名
```

测试自动注入误灰首行、假表头、叙述居中/加粗、全行`cantSplit`、段落格式丢失、财务灰色错用和固定行高。每个负向样例必须由指定错误码拒绝。
