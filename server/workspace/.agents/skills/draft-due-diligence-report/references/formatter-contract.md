# 格式化与交付契约

## Python运行时

- 直接运行技能脚本即可。`scripts/runtime_bootstrap.py`会在当前Python缺少`pypdf`、Pillow或`pdf2image`时，检查现有Codex工作区Python并重新执行当前脚本。
- 自举只使用本机已存在运行时，不联网安装包；环境变量`DD_SKILL_RUNTIME_BOOTSTRAPPED`防止循环，`DD_SKILL_PYTHON`可显式指定候选解释器。
- 若找不到具备依赖的解释器，脚本必须明确失败，不得降级跳过PDF正文、字体或像素门禁。

## Word构建

1. 从`assets/primary-dd-report-template.docx`建立工作副本，不修改模板资产。
2. 使用真实样式：封面标题、`Normal`、`Heading 1`、`Heading 2`、`Heading 3`、目录和表格。
3. 保留页眉内部声明和页脚页码字段；新分节明确设置是否链接前节。
4. 使用Word域生成目录和页码。无法在当前环境刷新字段时设置`w:updateFields=true`，并在Word/WPS打开后执行全选更新域。
5. 纵向正文使用参考报告页边距；宽表使用A4横向节，表后切回纵向。
6. 表格设置明确DXA宽度、列网格、单元格宽度、内边距和重复表头；禁止自动适配造成转换漂移。
7. 不设置会截断文字的固定行高，不用文本框或空表作为装饰布局。
8. 封面不使用横线、段落边框、形状或表格；目录不使用表格，必须保留真实TOC/PAGEREF域。
9. 严格样例模式复用参考表格的视觉角色，并按`table-semantic-contract.md`选择与目标公司业务同义的表头；2.5默认用组织架构图替换旧人员表；按`table-role-contract.md`与`assets/table-layout-profile.json`应用版式角色。
10. 生成前加载`assets/style-profile.json`；封面标题和Heading 1/2/3显式使用黑体，正文、表头和表体显式使用仿宋_GB2312，且中文字体同时写入`w:eastAsia`。全部表格文字严格12pt，表头和左栏标签仅用加粗区分。
10.1 表格段落行距按`table-layout-profile.json`显式写入：标签/表头1.15倍、普通表体1.5倍、段前段后为0；密集财务表仅按表号配置例外。表3和表5不得使用单倍行距。
11. 替换模板内容时只改占位run的文本并保留原`w:rPr`，或从同角色原型run复制格式；禁止清空段落/单元格后无样式重建，禁止全局宋体和全表8.5pt覆盖。
12. 多论点单元格使用多个真实段落并保持同角色格式；不得在一个run中堆叠软换行。
13. 所有表格统一通过`scripts/table_writer.py`写入。调用时必须显式给出`table_number`；不得存在`header_rows = header_rows or {0}`、`shade_header_rows(table, {0})`或对全部行添加`cantSplit`的默认逻辑。
14. 键值表首行是普通数据行，不是表头。表1/2/6右栏居中；表3/4/5右栏左对齐并允许长行跨页。表12为`类别｜资质、认证或荣誉情况`矩阵，第二列左对齐并允许长行跨页。矩阵表与财务表分别使用`D9D9D9`和`D7D7D7`，不得统一套色。

## 内容门禁

- 标题含目标公司全称和“尽职调查报告”；
- 报告有投资概要、公司/法律、产品或业务、财务、投资方案、风险和结论；
- 有数据截止日和单位/币种说明；第三方报告确有非审计、非保证或基准日限制时，在最相关位置准确说明一次。
- 默认终稿不得为了通过门禁强行添加“范围限制”“未取得”或“资料提供”措辞。影响投资结论的范围限制应在构建前阻断；非重大覆盖限制留在内部审计层。不得新增“报告基础与范围”或“编制说明”。
- 实际、预算、预测和投资测算视觉及文字上可区分；
- 重大风险与结论一致；
- 样例公司和无法溯源事实全部清除；
- 目录、交叉引用、页码和横竖版分节更新。
- 表格和组织架构图视觉角色稳定、业务表头与目标公司业务同义；人名/人数/地址/金额/职责等具体字段在内部可追溯，终稿不存在孤立编号、空编号或跳号。
- 2.5必须有可读组织架构图及职责说明；2.6使用`关联主体或事项｜关联关系及投资相关情况`并按重大事实动态生成行，不保留零星报销或无意义固定行。
- 2.3.1使用`股东｜认缴注册资本（万元）｜持股比例`呈现报告日有效结构；本轮投后权益归入7.2。2.7使用`类别｜资质、认证或荣誉情况`并排除负面法律事项。
- 默认投资建议稿的一级标题为`投资结论及建议`，按三个自然段依次总结公司与产品定位、行业/商业化/团队基础，以及包含投资主体、投资金额/区间、当前来源支持的估值类型/区间、交易结构和投后权益/计算机制的明确投资建议。用户明确说已决定投资时使用`投资结论`；不得把风险清单堆叠进结论，也不使用审批套话。
- 逐表满足`content-density-contract.md`的字段和论证链条；资料不足时先进入内部审计层，影响投资结论则阻断终稿。业务表允许合并或调整不适用的数据行，禁止编造事实、机械保留空行或用“不纳入/未取得”等排除性文字填充。原始亏损和负现金流金额不得在1.5、2.6、5.2.3及结论中重复出现。
- DOCX正文、表格、脚注、尾注和附录不得出现`SRC-*`、`CLAIM-*`、工作路径或证据索引串；不得出现未授权的表后分析/来源段落或独立“行业判断/项目判断”模块；不得出现来源/核验元叙事、排除性决策口径、模拟投后口径或风险状态标签。
- 页数范围、字符数和与样例的比例只作收缩预警，不作为单独通过条件。

## 结构校验

```bash
python scripts/validate_dd_report.py final.docx \
  --forbid-term 德塔智能 \
  --forbid-term 北京德塔源创 \
  --target-company 目标公司全称 \
  --render-dir render \
  --report-stage investment-recommendation \
  --strict-sample-schema
```

校验器同时检查精确的批注/修订标记、结论尾章顺序、投资建议稿/投资决策终稿的阶段语气、三段式投资建议、开放式尽调语言、交易义务措辞、可见推理标签、公式化AI总结、2.6风险尾巴、4.1`商业验证`重复列、封面装饰、目录是否被表格模拟、目录/页码字段、分节、27张表表头、表格角色填充/粗细/对齐/行距/段前段后/重复表头/跨页/行高、最终有效字体/字号、统一8.5pt覆盖、逐表段落/行数/内容深度、孤立编号、题文关键语义、内部证据编号、未授权前置说明、独立判断模块、表后段落漂移和渲染非空页。像素检查同时计算整页墨迹率和排除页眉页脚后的正文墨迹率；只有内部声明和页码、正文为空的页面同样判错。`--strict-sample-schema`是发布门禁，任何警告也会令状态为`fail`，不得带警告冻结。不得用`<w:ins`字符串前缀替代精确修订检测，因为它会误匹配`<w:instrText>`目录域；不得把段落和表格分组拼接后判断正文顺序。自动化门禁仍不能替代证据审阅和逐页视觉检查。

## 渲染与视觉QA

使用字体安全包装器调用文档技能的`render_docx.py`：

```bash
python scripts/render_docx_fontsafe.py final.docx \
  --output-dir render-round1 \
  --emit-pdf --verbose \
  --require-text 目标公司全称
```

包装器自动发现当前文档技能渲染器，并优先注入Codex捆绑LibreOffice的`fonts.conf`。若日志出现`Fontconfig warning: no <cachedir>`、中文正文缺失或页数异常压缩，该轮即使退出码为0也必须作废。逐页检查：

每一轮使用新的空输出目录；包装器默认拒绝非空目录，防止旧PNG或中间PDF混入当前轮次。只有明确清楚目录内容时才使用`--allow-existing-output`。

- 封面和目录是否完整；封面无横线/边框/形状，目录非表格且页码有效；
- 中文字体是否缺失或替换；
- 标题层级、页首留白和孤行；
- 表格是否跨边界、截断、挤压或出现空白页；
- 横竖版切换、页眉和页码是否连续；
- 风险表、财务表和结论是否清晰可读。
- 是否存在样例没有的“报告基础与范围”、表后`SRC-*`来源串或机械重复的“行业判断/项目判断”段落。

任何修订都回到DOCX，修订后重新执行结构校验和全页渲染。

冻结前至少经历“试用—找缺陷—修复—结构校验—全页渲染—重试”闭环。记录每轮页数、发现的问题、修复内容和验收结果；用户指出一张表的问题时必须横向扫描其余26张表。被拒绝的渲染不得覆盖最后一次合格基准；错误和未关闭警告均为0后才冻结。

## PDF导出

优先使用WPS或Microsoft Word原生导出最终冻结DOCX。Windows Word环境可运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/export_pdf_word.ps1 -InputDocx final.docx -OutputPdf final.pdf
```

不可用时才使用LibreOffice。最终PDF必须：

- 与DOCX同主文件名、同目录；
- 来自最新冻结DOCX；
- 全部页面再次渲染检查；
- 通过`validate_pdf_pair.py`的页数、DOCX正文覆盖率、横纵向、必需/禁止文本、逐页内部声明、结束标记、字体嵌入和非空页校验。

推荐命令：

```bash
python scripts/validate_pdf_pair.py final.docx final.pdf \
  --render-dir pdf-render \
  --report-stage investment-recommendation \
  --require-term 目标公司全称 \
  --forbid-term 德塔智能 \
  --header-term '内部声明的稳定核心文本'
```

仅当报告明确设计了结束标记时才追加`--end-marker`；参考报告和默认模板并不要求结束标记。如果LibreOffice是最终导出引擎，再创建全新渲染目录独立重导出，并追加`--baseline-render-dir 已验收渲染目录`执行N/N逐页像素一致性检查。两次PDF字节哈希不同但页面像素相同通常是创建时间等元数据差异，不视为版式漂移。

## 交付目录

只保留最终DOCX和PDF。证据台账、清单、日志、校验JSON、渲染PNG和中间PDF留在工作目录，不默认交付。
