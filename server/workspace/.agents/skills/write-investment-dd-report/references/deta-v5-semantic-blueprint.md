# 德塔 V5 内容语法蓝图

## 使用目标

`deta_v5_up_to_ic` 不是单纯的字体或页面主题，而是一套投委会阅读顺序：先给公司与交易的压缩判断，再展开主体、产品、业务、市场和财务事实，最后落到价格、交易保护、退出和结论。正文只呈现公司状态、经营证据、分析判断及交易含义；取数动作、核查步骤和底稿要求留在后台。

该配置只允许 `pre_ic` 和 `comprehensive_ic`。在创建正文前，必须按 [diligence-data-schema.md](diligence-data-schema.md) 完成字段数据层并通过 `audit_ic_completeness.py`。公开初筛和专项尽调不得套用完整上会结构。

## 从参考报告继承什么

- 继承：克制的黑白 A4 视觉、封面—目录—正文结构、保密页眉、连续页码、灰底键值表和标准分析表。
- 继承：投资概要先于背景介绍；交易参数、商业模式、投资价值和主要风险在前五个插槽内完成首次交代。
- 继承：公司事实用键值表，跨对象比较用分析表，关键客户和重大事项用短段落形成事实—判断—投资含义。
- 继承：宽财务表、股权表和情景测算使用横向节，不通过缩字硬塞进纵向页面。
- 修正：不复制原报告的稀疏分页、泛化市场判断、无来源预测或“持续跟踪、投后赋能”等软性风险措施。

## 默认章节与插槽

当 `meta.template_profile` 为 `deta_v5_up_to_ic` 时，默认采用八个编号章节和一个不编号结论：

1. **投资概要**
   - 公司情况：公司名称、成立时间、注册/经营地址、实际控制人、主营业务、发展阶段、核心判断。
   - 交易要点：投资方、方式、金额、投前/投后估值、项目类型、拟取得权益、交割与责任安排。未知参数不得代填；必须转化为是否报价、采用何种估值锚和何时进入条款谈判。
   - 行业概况：行业阶段、市场环境、需求驱动、进入壁垒和决定公司能否取得份额的因素。
   - 商业模式和经营管理：商业路径、客户与生态、交付方式、收费逻辑、团队组织、经营状态和管理基础。
   - 投资价值与风险：投资价值、关键证据、主要风险、估值或条款处理。
2. **公司概况**
   - 基础信息、历史沿革、股东与控制权、团队与组织、关联公司及交易、资质与合规。
3. **产品与技术**
   - 概念与技术栈、核心路线、产品矩阵、应用场景、技术沿革、知识产权与数据权属。
4. **业务情况**
   - 商业模式与销售策略、客户验证、合同—交付—验收—开票—收入—回款—复购闭环、供应商/采购/成本。
5. **行业和市场**
   - 需求趋势、政策与产业约束、市场分层、竞争与替代、公司获取市场的能力和证据。
6. **未来发展规划**
   - 业务与组织里程碑、历史财务质量、管理层预算、分析师情景、资金需求。不同性质的数据必须分列。
7. **投资方案**
   - 投资亮点、估值逻辑、投资方式、关键条款、退出路径和回报约束。
8. **风险提示与对策**
   - 风险事实、触发指标、影响、交割前条件、投后约束、责任人、期限、证据和救济。
9. **投资结论及建议**（不编号）
   - 明确“投资、附条件投资、暂缓或否决”；列明金额/报价原则、估值方法、关键条件及能够反转结论的事实。

专项报告可删减非适用内容，但不得用空章或通用文字凑齐上述结构。

## 表格语法

正文表格必须属于以下一种语义角色：

| 表格类型 | 典型列或字段 | 作用 |
|---|---|---|
| 公司/交易键值表 | 项目、内容 | 用最少篇幅锁定主体、交易和核心判断 |
| 历史沿革/股权表 | 时间、事项、股东、比例、控制关系 | 解释权益边界及控制权变化 |
| 产品矩阵 | 产品/服务、客户、收费、成熟度 | 判断产品是否可卖、如何交付及是否可复制 |
| 客户验证表 | 客户、阶段、合同、验收、收入、回款、复购 | 区分商机与已实现经营结果 |
| 市场分层表 | 细分市场、近期机会、中期空间、进入条件 | 把行业空间连接到公司可获得份额 |
| 财务表 | 期间、单位、实际/预算/预测 | 显示历史质量、驱动和资金缺口 |
| 投资亮点表 | 亮点、证据、投资含义 | 把事实转化为承保逻辑 |
| 风险控制表 | 风险、事实/触发、影响、控制/救济 | 把风险转化为可执行交易保护 |
| 退出表 | 路径、前提、时间、回报约束 | 说明资本回收依赖条件 |

表格行必须是公司事实、可比数据或分析结论，不得是分析师待办事项。

每张表必须在 `report.json` 中设置 `semantic_role` 和 `data_field_ids`。股权、客户闭环、财务、估值和风险等P0表格必须由对应结构化字段生成；“经营质量评价框架”“建议的经营里程碑”“建议的估值处理”不属于可交付表格角色。

## 正文与工作底稿的硬边界

下列标题或列名不得出现在正文：`核查框架`、`验证框架`、`核查重点`、`核查材料`、`应取得数据`、`需要回答的事实`、`必须完成的勾稽`、`完成标准`、`底稿要求`、`优先资料清单`、`尽调工作流`。它们只能进入：

1. 内部 `evidence.json`、来源清单和分析工作底稿；或
2. 报告最后一个精简的“尽调缺口/资料请求”附件。

正文遇到未知事项时，使用投资处理而非文件状态。例如：

- 不写：“尚未得到客户台账支持。”
- 写：“现阶段不把意向客户计入收入基准；估值仅锚定已验收并回款业务，客户集中度条件在交割前单列验证。”
- 不写：“尚不能证明平台化收入质量。”
- 写：“现有收入仍受项目交付人力约束，估值不采用纯 SaaS 倍数；续费率和实施人效达到约定阈值后再释放估值上调空间。”

公开信息只能验证工商、知识产权、招投标、政策、司法和披露交易等外部事实，不能替代未公开的客户台账、合同、银行流水或财务明细。公开资料不足时，应降低报告类型或调整估值和交易条件，不得创造私人经营数据。

## 页面与信息密度

- 一级章节原则上另起新页；不得为了复刻参考报告页码而制造空白页。
- 投资概要优先使用五张紧凑键值表，目标是在前 3—5 个正文页完成首次决策闭环。
- 六列及以上、三期以上财务数据或无法清晰阅读的股权/情景表，使用 `section_break` 切换至横向；结束后切回纵向。
- 横向页仅放宽表或与其直接相关的说明，不放一般正文。
- 连续两页有效内容低于约 25% 必须重排；表题与表格同页、逻辑行不拆页、标题后至少保留两行正文或完整表头。

## 专业口吻

- 章节开头先给结论，再给决定该结论的证据和交易含义。
- 明确区分公司陈述、外部事实、历史实际、管理层预算、分析师测算和投资判断。
- 使用具体对象、期间、单位和因果关系，避免“具备一定基础”“未来空间广阔”等可跨公司复用的句子。
- 风险措施必须具备可执行要素：责任主体、完成时点、验收证据以及未完成时的暂停付款、估值调整、回购、赔偿或其他救济。
