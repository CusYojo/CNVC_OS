# 投资建议书 PPT 输出契约

## 输入

必须提供：

- `template.file`：用户本次上传且有权使用的 `.pdf` 或 `.pptx` 模板；
- `project`：当前会话锁定且用户有权访问的项目字段；
- `sources`：本次运行输入的有序证据数组；
- `sourceCutoffDate`：格式为 `YYYY-MM-DD` 且不晚于运行日期的资料截止日；
- `parameters.language`：`中文`。

可选提供：

- `parameters.structureMode`：默认 `strict-template`；仅当用户明确授权时使用 `condensed-template` 或 `expanded-template`；
- `parameters.targetAudience`：例如投资团队、投资总监或投委会；
- 用户明确提出的投资关注点。

不得要求固定的公司模板名称、固定页数区间、固定十二章或固定视觉主题。模板文件本身决定页面数量、顺序、结构和视觉规则。

不得使用 `sourceCutoffDate` 之后形成的证据。证据顺序为当前项目资料库、项目档案、用户补充输入、当前项目已缓存公开证据、关键缺口定向网络补全。联网不可用时跳过补全并继续，不得把错误信息写入 PPTX。不得读取或复制 `docs/` 中特定项目的示例正文。

## 模板路由

| 输入模板 | 必经流程 | 进入替换的条件 |
|---|---|---|
| 原生 PPTX | 设置 `sourceMode=native-pptx`，记录模板哈希并逐页分析 | 模板可读且对象、母版和版式可检查 |
| PDF | 先执行 `pdf-to-editable-ppt`，再执行逐页分析 | `conversion-handoff.json` 的水印、可编辑性、替换就绪检查均通过，且哈希一致 |

PDF 转换产物未通过交接门槛时，不得执行 `editable-ppt-content-replacer`。不得在整页背景图上覆盖文字冒充可编辑 PPTX。

## 内部中间产物

每次运行至少生成以下内部审计产物：

- `template-profile.json`：模板级和逐页的尺寸、母版、版式、主题、字体、字号、行距、排版和对象分类；
- `template-frame-map.json`：每个输出页到 `sourceSlide`、源母版、源版式和叙事职责的映射；
- `business-content.json`：与模板逻辑章节一一对应的投资内容中间层；
- `replacement-manifest.json`：符合 `editable-ppt-content-replacer` `schemaVersion=1.3` 的白名单替换操作；
- `conversion-handoff.json`：仅 PDF 输入需要；
- 渲染图、Reviewer 结果和 QA 报告。

这些产物用于审计与复核，默认不作为最终附件交付。

## `BusinessContent` JSON

内容中间层只包含以下字段：

```json
{
  "title": "当前项目名称投资建议书",
  "executiveSummary": "一段基于证据、结合当前项目阶段的总体投资判断和主推进建议。",
  "sections": [
    {
      "title": "由模板识别的通用章节标题，或重写后的当前项目专属标题",
      "summary": "适合模板当前页面容量的一句话结论。",
      "findings": [
        {
          "text": "简洁、可上屏且保留单位、期间和口径的发现。",
          "status": "资料记载",
          "sourceIndexes": [0]
        }
      ]
    }
  ],
  "highlights": ["有证据支撑的投资亮点"],
  "risks": ["可能影响投资决策的主要风险"],
  "missing": ["仍需补充的关键证据"]
}
```

不得在该 JSON 中增加幻灯片、版式、图片、引文、备注或对象坐标字段；这些信息由模板画像、页面映射和替换清单承载。

`sections` 的标题、数量和顺序从模板中需要项目业务内容的逻辑章节动态识别。封面、目录、纯章节过渡页、来源页和结尾页不必作为 `sections` 返回。不得先生成固定章节清单再向模板中硬塞内容。

通用章节标题可以沿用；包含样本项目名称、样本结论或样本事实的标题必须重写。每节发现数量由模板槽位容量决定，不再固定为四项。内容超出槽位时应精炼表达，不得通过擅自缩小字体或压缩行距解决。

## 结构与视觉契约

在默认的 `strict-template` 模式下，输出必须：

- 保留模板页面尺寸、幻灯片数量、顺序、母版和版式继承关系；
- 从对应模板页复制页面并编辑继承对象，不从空白页重画近似布局；
- 精确保留字体家族、东亚字体、字号、字重、颜色、行距、段前段后、缩进、项目符号和对齐；
- 保留对象位置、尺寸、层级、图片裁切、表格样式、图表样式、主题色、背景、页眉页脚和公共装饰；
- 只替换被白名单标记的业务内容槽位；
- 将每个输出页映射到明确的模板源页和叙事职责。

`condensed-template` 或 `expanded-template` 只能在用户明确授权时使用。增删页面必须通过复制或省略现有模板页面完成，并在 `template-frame-map.json` 中记录原因；不得发明新母版、新主题或新视觉语言。

## 事实状态与引用

仅可使用以下状态：

- `资料记载`：由一项或多项输入来源直接支持；必须包含有效 `sourceIndexes`；
- `AI推断`：基于已识别证据形成的分析；必须包含支持该分析的索引；
- `待核验`：需要原始文件、第三方材料或访谈确认；有初步证据时应保留索引；
- `资料缺口`：所需证据不存在；通常使用空索引数组。

`sourceIndexes` 是输入 `sources` 数组中从零开始的位置。只能使用整数，不得输出 `S0` 等标签，也不得虚构索引。

同一事实、数字、风险或资料缺口只能在承担该叙事任务的页面完整出现一次。不得输出测试文字、占位语、连续复制内容或整段证据原文。

`executiveSummary`、结论页和下一步建议必须给出一致的主建议：`进入初筛`、`继续跟踪`、`申请立项`、`启动尽调`、`提请上会`、`提交投决`、`暂缓推进`或`归档`。建议必须与当前项目阶段匹配，不得声称已经改变项目阶段。

## 替换契约

`replacement-manifest.json` 必须满足：

- `schemaVersion=1.3`；
- 未列入白名单的对象默认 `KEEP`；
- 模板母版、主题、Logo、公共装饰、页眉页脚受保护；
- 每个业务对象具有稳定 `semanticKey`；
- 每项事实性替换具有 `evidenceIds`；
- 人物、产品、Logo 和图片通过实体绑定，不按位置盲替；
- 可选内容缺失时删除完整对象组，必需内容缺失时显示明确的待核验表达；
- 有来源的幻灯片在演讲者备注保留 `[Sources]` 证据块。

不得残留模板样本项目正文、图片、图表、人物、Logo、水印、空标签或占位框。

## 渲染与验收

最终必须满足：

- 仅生成一份中文 `.pptx` 及其预览，不得再生成第二份纯图片 PPTX；
- 核心文字、表格、受支持的图表和形状均为原生可编辑对象；
- 所有幻灯片均已渲染并逐页检查；
- 非白名单区域与模板对比无未授权漂移；
- 无文字溢出、截断、重叠、字体回退、异常换行、异常小字号或越界对象；
- 模板样本项目名称、水印和占位语检索结果为零；
- 事实页演讲者备注含 `[Sources]`，并可定位到实际使用的来源；
- “引用资料与责任声明”必须位于演示文稿末尾，使用最后一个合适的模板结尾页，只列实际引用来源，并保留“本演示文稿仅供内部讨论，不构成最终投资决策”；
- `pdf-to-editable-ppt`、`editable-ppt-content-replacer`、业务内容 Reviewer、`slides_test.py` 和模板高保真检查按适用范围全部通过。

若模板没有来源或责任声明承载页，必须先获得用户授权复制最接近的结尾页。页数、版式、可编辑性、来源、免责声明、样本内容清理或模板高保真任一检查失败，都必须判定为未完成。
