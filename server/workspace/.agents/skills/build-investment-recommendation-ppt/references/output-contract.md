# 投资建议书 PPT 输出契约

## 输入

必须提供：

- `project`：已获授权的项目字段。
- `sources`：本次运行输入的有序证据数组。
- `sourceCutoffDate`：格式为 `YYYY-MM-DD` 且不晚于运行日期的资料截止日。
- `parameters.template`：`公司标准模板`。
- `parameters.pageCount`：`8-10页`、`12-15页`或`18-20页`。
- `parameters.language`：`中文`。

不得使用 `sourceCutoffDate` 之后形成的证据。不得读取或复制 `docs/` 中特定项目的示例正文；这些内容不是运行时证据，也不是获准复用的内容。

## JSON 结构

仅返回一个包含下列键的 JSON 对象：

```json
{
  "title": "项目名称投资建议书",
  "executiveSummary": "一段基于证据的总体投资判断。",
  "sections": [
    {
      "title": "投资结论",
      "summary": "本节的一句话结论。",
      "findings": [
        {
          "text": "简洁、可上屏的发现。",
          "status": "资料记载",
          "sourceIndexes": [0]
        }
      ]
    }
  ],
  "highlights": ["有证据支撑的投资亮点"],
  "risks": ["可能影响投资决策的主要风险"],
  "missing": ["仍需补充的关键证据"]
}
```

不得增加幻灯片、版式、表格、图表、图片、引文或演讲者备注等字段。当前渲染器仅使用上述 `BusinessContent` 结构。

## 必需章节顺序

每个章节必须且只能出现一次，并严格按照以下顺序返回：

1. 投资结论
2. 项目概览
3. 行业与市场
4. 产品与技术
5. 商业模式与客户
6. 团队
7. 竞争分析
8. 财务与估值
9. 投资方案
10. 核心风险
11. 尽调缺口
12. 下一步建议

每节使用一至四项发现。`summary` 应为一句结论先行的表述。`highlights`、`risks` 和 `missing` 应分别包含三至五个非空字符串。

同一事实、数字、风险或资料缺口只能在承担该叙事任务的一页完整出现一次。章节摘要不得复述本页发现，目录、项目概览和结论页不得换词堆叠同一正文。不得输出测试文字、占位语、连续复制内容或整段证据原文。

## 发现状态与引用

仅可使用以下状态：

- `资料记载`：由一项或多项输入来源直接支持的表述；必须至少包含一个有效的 `sourceIndexes` 值。
- `AI推断`：基于已识别证据形成的分析；必须包含支持该分析的索引。
- `待核验`：需要原始文件、第三方材料或访谈确认的表述；存在初步证据时应包含相应索引。
- `资料缺口`：所需证据不存在；通常使用空索引数组。

`sourceIndexes` 是输入 `sources` 数组中从零开始的位置。只能使用整数，不得输出 `S0` 等标签，也不得虚构索引。

## 渲染与验收

视觉构建由渲染器负责。必须满足：

- 仅生成一份中文 `.pptx` 及其预览，不得再生成第二份纯图片 PPTX；
- 核心文字、表格、受支持的图表和形状必须为原生可编辑对象；
- 展示资料截止日和来源标签；
- 保留“本演示文稿仅供内部讨论，不构成最终投资决策”的免责声明；
- 沿用参考 PPTX 的白底、紫色页签、标题线、灰色信息区、公司标识、山景封面、表格和页脚体例；
- 最后一页为“引用资料与责任声明”，只列正文实际引用的来源；同一文件的多个片段合并列示定位；
- 幻灯片数量必须位于所选 `parameters.pageCount` 区间内。

页数不匹配必须判定为验收失败。JSON 仍须包含全部十二个章节，不得仅为适配页数区间而删除章节。当前 JSON 契约没有图表序列字段，因此应在发现正文中保留已核验数字、单位、期间和口径，不得虚构无证据支持的图表数据。
