# 投资分析深度门禁

## 适用原则

深度门禁用于防止报告以篇幅、模块数量、术语密度或风险罗列代替投资分析。标准版、深度版和对抗版必须执行；精简版可以减少问题数量，但不能降低单题的公司专属性和因果深度。

最终交付前使用 `scripts/validate_qa_report.py --strict-investment`。严格模式必须达到零错误、零警告。

## 问题门禁

起草前提取 3—7 个公司专属名词，覆盖产品、技术、客户类型、代表案例、交付方式或战略矛盾。公司名称不能作为唯一专属词。

- 至少 60% 的问题包含一个公司专属锚点；
- 至少 50% 的问题同时包含公司锚点、经济变量和决策张力；
- 公司专属度、因果深度或决策影响低于 3 分的问题必须删除、合并或重写；
- 标准版为 8—12 题，精简版为 5—7 题，深度版为 12—20 题，对抗版为 6—12 题；
- 最后一问必须包含推进、附条件、暂缓、否决或判断反转条件。

问题不得只是材料索取、事实盘点或模板化模块标题。证据弱但决策影响大的问题应保留，并在答案中采用保守投资处理。

## 答案门禁

每个答案应从事实或可观察状态出发，解释与本题相关的机制，并落到经营、投资或风险含义。至少 70% 的答案应形成以下五层中的三层：

1. 项目事实或可观察状态；
2. 因果机制或关键依赖；
3. 与本题相关的经营变量，包括客户、交付、技术、团队、治理、权属或财务变量；
4. 投资、估值、交易或推进含义；
5. 风险边界、反方解释、失效条件或里程碑。

客户、交付、财务、投资和风险是整份报告的覆盖面要求，不是每道专题题目的机械复述要求。整份报告至少覆盖以下五类中的四类：

1. 客户、采购、付费、销售周期、转化、续费或合同；
2. 交付、实施、人天、复用、标准化、产能或供应链；
3. 收入、毛利、利润、现金、回款、应收、营运资金或融资；
4. 投资主线、估值、回报、稀释、推进、暂缓或否决；
5. 证据、验收、风险、反方、依赖、集中度或替代方案。

正文密度目标按模式检查：精简版每题 160 个非空白字符，标准版 220 个，深度版 260 个，对抗版 200 个。字符数用于发现异常短答，不得作为唯一否决条件：单题不得低于 120 个非空白字符，全文平均不得低于对应模式目标的 70%，至少 70% 的答案形成上述五层中的三层，且全文至少覆盖四类投资维度。达到字数但没有因果链的长答案仍应判定为浅层；略低于目标但公司事实、相关机制、经营变量和投资处理完整的答案不得被机械替换为更短的兜底文本。

## 语言门禁

读者版必须使用完成态投资语言：

- 不自述投资经理身份；
- 不描述检索、审计或报告制作过程；
- 不使用“建议核验”“需要补充”“下一步应取得”等工作指令代替分析；
- 不使用“总体来看”“值得注意的是”“生态闭环”“多维度赋能”等模型化套话；
- 不展示来源清单、引用标签、原始 URL 或可点击外链；
- 不设置独立“结论：”标签或机械重复同一答案小标题。

## 下行与决策门禁

报告必须包含最强反方解释和下行传导路径。风险应说明会影响哪个经营或财务变量、方向如何、何时发生以及投资上如何处理。

最后的投资判断至少包括：当前主线、支持主线的关键事实、可能击穿主线的事项、推进或暂缓条件、估值或交易处理，以及使判断升级或降级的可观察里程碑。

## 交付检查

交付前确认：

- 问题数量符合所选模式；
- 公司专属度与投资争议度比例达标；
- 答案密度与因果深度达标；
- 没有未完成式工作语言、角色自述或审计自述；
- 最后一问包含明确决策条件；
- Markdown 校验零错误、零警告；
- DOCX 的正文、标题、表格、样式、页码和外部超链接检查通过。
