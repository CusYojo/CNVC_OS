# Q&A 生产契约

## 1. 模式与输出

### 正式文档模式

必填输入：

- `projectId`
- `sourceCutoffDate`
- `qaMode`：`投资委员会 Q&A` 或 `尽调 Q&A`
- `questionDepth`：`标准版` 或 `深度版`
- `outputFormat`：固定为 `PDF`

输出：

- 一份正式 PDF 下载产物。
- 不登记 DOCX、PPT 或 PPTX 下载产物。
- 排版中间文件只能留在服务器内部，不得出现在 artifact 列表。

### 单题会话模式

输入当前项目和用户确认的问题，返回结构化回答；不创建 artifacts。

## 2. 证据范围

允许使用：

1. 用户本次明确输入。
2. 当前项目档案、授权材料和访谈纪要。
3. 系统联网采集的公司官网、政府公示、监管披露、招投标、知识产权等一手公开资料。
4. 权威行业机构、数据库和可信媒体的公开资料。
5. 基于上述事实形成且说明边界的审慎分析。

禁止使用其他项目或模板样本事实。所有资料不得晚于截止日；网页无发布日期时，不得用其证明截止日前已经发生的事实。

联网检索至少覆盖：公司主体、产品技术、团队、行业市场、竞争、客户商业化、商业模式、融资、合规风险和近期动态。检索式、网址、访问日和实际使用来源保存到系统审计记录。

## 3. 动态问题

15 类只作为内部选题池，不要求逐类覆盖：

`企业介绍、商业模式、产品能力、团队、市场、竞争、财务、融资、风险、合规、知识产权、客户、行业、运营、未来规划`

标准版目标 7 题，深度版目标 10 题，均须落在核心规范的建议区间。问题应影响投资判断，并优先选择有项目证据或公开信息支持的事项。Duplicate Checker 去重后重新连续编号。

## 4. 回答

有可用证据时：

1. 一至三句直接答复结论、主要依据和成立条件。
2. 复杂问题使用二至五项分维度论证；简单问题可直接使用连续自然段。
3. 每个维度说明判断、依据、影响和边界。
4. 所有数字带单位、期间、时点和口径。
5. 同一事实只完整表达一次，不在直接答复、分维度和结尾换词复述。

项目资料不足时必须先联网补证。公开渠道仍未披露的非公开事项，不得编造，也不得输出“暂无相关资料”“暂无资料”等占位语；应形成具体核验结论：

```text
截至资料截止日，现有项目材料与本次公开检索未披露[具体事项]，因此现阶段无法判断[具体结论]。该判断仅表示可获得证据不足，不代表相关事项不存在；完成判断仍需核验[具体材料或访谈对象]。
```

## 5. 内部证据与 Reviewer

每个实质性主张在内部结构中保留：

- `sourceIndexes`
- `supportingQuotes`
- `confidenceStatus`
- `missingInformation`

Reviewer 检查重复、完整性、事实支持、数字口径、来源存在性和支持关系。不能支持的答案改为具体的证据边界与核验结论，不得改为占位语。

内部来源和 Reviewer 结果只用于审计与质量门禁。可见 PDF 不显示 `[S#]`、引用资料、链接清单、Reviewer 审阅结果、模板指纹或系统质量记录。

## 6. 正式 PDF 结构

1. 当前项目标题。
2. 问题目录（按需）。
3. 连续 `Qn：问题`。
4. `答复：`直接结论。
5. 分维度论证、事实、数据、表格或图片（按需）。
6. 判断边界或核验要求（按需、融入相应回答）。
7. 页眉和页码。

不得附加来源附录、Reviewer 附录、系统免责声明或模板解析信息。

## 7. 拒绝与失败

| 条件 | 行为 |
|---|---|
| 无项目访问权限 | 拒绝，且不泄露隐藏项目或来源 |
| 联网检索服务全部不可用 | 停止正式 PDF 生成并提示检查检索服务 |
| 公开信息与项目资料冲突 | 并列披露口径，说明对判断的影响和核验方法 |
| 只有公司单方陈述 | 标记为公司陈述，不升级为已核验事实 |
| 无法支持关键主张 | 输出具体核验边界，不编造、不输出占位语 |
| 要求 DOCX/PPT/PPTX | 说明正式 Q&A 只提供 PDF |
