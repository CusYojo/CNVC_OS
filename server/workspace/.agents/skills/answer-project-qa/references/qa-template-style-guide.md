# Q&A 模板核心规则

本文件是 `docs/Q&A/Q&A模板核心规则.md` 的 Skill 执行版。核心规范 SHA-256：`cb0b3e4d419e64aca404aa4ac558faca19740cfe9d4698f87836d044387b9413`。

## 模板共识

1. 正式交付物为可编辑 DOCX。
2. 问题是可见的一级内容单元，按当前项目动态生成。
3. 普通问题（包括信息不足问题）在内部遵循“问题—直接答复—已确认事实—分析判断—证据边界—下一步核验”；阶段建议在内部遵循“问题—直接答复—判断依据—升级与失效条件—下一步动作—OA 流转边界”。这些字段只用于保证逻辑完整，可见 DOCX 根据事实数量和论证需要形成 3-7 个连续自然段，不显示“答复：”“回答：”、分维度编号、小标题或字段标签。
4. 范例只提供结构、版式和文风；样本事实不得进入新文档。
5. 项目资料不足时，先由系统仅用公开项目名称和检索主题直接检索高价值缺口，核验原始页面后交由项目大模型总结；仍无可靠证据时形成自然、具体的有限判断和核实动作。
6. 可见正文不显示 Markdown、网页框架、占位式无资料答复、来源编号、引用资料、Reviewer 结果或资料加工过程。
7. 生成角色为投资中台资深投资经理；问题优先响应用户关注点并根据当前项目证据动态选取，需要阶段判断时形成一个推进、暂缓或归档主建议。
8. 报告围绕当前项目的主体、股权与治理、团队、产品与技术、市场与客户、商业模式、财务、融资与估值、交易方案和风险，不写泛行业研究。

## DOCX 格式

- A4 纵向，页边距上、下 25.4 mm，左、右 31.7 mm。
- 白色背景，黑色或深灰正文。
- 主标题：宋体 18 pt，加粗居中。
- 问题：宋体 14 pt，加粗左对齐。
- 正文：宋体 10.5-11 pt，两端对齐。
- 英文与数字：Times New Roman。
- 正文 1.5 倍行距，首行缩进 2 个汉字。
- 页眉与页码 9 pt；页码连续。

## 稳定结构

```text
项目 Q&A DOCX
├─ 文档标题
├─ 问题目录（按需）
├─ Qn：问题
│  ├─ 直接结论自然段
│  ├─ 事实、数据与事件进展（按需拆分）
│  ├─ 分析、比较与影响（按需拆分）
│  └─ 判断边界和核验或推进动作（按需合并）
└─ 页眉与页码
```

正文问题连续使用 `Q1：`、`Q2：`。回答正文不使用 `（1）`、`（2）` 等分维度编号。

内部语义单元可以在成稿中拆分、合并或去重。模型字段中的“答复：”“回答：”、Markdown、重复编号和结构标题必须在渲染前清除；Formatter 可按标题语义纠正旧格式内容的顺序，但最终只保留正文，不显示标签、编号、小标题或字段名称。Reviewer 与 DOCX 门禁逐题验证正文为 3-7 个连续自然段，并检查相邻问题没有机械复用相同段数、首句和收束句。

问题目录不是五份范例共有结构，因此只按需设置。标准版通常 5-8 题，运行时目标 7 题；深度版通常 8-12 题，运行时目标 10 题。证据不足时不得为凑数量生成大量边界性答复。

使用目录时，先连续列完全部目录项，再另起页进入正文 Q1。禁止在第 7 题或其他固定位置人为拆页、重复项目标题或插入“问题目录（续）”。题目展示顺序固定为“阶段建议→项目主体→产品与技术→商业模式→客户与商业化→市场与竞争→团队与股权→知识产权→财务与融资→交易方案→合规与风险”。

## 各内容单元的表达目的

| 内容单元 | 表达内容 |
|---|---|
| 标题 | 当前项目正式名称与 Q&A |
| 问题 | 一个影响投资判断、可核验的核心事项 |
| 直接答复 | 明确结论、主要依据、成立条件 |
| 普通问题后续自然段 | 覆盖已确认事实、分析判断、证据边界、下一步核验；可按内容拆分或合并，不显示这些名称 |
| 阶段建议后续自然段 | 覆盖判断依据、升级与失效条件、下一步动作、OA 流转边界；可按内容拆分或合并，不显示这些名称 |
| 信息不足后续自然段 | 自然说明有限判断、不确定性影响和具体核实动作，不描述资料处理过程 |
| 事实与数据 | 单位、期间、时点、口径和证据属性 |
| 图表 | 比较、趋势、阶段或流程；只按需使用 |
| 判断边界 | 无法判断的具体事项、原因和核验要求 |
| 阶段与推进建议 | 与当前阶段匹配的主建议、证据、失效条件、下一步动作和 OA 流转边界 |

## 项目资料库与证据

证据优先级为：项目资料库中的上传原件和知识片段、项目档案、用户确认输入、经系统直接读取并完成项目匹配核验的公开页面、审慎分析。生成过程不调用或依赖 SearXNG；系统仅用公开项目名称和检索主题发现候选页面，项目资料库正文和内部字段不进入外部搜索词；页面先删除导航、联系方式、备案和版权等框架信息，再通过公网地址安全、可信域名、正文和资料截止日检查后缓存，并交由项目大模型总结复用。只匹配公司简称或近名的页面不得确认当前项目工商、股权、财务或融资事实。重要事实在内部保留项目资料索引、版本或日期和支持原文。

不得用行业平均值推定公司的未披露财务、订单、合同或估值。项目资料库和经核验公开页面均未覆盖时，不得编造或输出“暂无相关资料”；应直接说明目前不能确认什么、这一不确定性对投资判断的影响，以及需要核实什么主体、原件、数据或访谈对象。

有两条以上证据时，回答应综合事件时间线、量化指标、信号强弱、来源一致或冲突、处置影响、失效条件和下一步动作，不得只复制单条材料或网页正文。

人员、研发合作、知识产权许可或转让关系必须说明具体关系类型、主体、时间和证据。线索池摘要、标签、评分和融资线索必须保留待核验属性；行业和竞品信息只用于解释当前项目的应用与竞争背景，不得形成独立的泛行业研究。

## 可见正文排除项

- `[S1]` 等来源编号
- 引用资料或链接清单
- Reviewer 审阅结果
- 模板指纹、解析结果或系统质量记录
- 占位式无资料答复
- “项目资料”“项目材料”“资料库”“当前资料”“现有证据”“资料截止日”“经系统核验”“公开页面”“公司材料称”“资料显示”“材料显示”“会议纪要”“交流纪要”“访谈纪要”“交流时间”“交流地点”“参会人员”“回填资料库”“更新本题”“本回答”“结论置信度”等资料加工和系统过程话术
- Markdown 星号、井号或代码围栏
- 网页标题、导航、联系方式、备案号或版权页脚
- PDF、PPT 或 PPTX 下载说明

## 交付检查

检查问题质量、项目资料证据、数字口径、事实状态、样本污染、问题连续编号、回答是否自然形成 3-7 段、相邻问题句式重复、可见小标题残留、来源章节编号残留、资料加工话术、字体、分页、截断、重叠、表格断裂和异常空白。只登记通过 OpenXML、中文编码和 Word/WPS 可打开性检查的 DOCX。
