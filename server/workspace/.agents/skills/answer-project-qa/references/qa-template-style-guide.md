# Q&A 模板核心规则

本文件是 `docs/Q&A/Q&A模板核心规则.md` 的 Skill 执行版。核心规范 SHA-256：`4e2b0f4cca3c15c6b83bc6425f373fa7f195d641912d726080d07a79388bf1fe`。

## 模板共识

1. 正式交付物为可编辑 DOCX。
2. 问题是可见的一级内容单元，按当前项目动态生成。
3. 普通问题（包括证据不足问题）遵循“问题—直接答复—已确认事实—分析判断—证据边界—下一步核验”；阶段建议遵循“问题—直接答复—判断依据—升级与失效条件—下一步动作—OA 流转边界”。
4. 范例只提供结构、版式和文风；样本事实不得进入新文档。
5. 项目资料不足时，先由系统仅用公开项目名称和检索主题直接检索高价值缺口，核验原始页面后交由项目大模型总结；仍无可靠证据时形成具体核验结论和材料补充要求。
6. 可见正文不显示 Markdown、网页框架、占位式无资料答复、来源编号、引用资料或 Reviewer 结果。
7. 生成角色为投资中台资深投资经理；问题优先响应用户关注点并根据当前项目证据动态选取，需要阶段判断时形成一个推进、暂缓或归档主建议。
8. 报告围绕当前项目的主体、股权与治理、团队、产品与技术、市场与客户、商业模式、财务、融资与估值、交易方案和风险，不写泛行业研究。

## DOCX 格式

- A4 纵向，页边距上、下 25.4 mm，左、右 31.7 mm。
- 白色背景，黑色或深灰正文。
- 主标题：宋体 18 pt，加粗居中。
- 问题：宋体 14 pt，加粗左对齐。
- 分维度标题：宋体 12 pt，加粗左对齐。
- 正文：宋体 10.5-11 pt，两端对齐。
- 英文与数字：Times New Roman。
- 正文 1.5 倍行距，首行缩进 2 个汉字。
- 页眉与页码 9 pt；页码连续。

## 稳定结构

```text
项目 Q&A DOCX
├─ 文档标题
├─ 问题目录（按需）
├─ Qn：问题
│  ├─ 答复：直接结论
│  ├─ （1）分维度论证（按需）
│  ├─ 事实、数据、案例或图表（按需）
│  └─ 判断边界或核验要求（按需）
└─ 页眉与页码
```

正文问题连续使用 `Q1：`、`Q2：`，分维度连续使用 `（1）`、`（2）`。

每个分维度小标题独立成段，只加粗编号与标题。模型字段中的 Markdown、重复编号和重复标题必须在渲染前清除并标准化；Formatter 按标题语义纠正错误编号和错序，合并同一维度被换行拆开的正文，删除来源材料自带的章节编号；Reviewer 与 DOCX 门禁逐题验证编号、名称、数量和相对顺序。

问题目录不是五份范例共有结构，因此只按需设置。标准版通常 5-8 题，运行时目标 7 题；深度版通常 8-12 题，运行时目标 10 题。证据不足时不得为凑数量生成大量边界性答复。

使用目录时，先连续列完全部目录项，再另起页进入正文 Q1。禁止在第 7 题或其他固定位置人为拆页、重复项目标题或插入“问题目录（续）”。题目展示顺序固定为“阶段建议→项目主体→产品与技术→商业模式→客户与商业化→市场与竞争→团队与股权→知识产权→财务与融资→交易方案→合规与风险”。

## 各内容单元的表达目的

| 内容单元 | 表达内容 |
|---|---|
| 标题 | 当前项目正式名称与 Q&A |
| 问题 | 一个影响投资判断、可核验的核心事项 |
| 直接答复 | 明确结论、主要依据、成立条件 |
| 普通问题分维度 | 已确认事实、分析判断、证据边界、下一步核验 |
| 阶段建议分维度 | 判断依据、升级与失效条件、下一步动作、OA 流转边界 |
| 证据不足分维度 | 与普通问题相同：已确认事实、分析判断、证据边界、下一步核验 |
| 事实与数据 | 单位、期间、时点、口径和证据属性 |
| 图表 | 比较、趋势、阶段或流程；只按需使用 |
| 判断边界 | 无法判断的具体事项、原因和核验要求 |
| 阶段与推进建议 | 与当前阶段匹配的主建议、证据、失效条件、下一步动作和 OA 流转边界 |

## 项目资料库与证据

证据优先级为：项目资料库中的上传原件和知识片段、项目档案、用户确认输入、经系统直接读取并完成项目匹配核验的公开页面、审慎分析。生成过程不调用或依赖 SearXNG；系统仅用公开项目名称和检索主题发现候选页面，项目资料库正文和内部字段不进入外部搜索词；页面先删除导航、联系方式、备案和版权等框架信息，再通过公网地址安全、可信域名、正文和资料截止日检查后缓存，并交由项目大模型总结复用。只匹配公司简称或近名的页面不得确认当前项目工商、股权、财务或融资事实。重要事实在内部保留项目资料索引、版本或日期和支持原文。

不得用行业平均值推定公司的未披露财务、订单、合同或估值。项目资料库和经核验公开页面均未覆盖时，不得编造或输出“暂无相关资料”；应明确说明现阶段无法判断什么、需要取得什么原件、数据或访谈，以及核验后应回填的项目资料。

有两条以上证据时，回答应综合事件时间线、量化指标、信号强弱、来源一致或冲突、处置影响、失效条件和下一步动作，不得只复制单条材料或网页正文。

人员、研发合作、知识产权许可或转让关系必须说明具体关系类型、主体、时间和证据。线索池摘要、标签、评分和融资线索必须保留待核验属性；行业和竞品信息只用于解释当前项目的应用与竞争背景，不得形成独立的泛行业研究。

## 可见正文排除项

- `[S1]` 等来源编号
- 引用资料或链接清单
- Reviewer 审阅结果
- 模板指纹、解析结果或系统质量记录
- 占位式无资料答复
- Markdown 星号、井号或代码围栏
- 网页标题、导航、联系方式、备案号或版权页脚
- PDF、PPT 或 PPTX 下载说明

## 交付检查

检查问题质量、项目资料证据、数字口径、事实状态、样本污染、问题与小标题连续编号、小标题名称/数量/相对顺序、来源章节编号残留、同一维度正文断裂、字体、分页、截断、重叠、表格断裂和异常空白。只登记通过 OpenXML、中文编码和 Word/WPS 可打开性检查的 DOCX。
