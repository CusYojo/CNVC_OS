# 项目 Q&A 模板结构与文风规范

## 模板共识

`docs/Q&A/` 中的业务样本题目随项目变化，但共享同一套文档母版。生成时严格复用母版，不复用任何样本项目事实或答案。

1. 文档主题为“某项目/某公司 Q&A”，问题是一级内容单元，不预设跨项目通用的固定问题标题。
2. 多问题长文档可先列问题目录，再按相同编号展开正文；单次回答直接展示当前问题，不生成空目录。
3. 每个问题先给出明确答复，再按二至五个分析维度展开。分析维度必须由当前问题和现有证据决定。
4. 只有产品矩阵、市场测算、财务对比、客户进度、竞争差异或证据冲突确实需要横向比较时才使用表格或图表。
5. PDF 样本页面以正式 A4 投资研究材料为基准。生成结果不复制页面或导出文件，只把标题明确、问题突出、正文紧凑、编号连续等特征转译为会话卡片中的等价标题层级和阅读顺序。

## 各内容单元的表达目的

| 内容单元 | 必须表达什么 | 写作要求 |
|---|---|---|
| 项目标题 | 标识当前项目及 Q&A 文档类型 | 使用当前项目名称，不沿用样本项目名 |
| 问题标题 | 呈现用户确认的问题及其决策焦点 | 保持原意；可修正明显病句，不替用户扩大结论 |
| 直接答复 | 第一时间回答“是什么、是否成立、为什么重要” | 一至三句；结论先行；证据不足时直接说明边界 |
| 分维度论证 | 解释结论由哪些业务、技术、市场、财务、团队或合规依据支撑 | 使用“（1）维度标题：判断—证据—影响/边界”的结构；二至五项 |
| 量化材料 | 说明规模、进度、差异或变化 | 数字必须带单位、口径、时点和来源；不可比数据不得强行比较 |
| 风险与不确定性 | 揭示结论可能不成立的条件、证据冲突和资料缺口 | 写具体风险，不使用“存在一定风险”等空泛句式 |
| 后续核验行动 | 把资料缺口转成可执行动作 | 明确核验对象、所需材料或访谈对象及拟验证事项 |
| 来源与责任边界 | 支撑追溯和内部审阅 | 作为回答附录置于末尾，不打断正文论证 |

## 写作风格

- 使用正式、克制、面向投资决策的中文书面语，保持研究材料口吻，不使用营销口号或聊天式寒暄。
- 采用“结论先行—分维度解释—量化或事实支撑—投资含义/适用边界”的论证链。
- 优先使用能承载判断的维度标题，例如“市场需求：……”“技术壁垒：……”“回款质量：……”，避免“情况一”“其他方面”等空标题。
- 一段只表达一个中心判断。关键要点之间不得换词复述同一事实。
- 可使用“从需求端看”“从供给端看”“综合来看”等过渡语，但不得机械重复。
- 对积极结论同时交代成立条件；对风险结论说明影响路径和可核验方式。不得把公司陈述写成已独立核验事实。
- 保留行业通用专业术语和用户原始术语；首次出现的不常见缩写应给出中文解释。
- 所有数值保留原始精度并标明币种、单位、期间或截止日。缺少口径时明确标为待核验。

## 按问题生成动态章节

问题标题和分维度标题必须根据当前问题动态生成，不得把模板样本的问题清单当成固定目录。可参考以下分析角度选择二至五项，不要求全部覆盖：

| 问题类别 | 常用分析角度 |
|---|---|
| 投资亮点 | 需求真实性、产品与技术、商业模式、团队能力、产业验证、增长路径 |
| 核心风险 | 未验证假设、客户或供应商依赖、交付与规模化、组织能力、下行情景 |
| 财务 | 收入质量、毛利与成本、回款与应收、现金流、融资与估值口径 |
| 客户 | 客户质量、集中度、订单阶段、交付验收、回款、渠道可复制性 |
| 竞争 | 市场边界、替代方案、技术差异、商业差异、可持续壁垒 |
| 合规 | 主体与治理、股权和控制权、知识产权、资质许可、关联交易 |
| 资料缺口 | 缺失文件、冲突信息、过期资料、访谈待确认事项、核验优先级 |

## 结构化字段到模板正文的映射

宿主系统使用结构化字段保存回答。生成时按以下方式映射，保证既符合模板正文，也满足审计要求：

1. `question` 对应问题标题。
2. `direct_answer` 对应“答复：”后的结论段；字段内容本身不要重复“答复：”或“回答：”标签。
3. `key_points[]` 对应分维度论证。每项写成“（序号）维度标题：核心判断。证据与口径。投资含义或适用边界。”，引用与事实状态由宿主界面展示。
4. `risks_or_uncertainties[]` 对应正文后的风险与不确定性。
5. `verification_actions[]` 对应建议核验动作。
6. `sources[]`、`evidence_count`、`confidence_status` 和 `disclaimer` 构成末尾审计附录，不插入直接答复或分维度论证中。

该映射只形成结构化会话回答，不形成 PPT/PPTX、DOCX、PDF、图片、预览图或其他可下载交付物。

## 表格与图表条件

- 三个及以上同口径对象需要比较时，可使用紧凑表格。
- 时间序列、市场规模、客户/产品进度、财务变化或竞争参数需要直观呈现时，可建议图表。
- 没有足够结构化数据时使用正文，不制作仅为装饰的表格或图表。
- 表格必须有清晰表头、单位和时点；图表必须有标题、单位、数据来源和口径说明。

## 生成前检查

1. 当前项目名称、问题和所有事实是否都来自项目上下文、用户输入或已授权证据。
2. 用户输入中的事实是否仅作为公司陈述或待核验事项，除非另有项目证据支持。
3. 直接答复是否真正回答了问题，而非重复问题或堆叠背景。
4. 分维度标题是否由当前问题动态生成，且每项都包含判断、证据和影响/边界。
5. 风险与核验动作是否具体、互不重复并与证据缺口对应。
6. 是否误用了样本项目名称、数字、结论、句子或固定问题标题。
7. 来源附录是否位于末尾，且只列正文实际使用的去重来源。
