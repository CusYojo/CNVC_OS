# Q&A 模板核心规则

本文件是 `docs/Q&A/Q&A模板核心规则.md` 的 Skill 执行版。核心规范 SHA-256：`b2b8b4c381b5f4d4cfbe96b4133cb7b55da1d0404d6be8600878c483bfb1d01f`。若业务规范更新，应同步更新本文件、Formatter 和验收断言。

## 模板共识

1. 项目 Q&A 是面向投资研究和项目评审的正式材料。
2. “问题”是可见的一级内容单元，问题和分析维度根据当前项目动态生成。
3. 15 类分类只用于内部覆盖与完整性检查，不渲染为固定业务章节。
4. 每题遵循“问题—直接答复—分维度论证—待补资料”的顺序。
5. 模板和核心规则只约束结构、版式和语言；样本项目事实、数字、句子和结论不得进入新文档。
6. 正式任务输出可编辑 Word 与同源 PDF；单题会话只映射为结构化卡片；两种模式均不生成 PPT/PPTX。

## 统一格式

### 页面

- A4 纵向：210 mm × 297 mm。
- 黑白公文版式，白色背景，不使用装饰性底图。
- 页边距：上、下 25.4 mm；左、右 31.7 mm。
- 正文版心：约 145-150 mm。
- 页眉：项目或公司名称加 `Q&A`，9 pt，居中。
- 页码：9 pt，页脚居中，连续编号。
- 保密水印仅在业务明确要求时使用，不得遮挡内容。

### 字体与字号

| 元素 | 中文 | 英文与数字 | 字号 | 样式 |
|---|---|---|---:|---|
| 文档主标题 | 宋体 | Times New Roman | 18 pt | 加粗、居中 |
| 问题目录 | 宋体 | Times New Roman | 12 pt | 加粗、左对齐 |
| 一级问题标题 | 宋体 | Times New Roman | 14 pt | 加粗、左对齐 |
| 分维度标题 | 宋体 | Times New Roman | 12 pt | 加粗、左对齐 |
| 正文 | 宋体 | Times New Roman | 10.5-11 pt | 常规、两端对齐 |
| 表格正文 | 宋体 | Times New Roman | 9-10 pt | 按列对齐 |
| 图题/表题 | 宋体 | Times New Roman | 10.5 pt | 加粗、居中 |
| 页眉/页码 | 宋体 | Times New Roman | 9 pt | 常规、居中 |

全文保持字体和层级样式一致。

### 段落

- 正文使用 1.5 倍行距和两端对齐。
- 普通正文首行缩进 2 个汉字。
- 问题标题、分维度标题和“答复：”不缩进。
- 正文段后 0-3 pt。
- 一级问题段前 12-18 pt、段后 6-9 pt。
- 分维度标题段前 6-9 pt、段后 3-6 pt。
- 标题不得孤立在页末；表头和表体不得无意义断开。

### 编号

- 目录与正文统一使用 `Q1：`、`Q2：`、`Q3：`。
- 分维度统一使用 `（1）`、`（2）`、`（3）`。
- 更细层级使用 `①`、`②`、`③` 或统一项目符号。
- Duplicate Checker 后重新编号；目录与正文逐项一致。

## 稳定结构

```text
项目 Q&A
├─ 文档标题
├─ 问题目录
├─ 连续问答正文
│  ├─ Qn：问题
│  ├─ 答复：直接结论
│  ├─ （1）分维度论证
│  ├─ （2）分维度论证
│  ├─ 事实、数据或案例
│  ├─ 图表或图片（按需）
│  └─ 小结与待核验事项（按需）
└─ 页面控制
   ├─ 页眉
   ├─ 页码
   └─ 保密水印（按需）
```

多问题正式文档必须包含问题目录。单题会话不生成空目录，只展示当前问题和回答。

正式任务可在正文之后附“引用资料”和“Reviewer 审阅结果”，用于证据追溯和质量审计；它们是系统审计附录，不是模板正文的固定业务章节。

## 各内容单元的表达目的

| 内容单元 | 必须表达什么 | 写作要求 |
|---|---|---|
| 文档标题 | 当前项目及 Q&A 类型 | 使用当前项目正式名称，不沿用样本名称 |
| 问题目录 | 全部问题及阅读顺序 | 只列问题；编号与正文一致 |
| 问题标题 | 一个影响投资判断的可核验事项 | 保持焦点单一；不预设营销结论 |
| 直接答复 | 结论、主要依据和成立条件 | 一至三句，结论先行 |
| 分维度论证 | 支撑结论的判断、依据、影响和边界 | 二至五项；标题承载判断 |
| 事实与数据 | 证明规模、进度、差异、变化或风险 | 标明单位、期间、时点、口径和来源 |
| 图表或图片 | 在文字难以高效表达时提供比较、趋势、阶段或流程 | 仅按需使用，必须有标题、单位、时点和口径 |
| 小结与待核验事项 | 汇总总体判断、成立条件和未决证据 | 仅复杂问题按需使用，不写空泛结论 |
| 页面控制 | 标识当前项目并保证连续阅读 | 页眉、页码；水印仅在业务明确要求时使用 |

系统审计附录中的“引用资料”只列正文实际使用的去重来源；“Reviewer”只记录重复、完整性、幻觉和引用检查，不新增事实。

## 回答写法

### 直接答复

直接回答“结论是什么、为什么成立、在哪些条件下成立”。字段本身不重复“答复：”标签，由 Formatter 添加。

### 分维度论证

证据充分时使用二至五项：

```text
（1）维度标题：核心判断。直接证据与口径。对投资判断的影响。适用边界或待核验条件。
```

维度标题应直接承载判断，例如“需求真实性”“技术壁垒”“回款质量”。不得使用“情况一”“其他方面”“相关说明”等空标题。

一段只表达一个中心判断；同一事实不在直接答复、分维度、风险和待补资料中重复。

### 数字和事实

- 金额、比例、日期、数量、客户和订单事实必须在引用来源中出现。
- 所有数字标明币种、单位、期间或截止日。
- 市场测算说明数量、单价、渗透率和基准/上下行情景。
- 客户进展区分接触、送样、合同、交付、验收、收入确认和回款。
- 公司陈述、预测、意向和已实现结果必须明确区分。
- 口径不一致的数据不得强行比较。

### 风险与边界

- 积极结论同时说明成立条件。
- 风险说明影响路径、触发条件和核验方式。
- 资料不足时严格使用 `暂无相关资料。`，不使用模板事实补写。

## 表格和图片

仅在以下场景使用：

- 三个以上对象按统一维度比较。
- 产品系列或应用场景较多。
- 技术、产品或业务发展跨多个阶段。
- 客户、订单、送样、市场或财务数据需要横向比较。
- 技术流程仅靠文字难以说明。

表格或图片必须有标题、单位、期间、截止日和必要说明。产品图片标注名称和用途；截图指出需要观察的功能。视觉元素不得替代正文结论。

## 正式 Word/PDF 映射

- Word 正文、表格和结构保持可编辑。
- PDF 由最终 Word 同源转换，不另行重新排版或改写内容。
- Formatter 不新增、总结或润色 Reviewer 已通过内容之外的事实。
- 引用资料和 Reviewer 结果位于最后，不插入正文论证。
- 交付前检查字体、编号、分页、表格、页眉、页码、截断、重叠和乱码。

## 单题会话映射

1. `question` 对应问题标题。
2. `direct_answer` 对应直接答复。
3. `key_points[]` 对应连续编号的分维度论证。
4. `risks_or_uncertainties[]` 对应风险和边界。
5. `verification_actions[]` 对应待补资料与核验动作。
6. `sources[]`、`evidence_count`、`confidence_status` 和 `disclaimer` 构成末尾审计信息。

会话只使用等价结构和阅读顺序，不模拟 A4 页面，也不生成文件。

## 生成前检查

1. 项目名称、问题和事实是否都来自当前项目上下文或获授权证据。
2. 问题是否聚焦一个可判断、可核验事项。
3. 直接答复是否在一至三句内回答问题。
4. 分维度是否连续编号、互不重复并包含判断、依据、影响和边界。
5. 数字是否包含单位、期间、截止日和来源。
6. 公司陈述、预测、意向和已实现事实是否区分。
7. 是否残留样本项目名称、数字、句子或结论。
8. 资料不足是否严格写 `暂无相关资料。`。
9. 目录、正文和引用编号是否一致。
10. 输出是否仅为单题结构化回答，或正式 Word 与同源 PDF；不得出现 PPT/PPTX。
