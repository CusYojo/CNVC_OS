# Q&A 模板核心规则

本文件是 `docs/Q&A/Q&A模板核心规则.md` 的 Skill 执行版。核心规范 SHA-256：`be68a72e62ff3754c33e2989221339921a4159804a00566bd1304549354726c2`。

## 模板共识

1. 正式交付物为 PDF。
2. 问题是可见的一级内容单元，按当前项目动态生成。
3. 每题遵循“问题—直接答复—分维度论证（按需）—判断边界（按需）”。
4. 范例只提供结构、版式和文风；样本事实不得进入新文档。
5. 项目资料不足时针对性联网补证；未公开事项形成具体核验结论。
6. 可见正文不显示占位式无资料答复、来源编号、引用资料或 Reviewer 结果。

## PDF 格式

- A4 纵向，页边距上、下 25.4 mm，左、右 31.7 mm。
- 白色背景，黑色或深灰正文。
- 主标题：宋体 18 pt，加粗居中。
- 问题：宋体 14 pt，加粗左对齐。
- 分维度标题：宋体 12 pt，加粗左对齐。
- 正文：宋体 10.5-11 pt，两端对齐。
- 英文与数字：Times New Roman。
- 正文 1.5 倍行距，首行缩进 2 个汉字。
- 页眉与页码 9 pt；页码连续。

## 稳定结构

```text
项目 Q&A PDF
├─ 文档标题
├─ 问题目录（按需）
├─ Qn：问题
│  ├─ 答复：直接结论
│  ├─ （1）分维度论证（按需）
│  ├─ 事实、数据、案例或图表（按需）
│  └─ 判断边界或核验要求（按需）
└─ 页眉与页码
```

正文问题连续使用 `Q1：`、`Q2：`，分维度连续使用 `（1）`、`（2）`。

问题目录不是五份范例共有结构，因此只按需设置。标准版通常 5-8 题，运行时目标 7 题；深度版通常 8-12 题，运行时目标 10 题。

## 各内容单元的表达目的

| 内容单元 | 表达内容 |
|---|---|
| 标题 | 当前项目正式名称与 Q&A |
| 问题 | 一个影响投资判断、可核验的核心事项 |
| 直接答复 | 明确结论、主要依据、成立条件 |
| 分维度论证 | 判断、依据、影响、边界 |
| 事实与数据 | 单位、期间、时点、口径和证据属性 |
| 图表 | 比较、趋势、阶段或流程；只按需使用 |
| 判断边界 | 无法判断的具体事项、原因和核验要求 |

## 联网与证据

证据优先级为：用户确认输入、项目资料、一手公开信息、权威行业信息、审慎分析。重要事实优先使用官网、政府、监管、公示和原始公告，并在内部保留网址、公开日期、访问日期、来源索引和支持原文。

不得用行业平均值推定公司的未披露财务、订单、合同或估值。公开渠道仍未披露时，不得编造或输出“暂无相关资料”；应明确说明现阶段无法判断什么，以及需要取得什么原件、数据或访谈。

## 可见正文排除项

- `[S1]` 等来源编号
- 引用资料或链接清单
- Reviewer 审阅结果
- 模板指纹、解析结果或系统质量记录
- 占位式无资料答复
- DOCX、PPT 或 PPTX 下载说明

## 交付检查

检查问题质量、联网补证、数字口径、事实状态、样本污染、连续编号、字体嵌入、分页、截断、重叠、表格断裂和异常空白。只登记通过检查的 PDF。
