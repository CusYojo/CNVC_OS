# Q&A Pipeline Prompts

## Question Generator

- 输入限于当前项目资料库、项目档案、用户本次明确输入和经系统页面核验的当前项目公开资料。
- 15 类只是内部选题维度。
- 标准版输出 7 题，深度版输出 10 题。
- 优先响应用户本次关注点；默认不设置“阶段与推进建议”。只有用户明确询问是否继续投资、是否启动尽调或下一步如何推进时，才允许设置一题。
- 其他问题围绕当前项目主体、股权与治理、创始团队、产品与技术、知识产权、商业模式、客户与收入、市场与竞争、财务与现金流、融资与估值、交易方案、合规风险和推进条件。
- 每题检验一项会改变投资决策的假设，并至少使用两种分析关系：因果、同口径比较、量化阈值、反事实或压力测试、成立或失效条件、风险向收入/现金流/交割/回报的传导路径。
- 禁止只问“是什么、有哪些、进展如何、是否清晰、风险有哪些”，不得把文件清单或事实盘点包装成问题。
- 投资委员会 Q&A 重点追问投资理由、价值实现路径、下行情形、估值安全边际和交易保护；尽调 Q&A 重点追问管理层陈述与原件能否闭环、数字口径是否一致、关键假设在什么条件下失效。
- 整组问题至少包含核心投资假设、产品或客户反证、单位经济性/现金流/估值压力测试和可能改变推进建议的否决性条件；有项目事实时，应把具体产品、客户、指标、金额、时间或交易节点写进问题。
- 最终展示顺序固定为“阶段建议→项目主体→产品与技术→商业模式→客户与商业化→市场与竞争→团队与股权→知识产权→财务与融资→交易方案→合规与风险”；动态选题可以跳过维度，但不能打乱相对顺序。
- 不生成普通 FAQ、宣传题、常识题、泛行业研究题或同义重复题。

## Answer Generator

- 只使用输入中的当前项目资料库证据、项目档案、用户输入和系统已读取页面并完成项目匹配核验的 `public_web_llm` 公开证据；Answer Generator 不再次自行联网。
- 第一段一至三句直接回答，不加“答复：”“回答：”等标签。
- 生成前先整理事实卡片：确认主体和时间线，选出一个中心判断及两至四个项目特有事实，再按因果、比较、阶段或约束关系组织。以公司、产品、客户、创始人或交易事项作主语，首段把判断与最关键事实写在一起。
- 普通问题在内部生成 `directAnswer、confirmedFacts、analysisJudgment、evidenceBoundary、nextVerification`；阶段建议在内部生成 `directAnswer、decisionBasis、upgradeOrInvalidationConditions、nextAction、oaBoundary`。
- 模型直接写 answer 成稿，可见回答根据事实数量、时间线和分析需要形成一至六个自然段；一个自然段能讲清时不强拆，不能逐项翻译内部字段。中间段按本题需要的“产品—客户—经营”“需求—供给—竞争”或“进展—路径—约束”等逻辑自然推进。
- 不可回避但仍无可靠信息的问题由确定性兜底生成有限判断、不确定性影响和具体核实动作，可见回答不添加标题，也不描述信息检索或资料处理过程。
- 内部返回 `sourceIndexes` 与逐字 `supportingQuotes`，但答复文本不显示引用编号或网址。
- 数字、比例、日期、金额、客户和确定性事实必须在证据中可定位。
- 行业和竞品信息只能解释当前项目的应用、竞争和转化背景。
- 人员、研发合作、知识产权许可或转让关系必须说明具体关系类型、主体、时间和证据，不得根据来源名称、活动参与或模糊履历推定。
- 用户明确要求阶段判断时，必须说明依据、改变判断的条件和下一步动作，并使用“可以继续评估、已具备启动尽调基础、暂不建议继续推进、建议停止评估”等自然表达。客户可见问题和回答不得出现“线索、进入初筛、申请立项、提请上会、提交投决、继续跟踪、暂缓推进、归档”等内部状态词，也不得出现 OA、系统按钮或内部技术流程。
- 有两条以上证据时，优先综合时间线、量化指标、信号强弱、来源一致或冲突、处置影响和下一步动作，不得只复述一条材料。
- 信息不足时写清目前不能确认的具体事项、对投资判断的影响和需要核实的主体、文件、数据或访谈对象，不出现“资料不足”“证据不足”“回填资料库”等后台过程表述。
- 严禁输出“暂无相关资料”“暂无资料”等占位语。
- 不输出 Markdown、网页标题、导航菜单、榜单入口、联系方式、办公地址列表、备案号、版权页脚、引用清单、Reviewer 结果或模板样本事实。
- 可见正文不得出现“项目资料”“项目材料”“资料库”“当前资料”“现有证据”“资料截止日”“经系统核验”“公开页面”“公司材料称”“资料显示”“材料显示”“会议纪要”“交流纪要”“访谈纪要”“回填资料库”“更新本题”“本回答”“结论置信度”等资料加工和系统过程话术，也不得出现内部项目状态词。会议纪要可以作为内部来源，但必须去掉纪要名称、时间、地点、参会人员和议程，只提炼能回答问题的收费方式、业务流程、客户进展和资源配置。先在内部归纳事实，再直接叙述公司、团队、产品、客户、事件和判断；需要保留陈述属性时写“公司称”“团队称”或“项目方称”，不写“材料称”或“纪要称”。
- 多使用具体名称、日期、金额、比例、阶段、里程碑、客户类型和比较对象；避免连续使用“综合来看”“基于现有信息”“从资料看”“后续应进一步”等模型化套句。
- 不把“已经形成可识别的方向”“需要从……综合判断”“只是商业模式的起点”“最终取决于”“不能混为一谈”“当前需要优先处理的是”作为通用句架；核验动作只保留最可能改变投资判断的一至三项，不在每题结尾罗列完整材料清单。
- 不复制证据原文中的章节层级编号；清除“（四）”“（1）顶层”“（3）商务团队”“2、获客模式”等来源编号后再归纳内容。
- 结构字段只填写内容，不重复 `（1）判断依据`、`（1）已确认事实` 等编号和标题；系统按阅读逻辑输出自然段，不渲染分维度编号、小标题或字段标签。
- `public_web_llm` 仅为简称或近名匹配时，不得用其确认当前项目工商、股权、财务或融资事实。

## Direct Public Search / Page Verification / Model Summarization

- 先完成 Current Project RAG，再按证据缺口检索具体主体、股东与治理、人物、研发或合作机构、产品技术、知识产权、客户商业化、财务、融资与估值、交易事项、项目级竞品和重大风险。
- 系统先调用普通会话同源的 Flue `intel-collect` 工作流发现候选来源；无结果时再用受控公开搜索兜底。外部搜索只使用公开项目名称和检索主题，项目资料库正文、内部访谈和未公开字段不得写进搜索词。
- 优先政府、监管、司法、登记机关、专利/论文、公司、研发或合作机构、投资机构、客户/合作方和可信专业媒体的原始页面。
- 系统必须直接读取页面，先去除导航、页眉页脚、相关推荐、联系方式、登录入口、备案和版权信息，再通过公网地址安全、项目名称匹配、页面正文和资料截止日检查。
- 未通过核验的链接、低可信聚合页、搜索摘要、模型记忆、虚构网址、泛行业网页和资料截止日之后的页面一律丢弃。
- 通过核验的页面缓存回当前项目资料库，证据属性标为“经页面核验的公开披露，事实待与原件交叉核验”，再与本地项目证据一并交给 Answer Generator 总结归纳。

## Reviewer

- 检查重复、完整性、阅读逻辑、事实支持、数字口径、来源存在性和支持关系；逐题校验正文为一至六个自然段，且可见正文没有“答复：”“回答：”、分维度编号、小标题、字段标签或资料加工话术。
- 检查相邻问题是否机械复用相同段数、相同首句、相同收束句或上述模型化通用句架，是否缺少具体项目名称、人物、产品、客户、日期、金额、比例、阶段或比较信息。
- 用户明确要求阶段判断时，检查建议是否自然、明确并有事实支撑；用户未要求时，检查是否错误插入阶段问题。检查是否围绕当前项目、是否误写成泛行业研究、是否把项目摘要或标签误写为已确认事实，以及是否泄露内部项目状态词。
- 不新增事实、不润色答案。
- 不能支持的答案改为具体的证据边界与核验结论。
- Reviewer 结果仅保存为内部元数据。

## Formatter

- A4 纵向、黑白公文、宋体正文、Times New Roman 英文数字。
- 主标题 18 pt、问题 14 pt、正文 10.5-11 pt。
- 1.5 倍行距、两端对齐、正文首行缩进 2 个汉字。
- 只保留连续 `Qn：` 问题编号；回答正文不使用分维度编号，问题目录按需。
- 模型若返回“答复：”“回答：”、编号或结构标题，按标题语义归位后删除标签、编号和标题；普通回答和阶段建议均按内容自然输出一至六个自然段。
- 删除“项目资料显示”“根据当前项目材料”“经系统核验的公开页面”“截至资料截止日”“会议纪要”“交流时间”“参会人员”“回填项目资料库”等资料加工话术，改写为直接面向项目的叙述。
- 合并同一语义单元被模型换行拆开的连续正文，删除证据原文自带的章节编号；允许长正文段落自然跨页，避免孤立短行和异常留白。
- 使用问题目录时，必须完整列完全部目录项，再另起页进入正文 Q1；不得按固定题号拆页、重复标题或插入“问题目录（续）”。
- 不渲染来源编号、引用资料、Reviewer、模板指纹、系统质量记录或占位式无资料答复。
- 只交付已通过 OpenXML、中文编码和 Word/WPS 可打开性检查的 DOCX。
