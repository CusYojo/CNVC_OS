# 图片稿到元素级可编辑 PPT 的语义桥接

## 核心原则

桥接 PDF 是扁平化源。OCR 只能识别文字候选，不能自动恢复真实图表数据、流程关系或图标语义。必须把图片生成前已经掌握的结构化内容传给 `pdf-to-editable-ppt`。

## `slide-semantics.json`

```json
{
  "slides": [
    {
      "slide": 1,
      "role": "cover",
      "title": "目标公司投资建议书",
      "verbatim_text": ["目标公司投资建议书", "一句话定位", "2026年8月"],
      "kpis": [],
      "charts": [],
      "tables": [],
      "flow_nodes": [],
      "connectors": [],
      "icons": [],
      "photos": [],
      "source_fact_keys": []
    }
  ]
}
```

所有页面文字必须与阶段 1 提示词中的 verbatim 文字一致。发现图片模型错字时先重生成页面；语义桥接不能被用来掩盖图片稿错误。

## OCR 校正

1. 使用 OCR/视觉识别获得坐标、段落和字号候选。
2. 使用 `verbatim_text` 替换 OCR 错字，不能改变事实含义。
3. 对标题、正文、大数字分别校准字号。
4. 确认旧栅格文字已被清除或完整遮盖，再放置新文本框。
5. 密集截图、代码、论文截图等低置信度区域宁可保留栅格，也不得生成错误文字。

## 语义对象重建

- 卡片与容器：原生形状，名称稳定且能单独选中。
- 图标：优先原生形状，其次独立 SVG；不得用字体字符冒充。
- 流程图：节点、标签和连接线分别重建；连接线必须绑定节点。
- 表格：有明确行列数据时重建为原生表格。
- 图表：有结构化系列数据时重建为原生图表；没有数据时不得宣称数据可编辑。
- 照片和复杂插画：可作为独立栅格图片，但必须准确披露。

## 覆盖清单

根据 `pdf-to-editable-ppt` 当前 `--overrides` schema 生成 `semantic-overrides.json`。每个重建区域包含：

- 原图区域 bbox。
- 清除旧像素的 cover 或修补背景。
- 新建对象及稳定名称。
- 对应 `source_fact_keys`。
- 预期可编辑类型。

移动任一新对象后露出旧文字、旧图标或旧图表即判失败。

## 可编辑范围

用户只说“可编辑 PPT”时按 `all`：所有可识别逻辑对象都必须重建或明确列入未解决清单。用户明确只要文字可编辑时才可使用 `text`，并在交付中说明其余视觉仍为栅格。
