# 输入、数据审计与联网补全

## 输入契约

优先自动识别以下材料：

- 参考模板：PDF、PPTX 或页面图片，可选。
- 项目资料：Word、PDF、PPTX、Excel、CSV、网页或用户消息。
- 目标：投资建议书、IC 报告、BP、路演、项目方案或其他演示稿。
- 受众、页数、语言、截止时间和可编辑范围。

数据不足不是编造授权。除非用户明确禁止联网，否则自动补全公开信息。

## 页面级充分性检查

为每页写独立 `research_question`，并判断最低有效内容是否满足：

- 行业页：规模、增速、驱动、政策或资本信号至少三类证据。
- 公司页：主体身份、成立时间、团队、融资和业务定位。
- 产品页：产品名称、目标用户、核心功能、交付形式和价值指标。
- 技术页：架构、差异点、测试/论文/专利证据和限制。
- 验证页：客户/合作方、时间、场景、合同状态和量化结果。
- 竞争页：同口径对比维度和可验证竞品事实。
- 财务页：历史实际、预测假设、单位、币种和期间。
- 投资页：估值、轮次、金额、用途、里程碑、风险和退出。

不满足即进入联网检索或尽调缺口，不得用形容词充当事实密度。

## 来源分级

1. A 级：政府、监管、工商/交易所、公司官方材料、论文、专利、官方政策、权威统计。
2. B 级：主流财经科技媒体、投资机构正式公告、行业协会或知名研究机构。
3. C 级：数据库聚合、招聘平台、自媒体和二次转载，只能作为线索或经限定的公开说法。

技术问题只依赖论文、专利、官方技术材料等一手来源。重大交易或财务数据优先 A 级并尽可能双源验证。

## 联网检索流程

1. 先锁定法定实体和别名，再组合检索词。
2. 每页分别搜索，避免用一个泛化搜索结果支撑整套演示稿。
3. 优先打开原始来源，不引用搜索结果摘要。
4. 记录发布日期、事件发生日期和访问日期。
5. 核对币种、单位、统计口径、预测/实际和含税/不含税。
6. 对融资、估值、收入、客户、订单和市场规模做交叉验证。
7. 冲突时保留不同口径并解释，不挑选更好看的数字。
8. 无法验证时标为 `public-claim`、`assumption` 或 `unknown`。

## 事实与来源结构

`project-facts.json` 示例：

```json
{
  "fact_key": "company.founded_at",
  "entity": "目标公司法定名称",
  "value": "2024-11-11",
  "status": "verified",
  "source_ids": ["S001"],
  "as_of": "2026-08-01"
}
```

`source-registry.json` 示例：

```json
{
  "source_id": "S001",
  "tier": "A",
  "title": "",
  "publisher": "",
  "url": "",
  "published_at": "",
  "accessed_at": "",
  "supports": ["company.founded_at"]
}
```

## 重大数据门禁

- 私营公司未公开收入、利润、估值和客户名单不得推测。
- 意向、框架协议、战略合作和试点不得写成确认收入或正式订单。
- 市场规模预测必须标记预测机构、基准年和目标年。
- 百分比必须说明分母；增长率必须说明同比/复合增长及期间。
- 同名公司、品牌与法定主体必须绑定，不能混用。

## 研究输出

- `research-questions.json`
- `source-registry.json`
- `project-facts.json`
- `conflicts-and-caveats.json`
- `diligence-gaps.json`

页面正文使用人类可读来源脚注或来源附录。最终答复提供可点击来源链接；禁止暴露工具内部引用标识。
