## 来源优先级

按以下顺序获取信息：

1. 当前对话和用户粘贴的表格；
2. 用户明确纳入范围的文件、附件和网址；
3. 用户已授权的数据库、连接器、数据仓库和 API；
4. 用户明确指定的工作区文件；
5. 对剩余可检索问题开展合法公开研究。

不得扫描无关目录、浏览历史、应用或数据库。查询必须只读、有边界，并只获取任务所需字段和期间。

对每个来源记录：文件名或系统、页码/章节/幻灯片/工作表/单元格或网址、发布日期、数据期间、单位和币种、完整性、访问日期及访问边界。对话中的陈述属于用户提供的证据，不等于独立验证。

## 证据台账

每项重要主张记录：

- 主题和主张；
- 事实、判断、预测或计算；
- 来源类型和来源系统；
- 来源及精确位置；
- 发布或文档日期、数据期间；
- 原始单位和币种；
- A—D 证据等级；
- 已验证、公司单方、冲突、过时或未解决状态；
- 对应报告问题；
- 内部取证动作。

## 证据等级

| 等级 | 含义 | 示例 |
|---|---|---|
| A | 可独立验证 | 已签合同、银行流水、验收、法定披露、监管记录、独立测试 |
| B | 获得交叉印证 | 客户或供应商访谈、两个相互兼容的独立优质来源 |
| C | 公司提供 | 管理层陈述、内部台账、内部测试 |
| D | 判断或预测 | 估算、目标、情景、未经验证的规划 |

不得只用 C/D 级证据支撑投资主线级结论而不进行范围处理。

内部可使用以下未解决标记：

```text
[待补充]
[来源待核验]
[仅有公司单方口径]
[公开信息未检索到]
[多来源口径冲突]
[数据时点较旧]
[数据质量待核验]
[公司预测]
[项目团队判断]
```

这些标记不得进入读者版。

## 商业状态标准化

保持以下状态独立：

```text
接触 → 需求确认 → Demo/POC → 送样/试用 → 招标
→ 正式合同/订单 → 交付 → 验收 → 收入确认 → 回款 → 复购/扩单
```

不得进行以下转换：

- 把合作意向写成订单；
- 用预计数量乘单价写成已签订单金额；
- 把样品或 Demo 写成客户验证；
- 把交付写成验收；
- 把验收写成收入或回款；
- 把客户 Logo 写成供应链准入；
- 把投资或战略合作写成采购；
- 把内部测试写成客户或独立验证。

同时区分：公司目标和外部预测、非独占许可和所有权、接触和正式合作、指控和立案、立案和终局裁判。

## 计算和冲突

每个衍生数字必须记录公式、输入、来源、期间、单位、地域、假设，并在不确定性重要时设置基础、上行和下行情景。

市场规模尽量同时使用自上而下和自下而上的方法。严格区分 TAM、SAM 和 SOM，不得重复计算客户、站点、设备或经常性收入。

来源冲突时，保留所有说法；比较日期、范围、定义、单位和证据等级；说明内部采用口径；未解决冲突不得被隐藏。

## 公开检索与合规

优先使用一手官方来源。重大市场、融资、财务、客户、性能、知识产权、诉讼、监管和政策主张，使用一个权威原始来源或两个相互兼容的独立优质来源验证。

不得把搜索摘要、聚合站、复制文章、转载、泄露信息、来源不明数据库或绕过访问控制的内容当作证据。不得加入无关个人信息或敏感信息。受版权保护的内容只做摘要，不大段复制。

标准读者版不包含网址、引用标签、来源清单或外部可点击链接。出处保留在内部台账；只有用户明确要求时才制作带引文版本。

## 最终证据审计

生成 DOCX 前，审计每项重要主张。重要主张包括精确数字、日期、客户和商业状态、技术性能、竞争比较、知识产权、融资、预测和投资结论。

每个问题至少映射一条内部台账记录。每项重要陈述必须完成以下一种处理：

- 按真实证据强度表述；
- 在冲突情况下选择并记录口径；
- 从判断中删除；
- 缩小结论范围；
- 明确作为预测或公司口径，不写成既成事实。

读者版不得包含证据等级、未解决标记、材料请求、访谈任务、责任人、期限，以及“建议”“待验证”“本报告”“未披露”“公开证据不足”“无法判断”等语言。证据不确定性在后台处理；正文只呈现可观察经营状态、因果后果和投资处理。
