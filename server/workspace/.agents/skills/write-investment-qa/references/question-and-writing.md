## 编辑主线

从编辑摘要开始，不从通用清单开始：

```text
这家公司最值得解释的三件事是什么？
读者读完后应记住哪个核心判断？
哪个事实最能证明公司没有停留在概念阶段？
哪个不确定性真正会改变判断？
```

提取 3—7 个公司专属名词：产品、技术、代表案例、客户类型、交付方式、商业阶段或战略矛盾。用这些名词构建整篇 Q&A 的主线。

## 公司专属问题

从五类素材中生成问题：

- 身份：公司实际是什么，不是什么；
- 专属概念：某个引擎、模型、产品或方法如何工作；
- 发展：产品和公司如何到达当前阶段；
- 证明：代表客户、项目或指标究竟证明什么；
- 矛盾：产品化、复制、单位经济和壁垒的关键不确定性。

沟通版和投资版至少 60% 的问题必须具备公司专属性。问题中应出现命名概念、案例、阶段、客户类型、商业机制或精确比较维度。只插入公司名称不算专属。

较弱：

> 公司的核心技术竞争力如何？

较好：

> “人机共生引擎”解决了传统 AIGC 工作流中的什么问题？

较弱：

> 公司产品是否实现落地？

较好：

> 光谷人工智能媒体创作中心证明了哪些可复制能力？

不要机械覆盖所有投资模块。删除与公司无关的模块；读者自然会一起讨论的内容应合并成一个问题。

## 模式路由

### 沟通版

使用 6—9 问。优先解释公司身份、命名产品或概念、发展路径、代表案例、商业模式、增长和一项关键限制。先解释，后限定；不强制给出投资结论。

### 投资版

使用 8—12 问。加入可量化优势、复制、单位经济、财务质量、估值分层和最重要反方。最终答案可给出投资含义，但不一定提出交易条款。

### 尽调版

使用 10—20 问。在内部工作文件中拆分状态链、定义冲突、证据要求和跟进动作。对外 Q&A 仍使用完成态口吻。

### 投委会版

使用 8—12 问。以总体判断、最强支撑、击穿性风险、成立条件和决策收束。只有存在可靠依据时才加入估值数字和交易条款。

## 五种答案结构

每个答案选择一种主要结构，相邻答案应有变化。

### 定义型

```text
一句话定义 → 工作机制 → 客户为什么愿意购买
```

### 发展型

```text
起点 → 关键变化 → 当前阶段 → 发展路径说明什么
```

### 判断型

```text
清晰判断 → 2—3 项事实 → 一项关键限制
```

### 案例型

```text
客户问题 → 公司动作 → 可观察结果 → 复制条件
```

### 比较型

```text
比较维度 → 差异 → 差异原因 → 投资含义
```

不要强行让每个答案覆盖所有组成部分。第一段必须直接回答。只有并列关系真实存在时才使用列表。

## 投资经理完成态口吻

证据处理全部放在后台。读者版由已经完成分析的投资经理撰写：

- 先写得到支持的结论，再写限制；
- 对无法支撑的事实直接做内部处理，不提出后续任务；
- 正文写可观察经营状态及其经济后果，不宣布缺少什么材料；
- 材料、访谈、责任人、期限和跟进动作全部进入内部尽调缺口表；
- 以因果判断、范围边界或投资处理结束，不以工作指令结束。

推荐改写：

| 未完成话术 | 完成态投资语言 |
|---|---|
| 建议核验订单 | 当前商业进展仍处于意向阶段，不构成订单储备，也不支撑近期收入预测。 |
| 该数据待验证 | 该指标只适合作为产品覆盖信号，不进入收入或估值测算。 |
| 后续需要关注产品化率 | 规模效应取决于单客户实施人天能否随产品成熟下降。 |
| 建议补充毛利率 | 当前合同以软件与专业服务组合交付，盈利弹性主要取决于复用率和交付人效。 |
| 建议继续推进 | 项目具备进入下一阶段的基础。 |
| 建议暂缓 | 项目现阶段不具备进入下一阶段的条件。 |

最终 Q&A 不得出现以下表达，除非它们是无法避免的正式专有名词：

`建议`、`待验证`、`待核验`、`待补充`、`有待观察`、`进一步核验`、`进一步验证`、`后续需要`、`下一步需要`、`仍需进一步`、`可以考虑`、`倾向认为`、`若情况属实`、`本报告`、`未披露`、`公开证据`、`证据边界`、`未获证实`、`不能据此`、`无法判断`、`无法获取`、`受限于公开信息`、`信息有限`、`资料有限`、`不作定量结论`、`不形成判断`。

即使没有显式标签，也必须保持以下区别：

- 意向、订单、交付、验收、收入、回款和复购；
- 内测、客户验证和独立测试；
- 公司口径、预测、分析师推论和独立事实；
- 所有权、许可、合作和访问权。

## 人工编辑规则

### 句子和段落节奏

- 根据问题重要性调整答案长度，不要让所有答案视觉等长；
- 混合短判断句和较长解释句；
- 相邻答案开头的前 12—20 个字不得相同；
- 每段只承担一个主要观点；
- 不得以材料请求、跟进任务或工作指令结束。

### 语言

使用具体主语和动词：

> 公司将设计师的修改动作记录为可复用工作流。

避免抽象名词堆叠：

> 公司实现了设计流程智能化能力的体系化沉淀与平台化赋能。

控制模板化短语：

- `现有材料显示`：全文不超过 2 次；
- `未披露`：沟通版、投资版、投委会版中为 0 次；
- `对投资判断而言`：全文不超过 2 次；
- 连续使用“其一、其二、其三”的答案不超过 2 个；
- 所有未完成话术和审计自述：0 次。

这些是上限，不是目标。能用具体经营状态表达时，不要添加通用限定语。

### 内容比例

沟通版大致保持：

```text
解释与综合判断 70%
关键限制 20%
投资或经营含义 10%
```

不要穷举所有想象风险。一项高优先级限制优于五项通用风险。

## 比较写法

只有比较能给读者提供稳定坐标时才使用对标公司。必须统一比较维度、期间、客户阶段和指标定义。

适合比较的维度：

- 产品重点；
- 购买方和使用场景；
- 交付方式；
- 验证深度；
- 产品化和复制；
- 收入模式和成本结构。

除非任务本身是对比研究，否则比较对象只出现在 2—4 个答案中。不得为增强具体感而引用其他公司无法确认的财务或经营数据。

## 改写示例

未完成版本：

> 现有测试提供积极但不足以支撑“技术领先”的信号。由于测试主要由公司内部完成，建议将独立复现设置为首期投资的硬前提，并进一步核验测试集、硬件环境和预算口径。

完成态版本：

> 公司的技术信号主要来自数据压缩和复杂物理求解两类任务。现有结果说明团队已经初步跑通“生成—评测—迭代”的技术闭环，但目前仍以内测为主。相关性能在第三方同口径测试完成前不计入已证实的核心技术壁垒。

后一个版本保留事实边界，同时给出具体解释和清晰的投资处理。
