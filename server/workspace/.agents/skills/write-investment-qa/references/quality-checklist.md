# 最终质量检查清单

## 通用内容门禁

必须满足：

- 一句话说清公司是什么；
- 每个答案第一段直接回应问题；
- 问题公司专属，不是通用清单；
- 重要事实和数字在后台可追溯；
- 商业、测试、预测、知识产权和数据权利状态准确；
- 重要不确定性有适度、清晰的范围边界；
- 名称、期间、单位、币种和比较定义一致；
- 没有无依据的精确数字、隐藏冲突、状态升级或宣传性绝对表述；
- 读者版没有建议、待核验、后续工作或材料索取语言；
- 每项重大不确定性都已在后台完成删除、缩小主张、保守处理或移除维度；
- 投资版和投委会版存在“可观察事实—商业机制—财务变量—投资或估值含义”的推演；
- 没有“本报告、由于未披露、公开证据不足、无法判断、不作定量结论”等报告自述。

## 模式门禁

### 沟通版

要求 6—9 问，至少 60% 为公司专属问题；答案结构有变化；公司故事清晰；至少包含一个代表性证明或案例；每个答案最多保留一项主要限制。不强制提供投委会结论、交易条款、责任人、期限或穷尽式风险。

### 投资版

要求 8—12 问，覆盖可量化差异、商业证明、产品化或复制、财务影响、估值分层和至少一项优先反方。至少一半问题必须同时包含公司专属名词和影响决策的经济张力。

### 尽调版

内部工作文件应明确未知项、证据要求和商业状态链。最终读者版仍使用投资经理完成态口吻。

### 投委会版

最后一个问题必须收束投资结论、最强支撑、击穿性问题和成立条件。内部文件保留所需证据。只有相关且有依据时才加入估值数字和交易条款。

## 自然语言门禁

出现以下情况时拒绝交付并重写：

- 三个以上问题可直接套用于任何公司；
- 相邻答案使用相同开场公式；
- 几乎所有答案使用相同编号分点；
- 答案长度异常一致；
- 限定语超过业务解释；
- 正文暴露证据台账机制；
- 抽象名词链掩盖主语、动作和结果；
- 用重复的“信息不足、不能判断”替代分析处理；
- 删除免责声明后，答案没有实质内容；
- 只对证据分类或说明缺失信息，不解释经济后果；
- 投资版或投委会版答案没有指出任何受影响的经济变量；
- 出现写作规则禁止的建议、未完成或审计自述语言。

使用所选 `--profile` 运行 `scripts/validate_investment_qa.py`。修正所有错误，逐项处理每个警告，不得为清除警告而删除合理边界。

## 来源门禁

在内部台账中确认来源名称、精确位置、日期、期间、单位、证据等级、状态和问题映射。重要事实、数字、客户状态、技术结果、比较、预测和投资结论必须全部映射。冲突必须明确处理。没有支撑的事实应删除、缩小范围、保守处理或不进入结论。

## Markdown 与 DOCX 门禁

确认 Markdown 只有一个一级公司或项目标题，其后为连续编号的二级问题标题；正文只由普通段落组成；无列表、表格、原始网址、Markdown 链接、占位符和手工分页空格。

确认 DOCX 完全符合唯一的 `lancheng_qa_a4_fixed`：A4；上下边距 25.4 毫米；左右边距 31.75 毫米；`FangSong` 固定字体；标题 16 磅；问题和正文 10.5 磅；22.8 磅固定行距；正文首行缩进 21 磅；页码使用 `Helvetica Neue` 9 磅且底部居中；页眉为空；问题与答案同页。不得出现字体回退、列表、表格、图片、形状、文本框、超链接、脚注、手工换行、手工分页、重复页或空白页。

同时提供 Markdown、DOCX、证据台账和渲染目录，使用 `--final-gate` 运行严格门禁；必须达到 0 个错误、0 个警告。

在最后一次修改后逐页打开所有 PNG，以 100% 检查：裁切、重叠、缺字、字体替换、标题悬空、缩进、标题位置、页脚偏移、意外空白页和过度留白。确认每页标题、问题、正文和页码使用同一固定视觉系统。版式固定不等于答案结构机械一致。

交付说明中记录页数、字体状态、证据审计结果、严格门禁结果和逐页视觉检查结果。
