# 专业投资 Q&A 写作

## 目标

先帮助读者理解公司，再帮助读者判断公司。围绕公司专属产品、案例、客户、交付方式和战略矛盾提出问题；以真正负责投资判断的投资经理口吻作答。每项关键事实都要说明它如何改变商业模式、盈利质量、现金转化、下行风险或估值。

正文只分析公司，不解释报告如何工作。不得用“本报告不……”“由于未披露……”“未获公开数据证实”“证据边界”“无法判断”“不作定量结论”等话术代替分析。应描述可观察的经营状态，指出因果机制，并形成投资处理。

默认使用中文。先稳定和验证 Markdown，再按唯一的 `lancheng_qa_a4_fixed` 版式生成 DOCX，并逐页检查。该技能不提供可选字体、可选字号或自适应排版；内容可以变化，视觉规则不得变化。

## 选择操作与写作模式

分别选择操作和写作模式。

操作：

- **新建：** 从资料建立新的 Q&A。
- **改写：** 保留有效主题，提升准确性、结构和专业口吻。
- **审计：** 评估既有 Q&A；除非用户要求，否则不直接改写。
- **更新：** 刷新事实和结论，同时保留来源冲突。
- **压力测试：** 生成能够击穿投资主线的问题和证据要求。

写作模式：

- **沟通版（默认）：** 6—9 问；解释公司、产品、案例、商业模式、增长与一项关键限制。
- **投资版：** 8—12 问；分析机会、壁垒、商业化、单位经济、财务质量、估值与风险。
- **尽调版：** 10—20 问；用于管理层访谈或资料室跟进，强调状态链、关键未知和取证动作。最终对外文稿仍使用完成态口吻。
- **投委会版：** 8—12 问；包括投资主线、反方风险、估值或条款、成立条件和最终判断。

用户只说“写一个项目 Q&A”时使用沟通版。只有请求或资料语境明确指向投资评审、尽调或投委会时，才切换相应模式。

## 工作流程

### 1. 明确任务

确定项目、读者、操作、写作模式、资料边界、保密要求、比较对象、输出格式和保存位置。对不影响判断的事项直接采用合理默认值：沟通版、合法的补充检索、敏感交易对手匿名、同时保留 Markdown，并在 `output/docx/` 下交付 DOCX。

### 2. 建立后台事实库

只使用对话、用户指定文件、已授权来源和合法公开信息。记录重要主张、精确定位、日期、期间、单位、证据等级和验证状态；保留冲突，不得择一掩盖。

在内部统一商业状态：

```text
接触 → 需求确认 → Demo/POC → 送样/试用 → 招标
→ 正式合同/订单 → 交付 → 验收 → 收入确认
→ 回款 → 复购/扩单
```

不得把前一状态升级成后一状态。除非用户明确要求，不得在读者版 Q&A 中展示证据等级、台账机制和取证任务。

### 3. 确立编辑主线

起草前在内部写清：

- 公司为谁提供什么，在什么已确认阶段；
- 投资人最需要弄懂的三件事；
- 3—7 个公司专属名词；
- 最强的正面解释与最重要的反方解释；
- `核心资产 → 商业机制 → 财务后果 → 估值处理` 的中心投资争议；
- 两项强化主线的可观察事实和两项击穿主线的可观察事实。

无法提取公司专属名词时，继续查阅资料或检索，不得直接生成通用问题。

### 4. 设计公司专属问题

先生成 12—20 个候选问题，再按叙事和决策价值筛选。沟通版与投资版中，至少 60% 的问题必须包含专属产品、案例、客户类型、商业阶段或比较维度。仅把公司名称放进通用问题不算公司专属。

投资版和投委会版中，至少一半问题必须是“投资争议”，而非事实索取。问题应把公司专属事实与壁垒、获客效率、定价权、续费、交付杠杆、毛利、营运资金、资本强度、复制、资源配置、下行风险或估值相连接。

优先使用：

> AiPin 能否把指数用户转化为更高客单价和续费？

避免使用：

> AiPin 的发展情况如何？

按理解顺序组织：

```text
公司身份 → 专属概念/产品 → 形成机制或发展过程
→ 代表性证明 → 商业模式 → 增长 → 关键限制
```

尽调版和投委会版可采用更偏决策的顺序。

### 5. 使用不同答案结构

遵循 Markdown 结构：

```markdown
# 项目或公司全称

## Q1：公司专属问题？

直接回答，再展开机制、事实和必要边界。
```

按问题选择主要结构，不得所有答案套用同一模板：

1. 定义 → 机制 → 客户价值；
2. 起点 → 变化 → 当前阶段 → 投资含义；
3. 判断 → 支撑事实 → 一项关键限制；
4. 客户问题 → 公司动作 → 可观察结果 → 复制条件；
5. 比较维度 → 差异 → 差异原因 → 投资含义。

沟通版单题通常为 250—450 个中文字符，答案长度应有自然差异。第一段直接回答。需要呈现并列维度时，使用独立普通段落，并以“第一、第二、第三”自然衔接。读者版不得使用项目符号、自动编号列表或表格，以免破坏固定版式。

投资版和投委会版的关键答案应完成以下推演：

```text
可观察事实 → 商业机制 → 财务后果
→ 投资主线或估值含义 → 一项优先级最高的失效条件
```

不得只在结尾添加“影响估值”。必须指出具体变量，例如获客成本、年合同额、续费率、实施人天、毛利、应收账款、回款、资本强度或估值倍数质量。每个关键答案至少包含一项能够改变投资判断的因果推论。

### 6. 完成证据审计

成文后，将重要事实、数字、客户状态、技术结果、比较、预测和投资结论映射回内部证据台账。逐项确认来源定位、日期或期间、证据等级和对应问题。修正无依据的精确数字、状态升级、错误比较、过时数据以及把公司目标写成既成事实的问题。

对于资料无法支撑的维度，在后台选择一种处理：删除、缩小主张、采用保守口径或从判断中移除。正文只写可观察状态和商业后果，不得宣布“缺少数据”、拒绝判断或解释证据审计过程。

### 7. 完成人工编辑

把全文当作投资会议发言逐句朗读。出现以下情况时必须重写：

- 三个以上问题可原样用于任何公司；
- 相邻答案以相同句式开头或结尾；
- 大多数答案长度和分点结构完全一致；
- 抽象名词掩盖了谁做了什么、产生什么结果；
- 限制性话术超过业务解释；
- 罗列所有可能风险，没有确定优先级；
- 删除免责声明后，答案没有实质判断；
- 只解释为什么无法判断，没有解释现有事实意味着什么；
- 提到产品或案例，却没有连接任何经济变量；
- 投资问题只索取公司事实，不包含决策张力；
- 出现“建议、待验证、待核验、待补充、有待观察、进一步核验、后续需要、下一步需要、可以考虑”等未完成话术；
- 出现“本报告、未披露、公开证据、证据边界、未获证实、不能据此、无法判断、无法获取、信息有限、资料有限、不作定量结论、不形成判断”等审计自述；
- 答案以工作指令结束，而不是以完成态判断、范围边界或投资处理结束。

### 8. 通过最终交付门禁

运行脚本时，以本技能 `SKILL.md` 所在目录作为技能根目录。Claude Code 中可直接使用 `${CLAUDE_SKILL_DIR}`；其他兼容客户端应解析技能目录后执行同目录脚本。

先运行内容与证据门禁：

```bash
python3 "${CLAUDE_SKILL_DIR}/scripts/validate_investment_qa.py" \
  /绝对路径/report.md \
  --profile communication \
  --evidence-ledger /绝对路径/evidence-ledger.md \
  --native-term 人机共生引擎 \
  --native-term 光谷项目
```

修正所有错误和警告后生成 DOCX：

```bash
python3 "${CLAUDE_SKILL_DIR}/scripts/render_investment_qa.py" \
  /绝对路径/report.md \
  /绝对路径/output/docx/report.docx

python3 "${CLAUDE_SKILL_DIR}/scripts/render_docx_pages.py" \
  /绝对路径/output/docx/report.docx \
  /绝对路径/tmp/rendered \
  --emit-pdf
```

逐张打开渲染后的 PNG，以 100% 比例检查字体、字号、行距、缩进、密度、裁切、孤立问题标题、分页、页码和空白。

最后运行严格门禁：

```bash
python3 "${CLAUDE_SKILL_DIR}/scripts/validate_investment_qa.py" \
  /绝对路径/report.md \
  --docx /绝对路径/output/docx/report.docx \
  --evidence-ledger /绝对路径/evidence-ledger.md \
  --render-dir /绝对路径/tmp/rendered \
  --profile communication \
  --final-gate \
  --native-term 人机共生引擎 \
  --native-term 光谷项目
```

严格门禁必须得到 0 个错误、0 个警告。任何正文或版式变更后，必须重新运行完整门禁并再次逐页打开图片检查。脚本成功生成 PNG 不等于完成视觉检查。

## 不可违反的规则

- 不得编造市场、客户、合同、财务、融资、性能、知识产权、法律、监管或估值事实。
- 不得把意向、目标、Demo、内测、交付或投资关系升级为更强商业状态。
- 不得在定义、阶段或口径不同的情况下直接比较。
- 不得在读者版中出现建议、待核验、材料索取或后续工作语言。
- 不得在读者版中出现报告自述和缺数免责声明。
- 不得修改 `lancheng_qa_a4_fixed` 的字体、字号、行距、缩进、页边距、标题间距、页码或分页控制。
- 不得在读者版 Markdown 或 DOCX 中使用项目符号、自动编号列表、表格、图片、形状、文本框、超链接、脚注、手工换行或手工分页；并列内容改写为连续普通段落。
- 固定正文与标题字体为 `FangSong`，页码字体为 `Helvetica Neue`；字体缺失时停止交付，不得静默替换。
- 不得用证据边界代替实际回答；把不确定性转化为可观察状态判断和商业因果。
- 不得把用户数、覆盖量、下载量、案例数量或产品功能直接称为壁垒、PMF、经常性收入或 SaaS 规模，必须解释转化机制。
- 不得对项目和专业服务混合收入直接套用软件估值倍数。应区分当前盈利价值、可识别经常性软件价值和未经验证的期权价值。
- 只有写作模式要求或用户明确提出时，才加入击穿性风险、最终投资结论或决策条件。
- 最新版本未通过证据审计、结构校验和逐页视觉检查时，不得交付 DOCX。
- 宁可给出简洁、准确的范围边界，也不得用流畅文字掩盖编造。

## 交付

先交付最终 DOCX，再链接经过验证的 Markdown。说明操作类型、写作模式、问题数量、研究边界、证据审计结果、严格门禁结果、DOCX 页数、固定字体状态和逐页视觉检查结果。除非用户明确要求，不交付内部证据台账。页数由内容自然决定，不属于可调版式参数。
