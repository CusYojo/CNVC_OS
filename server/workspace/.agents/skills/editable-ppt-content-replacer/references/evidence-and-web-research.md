# 联网补全与证据规则

## 适用范围

只在用户材料无法覆盖已声明内容槽位，或逐页内容方案未达到证据密度时联网
检索。先为每张正文页建立具体检索问题，再检索；不得先搜索大量信息后强行
填入模板。用户材料与公开资料冲突时保留两者并标记冲突，不静默覆盖。
逐页补充的详细门槛、内容项定义和分页检索重点见
[page-research-and-density.md](page-research-and-density.md)。

联网前先锁定 `projectIdentity`：至少用法定/正式名称、地区和一个可验证的
官方标识（官网域名、登记标识、创始人或明确产品）排除同名公司。身份置信度
没有达到 `high` 时停止检索和页面写入。官网域名必须匹配已登记
`company_official` 来源的实际主机名；没有官网时必须引用用户原始身份材料并
提供登记标识。不得把同名公司的资料填入当前项目。

## 来源优先级

1. 用户提供的原始材料；
2. 公司官网、公告、产品文档和正式新闻稿；
3. 监管披露、政府数据库、法院或知识产权机构公开信息；
4. 学术论文、标准机构和高校/研究机构材料；
5. 有明确方法和发布日期的行业研究报告；
6. 有编辑责任和署名的可信媒体；
7. 其他可定位原文的来源。

搜索结果页、搜索摘要、百科式聚合、内容农场、无发布方截图、AI 生成摘要
只能帮助发现原文，不能登记为证据。网络来源必须使用直接指向原文的
`http/https` URL。

## 重大数据

下列内容默认标记为 `materiality: "material"`：

- 收入、利润、现金流、预测和估值；
- 融资金额、轮次、投资方和交易条件；
- 客户、合同、订单、商业线索和合作关系；
- 市场规模、市场份额、排名和增长率；
- 员工数、产能、出货量和经营指标；
- 专利、认证、资质、奖项和监管许可；
- 产品性能、实验结果和对标结论。

重大数据满足以下任一条件后才能写成事实：

- 有用户原始材料或官方一手来源；或
- 至少两个相互独立、发布方不同的可信来源给出一致结论。

同一稿件的转载、同一数据库的镜像、同一集团旗下媒体不算独立来源。

## 证据类型

- `user-provided`：来自用户材料，必须记录文件和页码/章节定位。
- `official-fact`：来自公司、监管、政府、学术或标准机构的一手来源。
- `corroborated-fact`：来自至少两个独立可信发布方，结论一致。
- `derived`：由已登记输入计算，必须记录公式和口径。
- `estimate`：在证据基础上的测算，必须记录假设，并在页面中可见标注
  “估算”或“测算”。
- `unavailable`：已检索但无法证实，不得用来支持图片、图表或表格替换。

## 冲突和缺失处理

- 来源数字冲突：设置 `status: "conflicting"`，页面显示“待核实”
  “存在差异”或“口径不一致”，不得选择最有利数字冒充确定事实。
- 仅有一个非官方来源的重大数据：继续检索；仍无法交叉验证时不得写成确定
  事实。
- 重大必填槽位无证据：只在专用缺口页写“未披露”“待核实”或
  “公开信息未检索到”；普通业务页不得显示后台缺口提示。
- 可选槽位无证据：删除完整 `slotGroup`，包括内容和该槽位专属装饰。
- 官网、地址等非必要字段无证据：省略整个字段，不显示“未提供……”。
- 私有信息无法公开核验：不得从相似公司、行业均值或模板旧数据反推。

## 检索和登记流程

1. 为每张正文页建立 `researchQueries`，并为每个缺失槽位记录
   `semanticKey`、需要的字段、时间口径和重大性。
2. 搜索一手来源并打开原文，不以搜索摘要作为结论。
3. 记录来源标题、发布方、发布日期、访问日期、直接 URL 或用户材料定位。
4. 将事实拆成最小可验证陈述，每条生成一个 `evidenceId`，并用
   `semanticKeys` 声明它能支持的内容槽位。
5. 把核实结果写入唯一 `facts` 事实库，记录 `factKey`、最终展示值、单位、
   币种、期间、口径、状态和 `evidenceIds`。同一指标只能有一个当前有效值。
6. 将替换操作通过 `factKeys` 和 `evidenceIds` 绑定到事实与证据；操作的
   `semanticKey` 必须
   出现在所引用证据的 `semanticKeys` 中。
7. 在 `slideBrief` 中登记该页 `evidenceIds`、
   `contentItemSemanticKeys` 和 `pageResearchSummary`；行业、市场、政策、
   竞争或公开案例页至少引用一个网络原文来源。
8. 将同样的来源写入对应页面演讲者备注的 `[Sources]` 区块。
9. 运行清单校验器；身份未锁定、事实不一致、证据缺失、来源不足、估算未
   披露或冲突未标注时停止。

## 页面来源备注

每页只列该页实际使用的来源。示例：

```text
[Sources]
- 公司官网｜产品介绍｜https://example.com/product｜访问：2026-07-29
- 用户材料｜管理层访谈纪要，第 3 页｜访问：2026-07-29
[/Sources]
```

来源备注不代替正文中的“估算”“待核实”等可见限定，也不代替
`research-evidence-report.json`。
