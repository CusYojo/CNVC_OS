# 商业场景内容框架库

把内容结构、叙述逻辑、关键页面的"讲什么"做成可直接套用的框架。
每套框架 = 故事线 + 逐页内容范本。生成时从中选最匹配的填入 `outline.json`。

## T1 融资路演 / Pitch Deck（12-15 页）

基调：**数据驱动 + 宏大叙事**。每页落脚到"为什么我们能赢"。

### 故事线
```
问题 → 市场 → 方案 → 产品 → 壁垒 → 商业模式 → 数据 → 团队 → 竞对 → 规划 → 融资需求 → 愿景
```

### 逐页内容框架

| 页 | 角色 | 核心信息 | 推荐视觉框架 | 内容要点（填空区） |
|----|------|---------|------------|------------------|
| 01 | 封面 | 一句话价值主张 | 中心大字 + 底部 KPI 芯片带 | 公司名 + 一句话 slogan + 3 个核心指标 |
| 02 | 痛点 | 市场存在巨大未满足需求 | 鱼骨图 / 痛点卡片墙 | 3-5 个痛点卡片，每个带真实数据/引用 |
| 03 | 市场 | 机会空间 | 分层架构（TAM/SAM/SOM） | TAM: ___亿 SAM: ___亿 SOM: ___亿，CAGR: ___% |
| 04 | 方案 | 我们如何解决 | 漏斗图（混乱→有序） | 3 步解构：问题 → 我们的方法 → 效果 |
| 05 | 产品 | 让产品说话 | 产品架构图 + 核心功能卡 | 核心功能 ×4，每个带截图/示意 |
| 06 | 壁垒 | 为什么别人做不了 | 多层护城河架构 | 技术壁垒 ×2 + 数据壁垒 ×1 + 网络效应 ×1 |
| 07 | 商业模式 | 怎么赚钱 | 环形流程（价值流） | 收入来源 ×3，毛利率 ___%，LTV/CAC ___ |
| 08 | 数据 | 增长引擎 | KPI Dashboard 全景 | MAU/ARR/留存/增速/付费率，带趋势迷你图 |
| 09 | 团队 | 为什么是我们 | 人物卡片 + 能力雷达图 | 核心 3-4 人，每人一句话证明 + 能力标签 |
| 10 | 竞争 | 我们为什么赢 | SWOT 矩阵 / 2×2 象限 | 左边我们的优势，右边竞对对比表 |
| 11 | 路线图 | 钱用到哪里 | 阶段里程碑时间轴 | Q1-Q4 各 3 个里程碑 + 预计里程碑指标 |
| 12 | 融资 | 要多少 + 怎么用 | 饼图分配 + 底部横幅 | 融资 ___ 万，用途配比 ___%，预计达到 ___ |
| 13 | 愿景 | 终局想象 | 莫比乌斯环 / 房子型 | 一句话愿景 + 3 个支撑支柱 |

## T2 产品发布会 / Launch（15-20 页）

基调：**惊艳、极简、情感共鸣**。大图、大字、少文字。

### 故事线
```
悬念 → 现状吐槽 → 洞察 → 产品亮相 → 功能展示(分幕) → 设计哲学 → 生态 → 价格 → One More Thing → 总结
```

### 逐页内容框架

| 页 | 角色 | 核心信息 | 推荐视觉框架 | 内容要点 |
|----|------|---------|------------|---------|
| 01 | 封面 | 悬念/暗场 | 纯黑底 + 一点光 | 极简：一个词或符号 |
| 02 | 引子 | "你有没有遇到过…" | 痛点卡片 ×3 + 共鸣文字 | 不说产品，先说用户的痛 |
| 03 | 洞察 | "所以我们需要…" | 单一大字 + 支撑数据 | 一个核心洞察句，下方一行支撑数据 |
| 04 | 亮相 | 产品登场 | 全幅产品渲染图 + 一句话 | 产品名 + 核心定义（不超过 10 字） |
| 05-08 | 功能一幕 | 按优先级展示 | Bento 看板（大中小卡混排） | 主打功能 ×1(大卡) + 辅助功能 ×3(小卡) |
| 09-10 | 功能二幕 | 深度展示 | 分层架构 | 技术突破/数据表现/实际效果 |
| 11 | 设计 | 不仅仅是功能 | 对比矩阵（之前 vs 之后）| 工业设计/交互/细节 3 个面 |
| 12 | 生态 | 不止一个产品 | Hub-Spoke 放射图 | 核心产品 + 周边产品/服务 |
| 13 | 隐私/安全 | 建立信任 | 盾牌/锁 + 要点 | 3 条安全承诺 |
| 14 | 价格 | 惊喜时刻 | 对比表（含竞品价格）| 我们的价格 + 竞品价格 + "为什么值" |
| 15 | One More | 额外惊喜 | 暗场亮字 | 一个额外产品/功能/承诺 |
| 16 | 总结 | 回顾核心 | 全幅总结图 | 3-4 个核心要点 + 一句话收尾 |

## T3 年终述职 / 晋升答辩（10-14 页）

基调：**个人故事 + 数据佐证**。"我做了什么 → 产生什么价值 → 我成长了什么"

### 故事线
```
总览 → 亮点项目 1 → 亮点项目 2 → 亮点项目 3 → 数据总结 → 成长反思 → 未来规划 → 请求支持
```

### 逐页内容框架

| 页 | 角色 | 核心信息 | 推荐视觉框架 | 内容要点 |
|----|------|---------|------------|---------|
| 01 | 封面 | 述职人+年度+一句话 | 简洁 | "XXX 2025 年度述职" |
| 02 | 总览 | 全年关键数据 | KPI 芯片带 + 时间轴 | 核心指标 4-5 个(特大号)，下方一年大事时间线 |
| 03 | 项目一 | 最重要的项目 | 分层架构（目标→动作→结果） | 项目名 + 目标 + 我的角色 + 关键动作 + 结果数据 |
| 04 | 项目一数据 | 数据支撑 | 折线/柱状图 + 对比 | 前后对比数据、关键里程碑 |
| 05 | 项目二 | 第二重要的项目 | 同上 | 同上结构 |
| 06 | 项目三 | 第三重要的项目 | 同上 | 同上结构 |
| 07 | 综合数据 | 叠加所有项目 | Dashboard 全景 | GMV/效率/质量/满意度 4 维雷达图 |
| 08 | 团队协作 | 我不是一个人 | 环形连接图 | 跨部门协作关系 + 带动的团队 |
| 09 | 能力成长 | 我学到了什么 | 能力雷达图（之前 vs 之后）| 技术/管理/业务/沟通 4 维变化 |
| 10 | 不足与反思 | 诚实面对 | 鱼骨图（问题归因） | 2-3 个不足 + 根因 + 改进计划 |
| 11 | 明年规划 | 我要去哪里 | 阶段阶梯图 | Q1-Q4 各 3 个目标 + 预期产出 |
| 12 | 请求支持 | 我需要什么 | 清单卡片 | 资源/人员/预算/授权 |

## T4 项目汇报 / 周报月报（8-12 页）

基调：**结论前置 + 结构化**。先给结论，再给支撑。

### 故事线
```
结论 → 进度摘要 → 详细模块 → 问题与风险 → 下一步 → 需要决策
```

### 逐页内容框架

| 页 | 角色 | 核心信息 | 推荐视觉框架 | 内容要点 |
|----|------|---------|------------|---------|
| 01 | 结论先行 | "一句话+3个关键数" | 大标题 + KPI 芯片带 | 项目名 + 整体状态(红/黄/绿) + 3 个关键指标 |
| 02 | 进度总览 | 整体进度 | 仪表盘/进度环 | 总体完成 ___%，各模块进度条 |
| 03-06 | 模块详情 | 逐模块展开 | Bento 看板 | 每个模块：完成情况 + 亮点 + 数据 |
| 07 | 问题与风险 | 需要关注 | 风险矩阵（概率×影响） | 列出 Top 3 风险 + 应对方案 |
| 08 | 下一步 | 接下来做什么 | 里程碑甘特图 | 本周/下周/本月 各 3-5 个行动项 |
| 09 | 需要决策 | 请求决策 | 选项对比表 | 列出需要拍板的 1-3 件事 + 建议方案 |

## T5 学术答辩 / 论文汇报（15-25 页）

基调：**严谨、图表丰富、逻辑链完整**。

### 故事线
```
背景 → 问题 → 相关工作 → 我们的方法 → 实验 → 结果分析 → 讨论 → 贡献 → 未来工作
```

### 逐页内容框架

| 页 | 角色 | 核心信息 | 推荐视觉框架 | 内容要点 |
|----|------|---------|------------|---------|
| 01 | 封面 | 论文标题+作者+单位 | 简洁 | 标题、作者、导师、日期 |
| 02 | 背景 | 领域现状 | 分层架构（宏观→微观） | 领域背景 → 关键概念 → 趋势 |
| 03 | 问题定义 | 研究 gap | 对比表（已有方法 vs 缺口） | 已有方法做什么 + 缺什么 |
| 04 | 相关工作 | 文献综述 | 分类树 / 2×2 矩阵 | 主流方法分类 + 我们的位置 |
| 05 | 核心思路 | 文章贡献 | 三栏对比（问题→思路→贡献） | 一句话核心贡献 + 3 个创新点 |
| 06-08 | 方法详解 | 我们的方法 | 流程图/架构图 | 方法架构 + 关键模块逐项讲 |
| 09-11 | 实验设置 | 实验设计 | 表格（数据集/基线/指标） | 用什么数据、和什么比、怎么评估 |
| 12-15 | 实验结果 | 效果展示 | 柱状/折线/表格 | 主实验结果 + 消融实验 + 案例展示 |
| 16-17 | 分析讨论 | 深度分析 | 对比 + 可视化 | 为什么好、局限在哪 |
| 18 | 贡献总结 | 我们做了什么 | 三列总结 | 贡献 1/2/3 |
| 19 | 未来工作 | 下一步 | 时间轴 | 短期/长期 |

## 使用指引

生成 PPT 时：

1. 先选框架：从速查表中挑最匹配用户意图的场景框架
2. 再填内容：把用户的数据/需求填入每页的"内容要点"单元格
3. 再选视觉形式：根据"推荐视觉框架"从 image-prompt-guide.md §4 中选具体图表
4. 写 outline.json：套用 §7 JSON 结构，把本框架的内容蒸馏进去
5. 出图：照常走 image-prompt-guide.md §2 模板，保证 verbatim 铁律

**适配规则**：
- 用户自带了内容结构 → 沿用用户结构，不硬套框架
- 用户没给结构 → 默认用最匹配框架，先让用户确认页数和大纲
- 混合场景 → 从两个框架中各取需要的页面拼在一起
- 页数不强制：框架页数是建议值，用户可增减
