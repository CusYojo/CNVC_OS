## 5. 内容职责

| 位置 | 只回答的问题 |
|---|---|
| 公司简介 | 主体是谁、何时成立、做什么、服务谁、如何经营、处于什么阶段 |
| 核心团队 | 按成员分别说明谁负责什么，哪些可核验教育、任职和项目经历支持其岗位能力 |
| 产品及技术 | 按产品或技术能力分别说明定义、核心机制、明确指标、验证阶段、应用价值和商业化边界；知识产权只写清晰可还原的名称、类别和关联技术 |
| 投资理由 | 为什么值得投资；五项理由各含判断、证据、价值关系和限制 |
| 投资计划 | 估值、融资、我方金额、方式、比例、实施主体、交易路径和主要条件 |
| 投资情形分析 | 按七项固定顺序将基金规则与项目事实逐项比对 |
| 条件性结论 | 在哪些核验、程序和文件前提下形成何种初步结论，不限定固定开头 |
| 落款 | 基金管理人工商全称和正式出具日期 |

## 6. 七项合规核查

1. **投资方式及投资限制**：允许方式、禁止事项和本次交易法律性质。
2. **返投要求**：实缴规模、返投目标、已返投、已投、剩余可投、储备项目、本项目属性及投资后空间。
3. **关联交易**：标的、实控人、股东、团队、交易对手与基金、管理人、出资人的关联关系。
4. **投资方向**：项目实际业务和产业链位置与基金投资范围的对应。
5. **投资配置**：资产类型、直投或 SPV 穿透后的投资实质与配置要求。
6. **投资集中度**：协议分母、本次及累计暴露、投资后比例和上限比较。
7. **其他合规要求**：审批、许可、处罚、诉讼、知识产权、数据合规、劳动用工及其他未覆盖事项。

每项采用“核查标准 → 项目及基金事实 → 计算或比对 → 单项结论”。七项仅作为内容覆盖顺序，成稿中分别写成自然段，不显示 `1、` 至 `7、`，也不使用“投资方式及投资限制：”等冒号标签。资料不全时明确缺口，不把“未取得资料”写成“未发现异常”。

## 7. 禁止漂移

- 不把八个逻辑槽渲染为八个同级标题。
- 不把 `executiveSummary` 渲染为执行摘要。
- 不增加封面、目录、责任声明、风险提示、资料缺口或引用资料正文板块。
- 不显示状态标签、`[S#]`、模板路径、Skill 名称或生成引擎。
- 不显示来源材料编号、数字小标题或“学术团队：”“商务团队：”“业务主体：”“估值目标：”等标签式正文；应改写为自然段落。
- 不显示项目资料库、来源文件名、会议或访谈纪要、项目档案、证据状态或检索过程；先总结证据，再直接陈述事实、判断和具体核验条件。
- 不使用“具备初步判断依据”“已有商业化线索”“具备一定交付组织基础”“成长路径”“支撑强度”“利润留存能力”等模型化套话。
- 不使用“关键核验对象”“关键核验条件”“核验条件尚未闭环”“条件性分析”“条件化判断”“取证边界”“核验边界”“形成单项结论”“完成专项分析”“本节需取得”等内部流程用语。
- 不让相邻正文段落连续使用相同的“……方面，……”开头或“最终结论取决于……”收尾；核验边界必须写明具体事项。
- 不显示团队页、技术页、发展规划表或专利表的抽取长串；页眉、公司名、成员姓名、职位、表头、指标和下一页标题不得混排为一个段落。
- 不显示“名称类别关联度”“公司营收方面……研发投入方面……”等无法还原行列的文本，也不使用“增强备选方案方面”“公司估值口径方面”等机械标签。
- 不用模型自行概括的引号式定位或“平台化……加场景化……”等概念替代主体、动作、金额和状态。
- 不让其他文件的局部字重、段落数量或项目内容覆盖核心规范。
- 不为固定页数缩小字号、压缩行距或删除必要内容。
- 不交付需要 Word 或 WPS 修复、恢复后才能打开的 DOCX。
- 最终只登记并交付一份可编辑 DOCX，不生成 PDF、Markdown 或其他伴生产物。
