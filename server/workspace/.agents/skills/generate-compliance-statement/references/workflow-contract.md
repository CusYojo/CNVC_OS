# 合规性说明运行工作流与 RAG 契约

## 固定状态机

| 阶段 | 输入 | 产出 | 失败处理 |
|---|---|---|---|
| Template Parser | 登记的合规模板语料 | 每份模板的结构、样式和部件指纹 | 停止任务 |
| Document Blueprint | 模板解析结果、强制免责声明 | 本次唯一 Blueprint | 停止任务 |
| Section Tree | Blueprint | 八个逻辑槽及其版面映射 | 停止任务 |
| Project Retrieval | 当前项目、资料截止日 | 清洗后的项目证据 | 排除无效片段并登记缺口 |
| Chapter Evidence | 章节检索词、项目证据 | 每章独立 Evidence Packet | 无证据则固定资料缺口 |
| Chapter Generator | 单章契约、单章 Evidence | 单章 JSON | 使用可追溯兜底 |
| Content Reviewer | 全部章节、Blueprint、证据 | 通过或问题清单 | 定向重生成失败章节 |
| Formatter | 审核通过的内容、Blueprint | DOCX | 重新格式化一次 |
| Word Reviewer | DOCX、Blueprint、内容 | 通过或问题清单 | 不通过则禁止 PDF |
| PDF Export | 审核通过的 DOCX | PDF | 重新转换一次 |
| PDF Reviewer | DOCX、PDF | 一致性报告 | 不通过则任务失败 |

阶段不得跳过或调换。内容 Reviewer 通过之前不得运行 Formatter；Word Reviewer 通过之前不得生成 PDF。

## 当前项目范围

只检索任务 `projectId` 对应的数据，不允许全局检索或跨项目检索。允许的数据类型包括：

- 项目档案；
- 当前项目知识库；
- 当前项目上传的 Word、PDF、PPT、表格、图片和文本；
- 当前项目 FAQ、BP、合同、尽调、财务和行业资料；
- 当前项目会议、访谈和其他明确归属该项目的资料。

资料截止日使用日终边界。晚于截止日的资料不进入 Evidence。项目档案更新时间晚于截止日时，项目档案也不得进入。

## 证据清洗

在章节检索前执行：

1. 修复可确定的编码问题，排除仍含替换字符或不可读片段的内容；
2. 排除测试、占位、上传验证、解析验证和连续重复文本；
3. 合并同一来源的重复分片；
4. 同一文件每章只保留相关性最高且定位清楚的有限片段；
5. 保留全局证据数组原索引，禁止在章节内重新编号导致引用错位；
6. 不把模板文件加入项目证据数组。
7. 除程序性“结论”外，状态为`资料记载`、`AI推断`或`待核验`的 finding 均必须引用有效章节证据。

## 章节 Evidence Packet

每章使用独立对象：

```json
{
  "sectionTitle": "投资计划",
  "terms": ["估值", "融资", "投资额", "SPV", "资金用途"],
  "sourceIndexes": [0, 3],
  "items": [
    {
      "sourceIndex": 3,
      "sourceName": "本轮融资方案.docx",
      "chunkIndex": 2,
      "versionOrDate": "2026-07-20",
      "excerpt": "与本章直接相关的有限片段",
      "score": 8
    }
  ]
}
```

Evidence Packet 只存当前章所需片段，不存整库内容。产物元数据只登记来源索引和条数，不登记证据正文。

## 章节检索口径

| 章节 | 核心检索口径 |
|---|---|
| 公司简介 | 主体、成立、定位、业务、商业模式、收入、阶段 |
| 核心团队 | 创始人、职务、履历、任职、职责、背调 |
| 产品及技术 | 产品、技术、研发、专利、系统、客户验证、PoC、交付 |
| 投资理由 | 产业、政策、团队、技术、客户、订单、生态、商业化 |
| 投资计划 | 估值、融资、投资额、增资、股权、SPV、用途、条款、交割 |
| 投资情形分析 | 合伙协议、限制、返投、关联、方向、配置、集中度、审批、许可 |

不能仅因片段出现“投资”“项目”“公司”等泛词就把它送入合规检查。基金级检查必须有对应的基金协议、台账、核查表或交易文件。

## 逐章生成

一次请求只允许生成一个章节。章节请求只包含：

- 不可覆盖的事实和引用规则；
- Blueprint 的本章结构和容量；
- 本章 Evidence Packet；
- 当前项目字段；
- 资料截止日和用户合法的展示参数；
- 上次本章输出及 Reviewer 对本章的问题（仅重试时）。

不向模型展示其他章节全文，避免事实重复和跨章污染。章节完成后在应用层统一归一化状态、索引、七项检查顺序和缺失资料固定句。

## 无数据路径

Evidence Packet 为空时不调用模型，直接输出：

```json
{
  "text": "当前项目暂无相关资料。需补充对应的一手材料后再行核验。",
  "status": "资料缺口",
  "sourceIndexes": []
}
```

七项合规检查应保留检查项前缀，例如：

`返投要求：当前项目暂无相关资料。需补充基金返投条款、认定口径及最新返投台账后再行核验。`

## 重生成

Reviewer 问题必须包含问题代码、章节和 finding 索引。重试只发送失败章节；不要重跑已通过章节。

最多进行两轮模型重生成。仍失败时，用能够通过引用核对的确定性证据摘要或资料缺口替换失败章节。最终 Reviewer 必须重新审核整份内容；不得把“已执行重试”当作通过。
