# 合规性说明 Reviewer 与 Formatter 契约

## Content Reviewer

Content Reviewer 必须逐项返回问题代码、章节、finding 索引和原因。以下检查全部通过才可进入 Formatter。

### 结构

- 标题严格为`关于{项目名称}项目投资合规性的说明`；
- 八个逻辑槽名称、数量和顺序与 Blueprint 一致；
- `公司情况介绍`没有 findings，仅作一级容器；
- 公司简介、核心团队、产品及技术不遗漏；
- 投资情形分析恰好七项并按固定顺序；
- 结论恰好一项，以“综上”开头且不显示为版面标题。

### 固定内容

- `executiveSummary`完整包含强制免责声明；
- 结论保留人工审核和非正式法律意见边界；
- 文档 Formatter 必须输出落款、日期、责任声明、风险提示、资料缺口和引用资料。

### 引用与幻觉

- 除程序性“结论”外，`资料记载`、`AI推断`和`待核验`至少引用一条有效当前项目证据；
- 引用中的主体、数字、英文专名和关键中文词必须与 finding 对应；
- 引用索引必须在本次证据数组范围内；
- `资料缺口`不得带来源，并包含`当前项目暂无相关资料。`；
- 模板项目名称不得出现在非当前项目文档中；
- finding 与模板项目正文的中文三元组相似度过高时判定为模板复制或表面改写；
- 不得虚构法规、政策编号、许可、审批、备案、基金条款、返投、关联关系、集中度、估值、金额和比例；
- 数字存在冲突或无法勾稽时不得自行修正。

### 一致性

- 同一事实不得跨章节重复完整表述；
- 同一风险或资料缺口不得以不同措辞反复出现；
- 有待核验或资料缺口时，不得写“完全合规”“不存在风险”“均已核验”或类似无保留结论；
- `AI推断`必须使用条件性语言，不得伪装成证据原文。

## Reviewer 问题代码

至少支持：

- `TITLE_MISMATCH`
- `DISCLAIMER_MISSING`
- `SECTION_MISSING`
- `SECTION_ORDER`
- `SECTION_COUNT`
- `CONTAINER_CONTENT`
- `CHECKLIST_ORDER`
- `CONCLUSION_INVALID`
- `SOURCE_INDEX_INVALID`
- `CITATION_MISSING`
- `CITATION_IRRELEVANT`
- `MISSING_DATA_WORDING`
- `TEMPLATE_FACT_LEAK`
- `TEMPLATE_COPY`
- `DUPLICATED_FACT`
- `UNQUALIFIED_CONCLUSION`

## Formatter

Formatter 只消费审核通过的结构化内容和本次 Blueprint，不重新创作业务事实。

### Word

- 采用模板 A4 页面、页边距、分节、字体、字号、行距、缩进和对齐；
- 使用真实 Word 编号，不把编号写成普通文本；
- 保持四个一级部分、三个子节、理由/七项检查编号和无标题“综上”结论；
- 保持模板落款和日期位置；
- 状态及`[S#]`作为正文后的审计行，不替代正文；
- 文尾依次放置责任声明、风险提示、资料缺口和引用资料；
- 仅列正文实际使用来源，同一文件多个片段合并；
- 模板没有目录、表格、页眉或页脚时不增加；模板存在时必须保留并更新；
- 不增加通用封面、彩色卡片、装饰图形或其他文档 Skill 的样式。

### Word Reviewer

检查：

- DOCX 是有效 OpenXML，正文可编辑且无 U+FFFD；
- 标题、章节、结论、落款及文尾固定内容完整且顺序正确；
- 页面尺寸和页边距与 Blueprint 相同；
- styles、theme、fontTable 等保留部件与模板哈希一致；
- 一级、二级和独立重启的正文编号存在；
- 页眉、页脚、目录和表格的存在性与 Blueprint 一致；
- 不含非当前项目的模板主体或内部模板标识。

失败时重新运行 Formatter 一次，再次检查；仍失败则停止任务。

## PDF

PDF 只能由已通过 Word Reviewer 的 DOCX 转换，不得单独重新排版或从 Markdown 生成。

PDF Reviewer 检查：

- 文件头、页面和文本层可读取；
- 标题、全部章节、结论、落款、免责声明、风险提示、资料缺口和引用资料均存在；
- Word 中的全部数字可在 PDF 文本层找到；
- 一级、二级及七项检查编号必须在 PDF 页面中实际可见，不能只存在于 Word XML；
- PDF 对 Word 的中文二元组文本覆盖率不得低于 92%；
- 服务端缺少模板中文字体时，只允许对临时转换副本进行可审计的 CJK 字体映射，不得改写交付 Word；
- 含中文的 PDF 必须检测到实际 CJK 字体，文本层存在但页面字形回退为方框时不得通过；
- PDF 元数据记录其来源 DOCX。

失败时重新转换一次。第二次仍失败则任务失败，Word 和 PDF 均不得标记为可交付。
