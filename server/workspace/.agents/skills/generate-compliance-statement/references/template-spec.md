# 合规性说明模板规范

## 适用模板

- `docs/合规性说明/关于德塔智能项目投资合规性的说明_20260701.docx`
- `docs/合规性说明/20260615-蓝成合规性说明（初稿）V2-甬元改.docx`

两份样本只用于提炼结构、版式、段落模式和章节意图。样本中的项目事实、主体、人物、数字、日期、政策判断和结论不得进入新项目内容。

批准模板指纹：

| 文件 | SHA-256 |
|---|---|
| 关于德塔智能项目投资合规性的说明_20260701.docx | `5b51cda592736fc3b2bfc69bcc75875f5588496d47f7a6b6691b21daae8b115e` |
| 20260615-蓝成合规性说明（初稿）V2-甬元改.docx | `ce793bf645a35ffa81d76665f1acaad4d3f2d46d3a47f824f1be6c258cb84e1e` |

运行时仍须重新计算指纹并解析模板。模板指纹变化不是自动接受的新版本；必须重新建立 Blueprint 并通过模板语料一致性检查。

## Document Blueprint

Template Parser 必须从 DOCX OpenXML 实际解析，而不是仅加载本文件中的人工常量。Blueprint 至少包括：

```json
{
  "kind": "compliance-statement",
  "version": 1,
  "blueprintSha256": "sha256",
  "templates": [
    {
      "path": "absolute path",
      "sha256": "sha256",
      "page": {
        "widthDxa": 11906,
        "heightDxa": 16838,
        "marginTopDxa": 1440,
        "marginRightDxa": 1800,
        "marginBottomDxa": 1440,
        "marginLeftDxa": 1800,
        "sectionCount": 1
      },
      "features": {
        "tocPresent": false,
        "tableCount": 0,
        "headerParts": 0,
        "footerParts": 0
      },
      "paragraphRoles": {},
      "templateProjectNames": [],
      "templateParagraphs": []
    }
  ],
  "sectionTree": [],
  "logicalSections": [],
  "fixedContent": {}
}
```

两份模板共同确认的稳定特征为：单分节、A4 纵向、无 TOC 字段、无表格、无页眉页脚、无页码、四个一级部分、三个公司子节、理由和检查项使用阿拉伯数字编号、结论不设标题、落款位于结论之后。

模板文档属性中的历史页数可能因 WPS 缓存和字体环境而不准确，不得把缓存页数作为唯一门禁。以实际渲染结果、内容完整性和版式无缺陷共同判断篇幅；正常项目目标为与样本相近的简短说明体，不得通过缩小字号或删除必要内容强制固定页数。

## 页面与字体

| 项目 | 模板值 |
|---|---|
| 纸张 | A4 纵向，11906 × 16838 DXA |
| 页边距 | 左右 1800 DXA；上下 1440 DXA |
| 页眉/页脚 | 无可见页眉、页脚或页码 |
| 标题 | 黑体 14pt，居中，黑色，1.5 倍行距 |
| 一级标题 | 宋体 12pt，加粗，1.5 倍行距，段前 12pt |
| 二级标题 | 宋体 12pt，1.5 倍行距，首行缩进约 482 DXA；新文档统一加粗 |
| 正文 | 宋体 12pt，黑色，1.5 倍行距，首行缩进 480 DXA |
| 理由/检查项 | 宋体 12pt；编号和判断句加粗，论证正文常规字重 |
| 落款 | 宋体 12pt，右对齐，机构在前、日期在后 |

模板大量使用直接格式，实际生成时允许建立语义样式，但视觉结果必须保持上述值。

## 章节意图与容量

| 版面位置 | 要回答的问题 | 推荐容量 |
|---|---|---|
| 公司简介 | 主体是谁、做什么、如何形成收入、处于什么阶段 | 1–2段 |
| 核心团队 | 谁负责什么，履历如何支撑项目执行 | 每名关键人员1段 |
| 产品及技术 | 产品架构、关键能力、差异化、验证程度和边界 | 2–4段 |
| 投资理由 | 为什么值得投资，证据和分析是什么 | 3–5项 |
| 投资计划 | 估值、融资、投资方式、股权/SPV、用途、条款、交割前提 | 2–4段 |
| 投资情形分析 | 是否满足基金协议和监管边界 | 固定7项 |
| 综上结论 | 在哪些前提下可形成何种初步结论 | 1段 |

## 写作模式

- 事实部分：`主体/产品/人员 + 已发生或拟发生事项 + 当前阶段或边界。`
- 投资理由：`加粗判断句。`后接事实，再给出与投资判断的关系和限制。
- 合规检查：`加粗检查项：`后接基金依据、项目事实、计算或核验结果；最后写条件或缺口。
- 结论：使用“在完成……核验、履行……程序并以……为准的前提下，原则上……”。不得写无条件“完全合规”。

## 禁止漂移

- 不把八个逻辑数据槽渲染为八个同级标题。
- 不增加封面、执行摘要标题、彩色信息卡、表格化事实汇总或通用页眉页脚。
- 不把风险和资料缺口复制成模板正文前的独立章节；审计扩展仅置于正文、结论和落款之后。
- 不在正文显示模板版本、Skill 名称、模板路径或生成引擎。
- 不为追求三页而删减必要内容或缩小字号；篇幅随项目证据合理增减。
- 没有章节证据时逐字使用`当前项目暂无相关资料。`，不得换成“暂无可用信息”“尚未检索到”或模型推测。
