## 5. 内容职责

| 位置 | 只回答的问题 |
|---|---|
| 公司简介 | 主体是谁、何时成立、做什么、服务谁、如何经营、处于什么阶段 |
| 核心团队 | 谁负责什么，哪些可核验经历支持其岗位能力 |
| 产品及技术 | 产品定义、技术架构、差异化、验证阶段和商业化边界 |
| 投资理由 | 为什么值得投资；五项理由各含判断、证据、价值关系和限制 |
| 投资计划 | 估值、融资、我方金额、方式、比例、实施主体、交易路径和主要条件 |
| 投资情形分析 | 按七项固定顺序将基金规则与项目事实逐项比对 |
| 综上结论 | 在哪些核验、程序和文件前提下形成何种初步结论 |
| 落款 | 基金管理人工商全称和正式出具日期 |

## 6. 七项合规核查

1. **投资方式及投资限制**：允许方式、禁止事项和本次交易法律性质。
2. **返投要求**：实缴规模、返投目标、已返投、已投、剩余可投、储备项目、本项目属性及投资后空间。
3. **关联交易**：标的、实控人、股东、团队、交易对手与基金、管理人、出资人的关联关系。
4. **投资方向**：项目实际业务和产业链位置与基金投资范围的对应。
5. **投资配置**：资产类型、直投或 SPV 穿透后的投资实质与配置要求。
6. **投资集中度**：协议分母、本次及累计暴露、投资后比例和上限比较。
7. **其他合规要求**：审批、许可、处罚、诉讼、知识产权、数据合规、劳动用工及其他未覆盖事项。

每项采用“核查标准 → 项目及基金事实 → 计算或比对 → 单项结论”。资料不全时明确缺口，不把“未取得资料”写成“未发现异常”。

## 7. 禁止漂移

- 不把八个逻辑槽渲染为八个同级标题。
- 不把 `executiveSummary` 渲染为执行摘要。
- 不增加封面、目录、责任声明、风险提示、资料缺口或引用资料正文板块。
- 不显示状态标签、`[S#]`、模板路径、Skill 名称或生成引擎。
- 不让其他文件的局部字重、段落数量或项目内容覆盖核心规范。
- 不为固定页数缩小字号、压缩行距或删除必要内容。
- 不交付需要 Word 或 WPS 修复、恢复后才能打开的 DOCX。
- 最终只登记并交付一份可编辑 DOCX，不生成 PDF、Markdown 或其他伴生产物。
