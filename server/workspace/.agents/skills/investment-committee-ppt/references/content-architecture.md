# 内容架构与页数

## 从研究问题到章节

常见章节顺序如下，但按公司实际调整，不强制 24 页或 35 页：

1. 封面与项目身份。
2. 投资结论/审议摘要：事实型总览，不写广告口号。
3. 行业定义与变化来源。
4. 客户工作流、未满足需求和采购动因。
5. 公司定位与价值链位置。
6. 产品、技术、数据或服务的运行机制。
7. 团队与关键能力来源。
8. 客户案例、交付过程和验证结果。
9. 商业模式、定价、复购、回款与规模化路径。
10. 历史财务、预测、订单覆盖与资金需求。
11. 交易结构、估值、股权、治理与利益绑定。
12. 后续里程碑、待验证事项与审议落点。

早期技术公司可增加技术/产品/验证页；成熟公司可增加财务/运营/竞争页。页数是信息和阅读节奏的结果，不是预先目标。

## 信息覆盖矩阵

在制作前建立矩阵，至少包含：行业、产品、技术、团队、客户、商业、竞争、财务、交易、治理、风险/待验证、来源。每个维度标注：是否有材料、证据等级、对应页码、是否需要公开补充。

## 一页一结论

“一页一结论”不是“一页只放一个数字”，而是所有内容共同解释一个判断。允许图、文字、案例、数字同时存在，只要阅读路径一致。

判断是否过载：

- 标题需要“以及/同时/另外”串三个主题。
- 页面出现三个以上等权视觉岛。
- 读者无法说出先看哪里。
- 表格每行属于不同问题。

判断是否过空：

- 大面积留白没有形成视觉重心。
- 正文很小却只有几句话。
- 只列三四个大数字，没有背景、口径或机制。
- 图片承担装饰而不提供证据。

## 密度策略

增加密度的优先顺序：

1. 补齐因果和解释：背景 → 机制 → 证据 → 含义。
2. 把分散指标聚合为连续故事或一张可读图。
3. 放大正文并收紧无效间距。
4. 合并重复标题、边框和标签。
5. 调整图文比例。
6. 最后才考虑增加页或删减非核心内容。

密集不等于拥挤。不同层级之间要有稳定节奏，段内紧、段间松；同一行的基线与列宽要一致。

## 摘要页

摘要页应成为全稿索引，而不是四张结论卡。可采用一条主结论 + 三段证据链，或“行业变化 → 公司响应 → 商业验证 → 交易状态”的纵向/横向路径。每段只保留能在后文找到对应页的事实。

## 章节转换

通常不需要纯章节封面占页。可用小型章节标识、标题措辞、图片主题和页码变化完成转场。若使用章节页，应承载一句研究问题或关键结论。

## 结尾

最后一页不要做“谢谢”或重复摘要。优先用审议落点：已验证事实、交易结构、下一阶段关键验证与决策所需信息。仍保持陈述语气，不写营销式号召。
