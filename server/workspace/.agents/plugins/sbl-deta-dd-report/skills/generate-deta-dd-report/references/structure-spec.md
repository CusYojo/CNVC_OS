# 德塔 V5 章节与字段结构契约

本契约以 `assets/reference.docx`（源自 `20260717-德塔智能尽职调查报告V5.docx`）为章节骨架与视觉权威。项目事实、人物和客户名称必须替换。一级、二级章节及固定三级章节的编号、名称和顺序固定；`2.4`核心团队允许3至5个连续动态槽位。信息载体按读者任务选择，不再机械复制样本中的低价值列。用户已确认的批注优先于样本载体。

- 动态标题：`2.4.1`起连续编号，最多至`2.4.5`，后接核心人员真实姓名和角色。资料支持4或5名核心成员时必须完整列示，不得截断为3名；资料仅支持3名时保留3名，不得虚构补位。

## 投资概要载体

投资概要保留五个二级小节，但根据信息类型使用表格或正文：

1. `1.1 公司情况`（6行键值表）：`公司名称`、`成立时间`、`注册地址`、`实际经营地址`、`法定代表人/实际控制人`、`主营业务`。不设泛化的`发展阶段`和`核心判断`。
2. `1.2 交易要点`（6行）：`投资主体`、`投资方式`、`投资金额`、`投资估值`、`项目类型`、`收益与责任安排`。
3. `1.3 行业概况`：用2至3段正文说明行业阶段、采购标准和竞争重心，不使用表格包装普通叙事。
4. `1.4 商业模式和经营管理`（5行）：`商业路径`、`客户与生态`、`组织与人员`、`经营现状`、`管理基础`。
5. `1.5 投资价值与风险`：用正文列示5条完整投资价值，一项一个Word段落，每条写清事实、机制和投资意义；依次承担行业定位与付费基础、差异化技术路线、数据/反馈闭环壁垒、客户或生态商业验证、团队产业化能力五项责任。交易折价、分期支付、治理和下行保护移至`7.2`，不得替代公司价值。末尾以一个段落先指出统领性的商业化或价值兑现风险，再说明其他重大因素对收入底盘、成长价值和估值兑现的传导。该节正文总量不得低于650个中文字符。

保留的固定字段不是可润色文案。尤其不得把 `实际经营地址` 改成 `实际经营安排`，也不得把 `投资方式`、`投资金额`、`投资估值`合并或改名。

`注册地址`须优先采用最新营业执照或当前工商登记中的完整住所，通常应包含街道（镇）、道路、门牌及房号；仅写至省、市、区/县不构成完整字段值。确无证据时保留字段并写“未提供，待核实”，不得自行截短。

## 对齐与放行

- 正文中的公司、沿革、股东、穿透、组织、关联方和合规表保持德塔V5的表格几何与信息责任，但表头使用读者可理解的客观名称，如`人数/规划`、`基本情况`、`备注`，不使用“尽调材料、尽调证据、核验结果”等工作过程标签。
- `2.1 公司基本信息`标题下只保留九行基本信息表，不在表前或表后增加介绍、判断、风险或资料依据；`2.2 历史沿革`同样只保留`公司历史沿革`表，不在表外增加融资评价、属地判断或估值评论。
- `2.3.1 公司股东`在股东表前只保留一个截至日股权总括段，至少写明口径日、注册资本、实际控制人/创始人直接持股、持股平台合计、核心自然人及产业/财务投资人合计；不得使用融资过程或交易执行说明代替股权结构概括。
- `2.3.2 公司股权穿透及实际控制`保留一个穿透结论段及穿透表，表后不得追加关键人风险、董事席位或交割控制评论；此类分析归入第8章和投资方案。
- `2.4 核心团队介绍`标题下不写通用团队评价，直接进入3至5名核心人员小节，资料支持4至5名时优先使用4至5个槽位。排序固定为：①创始人、实际控制人、董事长或CEO等公司核心决策者；②CTO、首席科学家、核心算法/硬件/研发负责人；③产品、商业化、销售、运营或交付负责人；④其他对技术、客户、量产、财务或组织具有实质影响的关键成员。同一层级按对投资主线的重要性和履历证据强度排序。每人至少覆盖教育/专业背景、关键任职或项目经历、当前职责；人物身份、职称和履历必须逐人绑定，不得把顾问、院士、合作方或非全职人员排在全职核心人物之前，也不得错配资历。
- `2.5 组织架构`以组织表为主体，表前不写泛化组织判断。`尽调材料人数/规划`列必须是可计算的现有人数、规划人数或明确的“现有X人/拟增Y人”，不得写汇报关系、部门名称或职责；若组织交叉无法唯一分摊，应注明统计口径，禁止虚构人数。表后只允许保留与德塔V5相当的客观人员结构统计，不写投资控制。
- `2.6 关联公司及关联交易`只保留`事项｜核验结果`表，首列固定为
  `事项｜关联企业｜关联往来｜个人往来`，分别回答关联实体及控制关系、
  公司与关联实体之间的经营性/资金往来、公司与关联自然人之间的款项往来；
  不得改写为“实际控制人/主要关联自然人/其他关联企业/关联交易”的主体清单，
  表前表后不增加分析、交割安排或风险处置正文。
- `2.7 资质、荣誉及法律合规情况`只保留六行合规表，表前表后不增加分析或控制正文；不得在正式报告中保留`主要资料依据与使用边界`标题、资料清单或证据属性表，此类内容仅进入内部事实库和来源清单。
- `3.1`只保留`技术层｜核心模块｜输入/输出`，删除额外的“价值”列；`4.1`只保留`阶段｜主要产品｜收入来源`，删除“关键验证”列。`3.6`须使用具体的专利/软著清单，不使用泛化事项表代替知识产权明细；专利表固定为`专利名称｜申请号｜申请日｜发明人`，不设置“权利状态”列，且表后不追加专利数量、非员工发明人或境外技术归属的评价段。
- `5.1.1 政策层面`与`5.1.2 市场层面`各不少于3个实质段落；政策分析至少覆盖国家、数据要素和属地政策及商业传导，市场分析至少覆盖存量付费场景、增量需求、商业化层次和竞争边界。不得用单一政策摘录或市场规模表代替分析。
- `7.1 投资亮点`使用正文、一项一段，不展示“尽调证据”或内部证据类型。风险表保留`风险类别｜具体风险描述｜风险控制建议`，但正文不展示P0/P1/P2/P3内部编码。
- 正式报告不设置独立表格标题。凡紧邻表格的“主要专利申请”“公司历史沿革”“主要风险及应对措施”等居中加粗表题均须删除；表格语境由章节标题、表头和必要正文承担。
- DOCX 必须通过 `python3 "${CLAUDE_SKILL_DIR}/scripts/deta_structure_contract.py" audit --input /abs/report.docx`。
- 动态人物和客户名称不要求复制德塔样本。客户标题数量固定为4个；核心团队标题按资料动态设置为3至5个并连续编号，其中资料存在4至5名决策相关核心成员时不得遗漏。人物归属和优先顺序必须符合本契约。
- 空的样式段落不计入标题数量；读者可见的非空标题必须完全满足本契约。
- 任一固定章节、标题或已明确保留的字段不一致均为 P1 结构错误；表格只当内容需要行列比较时使用。
