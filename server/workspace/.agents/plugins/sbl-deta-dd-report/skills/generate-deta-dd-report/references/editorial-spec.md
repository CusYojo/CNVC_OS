# 德塔式报告编辑与去重契约

本契约用于解决“事实正确但重复、防御性措辞过密、价值逻辑被风险边界打断、结论不够干脆”的问题。结构和证据门禁优先，本契约不得用于删除重大风险或弱化交割控制。

## 信息锚点

同一事实簇只设置一个完整论证锚点，其他位置只保留该章节必须承担的最短信息。

| 事实簇 | 完整锚点 | 其他章节允许内容 | 禁止做法 |
|---|---|---|---|
| 技术链与产品协同 | 第3章 | 1.1仅写主营业务；1.5写价值结论；7.1写投资意义；结论原则上不再复述技术路径 | 在三个及以上章节重复“真实采集、合成、仿真、触觉”的完整链条 |
| 历史财务与收入确认 | 6.2.3 | 1.4写经营结论；1.1核心判断只写影响；结论仅在决定成立所必需时保留一个关键数字 | 多处同时复述收入、利润和收入确认差异的完整数字组 |
| 交易结构 | 7.2 | 1.2用字段化短值；结论直接写决定性金额、权益和付款边界 | 在1.2、7.2和结论三处完整复述金额拆分、持股比例和分期机制，或用“详见7.2”代替本节结论 |
| 风险与控制 | 第8章 | 1.5仅写主要风险摘要；结论仅写交割前置事项和未完成后果 | 在价值段、亮点段反复插入完整风险处置说明 |

## 章节责任

- `1.1 公司情况`：只放公司身份和经营定位的客观信息，不再设程序化的“发展阶段/核心判断”行。
- `1.5 投资价值`：固定用正文列示五条正向逻辑，每条按“事实基础 → 价值机制 → 投资意义”完成闭环，一项一个Word段落；顺序固定为“行业定位与付费商业基础、差异化技术路线、数据/反馈闭环壁垒、客户或生态商业验证、团队产业化能力”。老股折价、分期支付、治理安排和下行保护属于`7.2`，不得占用五条公司价值。风险另用一个段落，先指出唯一统领性的商业化或价值兑现风险，再说明财务、客户、IP/数据及量产等因素如何影响收入底盘、成长价值和估值兑现；不得只写并列风险清单。
- `5.1.1 政策层面`：不少于三个实质段落，分别说明国家产业定位、数据/人工智能政策对采购与产品形态的传导、属地产业政策与公司资源连接；不把政策目标直接写成公司收入。
- `5.1.2 市场层面`：不少于三个实质段落，覆盖已有付费市场、具身智能增量需求、项目制到产品化的商业层次及可获取市场边界；市场规模表必须由正文解释，不能以一张规模表代替市场分析。
- 第3章：唯一完整解释技术链、模块关系和产品协同的位置。
- `6.2.3 财务预测`：唯一完整呈现历史收入、利润、现金流及会计口径冲突的位置。
- `7.1 投资亮点`：用正文列示亮点和投资意义，不展示“尽调证据”、事实ID、证据类型或工作底稿字段。
- `7.2 公司估值与投资方式`：唯一完整呈现金额拆分、估值、完全稀释权益、分期和保护条款的位置。
- `投资结论及建议`：保持三段；第一段为建议及核心理由，第二段为交易执行摘要，第三段把交割事项压缩为一个并列句及一个未完成后果。

## 重复预算

- 技术链四要素同时出现的章节不超过2处，完整机制仅在第3章出现1次。
- “收入、净利润、收入确认差异”三个财务要素同时出现的章节不超过2处，完整数字组仅在6.2.3出现1次。
- “增资/老股金额、完全稀释持股、分期”完整交易元组不超过2处；结论优先交叉引用，不机械抄录。
- 同一解释性句子不得跨章节重复；同一重大数字原则上不超过2次。固定概要字段和决策执行所需数字可例外，但不得连同解释再次复制。

## 语言预算

防御性词语包括但不限于：`需进一步核对`、`尚未与账面勾稽`、`尚待`、`不承保`、`不释放`、`不计入`、`无法支持`、`不得外推`。“核查结论、尽调证据、关键验证、当前证据、投资处理”等工作流字段也不得出现在正式报告。

- 1.1核心判断最多1个不确定性限定，不使用引号强化负面判断。
- 1.5投资价值不使用防御性短语；边界移至主要风险。
- 7.1每项亮点先完成正向因果链；全部亮点合计最多2个简短边界提示。
- 结论前两段不展开核查措辞；控制要求集中在第三段，避免重复“需、尚未、不”。
- 用“以……为准”“交割前完成……核验”“达到……后计入”替代连续的否定表达，但不得改变事实强度或合同后果。

## 材料归因与缺口措辞预算

- 可由事实库支持的内容直接陈述为“公司……”，不使用“公司披露”“管理层披露”“材料显示”“尽调材料显示”等来源归因。确有时点必要时写明具体年月日，不使用“截至报告日”这种底稿式套话。
- `未提供`、`未显示`、`尚未完成勾稽`、`需进一步核对/核验`不得散落于公司、团队、业务、客户等经营正文。真正影响投资判断的缺口集中进入第8章风险表，并在结论第三段压缩为交割事项。
- `以……为准`只保留在正式权利义务、完全稀释股本或正式交易协议等法律效果确实取决于后续文件的位置；一般工商、团队、经营和资质事实改为直接判断，必要时绑定明确日期。
- 财务锚点6.2.3可保留一次“约450万元项目收入确认时点需进一步核对”，第8章可再保留一次对应控制；管理口径与账面口径差异继续作为核心发现，但不在其他章节复述核验过程。
- 固定模板字段或表头（如`尽调材料人数/规划`）不计入材料归因预算，不得为追求词频而破坏模板字段合同。

## 编号与章节自足门禁

- 两项及以上的编号枚举必须“一项一个Word段落、一项一行”；表格值单元格同样适用。禁止把`1. ……2. ……`连续写在同一段，也不得用手动换行伪装成独立段落。
- 正文禁止使用`详见`、`参见`、`见第X章`、`见X.X`或“按X.X所列”等方式替代本节应承担的内容。
- 删除交叉引用后，不机械复制完整锚点。应在当前章节直接写其决策所需的最短事实或结论；完整机制、计算和控制仍只在唯一信息锚点展开。
- `1.5 主要风险`只概括风险类别，不附“控制方案详见第8章”等导航尾句。
- P0/P1/P2/P3仅侜内部风险台账排序。正式报告用普通中文风险名称并按重要性排列，不暴露内部编码。
- 客户章节必须标明事实证据的真实阶段。只有已访谈客户的可归属笔录才能称为“客户访谈”；合同、验收或管理层口述不得冒充客户访谈。

## 价值完整性门禁

每条投资价值必须能回答三个问题：已有何种事实基础；价值通过什么机制形成；对收入、壁垒、客户、估值或下行保护产生什么影响。验证边界单列，不得让每条价值都以风险收尾。

五条投资价值还必须分别承担不同分析责任：第一条回答公司卡位何种产业变化且已有何种付费基础；第二条回答技术路线相对常见方案为何不同；第三条回答数据、模型、仿真或硬件入口如何形成反馈闭环与复用壁垒；第四条回答客户、合作伙伴或场景证据如何缩短商业化验证；第五条回答团队组合为何能够把研发成果转化为工程交付和产品化。任何一条不得由交易条款替代。

发布前运行 `python3 "${CLAUDE_SKILL_DIR}/scripts/editorial_quality_audit.py" --input /abs/final.docx`。任何语义重复、执行章节防御性措辞超预算、价值链不完整或结论超长问题均为P2，订正后方可发布正式稿。
