# 正式投资提案章节展开框架

在新建、润色或扩充正式投资提案时，先建立后台章节事实覆盖矩阵，再写正文。扩充以已确认事实的展开为目标，不以最低字数为目标。

## 通用段落结构

每个正文段落只承担一个主题，优先按以下顺序组织：

1. 总体定义：明确主体、业务或技术模块是什么。
2. 构成拆解：列明产品、人员、股权或业务组成。
3. 实现方式：说明输入、处理方法、输出或交付方式。
4. 量化信息：写明已确认的金额、数量、指标、期间、单位和口径。
5. 当前状态：区分已形成、已交付、正在工程化、在研和规划。

不得为了凑齐五项而补写材料中不存在的信息。一个段落通常使用其中二至四项即可。

## 章节覆盖矩阵

### 公司简介

优先覆盖：

- 主体身份：名称、成立时间、注册资本、法定代表人、注册地址；不写统一社会信用代码或18位信用代码。
- 办发布局：研发、生产、运营或注册地的现有分工。
- 业务定位：公司实际从事的业务及所处业务环节。
- 产品服务：现有产品线、服务类型及相互关系。
- 服务对象：客户类型和应用场景。
- 经营形态：项目制、产品销售、授权或服务等已经确认的方式。

材料充分时写三至五段；不要把工商信息、业务定位和产品结构压缩在同一句中。

### 核心团队

优先覆盖：

- 团队规模、学历结构和岗位构成。
- 实际控制人或创始人的履历、现任职责及与公司业务直接相关的经历。
- 运营、项目或产业负责人的经历和当前分工。
- 技术负责人、专家或研究人员的专业方向和现有职责。
- 算法、硬件、仿真、产品、财务和运营等职能配置。

材料充分时写三至六段。只写实际履职人员；教育背景、任职状态或全职状态存在冲突时降调或省略。

### 公司股权结构

优先覆盖：

- 明确截至日、注册资本和当前股东结构。
- 直接持股、间接控制和实际控制关系。
- 员工持股平台、期权池或代持，仅在事实已确认时写入。
- 公司设立、历次增资、股权转让和注册资本变化。
- 历轮融资金额、估值和完成状态。
- 本轮交易后的股权变化放在交易条件章节，避免混用当前与交割后口径。

材料充分时写二至四段，可增加简洁股权表；证据清单、工商附件和付款凭证不进入正文。

### 技术路线

先用一段定义总体技术架构，再按产品或技术模块逐项展开。每个模块优先覆盖：

- 输入：数据、设备、场景或用户指令。
- 方法：算法、模型、传感器、数据处理或仿真方法。
- 输出：数据集、控制信号、设备能力、训练结果或交付物。
- 指标：精度、响应、成本、效率等已确认指标及其适用口径。
- 场景：已确认的应用对象和任务。
- 状态：已形成、已交付、正在工程化、在研或规划。

材料充分时采用“一段总述＋每个模块一段”的结构。未经统一测试口径确认的排名、倍数和领先性结论不写入正文。

### 运营摘要

优先覆盖：

- 报告期营业收入、净利润等已经确认的经营结果。
- 收入对应的业务类别和产品服务构成。
- 项目制、产品销售、授权或数据服务等交付形态。
- 已确认的产品化、测试、交付或场景实施状态。
- 研发、运营和地域配置。
- 客户状态必须区分接触、测试、PoC、合同、验收、收入、回款和复购。

材料充分时写三至五段。不得在正文列举合同、发票、银行流水、验收单或证据目录。

### 投资亮点

写四至六项相互独立的客观事实归纳，优先覆盖：

- 产品和服务结构。
- 技术方法与现有产品衔接。
- 已确认经营结果或交付状态。
- 团队结构和相关经历。
- 股权、融资或交易安排。

不得使用“唯一”“领先”“壁垒显著”“成长性强”“投资价值高”等评价性词语替代事实。

### 风险控制

选择三至五项与项目事实直接相关的风险。每项只写一段，统一使用“风险—应对措施：”格式，只写公司已经采取的措施或用户明确提供的交易安排。优先考虑项目制收入、产品工程化、技术稳定性、数据管理、核心人员和经营场所等风险。

### 结论

当用户或原文已有明确投资建议时，结论使用一个完整段落，结构为：

`综合考虑【赛道窗口】、【技术路径及壁垒】、【商业化验证】、【团队构成】、【综合入股估值或价格折让】以及【回购、优先清算等下行保护】，项目组认为【投资判断】，建议在充分控制风险的情况下按主方案实施本次投资。`

只选用已经确认的维度。赛道窗口应有行业阶段依据；“全栈自研”应与知识产权和技术来源一致；“运营首年即盈利”应与锁定财务表一致；“院士领衔”应与实际任职或合作状态一致；综合入股估值、折让、回购和优先清算必须来自已确认交易条款。任一依据不足即删除相应分句，不得照抄模板示例。

## 后台覆盖矩阵

为公司简介、核心团队、股权结构、技术路线、运营摘要、投资亮点、风险控制和结论分别记录：

- `available_dimensions`：材料已经支持的事实维度。
- `used_dimensions`：正式正文实际使用的事实维度。
- `paragraph_count`：正式正文段落数。
- `source_status`：`sufficient` 或 `insufficient`。
- `missing_dimensions`：材料不足而未进入正文的维度。
- `decision_mode`：结论专用，明确为 `recommendation` 或 `neutral`。

结论的 `available_dimensions` 和 `used_dimensions` 只使用以下标准键：`赛道窗口`、`技术路径及壁垒`、`商业化验证`、`团队构成`、`综合入股估值或价格折让`、`下行保护`、`主方案`。推荐模式至少使用四项，且必须包含 `主方案`；`used_dimensions` 必须是 `available_dimensions` 的子集。

当 `available_dimensions` 已达到章节建议覆盖数而 `used_dimensions` 明显不足时，必须退回扩写。当材料不足时，将 `source_status` 标为 `insufficient` 并保持正文精炼，不得补写常识或推断。
