# 投资 Q&A 问题深度与自然表达

## 先提出判断，再选择事实

问题来自投资人需要理解的判断，不从材料中任取两组数字拼接。数字、客户名称和期间只是证据，不是每道问题的固定开头。对外 Q&A 中，至少一半问题应当能够脱离具体数字仍然成立，例如公司定位、商业模式、客户持续性、产品角色和团队执行。

每道问题只追问一个核心判断，但可以包含自然的递进关系。优先使用以下问题原型，并在同一报告中至少采用三种：

- `positioning`：公司与相邻类型企业的核心区别是什么；
- `market_need`：一项业务为何仍有客户需求，在公司当前阶段承担什么作用；
- `mechanism`：当前业务如何转化为可重复销售的产品或收入；
- `customer_case`：客户行为是否证明产品价值或商业化持续性；
- `transferability`：一个客户或行业的结果能否迁移到另一类场景；
- `product_role`：某项产品为何有独立价值，如何与主业协同；
- `revenue_quality`：有限客户数量下，收入、回款和采购行为是否具有质量；
- `valuation`：自身经营事实与行业参照如何共同支撑定价；
- `organization`：团队如何把研发能力转化为交付和收入。

## 回答不复制同一种骨架

保留第一句话直接回答的原则，但根据问题选择展开方式：

- 对比型问题可先界定相邻类型，再写公司差异和客户证据；
- 机制型问题按业务发生过程展开，不强制分成三点；
- 客户型问题优先讲清一个客户为什么采购、扩品或复购；只有比较客户质量时才并列两个案例；
- 跨行业问题先讲任务差异，再讲同一能力如何被另一个客户持续购买；
- 产品型问题围绕用途、客户行为和与主业的联系展开；
- 估值型问题可以分开写自身基础与行业参照；
- 团队型问题优先写实际交付，再补充职责分工。

只有机制题、客户决策题或因果型问题才写 `why_layer`。它回答事实背后的直接原因，例如客户为什么愿意扩大采购、真实数据为什么会提高合成数据的经营价值。估值、收入或组织事实已经足够回答时可以留空，不能为了填字段发明原因。

段数和句式由问题决定，不设报告级的变化配额；使用“第一、第二、第三”的问题不超过一半。相邻问题不连续复用相同首句和相同结尾。同一组客户不在过半回答中成对出现。回答可以落到投资含义，也可以停在“持续采购、跨行业复用、单独销售”等已经回答本题的商业事实。不要在每题结尾补“已经形成……基础”“具备……能力”或“验证了……价值”。

先做事实归属表。一个客户的复购过程可以是客户题的主证据；估值题只引用其中与定价直接相关的结果，不再复述全过程。团队题也不重复订单细节，只回答团队如何完成交付。事实复用是例外，不是写满每题的办法。

完成初稿后做一次删除测试：去掉最后一段，答案是否仍然完整？如果完整，就删掉。段落数量不能成为保留重复总结的理由。

再做一次朗读测试。圈出每题最有说服力的事实，检查它是否被套话包住。若整题连接过多、句法像说明书，应删掉部分连接词，让上下句自然承接。不要为了“像人写”而制造短句、反问或口号式收尾。

## 证据密度

对估值和财务问题保留必要数字。定位、商业模式、产品和团队问题只使用能改变判断的数字，其余事实用客户行为、产品用途、交付过程和商业结果表达。禁止为了满足数字数量而把两组材料数据塞进问题或每一段。

问题深度来自完整解释一个判断，不来自问题长度、数字数量或分点数量。允许个别问题比其他问题短，只要答案已经完整。
