# 投资 Q&A 证据与叙事双门禁工作流

## 阶段门

| 阶段 | 阶段文件 | 通过条件 |
|---|---|---|
| G0 输入准备 | `source_manifest.json`、`evidence_pack.md`、`packets/` | 重大材料解析成功；失败项已 OCR、转换或显式降权 |
| G1 事实与冲突 | `facts.json`、`rulings.json` | 重大数字含主体、期间、单位、状态和来源；冲突已裁决或保留 |
| G2 定位与质疑规划 | `qa_plan.json` | 受众与叙事模式、赛道三分法、项目站位和对应必要模块完整；6—9 问不重复 |
| G3 正文 | `qa_content.json` | 汇报时点锁定；对外只写成熟结论与已落地证据，内部模式另写风险处理 |
| G4 红队与评分 | `revision_log.json`、`quality_scorecard.json` | P0/P1 全部关闭；总分≥85；单项≥60%；无 hard failure |
| G5 硬门禁 | `qa_audit.json` | 事实、口径、敏感断言支持、叙事顺序、数字溯源和评分均通过 |
| G6 文档与视觉 | DOCX、`qa_verify.json`、逐页 PNG/PDF | OOXML 结构合格；逐页无截断、重叠、乱码、孤立问题或异常留白 |

## G0：材料准备

运行 `prepare` 后先读 `source_manifest.json`。`warning` 非空的关键文件不得默默跳过：扫描 PDF 先 OCR，旧版 Office 文件先转换，内嵌压缩包先解开。用哈希和相对路径识别重复版本。

同业估值、轮次、收入、客户和技术路线可能变化，必须联网更新。优先官网、投资方公告、监管披露和主要媒体；记录访问日期、轮次口径、币种和交易权利。

## G1：事实库与裁决

事实对象至少包含 `id`、`fact`、`category`、`status`、`materiality`、`source_ids`、`date_hint`。证据优先级默认为：签署交易文件/官方登记/审计或专项报告 > 合同、验收、发票、回款、客户直接访谈 > 会议纪要与现场记录 > BP、管理层预测和宣传材料。

冲突不得通过平均、拼接或选择更有利口径消失。`rulings.json` 同时保留 competing values、governing value、reason 和受影响事实 ID；否决值进入 `blacklist`。

## G2：先定位，再设问

1. 先选择 `external_decision_qa` 或 `internal_decision_qa`，再选择 `dual_use`、`internal_ic` 或 `reference_faithful`。
2. 建立纯通用世界模型厂商、本体厂自研团队、纯外包数据服务商三类玩家定位，再用项目事实写明自身站位。`reference_faithful` 仅在私有规划中保留该地图，并将结论分散到 Q1/Q4/Q7，不输出总览。
3. 按“投决影响×事实强度×可回答性”排序质疑。
4. 先确定问题原型，再选择证据，并用 `evidence_focus` 标明每题真正需要的证据范围。对外问题不强制引用数字，至少一半问题脱离数字仍可成立；八至九题至少覆盖五种问题原型，同一证据组合不得支撑过半问题。
5. 对外模式用 `coverage` 映射估值对标、客户验证、收入质量、产品/技术价值、商业化与组织能力；治理/IP和交易安排不强制进入。内部模式再覆盖治理/IP与交易安排。商业化与组织扩张只能映射到一个问题。
6. 每题规划 `mechanism_chain`、`competing_explanation`、`discriminator`、`economic_bridge`、`valuation_treatment`和 `boundary`。只有机制题、客户决策题或因果型问题才填写 `why_layer`；事实已经足够回答的估值、收入或组织题可以留空。这些是内部字段，不在正文显示标签。
7. 为重大事实指定一个主要问题。除非第二个问题确实需要，同一事实只在主要问题中展开；同一客户故事不得反复承担定位、产品、收入、估值和团队五种结论。

## G3：自然叙事与敏感断言

对外 `dual_use` 与 `reference_faithful` 的回答使用 1—4 个自然段，不设最低字数；内部模式使用 2—4 段：

1. 首段直接回答问题并给出已验证起点，对外模式不使用“经项目组核查”等内部叙述者。
2. 对外后续只放决定性事实；待确认事项和推理过程保留在内部底稿。
3. 对外模式不写付款、预留、补偿或重定价；内部模式按需说明交易影响。
4. 不用“小标题+冒号”，不使用“这说明、共同证明、这体现、这表明、由此可见、据此”等推导词。
5. 具体客户行为已经答完问题时直接结束，不另加“已经形成、具备能力”式总结；需要判断时，只写与本题直接相关的一句。不得给公司布置新任务，不得记录投后或审批过程。
6. 全文按比较、机制、客户案例、产品角色、估值或组织执行选择不同展开方式；分点题不超过一半，相邻问题不机械复制相同骨架。句子长短由内容决定，不用配额制造节奏，也不连续堆短句制造戏剧感。
7. 完稿后逐题朗读。删掉“这个顺序更能解释……”“最有分量的支撑是……”一类替听众总结证据的工整句，让订单、复购、回款等事实自己落地。

为联合研发、IP 归属、控制权稳定、股权激励、竞业和不可替代性等正向断言建立 `claim_support`。表达级别不得高于事实证据级别。

## G4—G6：订正与发布

红队仍以“不投资”为默认假设，但需额外检查两类错误：

- 防御性叙事：开篇就做条件性否定，或风险描述占全文过高。
- 模板化叙事：每题同样三段、相同结尾，反复出现付款与重定价，或把内部术语直接写进正文。
- 顾问式叙事：项目组已经完成尽调，却仍写“公司需要、建议进一步、后续验证”，或把未决事项悬置为新的问题。
- 受众混写：对外正文出现“项目组支持”、估值剔除、分期付款、专项预留、补偿或其他内部交易操作。
- 时点越级：在项目组建议阶段把拟议口径写成双方已约定、协议已明确或事项已完成。
- 融资包装过度：将采购升级为联合研发，将意向升级为合同，将管理层陈述升级为已落地制度。
- 伪对标：用海外基础模型或成熟平台的高估值直接证明早期项目定价合理，未披露轮次、规模与收入阶段差异。
- 制度前置：把拟写入股东协议或交割条件的控制权、激励、离职回购、IP 许可和开源合规安排写成已经落地。

硬门禁失败时修改底层事实、裁决、问题或答案，不通过删除不利事实、伪造数字、降低评分或使用 `--allow-failed-audit` 绕过。静态 `verify` 通过后仍须渲染并逐页检查。
