## AI-TASK-001 输入发送规则验收与幂等补强

- **任务编号**：AI-TASK-001
- **需求编号**：AI-002
- **名称**：输入发送规则验收与幂等补强
- **目标**：确保只有明确发送动作产生一次消息，中文输入法选词、普通 Enter、快速点击、生成中操作和失败恢复均不会产生非预期提交。
- **前/后端**：以前端验收和自动化为主；后端幂等依赖 AI-TASK-006。
- **当前实现**：`src/pages/AIAssistantPage.tsx` 已实现 Enter 换行、Ctrl/Command+Enter 发送、IME 组合态拦截、busy 与同步提交锁，以及失败后的安全草稿恢复。
- **修改内容**：补齐可复跑的键盘和提交测试；为每次明确提交生成客户端 requestId；统一快捷建议和按钮的发送门禁；在任务 API 上线后将 requestId 升级为服务端幂等键。
- **涉及文件**：`src/pages/AIAssistantPage.tsx`、`src/lib/aiMessageSafety.ts`、`server/src/routes/`、`server/src/services/`。
- **是否新增文件**：是；建议新增 `src/pages/__tests__/AIAssistantPage.input.test.tsx`、`src/lib/aiRequestId.ts`，服务端幂等测试随 AI-TASK-006 新增。
- **接口改动**：一期无破坏性接口改动；任务底座上线后，消息或任务创建请求增加 `Idempotency-Key` 或 `clientRequestId`。
- **数据库改动**：一期无；后续由 `ai_tasks.idempotency_key` 承接。
- **迁移**：一期不需要；幂等字段迁移归 AI-TASK-006。
- **依赖**：现有 Flue SDK；服务端幂等部分依赖 AI-TASK-006。
- **阻塞**：需产品验收 Q-AI-005、Q-AI-007；不阻塞测试工程建设。
- **风险**：Flue SDK 可能在网络重试时产生重复提交；不同输入法事件顺序存在浏览器差异。
- **复杂度**：M。
- **工作量**：1～2 人日；不含统一任务 API。
- **测试**：Chrome/Safari/Edge；macOS/Windows；拼音、五笔等至少两类中文输入法；按钮双击、快捷建议连击、网络失败、停止后重发。
- **验收**：普通 Enter 仅换行；IME 确认不发送；Ctrl/Command+Enter 只发送一次；生成中无法重复提交；失败恢复不覆盖新草稿。
- **回滚**：保留当前键盘实现；自动化测试可独立回滚；若 requestId 引发兼容问题，关闭服务端幂等开关并保持前端同步锁。
- **状态**：已实现待验收。
