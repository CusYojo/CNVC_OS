# AI-007～AI-010 开发与业务预验收报告

## 1. 验收结论

AI-007 合规性说明、AI-008 投资提案、AI-009 投资建议书（PPT）和 AI-010 尽调报告已完成开发侧实现，并通过自动文件门禁与生产构建；PPT 已完成逐页视觉预验收，DOCX 已完成结构、编码和字体标记检查。

当前结论为：**技术与脱敏样件预验收通过，可以进入产品、投资业务和法务人工 UAT；尚不能视为法务批准、投资业务签字或生产发布批准。**

### 1.1 本次问题根因

1. 纯文本资料过去统一按 UTF-8 解码，WPS/Windows 常见的 UTF-16 或 GB18030 文件会在入库时产生 `U+FFFD`，损坏内容随后被 RAG 带入所有业务产物。
2. 旧 DOCX 生成器从空白文档重建统一彩色卡片版式，只校验模板路径存在，没有读取 `docs` 模板；同时把 `Arial Unicode MS` 写入全部字体槽位。
3. 旧 PPTX 从空白页生成，中文文本仍标记为 `en-US`，东亚主题字体为空，也没有继承模板的公司资产和视觉规则。
4. Q&A 和任务卡曾直接展示 Skill/模板内部版本信息，阅读格式与 `docs/Q&A` 的正式“问题—答复”样本不一致。

## 2. 本次实现范围

- 四类文档快捷入口均先确认项目、资料截止日及业务参数，再创建持久化 AI 任务。
- 统一任务状态为 `pending → running → succeeded | failed | cancelled`，支持进度、阶段、取消、错误编号、失败重试和服务重启恢复。
- 同一用户的幂等键重复提交返回原任务；相同幂等键配不同参数返回冲突。
- 任务、产物及来源按用户、项目、会话和任务归属保存；下载及预览必须通过鉴权接口。
- 任务文件路径由服务端在受控根目录内生成，客户端不能提交任意存储路径。
- 正式产物保存模板版本、资料截止日、质量状态、版本号及来源定位。
- 四类文档任务分别绑定独立中文业务 Skill，正式产物同时保存 Skill 名称、SHA-256 版本和完整摘要。
- Skill 的目录名和 frontmatter `name` 按规范保留小写 ASCII kebab-case 技术标识；用户可见名称、说明、工作流、输出契约和默认提示均为中文。
- 合规性说明同时交付可编辑 DOCX 和页面内 Markdown 预览。
- 投资提案交付可编辑 DOCX，并明确不替代投资建议书。
- 投资建议书交付原生 PPTX 和 1600×900 封面预览；文字、表格和基础形状可编辑。
- 尽调报告交付可编辑 DOCX，并区分“资料记载、AI 推断、待核验、资料缺口”。
- 前端支持刷新后恢复任务、运行态轮询、任务卡、来源数量、错误编号、鉴权下载和项目交付物中心。
- 文本上传支持 UTF-8、UTF-16LE、UTF-16BE 和 GB18030 识别；历史知识片段含 `U+FFFD` 或常见 mojibake 时，生成前会清洗可读部分或拒绝该片段，不再把损坏字符写入正式文件。
- DOCX 使用宋体/黑体或仿宋/黑体的东亚字体标记，不再强制使用 `Arial Unicode MS`；PPTX 中文文本统一标记 `zh-CN`，东亚主题字体为“微软雅黑”。
- 用户界面不再展示内部模板 ID、Skill 版本或样本文件技术编号；审计信息仍保存在服务端元数据中。

这些文件当前作为结构、章节和视觉方向的版本化样本，不代表已经完成法务或投资业务正式批准。

- DOCX 运行时会读取主样本并记录模板摘要，继承可安全复用的字体表/主题，同时按样本的页边距、中文字体、页眉页脚、页码和长文档分节规则生成新正文。
- PPTX 运行时会读取主样本，只继承公司级 Logo、山景和紫色版式规则；不会继承样本项目正文、照片、证书、产品图或投资人 Logo。
- 由于原样本含真实项目内容和专属媒体，当前不会无差别复制完整二进制母版，避免跨项目泄露。

本轮机器报告写入完成后，所创建的精确脱敏验收项目已从开发数据库清理，生成文件已移至系统临时目录，不会继续出现在业务项目列表或仓库交付物中。
