# AI 智能助手测试计划

> 项目需求依据：`docs/需求分析.md` V1.2  
> 覆盖需求：AI-001～AI-011、PPT-001～PPT-003、SYS-001～SYS-003、KB-001～KB-002  
> 覆盖任务：AI-TASK-001～AI-TASK-022  
> 说明：性能阈值、观察周期和浏览器版本尚未由产品与运维确认的部分，均标记为“待确认”，不作为已批准指标。

## 1. 测试目标

1. 验证 AI-002、AI-004、AI-005 已落地部分符合项目需求并可稳定复跑。
2. 验证统一偏好、任务、运行、产物、来源和权限模型在刷新、重启和并发条件下保持一致。
3. 验证五个快捷入口均确定性加载对应中文 Skill，业务定义、参数、任务状态、产物和来源符合确认后的模板。
4. 验证 AI 输出不会把企业自述、AI 推断或缺失信息冒充已核验事实。
5. 验证用户不能访问无权限项目、任务、知识片段或产物。
6. 验证 Flue、LLM/OCR、数据库、文件系统和 Office 生成器异常时能够安全降级和恢复。
7. 建立可在本地、CI、测试环境和发布 smoke 中重复执行的证据链。
8. 验证 PPT 标题/解释层级、主题替换、多模态元素分离及 Office/WPS 稳定性符合 V1.2。
9. 验证材料生成四类一级入口与 AI 五类快捷任务保持清晰边界，旧记录和历史文件不丢失。
10. 验证标准样本、SOP、知识更新与失效、权限、脱敏和来源版本可追溯。

## 3. 测试范围

### 3.1 范围内

- React 页面、Hooks、消息和任务组件。
- Zustand 与服务端状态同步。
- Express 路由、中间件和 TypeScript Service。
- PostgreSQL schema、迁移、约束和并发。
- Flue Agent/Workflow 契约、流式消息和工具事件。
- 文件上传、正文提取、OCR、切块、检索和来源定位。
- 任务状态机、幂等、取消、失败、重试和重启恢复。
- 产物归属、版本、质量、预览、下载和归档。
- PPTX/DOCX 文件质量及 Office/WPS 兼容。
- PPT 参考版式、标题/解释层级、主题色替换和多模态技术验证。
- 材料生成四入口、AI 五快捷任务及两者的信息架构边界。
- 标准样本/SOP、知识更新/失效、索引版本、允许范围和脱敏。
- JWT、项目 ACL、内部凭据、路径安全、日志脱敏和限流。

### 3.2 默认范围外

- 在线编辑 Office 文件。
- 多语言模板。
- 多套尽调类型和复杂审批流。
- 所有装饰元素完全对象化。
- 未经确认的历史工作区自动归属推断。
- 外部模型本身的通用能力评测；只测试项目使用到的契约和业务输出。
- 未获授权的周琴、沈阳或其他真实敏感样本；样本未批准前只建立不含真实正文的测试脚手架。

## 4. 测试环境

| 环境 | 用途 | 必备组件 | 数据要求 |
|---|---|---|---|
| 本地单元环境 | 快速开发反馈 | Node.js、测试运行器 | 全部 mock 或 fixture，不连接真实服务 |
| API 集成环境 | 路由、数据库、迁移 | Express、隔离 PostgreSQL | 每次可重建，禁止连接生产库 |
| Flue 契约环境 | 消息、工具、取消、历史 | mock Flue + 指定真实测试 Flue | 使用脱敏会话和固定 fixture |

### 4.1 浏览器和系统矩阵

最低建议矩阵：

- macOS：Chrome、Safari。
- Windows：Chrome、Edge。
- 中文输入法：macOS 拼音、Windows 微软拼音；其他项目常用输入法由产品确认。
- Office：Microsoft PowerPoint 和 WPS 的正式版本范围待确认。

### 4.2 测试账号与权限

至少准备：

- 用户 A：可访问项目 A，不可访问项目 B。
- 用户 B：可访问项目 B，不可访问项目 A。
- 管理员：可查看审计和系统健康，但不默认读取项目正文。
- 服务身份：仅可调用指定内部 RAG/任务回调接口。

账号密码、token、项目资料和服务 secret 不写入仓库或测试报告。

## 5. 测试数据

### 5.1 项目资料集

每类至少包含：

- 正常文本 PDF。
- 扫描 PDF。
- DOCX。
- XLSX，包含多工作表、公式和中文表格。
- PPTX，包含多页中文文本。
- PNG/JPG。
- TXT/Markdown/CSV。
- 损坏文件、空文件、超大文件和不支持格式。
- 同名文件和同内容不同名文件。

### 5.2 AI 消息 fixture

- 标准 user/assistant 文本。
- legacy content。
- `messages` 或 `parts` 非数组。
- 空 part、未知 part。
- tool input/output 为字符串、对象、数组和错误。
- 循环引用、BigInt、异常 getter。
- 超大文本、超深对象、超多 part。
- 流式结束、工具未结束、取消和重连事件。

### 5.3 业务金样

由产品、投资业务和法务共同提供：

- 合规性说明模板及预期免责声明。
- 投资提案模板和一份通过验收的内容样例。
- 尽调报告目录、事实/推断/待核验标识样例。
- 投资建议书模板、字体、页数和可编辑元素样例。
- Q&A 分类与问题样例。
- PPT-001 批准的沈阳参考文件或书面指定的替代基准。
- PPT-002 获授权并完成脱敏/受控保管的周琴样本。
- PPT-003 企业主色、辅助色、禁用色和主题版本。
- SYS-002 旧入口到四类新入口的映射及历史记录 fixture。

金样只作为业务验收基准，不直接复制真实敏感项目内容到自动化仓库。

### 5.4 标准样本与 SOP 数据

五类能力分别准备：

- 唯一生效标准样本、优秀样本和不合格样本。
- 文档类型、版本、有效日期、保密等级、允许范围和批准记录。
- 章节、必填字段、数据口径、审核、命名、版本和归档规则。
- 已脱敏自动化金样，以及不得进入自动化仓库的受控真实样本清单。
- 过期、失效、未授权、版本冲突和缺少元数据的反例。

在 AI-TASK-022 完成前，现有目录中的文件只能作为候选样本，不能默认视为等效标准模板。

## 8. 核心功能用例

### 8.1 AI-002 输入与发送

| 用例 | 操作 | 预期 |
|---|---|---|
| 普通 Enter | 输入两行文本并按 Enter | 仅插入换行，无网络请求 |
| 快捷发送 | 按 Ctrl/Command+Enter | 只产生一次提交 |
| IME 选词 | 中文输入法组合态按 Enter | 完成选词，不发送 |
| 按钮双击 | 快速双击发送按钮 | 只产生一个逻辑请求 |
| 生成中提交 | streaming/submitted 时点击发送和建议 | 不提交、不排队 |
| 失败恢复 | 网络拒绝后继续输入新草稿 | 原问题只在输入为空时恢复，不覆盖新草稿 |
| 停止生成 | 点击停止后等待状态稳定 | 当前生成终止；按规则允许新提交 |

### 8.2 AI-004 白屏与恢复

| 用例 | 故障 | 预期 |
|---|---|---|
| 单 part 异常 | part getter 抛错 | 仅该 part 显示错误卡片 |
| 单消息异常 | 非法 messages/parts | 该消息降级，其他消息可用 |
| 工具输出超大 | 大对象或深层对象 | 页面保持响应，内容受控折叠或截断 |
| 标题总结失败 | 500/超时 | 会话和回答不丢失，保留兜底标题 |
| 产物刷新失败 | workspace 500 | 聊天保持可用，产物区显示局部错误 |
| 切会话竞态 | 完成瞬间切换会话 | 不把旧会话状态写入新会话 |
| 页面刷新 | 回答结束后刷新 | 可恢复会话和已登记产物 |
| 错误上报 | 任一渲染异常 | 可按错误编号查询脱敏上下文，无正文和 token |

### 8.3 AI-005 产物权限

| 用例 | 操作 | 预期 |
|---|---|---|
| 当前任务产物 | 用户 A 查询自己的项目任务 | 可见 |
| 跨项目 ID | 用户 A 构造项目 B artifact ID | 403 或不泄露存在性的 404 |
| 路径猜测 | 构造 uploads、脚本、日志路径 | 不可读取 |
| 路径穿越 | `../`、编码斜杠、双重编码 | 400/404，不越出根 |
| 下载 | 合法 artifact ID 下载 | 带鉴权、文件名和 MIME 正确 |
| 旧共享文件 | 普通用户查询 | 默认不可见；管理员按兼容规则只读 |
| 版本 | 同任务生成 V1/V2 | 两版本均可追溯，默认展示规则正确 |

### 8.4 统一任务状态

覆盖状态：

```text
pending → running → succeeded
                  ↘ failed
                  ↘ cancelled
```

必须验证：

- 同一用户和幂等键并发创建只返回同一逻辑任务。
- 不同用户使用相同幂等键互不影响。
- worker 取得租约、续租、失联和恢复。
- 取消与成功同时发生时结果唯一且可解释。
- failed 重试创建新运行记录，不覆盖原运行。
- 刷新、重新登录和服务重启后状态可查询。
- 重复 Flue 回调或网络重放不重复登记产物。
- 不可取消阶段返回明确结果。

### 8.5 默认选择

- 按 Q-AI-008～Q-AI-010 的书面结论验证对象、优先级、允许修改/强制锁定和生效范围。
- URL、历史会话、本地值或服务端偏好只验证确认后实际采用的来源，不预设完整优先级。
- 对象删除、归档或权限取消后安全回退。
- 仅在确认跨设备时验证同步、冲突和旧本地值迁移。
- 强制锁定场景下前端不可改；仅在存在服务端策略时验证后端拒绝绕过。
- 若“智灵动力”最终指 Agent/模型，验证显示名称、实际 Agent/模型和任务记录一致。

## 9. 业务任务测试

### 9.1 共同要求

五类快捷入口均验证展示、权限和点击行为；只有经确认采用“独立任务”形态的入口，才执行下列任务、产物和恢复检查。若确认采用“填入输入框”或“立即发送”形态，应分别验证不创建任务或只提交一次，不套用长任务断言：

- 入口是否按角色和项目权限展示。
- 参数默认值、必填、长度、枚举和截止日校验。
- 点击行为与产品确认一致。
- 重复点击和网络重试不会重复创建任务。
- 独立任务有真实阶段、取消、失败、重试和恢复。
- 需要文件或归档交付时，成功结果登记 artifact 和 sources。
- 同时在消息区和产物中心展示时，两处指向同一 artifact version。
- 无证据内容不写成已核验事实。
- 下载、预览、归档和审计符合权限。
- 五个 Skill 的显示名称、说明、工作流、引用契约和默认提示均为中文；目录名、frontmatter `name` 及 JSON/API 字段可保留规范要求的英文技术标识。
- 每次正式执行记录实际加载的 Skill 名称、版本和 SHA-256 摘要，不能只依赖提示词或前端文案宣称已启用 Skill。

### 9.2 合规性说明

- 模板版本和免责声明逐字比对。
- 已核验事实、风险、待核验和资料缺口分区。
- 关键表述来源可定位。
- 缺少法律依据时不得生成肯定法律结论。
- 审核前后状态和可见范围符合确认规则。
- 若批准同时输出 DOCX 和页面内容，两者语义一致；未批准文件输出时不执行该断言。

### 9.3 投资提案

- 与投资建议书的标题、结构和用途不混淆。
- 不同目标受众使用正确模板和权限。
- 企业预测、公开事实和 AI 推断明确区分。
- 资料截止日和模板版本进入产物元数据。
- DOCX/PPTX 等输出以产品确认格式为准。

### 9.4 尽调报告

- 章节完整且顺序符合批准模板。
- 每个关键结论有来源或明确“无证据/待核验”。
- 文件、页码/幻灯片/工作表和片段定位正确。
- 冲突资料不能静默选取单一结论。
- 资料截止日之后的数据不混入报告。
- 长任务可恢复，单章节失败可解释。
- 报告不冒充已经完成法律、财务或商业尽调。

### 9.5 Q&A

- Q&A 与自由聊天的差异符合 Q-AI-024 结论。
- 问题库按投资亮点、核心风险、财务、客户、竞争、合规和资料缺口七类展示；点击问题只填入输入框，必须等待用户明确确认发送。
- 用户确认后只调用一次 `POST /api/ai/qa`，请求中的项目、会话、分类、问题和资料截止日正确；不得同时发送普通 Flue 消息或拼接 `【业务技能】answer-project-qa` marker。
- Express 必须校验用户、项目和会话权限，并确定性加载 `answer-project-qa`；返回的 `skillName`、`skillVersion` 和 `skillSha256` 与服务端当前 Skill 一致，`templateVersion` 和 `referenceTemplates` 与当前 docs Q&A 模板登记一致。
- RAG 只使用当前用户有权访问、日期不晚于截止日的当前项目资料，不得混入全局知识库、其他项目或无权限来源。
- 回答区分已核验事实、企业自述、AI 推断和待核验事项；重要要点引用来源，来源带标题和定位，`evidenceCount` 与去重来源一致。
- 无资料命中、解析失败或证据冲突时降低置信状态并说明证据不足，不得补写项目事实。
- 固定责任声明完整展示，且不得将回答表述为正式法律意见、已完成的尽职调查或最终投资决策。
- Q&A 用户问题和结构化回答保存到当前会话；刷新、重新登录和再次打开会话时，`GET /api/ai/qa?conversationId=...` 恢复相同回答、Skill 版本和来源。
- 其他用户读取该会话返回不泄露存在性的 404；无项目权限用户创建回答返回 403。

### 9.6 材料生成四入口与 AI 五入口边界

- 材料生成主界面恰好显示“提案、建议书、PPT、微信说明”四类，并符合批准顺序和设计。
- AI 助手恰好显示“合规性说明、投资提案、投资建议书（PPT）、尽调报告、Q&A”五类。
- 两套入口共享任务、知识和产物底座时，显示名称、路由、参数和交付类型不发生错误串用。
- 旧材料类型按书面映射进入正确入口；无法确认的历史记录保持原名并可受控访问。
- 隐藏的旧入口不再出现在主界面，但历史文件、已完成任务和批准深链不被删除。
- `materials_entry_v2` 关闭后可恢复旧入口，AI 五类入口状态不受影响。

### 9.7 项目知识库与标准样本/SOP

- 上传“已接收、解析中、成功、失败”状态与真实摄入状态一致。
- 同一来源更新后新版本生效，旧分块按规则失效且不与新内容同时误命中。
- 失效、过期、未授权或超出允许范围的样本不参与新生成。
- 项目、机构和线索 scope 不能跨权限检索；标准样本管理权限与普通项目资料权限分开验证。
- 检索和生成结果记录来源文件、版本、定位、知识有效状态和模板/SOP 版本。
- 输出明确区分“知识库已提供事实”“模型推断”“待核验信息”和资料缺口。
- 五类能力分别使用批准的生效标准模板；标准版本切换后新任务使用新版本，历史产物仍可追溯原版本。
- 脱敏检查覆盖个人信息、商业秘密、token、内部路径及不允许进入自动化仓库的正文。
- 样本用途默认限于模板配置、RAG、流程设计、测试和验收；未经单独批准不得作为模型微调训练数据。

## 10. PPTX/DOCX 文件质量

### 10.1 PPTX 自动检查

- 文件是有效 ZIP/OpenXML。
- 不存在断开的媒体和关系引用。
- 页数与任务参数一致。
- 模板、主题、页面尺寸和字体元数据正确。
- 文字、表格、基础图表和形状的原生对象数量满足确认边界。
- 文本无明显越界、遮挡和空白页。
- 图片版、预览版和正式版的版本号一致。
- 文件名、项目名、截止日、模板版本和来源正确。
- 失败文件不登记为 `succeeded`。

### 10.2 Office/WPS 人工检查

- 按确认版本打开无修复提示。
- 中文字体显示正常。
- 确认范围内的核心元素可选择和编辑。
- 修改后可正常保存和重新打开。
- 页面比例、页码、页脚和来源可读。
- 图片层边界符合产品确认，不把图片层宣称为语义可编辑。

### 10.3 DOCX 检查

- 标题层级、目录、表格、页眉页脚和免责声明正确。
- 中文字体和分页正常。
- 来源与正文引用一致。
- 页面结果与下载文件使用同一内容版本。

### 10.4 PPT-001 参考版式与可编辑层级

- 使用批准的沈阳参考 PPT 或书面指定替代基准，记录文件版本和摘要。
- 每页标题与内容解释层级明确，标题、正文和关键说明可分别选中及编辑。
- 背景、装饰和内容元素不无必要地合并为整页图片。
- 典型封面、目录、章节、内容、图表和结论页按批准的字号、间距和留白规则检查。
- 长标题、长正文、缺图、空数据和中英文混排时无明显遮挡、溢出或字体异常。

### 10.5 PPT-002 多模态技术验证

- 输入样本、参考文件、模型/Workflow、提示、依赖和版本全部可追溯。
- 相同条件可重复运行；随机性和不可重复因素在报告中说明。
- 分页比较标题、正文、图片、图表和形状的分离度及核心元素可编辑性。
- 在批准的 Office/WPS 环境完成打开、编辑、保存和重新打开。
- 记录每次生成耗时、失败阶段、失败率和人工修订动作/成本。
- 输出生成结果、问题清单和“满足、部分满足或不满足”的结论；上线阈值未确认时不得自行判定通过。
- 真实样本和生成结果按授权存储，验证报告不得泄露敏感正文。

### 10.6 PPT-003 主题配色

- 主色、辅助色、禁用色、深浅色和主题版本与批准清单一致。
- 标题、正文、强调、图表和背景形成稳定颜色层级。
- 更换主题后文本、形状和原生图表颜色可更新，不依赖整页背景图片。
- 正文、图表标签和背景的对比度按批准阈值测试；阈值未确认前只记录实测值。
- Office/WPS 打开、编辑和保存后颜色不发生不可解释漂移。
- 回切上一主题版本后新生成文件使用旧主题，已生成文件保持原版本可追溯。
