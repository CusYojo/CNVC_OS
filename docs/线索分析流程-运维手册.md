# 共有池线索分析流程（核心功能 · 运维手册）

> 项目：赛智伯乐投资中台 MVP（101.126.131.28:/data/cybernaut-mvp）
> 最后更新：2026-07-14

## 一、这条流程做什么

任何线索（36氪数据库 / 雷达其他信源 / 任何渠道）入池后，**统一走 AI 分析**：

```
线索入池
  → 汇总已入库的线索资料、雷达资料和结构化字段
  → Pro模型综合分析（score-project / score-paper）
  → 保留原始 team/融资/股东/工商/来源并回填评分结果
  → 完整度按真实资料算（排除占位符）
```

核心理念：**完整度/评分只反映已经入库、可追溯的真实资料**。分析阶段不联网补全，缺失事项保留证据边界。

## 二、组成部分

### 1. 评分服务（flue，独立项目 /data/cybernaut-assistant，:8791）
- workflow：`score-project`（普通线索评分）、`score-paper`（论文线索评分）
- 模型配置：`.env` 的 `SCORE_MODEL=zeelin/DeepSeek-V4-Pro`（改后重启 flue 生效）
- 重启 flue：`cd /data/cybernaut-assistant && PID=$(pgrep -f "cybernaut-assistant.*server.mjs"); kill $PID; sleep 3; (nohup node --env-file=.env dist/server/server.mjs > server.log 2>&1 &)`

### 2. 后端评分队列（/data/cybernaut-mvp/server/src/routes/meta.ts）
- `doScore()`：单条完整链路（读取入库资料→评分→回填→完整度）
- 全局队列 N 并发：`SCORE_QUEUE_CONCURRENCY`（默认3）
- `saveLeadScoring()`：把分析产出回填到 leads 独立列（team/funding_rounds/sources/summary）
- 完整度 SQL 表达式（aiSummaryService.ts `completenessExpr`）：8位纯资料，用 `jsonb_path_exists` 排除"待核验/未披露/待核实"占位符

### 3. 批量分析器（/data/cybernaut-mvp/batch_analyze.mjs）★核心运维工具
稳定·多并发·精准·幂等。用法：
```bash
node batch_analyze.mjs                    # SCOPE=todo 补漏(默认):补齐所有未充分分析的
SCOPE=page1 node batch_analyze.mjs        # 只扫第一页(最新50)
SCOPE=all FORCE=1 node batch_analyze.mjs  # 强制全量重分析
CONCURRENCY=3 node batch_analyze.mjs      # 并发数(匹配后端队列)
```
- "已充分分析"判定（幂等基础）：`scoring.dimensions 非空 且 scoring含【预测】标记 且 score>0`
- 每条失败自动重试1次，单条最多等10分钟（Pro较慢）
- 可反复跑、断点续、自动补漏

### 4. 定时任务（crontab）
```
0 8 * * *  run_daily_intake.sh      # 入池36氪50 + 雷达抓取 → 新线索当天分析
0 2 * * *  run_batch_analyze.sh     # 兜底补漏(SCOPE=todo):失败重试/漏评/存量
```

## 三、常见运维场景

| 场景 | 操作 |
|---|---|
| 想让第一页/存量重新分析 | `SCOPE=page1 node batch_analyze.mjs` 或 `SCOPE=all FORCE=1` |
| 换了评分模型要生效 | 改 flue `.env` SCORE_MODEL → 重启 flue → `SCOPE=all FORCE=1 node batch_analyze.mjs` |
| 有线索没评分/评分失败 | 直接 `node batch_analyze.mjs`(SCOPE=todo 自动找出补齐) |
| 看进度 | `tail -f logs/batch_analyze_cron.log` 或对应 log |

## 四、坑与注意

1. **改后端评分逻辑后必须**：`npx tsc -p server/tsconfig.build.json` → `pkill -9 -f "node server-dist"` → 重启。
2. **score 列 = AI评分(scoring.total)**，不是雷达 attention_score。未评分的应为0（否则会用雷达分冒充高分排前）。入池写 score 时注意。
3. **并发上限受 flue/zeelin 承载约束**，默认3安全。调高需观察失败率。
4. **Pro模型比Flash慢**（单条约120-150s），批量分析器超时设10分钟+重试1次，不要设太短否则误判失败。
5. **完整度只认真值**：数组里全是"待核验/未披露"占位符的不算"有资料"（如论坛纪要类）。
6. **scoreStatus 是内存态**，后端重启丢失（不影响已落库的 scoring）。批量分析器用 DB 状态判定，不依赖内存。
