# 投资项目审批流程调整设计

## 目标

在保留现有 FDE 八阶段、OA 审批记录、材料门禁和治理职责体系的前提下，调整投资项目各阶段的执行人与审批人规则：普通领导审批由项目设立时配置的董事长或总裁任意一人完成，最终投决必须由董事长和总裁两人依次通过。

本次使用现有审批引擎与项目治理数据，不把规则硬编码到单一页面，也不重构为新的通用流程引擎。

## 流程规则

| 阶段流转 | 执行与审批规则 |
| --- | --- |
| 入库 → 立项 | 老板审批；项目配置的董事长、总裁任意一人通过 |
| 立项 → 尽调计划制定 | 投资项目组任意一人可以开始制定计划，无审批 |
| 尽调计划制定 → 尽调计划审核 | 投资项目组任意一人可以提交符合材料和完整性门禁的计划 |
| 尽调计划审核 → 启动尽调 | 老板审核；项目配置的董事长、总裁任意一人通过 |
| 启动尽调 → 内核 | 老板审批；项目配置的董事长、总裁任意一人通过 |
| 内核 → 投决 | 财务 → 法务 → 老板，严格串行；财务、法务、老板各职责节点内部任意一名已配置人员通过 |
| 投决 → 打款 | 董事长 → 总裁，严格串行；两人必须分别通过 |
| 打款 → 完成交割 | 财务审批；已配置财务人员任意一人通过 |

“老板”是业务概念，界面显示为“董事长/总裁”。普通老板审批节点聚合项目治理中的 `chairman` 与 `president` 职责并采用或签。投决不使用聚合节点，而是保留董事长、总裁两个独立串行节点。

## 投资项目组权限

投资项目组以项目成员关系为准，包含项目负责人。以下操作由任意启用的项目组成员执行：

- 从立项进入尽调计划制定；
- 新建、编辑并完成尽调计划；
- 将完整计划提交至尽调计划审核。

非项目组成员不得执行上述操作。系统管理员保留现有管理能力，但不能用管理员身份绕过材料、日期、行动负责人和交付物完整性校验。

## 审批节点与数据流

审批发起时，根据项目当前治理职责生成审批快照：

1. 普通老板节点合并董事长和总裁的有效账号，节点模式为或签。
2. 内核生成财务、法务、老板三个节点，按顺序逐个开放。
3. 投决生成董事长、总裁两个独立节点，按顺序逐个开放。
4. 打款只生成财务节点。
5. 每个节点完成后关闭该节点其余人员的待办，再为下一节点创建待办。

已经发起的审批继续使用原有审批快照，不在进行中改写节点。新规则用于新发起的审批；退回补充后重新提交时重新解析当前有效职责人员并生成新快照。

## 配置和资格校验

- 普通老板审批至少需要一名启用且资格有效的董事长或总裁。
- 投决必须同时存在启用且资格有效的董事长和总裁；缺少任一职责时禁止发起，并明确指出缺岗。
- 内核必须配置至少一名财务、至少一名法务，以及至少一名董事长或总裁。
- 打款必须配置至少一名财务。
- 同一职责配置多人时采用或签，任意一人通过即可完成该职责节点。
- 申请人不能审批自己。若排除申请人后某节点没有其他有效审批人，禁止发起并提示调整发起人或职责配置。

## 界面调整

- 项目流程页的审批链说明与真实规则保持一致。
- 发起审批前展示串行节点顺序、各节点审批人及或签/必签含义。
- 普通领导节点统一显示“董事长/总裁审批”。
- 投决明确显示“董事长审批 → 总裁审批（两人均需通过）”。
- 尽调计划区域向全部投资项目组成员开放编辑和提交入口，并在无权限时说明原因。

## 拒绝、退回和并发

- 任一节点拒绝时，整条申请按现有规则结束，不继续后续节点。
- 任一节点退回时，由发起人或有权的项目组成员补充后重新提交。
- 或签节点首位有效审批人通过后节点完成；后续重复审批请求返回明确的状态冲突。
- 沿用现有项目版本、计划版本、材料快照和审批锁版本校验，防止并发覆盖。

## 兼容策略

- 保留八阶段名称和顺序，不迁移历史项目阶段。
- 保留历史审批请求、节点和记录，不重写已经发生的审批事实。
- 发布新的工作流策略版本，并将所有现有 FDE 投资项目的策略版本绑定切换到新版本；已发起审批继续使用其持久化的节点快照，不重算、不改写进行中的审批人员与顺序。
- 前端展示、默认策略契约、数据库策略版本、服务端节点解析和验收测试必须同步更新，避免配置与运行行为分叉。

## 验证范围

1. 普通老板节点配置两人时，任意一人通过即可进入下一阶段。
2. 投决必须董事长和总裁依次通过，任一人未通过时不得进入打款。
3. 内核严格按财务、法务、老板顺序流转，职责内多人任意一人通过。
4. 打款只要求财务审批。
5. 任意投资项目组成员可以制定和提交尽调计划，项目外人员被拒绝。
6. 缺少必要职责、审批人与申请人冲突、人员停用时均不能发起。
7. 已发起流程保持原审批快照，新流程使用新规则。
8. 审批链界面、待办生成与关闭、审批历史和项目阶段推进一致。
9. 相关契约测试、服务端流程测试、前端类型检查和生产构建通过。

## 非目标

- 不改变项目材料门禁与计划完整性标准。
- 不引入跨节点并行审批。
- 不删除或改写历史审批记录。
- 不调整非投资项目和旧版项目流程。
- 不在本次设计中实施此前暂停的“投资项目组创建界面”改造；本功能按现有项目成员数据识别投资项目组。
