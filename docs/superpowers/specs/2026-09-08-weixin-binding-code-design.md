# 微信绑定码与管理员审批设计

## 目标与范围

平台用户生成一次性绑定码，在微信机器人会话中发送“绑定 123456”后形成待审批申请。管理员批准后，微信身份才与平台用户建立有效绑定，并可使用文章收录、知识库和 AI 会话能力。

本次包含绑定码生成、微信提交、管理员审批、结果通知、旧绑定替换、审计和管理页面。不改变微信扫码连接机器人本身的流程，不允许绑定申请绕过现有业务角色和数据权限，也不允许未绑定微信用户自动映射到机器人管理员。

## 角色与权限

- 已登录且状态为“启用”的平台用户可以为自己生成绑定码、查看自己的最近申请和撤销尚未提交到微信的有效绑定码。
- “系统管理员”和“运营管理员”，或具备 `im.manage` 权限的账号，可以查看和处理绑定申请。
- 申请人不能替其他平台用户生成绑定码，管理员也不能通过审批改变申请绑定的平台用户。
- 审批只建立身份映射，不授予新的业务角色。知识库写入、项目访问和 AI 能力继续使用被绑定平台账号的现有权限。

## 用户流程

1. 用户登录平台，在个人设置的“微信机器人”区域点击“生成绑定码”。
2. 服务生成 6 位数字码，页面展示绑定码、10 分钟有效期和“在微信中发送：绑定 123456”的说明。
3. 用户给已经连接的平台微信机器人发送绑定命令。
4. 机器人验证绑定码，记录微信发送者身份和目标机器人，原子消费绑定码并创建一条 `pending` 审批申请，然后回复“绑定申请已提交，请等待管理员审批”。
5. 管理员进入“系统管理 → IM 机器人 → 绑定审批”，核对平台用户、部门、角色、微信身份掩码、机器人和申请时间，填写处理理由后批准或拒绝。
6. 批准时，在同一数据库事务中停用该微信身份以及该平台用户在该机器人下的旧有效绑定，再创建或启用唯一的新绑定，并将申请标记为 `approved`。
7. 拒绝时，将申请标记为 `rejected`，不改变任何现有绑定。
8. 审批事务完成后发送微信通知。通知失败只记录投递失败，不回滚已完成的审批；管理员页面显示通知状态并可重试通知。

## 数据模型

新增 `weixin_binding_codes`：

- `id`：UUID 主键。
- `user_id`：生成绑定码的平台用户。
- `code_hash`：绑定码加服务端 pepper 后的 SHA-256；数据库不保存明文码。
- `status`：`active`、`consumed`、`expired`、`revoked`。
- `expires_at`、`consumed_at`、`created_at`、`updated_at`。
- 同一用户最多一个 `active` 码；生成新码时原有 active 码改为 revoked。

新增 `weixin_binding_requests`：

- `id`：UUID 主键。
- `code_id`、`bot_id`、`user_id`。
- `external_user_id`：微信发送者稳定 ID。
- `external_conversation_id`：沿用现有 `${accountId}:${externalUserId}` 会话键。
- `context_token_ciphertext`：审批完成后通知用户所需的加密上下文；不通过列表接口返回。
- `status`：`pending`、`approved`、`rejected`。
- `reviewer_user_id`、`review_reason`、`reviewed_at`。
- `binding_id`：批准后生成的现有 `im_bot_bindings` 记录。
- `notification_status`：`pending`、`sent`、`failed`，以及 `notification_error`、`notified_at`。
- `created_at`、`updated_at`。

约束和索引保证一个绑定码只产生一条申请；同一机器人、微信身份仅有一条 pending 申请；审批使用行锁和状态条件更新实现并发幂等。表结构通过新的顺序迁移创建，应用启动不执行 DDL。

## 服务边界与接口

新增独立的绑定领域服务，负责生成、消费、审批和查询，不把规则继续堆入 `weixinMessageBridge.ts`。微信桥接层只识别严格格式 `^绑定\s*([0-9]{6})$`，把机器人、微信发送者和上下文交给领域服务。

用户接口：

- `POST /api/integrations/im/weixin/binding-codes`：生成新码，返回明文码和过期时间；明文只返回这一次。
- `GET /api/integrations/im/weixin/binding-self`：返回当前绑定、有效码元数据和最近申请，不返回码哈希或微信完整敏感标识。
- `DELETE /api/integrations/im/weixin/binding-codes/:id`：撤销自己的 active 码。

管理员接口：

- `GET /api/integrations/im/weixin/binding-requests?status=pending|resolved`：分页查询。
- `POST /api/integrations/im/weixin/binding-requests/:id/resolve`：提交 `approved|rejected`、理由和幂等键。
- `POST /api/integrations/im/weixin/binding-requests/:id/notification/retry`：审批结果已确定但通知失败时重试。

所有写接口沿用现有登录、CSRF、Origin、输入校验和审计机制。绑定码比较使用恒定时间比较；每个微信发送者和 IP 设置失败次数限制，连续错误只返回统一提示，避免枚举有效码。

## 页面设计

个人设置增加“微信机器人”卡片，展示当前绑定状态、生成绑定码按钮、倒计时和最近申请结果。刷新页面后不再显示绑定码明文，只能撤销并重新生成。

IM 机器人管理页面增加“绑定审批”标签和待审批数量。审批详情展示机器人、平台用户名、部门、有效业务角色、申请时间和脱敏微信身份；批准与拒绝都必须填写至少 2 个字的理由。提交期间锁定表单，网络结果不确定时保留相同幂等键重试。

## 状态与错误处理

- 无效、过期、已使用或已撤销的码统一回复“绑定码无效或已过期，请回到平台重新生成”。
- 同一微信身份重复提交同一申请，返回原待审批状态，不创建重复申请。
- 微信身份已有其他待审批申请时，提示先等待或由管理员处理原申请。
- 已绑定用户发送新的有效绑定码，可以申请换绑；只有审批通过才替换旧绑定。
- 平台用户被停用、机器人被停用或审批人失去权限时，审批失败且不改变绑定。
- 未绑定用户的普通消息、文章链接和文件只回复绑定指引，不创建管理员账号会话或写入业务数据。

## 审计与隐私

记录绑定码生成、撤销、消费，申请创建、批准、拒绝、旧绑定停用、新绑定建立以及通知结果。审计记录包含操作者、目标用户、机器人、申请 ID、结果和请求 ID，不保存明文绑定码、机器人凭据、完整上下文令牌或文章内容。

管理列表对微信身份做脱敏；仅领域服务可读取通知上下文密文。日志使用现有脱敏方法，任何错误均不得输出绑定码、机器人令牌或 context token。

## 测试与验收

- 合约测试：命令格式、6 位码、过期时间、状态流转和公共字段脱敏。
- 服务测试：生成新码撤销旧码、错误码、过期码、单次消费、跨用户盗用、重复提交和并发审批。
- 权限测试：普通用户只能操作自己；管理员和 `im.manage` 可审批；停用用户、纯系统管理账号审批后仍不获得业务权限。
- 绑定测试：批准后停用冲突旧绑定，拒绝不改绑定，重复审批幂等且不重复创建。
- 桥接测试：未绑定普通消息不再映射管理员；绑定命令创建申请；审批通知成功、失败和重试。
- 页面测试：生成码、倒计时、刷新不泄露明文、待审批列表、必填理由、结果不确定时原请求重试和权限隐藏。
- 回归测试：原微信文章收录、知识库权限、项目待复核、已有管理员绑定和机器人扫码连接继续有效。

验收标准是：一个启用的业务用户能够生成码并提交微信申请，管理员批准后该微信身份只绑定到该用户；审批前无法写入任何业务数据；三次重复消息或并发审批都只产生一个绑定和一个确定结果。
