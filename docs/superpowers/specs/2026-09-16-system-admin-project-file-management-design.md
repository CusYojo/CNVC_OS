# 系统管理员项目材料完整管理与上传状态修复设计

## 背景

系统管理员已经可以在尽调流程中自行提交并确认审批，但项目文件权限仍沿用业务成员规则。纯系统管理员上传材料时，服务端返回 `PROJECT_FILE_UPLOAD_FORBIDDEN`，文件没有保存、也没有进入解析流程。与此同时，上传结果区域使用固定的绿色成功样式，导致上传失败看起来与成功相同。

## 目标

1. 所有启用状态的“系统管理员”角色账号，对项目中心全部项目拥有项目材料的完整管理权限。
2. 系统管理员可上传、查看、下载、绑定、替换和删除项目材料，不受项目成员关系及项目生命周期限制。
3. 该权限只扩展项目文件与材料操作，不自动授予项目业务职责或普通审批职责。
4. 上传界面准确区分成功、解析异常、部分失败和完全失败，不再用绿色表示失败。

## 权限设计

### 身份判定

权限例外只对当前处于启用状态、且具有 `system_admin` 分类角色的用户生效。停用账号或已移除系统管理员角色的账号立即失去例外权限。

### 文件域权限

系统管理员在所有项目上可执行：

- 打开文件工作区并查看文件清单；
- 上传项目材料；
- 查看和下载文件；
- 将文件绑定到流程材料槽位；
- 替换材料文件；
- 删除项目文件。

该权限覆盖进行中、已关闭和已归档项目。既有审计记录、上传者信息和文件版本规则保持不变。

### 非文件域边界

完整文件管理权限不改变项目成员、项目负责人、投资项目组成员或任何审批职责的判定。系统管理员的自确认审批仍只走已经实现的专用管理员确认流程，不能借由文件权限代替老板、财务、法务等业务审批人。

## 后端结构

在项目文件访问服务中增加单一、可复用的“启用系统管理员”权限谓词，并由文件工作区和单文件访问判断共同使用：

- 工作区查询和上传权限允许启用系统管理员访问任意项目；
- 单文件的 `view`、`download`、`manage`、`delete` 均允许启用系统管理员；
- 材料绑定继续复用单文件访问校验，因此自然获得管理员权限；
- 普通用户继续执行现有项目范围、业务角色和生命周期限制。

不得把系统管理员加入通用 `businessRole` 判定，以免权限扩散到非文件业务操作。

## 前端上传结果模型

把当前的字符串摘要改为结构化结果，至少包含：文件名、结果类型、用户可读信息。结果类型包括：

- `success`：上传成功并进入正常处理，绿色；
- `parse_warning`：文件已保存，但内容解析失败或异常，橙色；
- `duplicate`：重复文件未重新上传，信息色；
- `error`：上传请求失败或文件未保存，红色，并显示服务端可用的错误信息。

批次汇总规则：

- 全部成功：绿色，标题“上传成功”；
- 至少一个失败或解析异常、同时存在成功：橙色，标题“部分文件处理异常”；
- 全部失败：红色，标题“上传失败”；
- 仅重复文件：信息色，标题“未上传新文件”。

失败批次不得再显示“已完成上传”或绿色容器。Toast 与弹窗内结果使用同一汇总函数，避免两套状态判断再次分叉。

## 错误处理

- 403 等上传请求错误归为 `error`，文件未保存，不得描述为解析失败。
- 上传成功后服务端明确返回解析失败时归为 `parse_warning`，说明“文件已保存，内容解析失败”。
- 无法安全展示服务端细节时使用稳定的中文兜底信息，同时保留已有日志记录。
- 单个文件失败不阻断同批次其他文件上传，最终按批次结果汇总。

## 测试与验收

后端测试覆盖：

- 启用系统管理员可在非成员项目及非活动项目中上传、查看、下载、管理和删除文件；
- 系统管理员可将文件绑定到流程材料；
- 停用管理员及普通非成员仍被拒绝；
- 文件权限扩展不改变业务审批职责。

前端测试覆盖：

- 全成功为绿色；
- 全失败为红色且展示真实原因；
- 成功与失败混合为橙色；
- 文件已保存但解析失败为橙色；
- 仅重复文件为信息色；
- Toast 和弹窗汇总结果一致。

验收时使用系统管理员在一个非成员项目上传材料，并确认文件可见、可下载、可绑定和可删除；再模拟上传失败及解析失败，核对颜色、标题和文案。

## 不在本次范围

- 调整老板、财务、法务等业务审批流；
- 自动把系统管理员加入项目成员；
- 修改文件解析器本身的解析能力；
- 改变非管理员用户的文件权限。
