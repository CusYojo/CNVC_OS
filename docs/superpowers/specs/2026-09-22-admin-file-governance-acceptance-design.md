# 系统管理员项目文件治理验收契约设计

## 背景

系统已经按批准需求允许启用的系统管理员管理项目文件，但 `fdeGovernanceAcceptance.ts` 仍断言系统管理员不能看到项目文件，导致完整 FDE 验收在主流程通过后失败。该断言与当前业务规则冲突。

## 目标

更新治理验收契约，使其准确表达当前权限边界：

- 启用的系统管理员可以查看项目文件。
- 文件访问权不自动授予项目业务访问权。
- 系统管理员仍不能仅凭系统管理角色查看该项目的项目列表项、会议、任务、风险或审批记录。
- 普通非项目成员不能获得项目文件权限。

## 方案

修改两个验收脚本中与系统管理员项目文件访问有关的旧断言：

- 在 `server/src/scripts/fdeGovernanceAcceptance.ts` 中，将“管理员文件列表不包含该项目文件”改为“管理员文件列表包含该项目文件”。
- 保留同一区块中项目、会议、任务、风险隔离断言。
- 保留后续 OA 审批隔离断言。
- 增加普通非成员不能看到该项目文件的断言，证明放宽仅针对启用的系统管理员，而不是所有账号。
- 更新 checks 名称，明确这是“管理员文件域例外，其他 FDE 业务域仍隔离”。
- 在 `server/src/scripts/fdeFileAcceptance.ts` 中，将管理员从统一拒绝访问名单中移出并增加允许访问断言；时间协调人和普通非成员仍必须被拒绝。
- 在 `server/src/scripts/fdeOfficeAcceptance.ts` 中，仅将创建关联项目的合成 `author` 账号部门设为 `投资部`，使办公验收夹具满足当前项目负责人资格；其他合成账号继续使用随机隔离部门。

不修改生产权限实现、数据库结构、API 或前端行为。

## 数据流与权限边界

```text
系统管理员
  └─ listAllFiles → 可见项目文件
  ├─ listProjects → 不因文件权限获得项目列表访问
  ├─ listMeetings → 不可见
  ├─ listTodos → 不可见
  ├─ listRisks → 不可见
  └─ listOaApprovalRequests → 不可见

普通非项目成员
  └─ listAllFiles → 不可见项目文件
```

## 验证

1. 使用 Node.js 22 运行管理员专项权限测试。
2. 在专用隔离库 `sbl_jedi_acceptance_20260828` 中运行 `fdeMigrationAcceptance.ts`。
3. 确认完整 FDE 验收退出码为 0。
4. 确认随机前缀临时表和临时文件已清理，业务前缀未修改。
5. 确认 Git 工作区只包含预期验收契约变更。

## 非目标

- 不授予系统管理员完整项目成员权限。
- 不改变管理员自审批、投资基金维护或尽调计划权限。
- 不修改生产数据库数据。
- 不处理本次范围外的 Windows/Linux 测试兼容问题。
- 不放宽项目负责人必须属于投资部的生产规则。
