# 投资项目投后阶段设计

## 目标

在 FDE 投资项目的打款后增加持续的“投后”阶段。项目进入投后后继续保留在项目栏目，并提供投后文件、投后说明和向项目领导发送站内提醒的能力。

## 流程与项目状态

FDE 流程调整为：入库 → 立项 → 尽调计划制定 → 尽调计划审核 → 尽调 → 内核 → 投决 → 打款 → 投后。

打款仍由财务审批。打款审批通过后，项目阶段更新为“投后”，生命周期保持 `active`，不再设置为 `已 Close` 或从项目列表过滤。投后是持续管理阶段，不配置自动结束流转。

测试库中现有 FDE 投资项目如阶段为 `已 Close`，迁移为“投后”；既有审批单、文件与操作记录保留。

## 投后页面

项目详情在“投后”阶段展示 B 双栏布局：

- 左侧为投后文件区，沿用项目文件存储与权限模型，支持上传并显示文件列表。
- 右侧为投后情况更新区，支持反复新增说明。每条记录保存正文、创建人、创建时间和可关联的文件。
- 最新说明置顶，历史说明按时间倒序保留，不能由普通用户改写他人已保存的记录。

## 领导提醒

保存投后说明时，填写人可选择董事长、总裁中的一人或两人作为接收人。系统写入项目消息/通知与待办记录，内容关联项目和该条投后说明；不调用外部即时通信渠道。无可用接收人时禁止发送提醒，但说明可以不带提醒单独保存。

## 权限和数据

项目成员可上传投后文件和新增投后说明；领导本人和有项目访问权限的人员可查看。提醒接收人必须是该项目治理配置中的董事长或总裁；缺少治理绑定时，不回退通知其他角色。

新建投后说明表，与项目、创建人及可选关联文件关联。提醒复用现有通知/待办基础设施，避免复制一套消息中心。

## 验收

- 财务批准打款后，项目阶段成为“投后”，且仍出现在项目栏目与流程页面。
- 投后阶段页面同时显示文件区和说明区。
- 项目成员可保存多条投后说明并上传文件。
- 选择董事长/总裁后，接收人获得关联项目的站内通知和待办。
- 已关闭 FDE 项目迁移为投后，且现有审批与文件不丢失。
- 非项目成员不能新增投后更新；未配置目标领导时不能发送提醒。
