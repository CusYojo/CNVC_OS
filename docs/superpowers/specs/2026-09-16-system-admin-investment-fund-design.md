# 系统管理员投资基金维护设计

## 背景

项目详情的编辑弹窗允许输入“投资基金（内核必填）”，但 FDE 项目保存接口把投资基金与项目要求统一限制为仅项目负责人修改。系统管理员在跨项目闭环测试中可以维护材料、配置尽调计划并走专用确认审批，却无法补齐内核前必填的投资基金。

## 目标

1. 所有启用的系统管理员可以修改任意活动 FDE 项目的投资基金。
2. 系统管理员不因此获得项目要求的负责人专属修改权。
3. 审批进行中继续冻结投资基金和项目要求，避免审批证据在处理中变化。
4. 保留版本冲突校验和审计记录。

## 权限规则

### 投资基金

以下账号可修改：

- 项目负责人；
- 启用的系统管理员，包括账号主角色为“系统管理员”或拥有启用的 `system_admin` 分类角色。

项目必须处于现有接口允许编辑的状态。存在审批中实例时，任何账号都不能修改投资基金。

### 项目要求

仍然只有项目负责人可以修改。系统管理员若不是负责人，提交包含实际项目要求变更的请求时继续返回 `FDE_OWNER_REQUIRED`。

### 其他字段

名称、行业、融资轮次等字段沿用现有编辑规则，本次不扩大或收紧。

## 后端设计

`projectService.updateProject` 将目前合并的判断拆成两个独立变更标志：

- `investmentFundChanged`；
- `requirementsChanged`。

使用已经统一的 `isEnabledSystemAdmin` 判定管理员身份：

- `requirementsChanged && 非负责人`：拒绝；
- `investmentFundChanged && 非负责人 && 非启用系统管理员`：拒绝；
- 任一受控字段变化且存在审批中实例：拒绝。

不得通过请求中携带未变化的字段触发误拒绝；判断以新值与锁定行当前值是否真正不同为准。

## 前端设计

继续使用现有路径：

```text
项目详情 → 项目概况 → 编辑项目 → 投资基金（内核必填）
```

无需新增弹窗或成员关系。保存成功后刷新项目数据并关闭编辑弹窗；保存失败继续显示后端具体原因。

## 审计

沿用“项目管理 / 编辑项目”审计，并在投资基金发生变化时将目标摘要补充为投资基金变更，记录项目、原值和新值。审计不得记录凭据或无关敏感信息。

## 测试与验收

测试覆盖：

- 主角色系统管理员可修改非本人项目的投资基金；
- `system_admin` 分类角色账号可修改；
- 停用管理员与普通非负责人被拒绝；
- 系统管理员不能修改项目要求；
- 项目负责人仍可修改两者；
- 审批中时系统管理员和负责人都不能修改投资基金；
- 携带与当前值相同的项目要求不会阻止管理员修改投资基金；
- 版本冲突仍被拒绝；
- 投资基金变更写入审计。

浏览器验收使用当前系统管理员和测试项目：保持项目负责人“余勤”不变，从“编辑项目”填写投资基金并保存；刷新后基金值保留，内核阶段的“明确投资基金”门禁变为通过。

## 不在本次范围

- 系统管理员修改项目要求；
- 自动调整项目负责人或成员；
- 审批中热修改投资基金；
- 新增基金字典、基金选择器或基金主数据管理。
