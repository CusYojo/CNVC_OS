# 生命周期节点材料批量上传结果分类设计

## 背景与问题

用户从“项目中心 → 项目详情 → 项目生命周期节点”上传阶段材料时，前端复用项目详情页的批量上传弹窗。当前弹窗虽然已经有“成功入库、已存在、解析失败、失败”四种计数，但重复识别只覆盖后端错误码 `DUPLICATE`。

当上传文件与项目资料库内已有文件内容相同、但文件名不同时，后端返回 `DUPLICATE_CONTENT`。前端没有把该错误归入重复资料，最终把它计为失败，导致类似“上传 100 个，50 个重复”被展示为“成功 50、失败 50”。这会把正常去重误报成系统故障。

## 目标

批量上传完成后，把每个文件准确归入以下四类，并分别解释：

1. 成功入库：上传接口成功接收文件并开始或完成解析。
2. 资料已存在：后端返回 `DUPLICATE` 或 `DUPLICATE_CONTENT`，本次没有重复入库。
3. 解析失败：文件已经上传，但正文提取、OCR、分块或知识库写入失败。
4. 上传失败：文件读取、网络传输、权限、格式或服务端校验失败，文件没有成功进入解析链路。

重复资料不是失败，不使用错误数量或错误文案表达。

## 范围

本次修改覆盖项目详情页上传弹窗。生命周期工作台通过 `FdeWorkflowPanel` 的 `onUpload` 打开同一个弹窗，因此修改会同时作用于生命周期节点的材料上传入口和项目文件页的上传入口。

不修改：

- 后端去重规则和数据库唯一性规则。
- 项目知识库文件状态模型。
- AI 助手聊天附件上传。
- 材料送审时选择已有项目文件的流程。

## 结果模型

单文件上传函数返回带详情的判别联合类型：

- `success`：包含当前上传文件名。
- `duplicate`：包含当前上传文件名，以及后端能够提供时的已存在文件名和错误说明。
- `parse_failed`：包含文件名和解析错误说明。
- `upload_failed`：包含文件名和上传错误说明。

批量处理器按结果类型分组，不再只累计数字。每一组同时保存数量和文件级详情，供汇总和展开列表使用。

## 错误归类规则

| 条件 | 分类 | 用户文案示例 |
| --- | --- | --- |
| 上传接口正常返回，解析状态不是失败 | 成功入库 | `商业计划书.pdf 已成功入库` |
| `ApiError.code === 'DUPLICATE'` | 资料已存在 | `商业计划书.pdf 已存在` |
| `ApiError.code === 'DUPLICATE_CONTENT'` | 资料已存在 | `新版BP.pdf 与“商业计划书.pdf”内容相同，已跳过` |
| 上传接口正常返回，但返回解析失败状态或解析错误 | 解析失败 | `财务底稿.xlsx 解析失败：工作表损坏` |
| 文件读取、超时、网络、权限、格式或其他接口错误 | 上传失败 | `访谈录音.wav 上传失败：文件格式不支持` |

错误说明必须使用现有 `ApiError.message` 或安全的本地错误文本，不展示堆栈、路径、请求凭据或服务端内部信息。

## 界面设计

上传完成后，弹窗保留在当前页面并展示一张结果卡片。

卡片顶部为本批摘要，例如：

`本批 100 个：成功入库 50，资料已存在 45，解析失败 3，上传失败 2`

数量为 0 的类别不出现在摘要中。

卡片下方按以下顺序展示非空分组：

1. 成功入库：绿色。
2. 资料已存在：琥珀色或中性色，明确标记“已跳过，未重复入库”。
3. 解析失败：红色。
4. 上传失败：红色。

每组默认显示前三个文件。超过三个时显示“展开全部 N 个”，展开后显示完整文件列表，并可再次收起。文件名允许换行和断词，避免长文件名撑破弹窗。

Toast 只提供简短总览：

- 没有失败，仅有成功或重复：成功或信息提示，不使用红色。
- 存在解析失败或上传失败：错误提示，并引导在弹窗内查看明细。
- 全部重复：信息提示“所选资料均已存在，本次未重复入库”。

## 数据流

1. 用户在生命周期节点点击上传材料，打开项目详情页共用上传弹窗。
2. 前端并行读取并上传各文件。
3. 每个上传请求将成功响应或 `ApiError` 映射为四类结果之一。
4. `Promise.allSettled` 仅负责隔离单文件异常；异常原因仍转换为带文件名和错误说明的 `upload_failed` 结果。
5. 批量处理器生成分类汇总并更新弹窗结果卡片。
6. 成功入库的文件继续同步到项目文件列表；重复和失败项不创建伪文件记录。

## 测试与验收

新增可独立测试的分类和汇总逻辑，至少覆盖：

1. `DUPLICATE` 被归入资料已存在。
2. `DUPLICATE_CONTENT` 被归入资料已存在，而不是上传失败。
3. 异名同内容时保留当前文件名和后端返回的已存在文件名。
4. 文件已上传但解析失败时归入解析失败。
5. 网络、权限或格式错误归入上传失败。
6. 混合批次生成四类独立计数。
7. 全部重复时不出现“解析失败”或“上传失败”。
8. 默认只显示每组三个文件，展开后显示全部。
9. 生命周期节点和项目文件页仍打开同一个上传弹窗。

实现后运行相关单元测试、TypeScript 类型检查，并在真实页面用包含成功、同名重复、异名同内容重复和无效文件的混合小批次进行交互验收。
