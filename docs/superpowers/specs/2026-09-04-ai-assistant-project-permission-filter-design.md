# AI 助手项目权限过滤设计

## 背景与目标

AI 助手当前直接使用全局 Zustand `projects` 缓存作为项目选择器的数据源。该缓存由 `/projects?pageSize=100` 填充，虽然列表接口已有项目访问权限过滤，但没有限定项目分类和生命周期，并且最多只取 100 条，因此会混入项目池、关闭或归档项目，也可能遗漏用户有权访问的项目。

目标是让 AI 助手只允许当前登录用户选择其有权访问的、生命周期为 `active` 的普通项目和重点项目。该口径使用项目中心现有的项目访问规则，但不采用项目中心默认的 `scope=mine` 限制。

## 方案

新增一个面向 AI 助手的只读项目候选接口。服务端以当前登录用户为主体，复用 `projectAccessCondition`，并在同一条数据库查询中增加以下条件：

- `projects.lifecycle = 'active'`
- `projects.classification IN ('normal', 'key')`
- 当前用户满足既有项目访问规则

接口只返回选择器需要的稳定元数据，不返回项目正文、评分或其他敏感详情：

```ts
type AiAvailableProject = {
  id: string
  name: string
  classification: 'normal' | 'key'
}

type AiAvailableProjectsResponse = {
  list: AiAvailableProject[]
}
```

候选项目按置顶状态、更新时间和项目 ID 的既有稳定顺序返回。接口不依赖全局项目缓存，也不使用固定 100 条的页面截断。

## 数据流与权限边界

打开 AI 助手时，页面单独请求候选接口并维护加载结果。新建会话弹窗、项目切换选择器及默认项目解析统一使用该候选列表；全局 `projects` 仍用于项目中心等既有页面，不改变其行为。

创建项目会话时，服务端必须再次校验所提交的 `projectId`：项目存在、当前用户可访问、生命周期为 `active`，并且分类为 `normal` 或 `key`。校验失败时返回明确的 403 业务错误，不能仅依赖前端隐藏选项。已有会话的历史读取继续使用既有访问校验，避免因项目后来关闭或归档而无提示丢失历史会话；但不能再用该项目创建新的 AI 项目会话。

如果候选接口加载失败，项目选择器展示加载失败状态并禁止创建项目会话，不回退到未经限定的全局缓存。若候选列表为空，沿用“当前账号暂无可用项目”的提示。

## 代码边界

- 后端项目访问服务：增加“AI 可选项目”查询及单项目资格校验，复用现有访问条件。
- 后端路由：增加已登录用户专用的只读候选接口。
- 会话服务：创建项目会话时使用资格校验；全局会话不受影响。
- AI 助手页面：改用专用候选接口和精简候选类型，不再把全局 `projects` 作为选择器权威来源。
- 测试：覆盖权限隔离、分类与生命周期过滤、无固定 100 条截断、伪造 `projectId` 拒绝、空列表及加载失败行为。

## 验收标准

1. 普通用户只能看到其按项目中心权限规则可访问的活动普通项目和活动重点项目。
2. 系统管理员仍需遵守分类和生命周期限制，不能在 AI 助手中选择项目池、关闭、归档或已删除项目。
3. 用户无权访问的项目不会出现在接口响应或下拉框中。
4. 即使绕过前端直接提交无权或不符合分类/生命周期条件的项目 ID，也不能创建项目会话。
5. 有权项目数量超过 100 时，候选接口不会因现有全局缓存分页而静默漏项。
6. 项目中心、全局项目缓存及历史会话读取行为保持不变。

## 非目标

- 不修改项目中心的筛选器、默认 `scope=mine` 展示或项目权限模型。
- 不改变模型选择权限。
- 不迁移或删除已有 AI 会话。
- 不调整项目分类和生命周期业务流程。
