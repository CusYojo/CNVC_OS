# 系统管理员尽调计划闭环设计

## 背景

系统管理员已具备跨项目材料管理及专用自确认审批能力，但尽调计划编辑仍只允许项目负责人或投资项目组成员。当前项目负责人为其他用户时，管理员可以进入“尽调计划制定”阶段并尝试提交，却无法配置计划。页面同时错误显示“无需确认计划、无阻塞、可发起审批”，直到后端提交时才以缺少有效倒排计划拒绝，形成操作断点。

## 目标

1. 所有启用的系统管理员可在全部进行中投资项目中创建、生成、编辑和保存尽调倒排计划。
2. 管理员无需成为项目负责人或项目组成员，且不会因此写入或污染项目成员、职责记录。
3. “尽调计划制定”阶段没有完整有效的倒排计划时，前端立即显示阻塞并提供直达配置入口。
4. 前端提示与后端阶段门禁保持一致，不能再出现页面显示可提交、提交后才报缺少计划的情况。

## 权限边界

后台统一使用“启用系统管理员”判定：账号状态必须为启用，并满足账号主角色为“系统管理员”或拥有启用的 `system_admin` 分类角色。

该身份可执行：

- 在活动项目的“项目任务”页打开项目计划编辑器；
- 设置周期与最终日期；
- 生成倒排计划；
- 修改计划行动的名称、负责人、参与人、截止日期和交付物；
- 保存尚未进入审核的计划。

该权限不包含：

- 自动成为项目负责人或项目组成员；
- 以普通业务身份修改已审批锁定计划；
- 替代老板、财务、法务等正常业务审批职责；
- 编辑关闭或归档项目的计划。

管理员专用自确认审批规则保持不变。

## 后端设计

将系统管理员身份判定抽成可复用的项目业务权限谓词，供文件权限与尽调计划权限共同调用，避免两处管理员定义漂移。

`requirePlanEditor` 在确认账号启用后，按以下顺序授权：

1. 启用系统管理员；
2. 项目负责人；
3. 投资项目组成员；
4. 其他账号拒绝。

`getFdeWorkflow` 返回的 `capabilities.canEditPlan` 使用同一判定，因此前端按钮展示和保存接口不会分叉。已锁定计划仍遵循现有已审批计划修订规则；本次只解决“尽调计划制定”阶段的草稿创建和编辑。

阶段提交继续由后端 `evaluateFdeStageGate` 校验完整有效的倒排计划，不能仅依赖前端按钮。

## 前端设计

### 当前阶段门禁

当项目处于“尽调计划制定”时，也必须检查计划是否存在且完整有效。页面状态调整为：

- 没有计划：显示“尚未配置有效倒排计划”；
- 有草稿但不完整：显示“倒排计划尚未完整保存”；
- 有完整草稿：显示“计划已配置，可提交审核”；
- 已进入审核：显示现有审核状态。

未满足计划条件时：

- 隐藏或禁用“发起阶段审批”；
- 阻塞区显示“缺少有效倒排计划”；
- 提供“去配置计划”按钮，跳转至当前项目的 `?tab=tasks`；
- 顶部不再显示“无需确认计划、无阻塞、可发起审批”。

### 项目计划入口

系统管理员进入“项目任务”后，在“项目计划”卡片看到“配置计划”或“编辑计划”。新计划操作顺序为：设置最终日期、生成计划、检查行动信息、保存修订。

## 数据流

1. 项目详情加载 `/projects/:id/fde-workflow`。
2. 后端返回管理员可编辑能力及计划的真实状态。
3. 流程页根据当前阶段和计划状态计算阻塞项。
4. 用户点击“去配置计划”进入项目任务页。
5. 管理员生成并保存计划，后端使用管理员权限判定放行并执行既有计划校验。
6. 页面重新加载流程数据；有效计划通过前端就绪检查。
7. 提交审批时后端再次执行阶段门禁，形成双层保护。

## 错误处理

- 停用管理员与普通非成员保存计划时返回现有 403 权限错误。
- 计划缺少负责人、参与人、截止日期、交付物或日期顺序错误时，保留具体校验信息。
- 项目关闭、归档或已有活动审批时，继续按现有规则拒绝修改。
- 前端加载计划失败时不得推断为“无需计划”或“可发起审批”。

## 测试与验收

后端测试覆盖：

- 主角色为“系统管理员”的启用账号可编辑非本人、非成员项目的草稿计划；
- 拥有启用 `system_admin` 分类角色的账号同样可编辑；
- 停用管理员、普通非成员仍被拒绝；
- 管理员不能利用本权限绕过已锁定计划修订规则；
- 阶段提交仍拒绝不存在或无效的计划。

前端测试覆盖：

- “尽调计划制定”且无计划时显示阻塞，不显示“可发起审批”；
- 阻塞按钮跳转到 `?tab=tasks`；
- 管理员能力为真时显示“配置计划”；
- 有效计划保存后显示可提交状态；
- 加载失败不显示可提交状态。

浏览器验收使用当前系统管理员账号和截图中的测试项目：在不改变项目负责人“余勤”的前提下，进入“项目任务”配置并保存计划，返回“流程推进”后发起审批，确认不再出现缺少排期错误。

## 不在本次范围

- 修改项目负责人“余勤”或项目成员关系；
- 调整尽调计划模板的行动内容与周期算法；
- 扩大普通用户的计划编辑权限；
- 调整其他阶段的业务审批人规则。
