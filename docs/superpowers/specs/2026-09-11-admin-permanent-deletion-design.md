# 管理后台数据彻底删除功能设计

## 目标

在系统管理后台增加统一的“数据彻底删除”中心，仅允许启用状态的系统管理员永久删除以下对象：

1. 项目池中的线索项目；
2. 已立项的正式项目；
3. 公司知识库条目。

删除必须经过三次明确确认。删除成功后，目标业务对象及其从属数据不可恢复；系统只保留最小化的删除审计凭证。

## 入口与权限

入口位于系统管理页面，名称为“数据彻底删除”。普通用户、业务负责人及其他管理角色均不展示入口，也不能调用对应接口。

前端隐藏入口只用于减少误操作。后端接口必须使用现有 `requireSystemAdmin` 中间件，并在执行事务前再次确认当前账号仍处于启用状态且拥有系统管理权限。权限失效、会话过期或 CSRF 校验失败时不得执行任何删除。

## 对象查找与影响预览

管理员先选择对象类型，再按名称或 ID 搜索。搜索结果显示对象名称、ID、当前状态、创建时间和来源，避免同名对象被误选。

选中对象后，后端生成只读影响预览。预览至少包含：

- 将被删除的主对象；
- 关联评论、权限、版本、事件、任务、流程、事实、来源和微信入库记录的数量；
- 关联文件数量及存储状态；
- 受影响的转换关系，例如线索已经转换成正式项目；
- 阻止删除的条件。

影响预览返回一个短时有效、绑定管理员与目标对象的确认令牌。最终删除时重新计算影响范围，令牌过期或对象已变化时要求管理员重新预览。

## 三次确认

三次确认在同一个向导中依次完成，不能跳步，也不能由浏览器记住答案。

### 第一次确认

展示目标名称、对象类型和影响数量，并明确提示“删除后不可恢复”。管理员点击“我确认继续”。

### 第二次确认

管理员必须输入目标对象当前的完整名称。前后空白可以忽略，其他字符必须完全一致。名称不一致时不能进入下一步。

### 第三次确认

管理员必须逐字输入：

> 我已熟知删除项目的风险，我愿意承担责任。

该文本适用于线索项目、正式项目和知识库条目。后端执行精确匹配，不忽略标点，不接受同义表达。提交按钮使用“永久删除”字样，并在请求进行中禁止重复提交。

## 删除接口与幂等性

后台提供统一的预览接口和执行接口。执行请求包含对象类型、对象 ID、影响预览令牌、对象完整名称和风险确认文本。

后端按照以下顺序校验：

1. 身份、启用状态与系统管理员权限；
2. 请求结构、对象类型与对象存在性；
3. 影响预览令牌的管理员、对象、版本和有效期；
4. 输入名称与数据库当前名称完全一致；
5. 风险确认文本完全一致；
6. 当前影响范围与预览一致。

同一确认令牌只能成功使用一次。重复请求返回已完成结果或明确的已删除状态，不重复清理文件和数据。

## 数据清理边界

删除服务按对象类型维护显式清理清单，不能依赖未经核对的级联删除，也不能拼接动态表名。所有数据库操作使用 Drizzle 或参数化 SQL。

### 项目池线索

删除线索主记录，以及以该线索为所有者的事实、证据、来源文档、冲突、实体关系、补全任务、专题运行、评分任务、评分历史、投资画像、研究画像、管线记录和人工复核记录。

如果线索已转换为正式项目，默认阻止删除，并要求先删除对应正式项目或解除经业务确认的转换关系。系统不得通过删除线索连带删除正式项目。

### 正式项目

删除正式项目主记录，以及项目成员、职责、治理变更、计划、阶段日期、时间线、周计划、会议关联、风险、材料、档案、AI 任务引用、Agent 配置与运行记录等从属数据。

项目文件的数据库元数据在事务内清理。实际文件或 OSS 对象在数据库事务成功后进入可靠清理任务；清理失败必须记录并可由管理员重试，不能把已经删除的业务记录恢复为半成品。

与项目有关但同时属于公司级公共知识的条目不自动删除，只解除项目关联。专属于该项目且无其他引用的文件和记录才进入物理清理范围。

### 公司知识库

删除知识库主条目，以及访问授权、评论、评分、版本、命令和事件。解除微信入库记录中的知识条目关联，保留微信入库任务的最小状态用于幂等和故障追踪，不保留已删除知识正文。

知识条目引用的文件只有在没有项目、材料、档案、AI 任务或其他知识条目引用时才物理删除；仍被引用时只解除本条目的关系。

## 事务、文件与失败处理

每次只删除一个主对象。数据库清理在单个事务内完成，任一步失败则全部回滚。事务提交前不删除磁盘或 OSS 文件。

事务提交后创建并执行文件清理任务。文件清理任务按存储键幂等执行，成功、失败和重试次数可在后台查看。数据库删除成功但文件清理暂时失败时，界面显示“业务数据已删除，文件清理待重试”，不得把整个操作显示为未发生。

对象在确认期间被修改、归档、转换或增加引用时，执行接口返回冲突，要求重新生成影响预览。

## 审计

审计记录与被删除对象分离保存，业务清理事务不能删除它。审计仅保存：

- 操作管理员 ID 与显示名称；
- 对象类型、原对象 ID 与删除时名称；
- 删除时间；
- 影响数量摘要；
- 确认令牌摘要与请求 ID；
- 数据库删除结果和文件清理状态。

审计不保存文章正文、项目材料、文件内容、评论内容、模型输出或风险确认原文。风险确认是否通过以布尔值和固定确认版本记录。

## 前端状态

删除中心提供对象类型切换、搜索结果、影响预览和三步确认向导。危险操作统一使用红色视觉语义。

删除成功后关闭向导并刷新搜索结果。失败时停留在当前步骤，显示后端返回的可操作错误；权限失效时退出删除流程。输入名称或风险文本变化后，最终提交状态重新计算。

## 测试与验收

测试使用隔离测试库和临时文件目录，不连接或修改业务数据。

必须覆盖：

- 普通用户、非系统管理角色和停用管理员均被后端拒绝；
- 三个确认步骤不能跳过；
- 名称或风险文本不完全一致时零写入；
- 令牌过期、跨管理员使用、跨对象使用和对象变化时零写入；
- 三类对象的从属记录按清单删除，共享记录和共享文件保留；
- 正式项目转换关系阻止线索误删；
- 数据库中途失败时完整回滚；
- 文件只在事务提交后清理，失败可重试且不会重复删除；
- 重复请求幂等；
- 审计存在且不包含业务正文或确认原文；
- 删除成功后列表、详情页和直接 URL 均不再返回目标对象。

实现完成后运行相关服务端测试、前端交互测试、`npm run check:types`、补丁空白检查和生产构建。未经单独授权，不对业务库执行真实删除，不部署服务器。
