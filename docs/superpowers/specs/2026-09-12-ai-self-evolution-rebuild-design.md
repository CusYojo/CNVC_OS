# AI 自进化重建实施规格

## 背景与基线

本次在 `sbl_jedi` 的 `feat/ai-self-evolution` 分支重新实现 AI 自进化能力。产品与架构依据为 `ai-self-evolution-design.md` v0.2。工作区中的 `ai-evolution-isolated` 仅作为历史实现参考，不直接整体合并，避免引入过期耦合。

服务器可能保留旧版自进化表和数据。数据库处理采用非破坏式兼容迁移：先只读盘点实际结构和迁移历史，再补齐缺失表、字段、索引及约束。默认不删除表、不清空数据、不覆盖历史任务；无法安全自动兼容的结构差异必须停止并输出人工处置清单。

## 目标范围

按原设计 EVO-01～EVO-16 落地统一的经验、技能、代码进化框架，交付以下闭环：

1. 用户通过智能助手创建、修改并执行进化提案。
2. 服务端持久化提案、运行、事件、预算、租约和审计信息。
3. 受控执行器生成候选，平台独立评估并展示差异和证据。
4. 用户按权限批准、拒绝、发布或请求回退固定哈希的候选。
5. 经验与技能使用不可变版本和作用域指针；后续任务记录实际应用快照。
6. UI 提供聊天卡片、右侧自进化工作台以及窄屏抽屉，并支持刷新和断线补偿。

第一优先级是代码进化到隔离预览的真实闭环；经验、技能沿用统一契约随后接入。模型参数训练、自动扩大权限、自动执行正式数据库迁移和无人批准的生产发布不在范围内。

## 架构与组件边界

- 浏览器层：`src/components/ai-evolution/` 承担提案、任务、差异、评估和发布状态展示；`src/hooks/useAiEvolution.ts` 负责 API、事件增量同步与断线恢复；`AIAssistantPage.tsx` 只负责接线。
- 契约层：`server/src/contracts/aiEvolutionContract.ts` 定义浏览器可安全导入的类型、状态机和错误码，不导入数据库或文件系统模块。
- API 层：`server/src/routes/aiEvolution.ts` 沿用会话、CSRF、Origin、分页和幂等规则，身份和权限始终由服务端判定。
- 业务层：编排、权限策略、经验解析和评估拆分为独立服务；普通聊天 Runtime 只暴露窄工具，不获得 Shell、源码写入或发布权限。
- 持久层：MySQL 是权威数据源；repository 封装事务、乐观锁、租约、递增执行令牌和过期结果拒收。
- 执行层：每个代码任务使用授权仓库的固定 `baseCommit` 和隔离目录。执行器不能读取生产凭证、正式数据库、部署指针或无关宿主目录。
- 发布层：候选构建显式指定输出目录且绝不自动激活；正式发布由独立适配器消费已批准的固定候选。

## 数据与迁移策略

核心模型包括提案、运行、事件、审计、模型调用、候选、评估、批准、经验及版本、应用快照、技能及版本、发布任务、反馈与回退请求。

迁移按当前仓库的 Drizzle journal 顺序追加，不重写已发布迁移。实施前新增只读兼容审计，比较服务器实际表与期望结构，并将结果分为：完全兼容、可增量修复、需要人工处置。迁移脚本需满足幂等或可明确识别“已存在且一致”，且应用启动不能自动执行 DDL。

正式迁移前必须确认目标库和 `DB_FREFIX`、生成结构与数据备份证据、执行预览，并使用独立迁移账号。结构不一致、外键数据不完整或迁移历史冲突时禁止继续。回退以恢复版本指针和代码候选为主；数据库变更提供独立恢复方案，不能把代码回滚等同于数据回滚。

## 生命周期与安全

提案、执行和发布分别使用独立状态机。运行通过数据库租约、心跳、attempt 和 lease token 保证单一有效执行权；提交结果必须匹配任务、尝试、令牌和输入哈希。取消是持久化请求，只有执行器停止被确认后才进入已取消状态。

批准绑定候选哈希、评估哈希、范围、环境和有效期。候选内容、评估结果或合并基线变化后批准自动失效。权限分离为对象访问、个人经验、共享经验、技能发布、仓库开发、目标环境发布和数据库迁移，不因管理员身份自动叠加。

附件、网页、聊天引用和候选代码均作为不可信输入；其中的命令不能提升权限或修改平台门禁。固定验收文件不在执行器可写范围内。

## 错误处理与可观察性

API 明确区分权限不足、版本冲突、幂等冲突、预算不足、环境不可用、验收失败和信息缺失。事件采用单调序列，客户端可按 `afterSequence` 补拉并去重。

任务记录阶段、预算、模型实际或未知用量、检查点、错误摘要和审计。日志与页面输出脱敏；清理任务只处理有明确任务归属的预览、缓存和产物目录。

## 验证策略

实现按 EVO 任务分批提交，每批先运行针对性测试，再运行 `npm run check:types` 和适用的平台门禁。数据库测试仅使用明确隔离的测试库，不对业务库启用写入验收开关。

最终逐项执行原设计 AT-01～AT-18，并使用 PASS、FAIL、BLOCKED、NOT_RUN、SKIPPED 记录证据。重点包含：跨用户隔离、恶意附件、候选构建不激活、验收不可篡改、租约恢复和旧结果拒收、取消与预算、经验双入口快照、技能新旧对比、批准失效、发布回退、刷新断网及窄屏交互。

源码完成、测试通过、本地生效、服务器迁移和生产发布分别报告，任何一项不以另一项替代。

## 实施顺序

1. 盘点当前分支、历史实现和服务器残留结构，冻结首批验收样本。
2. 建立契约、权限矩阵、schema、迁移及非破坏兼容审计。
3. 实现提案 API、助手工具、任务租约、取消与恢复。
4. 实现代码隔离执行、纯候选构建、预览和独立评估。
5. 实现工作台、聊天卡片、候选审阅、批准和拒绝。
6. 接入经验版本、解析快照、反馈与停用。
7. 接入技能候选、对比评测、作用域发布与回退。
8. 实现发布任务、成本配额、保留清理、效果观察和故障演练。
9. 在获得明确部署授权后执行服务器只读审计、备份、迁移预览、迁移、构建发布和在线验收。
