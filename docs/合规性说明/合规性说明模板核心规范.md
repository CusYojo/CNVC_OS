# 合规性说明模板核心规范

## 1. 适用范围

本规范用于根据项目资料、基金资料和用户输入生成“项目投资合规性说明”。生成结果应同时满足：

- 文档格式与合规性说明模板一致。
- 章节名称、顺序和层级固定。
- 每个章节只表达其承担的内容。
- 所有事实、测算和判断均可追溯。
- Microsoft Word 与 WPS 可直接打开且显示一致。

## 2. 文档格式

### 2.1 页面设置

| 项目 | 固定规则 |
| --- | --- |
| 纸张 | A4，21.00 cm × 29.70 cm |
| 方向 | 纵向 |
| 上边距 | 2.54 cm |
| 下边距 | 2.54 cm |
| 左边距 | 3.175 cm |
| 右边距 | 3.175 cm |
| 页眉距边界 | 约 1.50 cm |
| 页脚距边界 | 约 1.75 cm |
| 分节 | 全文一个节 |
| 分栏 | 单栏 |
| 页眉页脚 | 无可见内容，不显示页码 |

页数根据内容自然形成，不通过缩小字号、压缩行距或插入无意义分页符控制页数。

### 2.2 字体与字号

| 文本角色 | 字体 | 字号 | 字形 |
| --- | --- | --- | --- |
| 文档标题 | 黑体 | 四号，14 pt | 常规 |
| 一级标题 | 宋体 | 小四，12 pt | 加粗 |
| 二级标题 | 宋体 | 小四，12 pt | 加粗 |
| 正文 | 宋体 | 小四，12 pt | 常规 |
| 投资理由正文 | 宋体 | 小四，12 pt | 常规 |
| 合规核查正文 | 宋体 | 小四，12 pt | 常规 |
| 综合结论 | 宋体 | 小四，12 pt | 常规 |
| 落款和日期 | 宋体 | 小四，12 pt | 常规 |

全文使用黑色或“自动（黑色）”，不使用斜体、下划线、彩色字、底纹、艺术字或文本框。英文和数字随所在段落使用宋体，不单独切换字体。

### 2.3 行距与段落间距

- 全文统一使用 1.5 倍行距。
- 文档标题段前、段后均为 0 pt。
- 一级标题段前 12 pt、段后 0 pt。
- 公司介绍和投资计划正文段前、段后均为 0 pt。
- 投资理由和投资情形分析正文段前、段后均为 0 pt。
- 综合结论、落款单位和日期段前 12 pt、段后 0 pt。

所有参数必须显式写入文档，不依赖 Word 或 WPS 的默认样式。

### 2.4 对齐与缩进

#### 文档标题

- 居中对齐。
- 无首行缩进。
- 独占一段。
- 标准形式：`关于{项目简称}项目投资合规性的说明`。

#### 一级标题

- 左对齐。
- 使用中文自动编号：`一、`、`二、`、`三、`、`四、`。
- 编号和标题位于同一段。
- 显式清除段落的字符首行缩进，禁止继承 `List Paragraph` 或其他列表样式的首行缩进。
- 编号级缩进为左侧 720 DXA、悬挂 720 DXA，使编号从正文左边界开始。

#### 二级标题

- 左对齐。
- 使用全角括号自动编号：`（1）`、`（2）`、`（3）`。
- 不得写成半角 `(1)`。
- 标题文字加粗。
- 段落级显式设置左缩进 0 DXA、首行缩进 482 DXA；不得仅依赖编号或列表样式的默认缩进。
- 编号级缩进为左侧 1140 DXA、悬挂 720 DXA。

#### 普通正文

- 两端对齐。
- 首行缩进约 0.85 cm，相当于小四号中文约两个字符。
- 每个逻辑单元独立成段。

#### 投资理由和合规核查正文

- 均使用连续正文段落，不设置阿拉伯数字小标题或条目编号。
- 两端对齐，首行缩进约 0.85 cm。
- 全段使用常规字形，不把判断句或核查主题单独加粗。
- 禁止以“学术团队：”“业务主体：”“投资方式及投资限制：”等短标签加冒号开头；应改写为完整主谓句或“……方面，……”的自然叙述。

#### 落款

- 管理人名称右对齐。
- 日期另起一段并右对齐。
- 日期形式：`YYYY年   M   月   D   日`。

### 2.5 编号规则

| 层级 | 显示形式 | 用途 |
| --- | --- | --- |
| 一级 | `一、` | 四个主体章节 |
| 二级 | `（1）` | 公司简介、核心团队、产品及技术 |

除一级、二级正式章节外，正文不使用自动编号或手写数字小标题。

### 2.6 分页规则

- 不使用表格、图片、图表或浮动对象承载正文。
- 一级标题应与其后第一段保留在同一页。
- 二级标题应与其后至少一段内容保留在同一页。
- 落款单位和日期不得拆分到不同页面。
- 不得出现孤立标题、异常空白页或仅剩少量文字的尾页。

## 3. 文档结构

### 3.1 固定结构树

```text
关于{项目简称}项目投资合规性的说明
├── 一、公司情况介绍
│   ├── （1）公司简介
│   ├── （2）核心团队
│   └── （3）产品及技术
├── 二、投资理由
│   └── 五段连续正文
├── 三、投资计划
├── 四、投资情形分析
│   └── 七段连续正文，依次覆盖七项核查
├── 综合结论
└── 落款与日期
```

### 3.2 章节逻辑

1. **公司情况介绍**回答标的公司是谁、谁在做、做什么。
2. **投资理由**回答为什么投资该项目。
3. **投资计划**回答怎么投、投多少、取得什么权益。
4. **投资情形分析**回答本次投资是否符合基金和监管要求。
5. **综合结论**汇总逐项核查结果并说明成立前提。
6. **落款与日期**标注文档出具主体和时间。

章节名称、顺序和七项合规核查不得调整、合并或删除。

## 4. 各结构的核心内容

### 4.1 文档标题

标准写法：

```text
关于{项目简称}项目投资合规性的说明
```

项目简称必须与投资决策材料一致。标题不添加文号、副标题、版本号或宣传性表述。

### 4.2 一、公司情况介绍

本章建立项目事实底座，不提前作投资合规判断。

#### （1）公司简介

依次表达：

1. 公司法定全称、成立时间和注册地。
2. 公司来源、股东背景或孵化背景。
3. 公司定位及所属行业。
4. 核心产品、服务对象和应用场景。
5. 商业模式及当前发展阶段。

内容应来自工商资料、公司介绍、商业计划书或尽调材料。不得使用无法核验的“唯一”“首创”“绝对领先”等宣传表述。

#### （2）核心团队

每位核心人员单独成段，表达：

1. 姓名和现任职务。
2. 教育及专业背景。
3. 与项目相关的重要任职、科研或创业经历。
4. 能证明其胜任当前岗位的能力。
5. 在公司中的职责分工。

仅保留与项目直接相关且可核验的经历，不将顾问、兼职人员表述为全职核心成员。

#### （3）产品及技术

依次表达：

1. 核心产品或平台定义。
2. 客户类型和应用场景。
3. 技术架构、关键模块及技术路线。
4. 数据、模型、算法、软件和硬件的协同方式。
5. 技术或产品差异化。
6. 当前验证阶段和商业化进展。

必须区分已经实现、正在验证和未来规划；不得将合作交流、PoC 或采购意向写成正式合同、交付或收入。

### 4.3 二、投资理由

投资理由固定使用五段连续正文。每段均完整表达核心判断、事实论证、投资价值影响和仍需验证的条件，但不显示数字小标题：

```text
{核心判断}。{事实依据}。{事实对投资价值的影响}。{仍需验证的条件，如有}。
```

五条理由应围绕项目最重要的投资价值展开，通常从以下信息中选择：

- 政策和行业趋势。
- 核心团队能力。
- 产品或技术差异化。
- 客户验证或产业生态。
- 商业模式、订单潜力和成长空间。

整段使用常规字形。理由必须有项目材料支撑，不重复堆砌公司介绍，不以“政策趋势：”“团队能力：”等标签开头。

### 4.4 三、投资计划

投资计划使用连续正文段落，核心内容包括：

1. 投前估值、投后估值和本轮融资总额。
2. 我方投资金额。
3. 增资、股权受让或其他投资方式。
4. 预计取得的持股比例及计算口径。
5. 投资实施主体和交易路径。
6. 主要交易条件、交割条件及最终文件依据。

关键数据必须相互校验：

- 投后估值与投前估值、本轮增资金额口径一致。
- 投资金额、持股比例和估值口径一致。
- 金额单位、股权口径和统计日期在全文一致。

涉及 SPV、共同投资、资金用途、保护条款或退出安排时，应根据已取得的交易材料如实写入，不使用预设条款补全缺失信息。

### 4.5 四、投资情形分析

本章固定包含七项核查。每一项均按以下逻辑写作：

```text
核查标准 → 项目及基金事实 → 计算或比对 → 单项结论
```

#### 投资方式及投资限制

核查本次交易是否属于基金允许的投资方式，是否涉及借贷、委托贷款、担保、房地产、二级市场交易或其他受限事项。

必需数据：

- 基金合伙协议中的投资方式和投资限制条款。
- 本次交易结构及法律性质。

#### 返投要求

核查本项目是否属于返投项目；如不属于，投资后基金是否仍有能力完成返投义务。

必需数据：

- 基金实缴规模及数据基准日。
- 返投目标和认定口径。
- 已完成返投金额。
- 已交割金额和剩余可投资金额。
- 返投储备项目。
- 本项目注册地、投资金额和返投属性。

金额和日期必须采用同一统计口径。缺少基金台账时不得自行推算。

#### 关联交易

核查标的公司、实际控制人、主要股东、核心团队和交易对手是否与基金、管理人、出资人或相关方存在关联关系。

必需数据：

- 最新股权结构和实际控制人信息。
- 关联关系核查表。
- 管理人、基金和重要出资人关联方清单。
- 共同投资人及其他交易对手信息。

#### 投资方向

核查项目主营业务、产品、技术和产业链位置是否符合基金合伙协议约定的投资领域。不得仅根据公司名称、行业标签或宣传材料作判断。

#### 投资配置

核查本次投资属于股权直投、基金份额、可转债或其他何种资产类型，是否符合基金配置要求。使用 SPV 时，应穿透说明投资实质。

#### 投资集中度

核查本项目投资金额或投资比例是否超过单一项目、行业或其他集中度限制。

必须列明：

- 适用的基金规模及计算口径。
- 集中度上限。
- 本项目投资金额。
- 需要合并计算的关联项目或追加投资。
- 投资后比例和比较结果。

不得仅写“未超过上限”而省略计算口径。

#### 其他法律法规、监管规定及基金要求

核查除前六项外是否存在其他明显违法违规、监管禁止或违反基金约定的情形，包括必要的主体资质、诉讼处罚、知识产权、数据合规和劳动用工事项。

未取得资料不等于未发现问题。存在资料缺口时，应写明待核验事项和完成条件。

### 4.6 综合结论

综合结论紧接七项核查之后，以“综上”开头，只汇总前文已经论证的结果。

标准表达：

```text
综上，在完成上述尽调核验、投资决策程序及交易文件约定的前提下，本项目投资方向、投资方式、投资配置、集中度及关联交易安排原则上符合基金合规性要求。
```

结论必须使用“在……前提下”“原则上符合”等审慎措辞，不使用“绝对合规”“不存在任何风险”等无条件表述。

### 4.7 落款与日期

落款由两行组成：

1. 基金管理人工商登记全称。
2. 文档正式出具日期。

不得使用项目公司名称、基金简称、撰写人员姓名或系统生成时间代替。

## 5. 数据与写作规则

### 5.1 信息状态

生成时必须区分：

1. **资料记载**：项目或基金材料中明确记载的事实。
2. **计算结果**：可由已有数据计算，并写明公式、口径和基准日。
3. **分析判断**：基于已知事实形成的判断，不表述为已审计事实。
4. **资料缺口**：现有材料不足以支持结论，明确待补材料和待核验事项。

以上状态只用于生成、引用和审计，不作为客户可见措辞。DOCX 正文不得自述“资料记载”“资料显示”“会议纪要记载”“项目档案显示”或检索过程。

### 5.2 禁止事项

- 编造公司、团队、客户、合同、订单、回款或基金台账。
- 将预测、意向、访谈或管理层口述写成已实现事实。
- 根据行业平均值推定项目具体数据。
- 将“未提供材料”改写为“未发现异常”。
- 引用不存在或无法定位的来源。
- 在结论中新增前文未核查的判断。

### 5.3 写作风格

- 使用正式、客观、审慎的书面语。
- 采用投资机构正式说明文件的叙述方式：先写主体、时间、动作、金额、比例和当前状态，再在同段末尾写必要判断。
- 公司、团队、产品和交易信息使用直接陈述句，不先加“价值判断”“线索总结”或口号式概括。
- 投资理由可以用一句简短判断开头，但判断必须紧接具体事实，不使用“具备初步判断依据”“已有商业化线索”“形成成长路径”等模型化套话。
- 审慎措辞只在确有不确定性时使用。优先写明尚待确认的具体事实、文件或计算口径，不在每段末尾机械重复“仍需核验”“最终结论取决于”。
- 每段围绕一个事实主题展开，通常使用 2 至 4 句；长句只承载同一逻辑链，不连续堆叠“能力、基础、路径、空间、支撑”等抽象名词。
- 使用“公司已……”“公司拟……”“本轮……”“截至……”“在……方面”等自然句式；不得编造引号式定位、概念标签或模型自行概括的商业术语。
- 同一章节中相邻段落不得使用完全相同的开头、转折和收尾模板。
- 避免宣传性、情绪化和绝对化表达。
- 同一名称、金额、比例、日期和统计口径在全文保持一致。
- 段落围绕一个逻辑中心，避免长句堆叠多个无关观点。
- 正文不得出现来源材料编号、数字小标题或“短标签：内容”式表达；将主题自然融入完整段落。
- 正文不得提及项目资料库、来源文件名、会议或访谈纪要、项目档案、证据状态和检索过程。应先归纳证据，再直接陈述项目事实、分析判断和具体核验条件。

以下表达视为叙述风格漂移，应在生成或复核阶段改写：

- “具备初步判断依据”“可形成初步投资判断”“已有商业化线索”；
- “具备一定交付组织基础”“客户验证已出现多场景线索”；
- “平台化……加场景化……”“组织收缩和商业化验证并行”；
- “支撑强度”“成长路径”“利润留存能力”等脱离具体事实的抽象概括；
- 三段以上连续使用“……方面，……”开头，或两段以上连续使用“最终结论取决于……”收尾。

## 6. 最终验收清单

### 格式

- A4 纵向及页边距正确。
- 标题为黑体四号，正文为宋体小四。
- 一级标题、二级标题均为宋体小四加粗，编号位置与正文左边界关系一致。
- 全文为 1.5 倍行距。
- 一级编号为中文数字，二级编号使用全角括号。
- 正文均采用连续段落和统一首行缩进，不使用数字小标题。
- 无乱码、缺字、方框字、异常空白页和编号重排。
- Word 与 WPS 均能直接打开，不触发修复或恢复提示。

### 结构

- 标题包含正确的项目简称。
- 四个一级章节名称和顺序正确。
- “公司情况介绍”包含三个固定二级结构。
- “投资理由”包含五段连续正文。
- “投资计划”覆盖估值、金额、方式、比例和交易路径。
- “投资情形分析”以七段连续正文完整覆盖七项核查。
- 综合结论为条件式结论。
- 落款包含管理人全称和正式日期。

### 内容

- 公司、团队、产品和技术信息可追溯。
- 投资理由均有事实依据。
- 估值、投资金额和持股比例相互一致。
- 返投分析包含基准日、基金台账和投资后测算。
- 关联关系覆盖标的公司、实控人、股东、团队和交易对手。
