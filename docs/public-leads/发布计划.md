# 公共线索池发布计划

> 正式依据：`docs/需求分析.md` V1.2。  
> 本文是辅助发布建议，不替代项目发布审批、正式项目需求或运维变更单。  
> 发布范围覆盖 POOL-001～POOL-014，并分别追踪 POOL-009 旧口径与新口径。
> 任务范围：LEAD-TASK-001～LEAD-TASK-036。
> SYS-001 将线索池数据抓取和数据质量列为 P0；发布资源优先保障对应单元，但 P0 不豁免来源、审核、安全、迁移和回滚门禁。

## 1. 发布原则

1. 数据模型先扩展、后切读、最后才考虑删除旧字段或接口。
2. 所有历史回填先 dry-run、再抽样、再分批、最后全量。
3. 新同步、标签、估值和列表目标上使用独立 feature flag；当前部分标签、估值和六列布局已直接进入相同页面/API 路径，尚未发现对应开关，发布前必须补齐或准备代码版本回滚。
4. 任何阶段都要能停止新增写入并回到旧读取路径。
5. 页面入口删除不等于后端能力可直接删除。
6. 不在发布操作中修改或输出现有 `.env` 密钥值。
7. 不把“代码已实现待验收”当成“已生产发布”。
8. 自动估值默认关闭；未通过来源、证据、审核和防臆测门禁时，不得向普通用户展示候选数值。

## 2. 当前部署风险

### 2.1 服务拓扑不完整

`docker-compose.yml` 只包含 PostgreSQL，实际运行还依赖：

- Node API。
- Vite/静态前端。
- Radar FastAPI。
- Flue。
- SearXNG。
- 外部 GSData、RSS、arXiv。
- cron/systemd。

发布前必须形成环境矩阵：

| 服务 | 开发地址 | 测试地址 | 生产地址 | 启动方式 | 健康检查 | 负责人 |
|---|---|---|---|---|---|---|
| Web | 待登记 | 待登记 | 待登记 | Vite/静态服务 | 页面与静态资源 | 待确认 |
| Node API | 默认 `127.0.0.1:3100` | 待登记 | 待登记 | systemd/容器 | `/api/health` | 待确认 |
| PostgreSQL | 默认 `5432` | 待登记 | 待登记 | Docker/托管 | `pg_isready` | 待确认 |
| Radar | 本地脚本默认 `9888` | 待登记 | 文档曾写 `8121` | uvicorn/systemd | `/api/health` | 待确认 |
| Flue | 文档存在 `3584/8790/8791` | 待登记 | 待登记 | 独立服务 | 待补 | 待确认 |
| SearXNG | 代码默认 `8888` | 待登记 | 待登记 | 独立服务 | 待补 | 待确认 |

### 2.2 配置与密钥

- 文档要求 `.env.example`，仓库当前没有该文件。
- 根目录没有统一 `.gitignore`。
- 工作区存在 `.env`、数据库 dump 和 Radar 凭据 JSON。
- Node 和脚本有默认内部密钥 fallback。
- 发布前需要密钥轮换、权限收敛和敏感文件清单；不得在日志、截图或文档中记录密钥值。

### 2.3 数据与任务

- Radar 原始候选是 JSONL，写入和回填需要备份与原子替换。
- Node 同步和评分任务目前为内存态。
- 现有 cron 与未来自动调度可能重复执行。
- `server/src/db/migrate.ts` 是启动时顺序 DDL，不是完整版本化迁移体系。
- `leads` 尚无稳定唯一键；直接加唯一约束前必须处理历史重复。

### 2.4 当前页面改造已无开关混入

- `src/pages/SourcingPage.tsx` 已直接使用行业/地区筛选、六列核心布局、估值、AI 技术评分和更新时间。
- `server/src/services/aiSummaryService.ts` 与 `server/src/routes/meta.ts` 已直接返回/接受对应临时 DTO 和筛选参数。
- 当前未发现标签式首页、估值列、新布局或核心字段的独立 feature flag；因此下文所述 flag 是发布目标，不是现成回滚能力。
- R6/R7 进入候选版本前必须二选一：补齐服务端可控开关并验证旧/新合同兼容，或准备并演练回退到不含该临时实现的代码版本。

| R0 工程与确定性缺陷 | 测试/类型基线、重复采集、主体 fallback、融资过滤 | 001、028～031 | 否 |
| R1 可观测与性能 | 同步 run、日志、统计和索引 | 002、005、008 | 是 |
| R2 Radar 增量 | cursor、JSONL Upsert | 003、004 | 可能 |
| R3 主库幂等 | 来源身份、事务合并、历史 | 009～011 | 是 |
| R4 任务可靠性 | 自动同步、评分任务 | 006～007 | 是 |
| R5 数据回填 | 来源、主体、标签、估值 | 012、016、020、024 | 是/数据 |
| R6 标签产品 | 标签入口、字典、线索/项目标签 | 013～018 | 是 |
| R7 页面/API 语义 | 渠道、估值、布局、名称、融资 DTO、核心信息；收口当前无开关临时实现 | 019、021～023、026～027 | 可选 |
| R8 能力退场 | 转专属接口兼容/废弃 | 025 | 可能 |
| R9 自动估值补全 | 来源合同、检索抽取、候选审核、首页状态、回填监控 | 032～036 | 是/数据 |

每个发布单元独立执行门禁；只要求该单元直接关联的项目需求和依赖已确认，不能用无关的标签、估值或布局待确认项阻塞 R0/R1 等单元。

| 发布单元 | 必需确认/依赖 | 迁移要求 | 单元 No-Go 条件 |
|---|---|---|---|
| R0 | 测试框架技术评审；POOL-009 新口径可暂用“旧/新口径”追踪 | 无业务迁移；历史疑似重复仅只读审计 | 一次采集仍重复；主体/融资正常样本回归失败 |
| R1 | 本单元涉及的 SLA、指标、告警和性能阈值 | 仅批准的 run/index 变更 | 任务不可恢复、查询明显退化 |
| R2 | Cursor 排序窗口、JSONL 更新与保留策略 | JSONL 备份、原子替换和恢复演练 | 漏数、乱序或源文件损坏 |
| R3 | 稳定来源键、主体键、字段冲突与历史范围 | 唯一约束前 dry-run；分批回填 | 误合并、冲突静默覆盖 |
| R4 | 调度器、队列/重试、并发和通知策略 | 仅批准的任务表/索引 | 双调度、重复消费、重启丢任务 |
| R5 | 本批次标签/主体/估值模型、准确率和回滚标准 | 每个数据域独立 dry-run/apply/verify/rollback | 无逆向数据、抽样不达标 |

| R7 | 本批次渠道、估值、布局、名称、融资和核心字段口径 | 纯 UI 无迁移；数据模型按依赖单元 | 原型未验收、值无来源、核心性能退化 |
| R8 | 转换能力范围、调用方审计和兼容窗口 | 默认不删列；contract 后置 | 仍有调用方却删除 API/字段 |
| R9 | 可信来源白名单、估值口径、自动展示阈值、审核角色、频率、成本和回填范围 | 候选/证据 expand；旧估值不自动晋升；回填分批可撤销 | 融资额被当估值、无来源数值、越权审核、来源违规、预算失控或回填不可逆 |

## 4. 发布前置条件

### 4.1 项目需求

以下确认项只在本次发布单元直接关联时适用：

- POOL-001 SLA、自动/手工同步和通知策略确认。
- POOL-002 主体唯一键、冲突优先级和历史范围确认。
- POOL-003～005 标签定义确认。
- POOL-006 渠道取消范围确认。
- POOL-007 估值口径确认。
- POOL-008/010 原型和字段优先级确认。
- POOL-009 新旧编号决议。
- POOL-009 新口径的历史回填、融资多轮和转换能力去留确认。
- POOL-011 正式行业/地区等字典、多选与组合规则、标签归并/退场及历史回填确认。
- POOL-012 首页路由、核心字段去留、AI 技术评分口径和目标原型确认。
- POOL-013 各来源 SLA、抓取频率、告警接收人和最大延迟确认。
- POOL-014 来源白名单、估值口径、自动展示阈值、审核角色、更新频率、成本和历史范围确认。

### 4.2 工程

- `npm run check`、公共池测试和生产构建通过。
- Node、Radar、Flue、SearXNG 健康检查明确。
- API 合同完成向后兼容评审。
- 数据库备份与恢复演练通过。
- 迁移在生产规模脱敏快照通过。
- feature flag、指标、告警和日志脱敏完成。
- 对已经直接混入 `/sourcing` 的标签、估值、技术评分、更新时间和六列布局，已补齐独立开关或完成代码版本回滚演练；不得假设开关已经存在。
- 无 P0/P1 未关闭缺陷。

### 4.3 运维

- 明确唯一调度器；发布窗口内暂停旧 cron 或新 worker，避免双跑。
- 明确 Radar JSONL 备份目录、保留期和恢复步骤。
- 明确数据库连接池、磁盘、CPU、告警和值班人。
- 明确外部服务限流、超时和故障联系人。
- 明确自动估值来源条款、白名单、访问频率、日预算、内容留存和紧急停用负责人。

## 5. 七阶段发布流程

### 阶段 0：冻结与备份

1. 记录版本、迁移版本、配置键清单和 feature flag。
2. 暂停会冲突的自动任务。
3. PostgreSQL 一致性备份。
4. 备份 Radar `data/*.jsonl` 和状态文件。
5. 导出 leads 数量、重复分布、标签/融资/主体关键指标。
6. 验证恢复介质可读取。

退出条件：备份完成、恢复命令经过非生产演练、变更窗口批准。

### 阶段 1：Schema Expand

1. 只新增表、列、索引和 nullable 合同。
2. 大表索引使用低锁策略。
3. 不删除 `risk_tags`、旧 JSONB、转换列和旧接口。
4. 部署后端对新字段的兼容读取，默认仍走旧路径。

退出条件：旧版本应用仍可运行；数据库错误率、锁等待和延迟正常。

### 阶段 2：双写与影子比对

1. 若本次发布单元已批准新的来源身份、同步 run、标签或融资事件模型，才对相应对象双写；未确认的数据模型不得进入本阶段。
2. 若包含 R9，只把自动估值结果写为候选/证据，不得覆盖人工值或直接成为正式展示值。
3. 页面仍读旧数据。
4. 仅对本次批准范围影子计算新匹配、估值或主体结果，不对用户展示。
5. 输出差异、冲突、低置信度、无公开信息、来源失效和成本报告。

退出条件：重复率、差异率和性能达到确认阈值。

### 阶段 3：Canary 同步

1. 只选 1～2 个来源启用 cursor 和 Upsert。
2. 限制每批大小与并发。
3. 观察 created/updated/unchanged/conflict/failed。
4. 验证服务重启后 cursor 和任务恢复。
5. 逐来源扩大，不一次全开。
6. 若包含 R9，检索来源数量、canary 线索、并发、日预算和观察周期必须使用已批准值；候选保持审核可见，默认不向普通用户展示。
7. 验证融资金额不被当作估值、同名主体不串线、非白名单来源被拒绝、无可靠证据不输出具体数值。

退出条件：连续多个周期无漏数、无错误合并、无任务堆积。

### 阶段 4：历史回填

1. 运行 dry-run。
2. 产品/数据抽样高、中、低置信度记录。
3. 先写来源身份和安全字段。
4. 只有纳入本发布单元且模型已批准的数据域才执行回填；主体、标签和估值分别独立批次，不混成一次迁移。
5. 每批记录 runId、checkpoint、checksum 和逆向数据。
6. 低置信度进入人工队列，不自动覆盖。
7. 自动估值历史补全只处理批准范围内缺失/过期且有稳定主体的线索；候选与正式值分离，预算或来源限流触发时可暂停。

退出条件：对账通过；业务签字；回滚样本验证通过。

### 阶段 5：读流量与前端灰度

1. 先为内部测试账号启用新 API/DTO。
2. 再灰度标签、估值、主体和列表布局。
3. POOL-006 按 Q-POOL-018～019 的确认范围处理；若仅取消 UI，底层来源继续保留；若扩大到底层语义，则执行批准的兼容和数据处置方案。
4. POOL-009 旧/新分别验收。
5. POOL-011 按批准行业/地区等业务维度灰度；POOL-012 按原型灰度估值、AI 技术评分和数据更新时间。
6. 自动估值先向审核角色开放；只有人工批准或达到正式确认的自动展示阈值后，才向对应灰度用户显示。
7. 监控前端错误、接口 p95、空值/待核验比例、候选审核、来源访问和用户操作。

退出条件：UAT 通过；关键指标无退化；支持人员确认。

### 阶段 6：全量、观察与收口

1. 全量打开 feature flag。
2. 观察至少一个完整数据更新周期。
3. 恢复或启用唯一调度。
4. 更新运维手册、接口文档、需求追踪和已知问题。
5. 对 POOL-013 至少观察一个批准的数据更新周期；对 POOL-014 同时观察来源成功率、候选准确率、审核积压、预算和错误自动展示。
6. 只有完成调用方审计和兼容窗口后，才安排 contract migration：
   - 废弃旧参数。
   - 停止旧字段双写。
   - 处理转换接口。
   - 删除确认无用的旧代码。

退出条件：生产验收完成；回滚窗口结束；遗留项进入独立任务。

## 6. 发布监控

### 6.1 数据时效

- 来源发布时间 → Radar 抓取。
- Radar 抓取 → 主库同步。
- 主库同步 → 页面可见。
- 入池 → AI 分析完成。
- 各阶段 SLA 达标率。

### 6.2 同步质量

- fetched、created、updated、unchanged。
- filtered、invalid、conflict、failed。
- cursor lag 和 backlog。
- 来源重复率和主库重复率。
- JSONL/数据库增长速度。

### 6.3 数据质量

- 公司主体待核验比例。
- 主体低置信度与人工驳回率。
- 融资字段覆盖率。
- 来源账号误作投资机构率。
- 标签未知值/低置信度率。
- 估值无法规范化率。
- 自动估值候选准确率、来源覆盖率、冲突率和“暂无公开估值”比例。
- 融资金额误作估值数、无来源数值数和错误自动展示数。
- 候选批准/驳回/过期数量、审核耗时和人工值覆盖拒绝数。

### 6.4 系统稳定性

- Node/Radar 5xx、超时和进程重启。
- PostgreSQL 连接、锁、慢查询和磁盘。
- Flue/SearXNG 成功率和耗时。
- 评分队列长度、最长等待、重试和死信。
- 前端白屏、ErrorBoundary、资源加载和 API 错误。
- 自动估值队列、来源限流、单候选成本、日预算、死信、补跑和 checkpoint。

## 7. 分层回滚

### 7.1 前端

- 若对应开关已经落地并验证，关闭标签式首页、估值列、新布局和核心字段 flag；在此之前回退到不含临时改造的已验证 Web 版本。
- 回到旧表格和旧 DTO。
- 前端回滚不得清除已写入的新数据。

### 7.2 API

- 切回旧查询/匹配 selector。
- 保持新响应字段可选，不突然改变旧字段语义。
- cursor 故障时回到有界全量扫描，并记录可能遗漏窗口。

### 7.3 Worker

- 停止自动同步和评分 worker。
- 保留手工同步。
- 将运行中任务标记 paused，而不是删除。
- 释放过期租约后再恢复。

### 7.4 数据库

- Expand 阶段通常不逆向删表/列。
- 错误数据通过 runId 和字段历史恢复。
- 唯一索引如导致异常，可在确认旧路径安全后移除。
- 大规模问题使用发布前备份恢复，并冻结写入。

### 7.5 Radar JSONL

- 停止 Radar 写入。
- 校验备份 checksum。
- 恢复指定版本文件。
- 清理临时文件并重新启动只读校验。
- 不在未备份情况下直接覆盖整个数据目录。

### 7.6 外部服务

- Flue/SearXNG 故障时停止新评分，线索保持“待分析”。
- 不因 AI 失败回滚原始线索。
- GSData/RSS/arXiv 故障按来源隔离，不阻断其他来源。
- 自动估值来源、检索或抽取异常时关闭 `valuation_enrichment` 开关并停止 worker；候选保持只读，既有人工/正式估值继续可用。
- 发现来源条款、版权、安全或错误数值风险时，按来源单独禁用并保留审计，不继续重试。

## 8. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 错误主体合并 | 高 | 稳定来源映射、低置信度隔离、人工锁、字段历史。 |
| 历史回填覆盖人工值 | 高 | dry-run、优先级矩阵、分批、runId、逆向数据。 |
| 新旧调度双跑 | 高 | 唯一调度责任、分布式锁、发布窗口暂停旧 cron。 |
| cursor 不稳定导致漏数 | 高 | 稳定排序、重放窗口、对账、全量校验。 |
| 大表迁移锁表 | 高 | expand-only、并发索引、低峰窗口、超时和演练。 |
| Flue/外部数据源不可用 | 中 | 来源隔离、重试/死信、待分析状态、降级。 |
| 页面删除入口但 API 仍被调用 | 高 | 调用方审计、废弃期、指标、分阶段 contract。 |
| 标签/估值口径反复 | 高 | 正式项目需求确认后才开发，字典和规则版本化。 |
| 配置端口或密钥错误 | 高 | 环境矩阵、启动检查、密钥轮换、禁止默认值。 |
| 回滚后新数据不可读 | 中 | 新字段可选、旧读取保留、contract 延后。 |
| 融资金额或模型推断被当作估值 | 高 | 来源合同、反例测试、候选隔离、人工审核和零无来源数值门禁。 |
| 自动估值来源违规或检索被攻击 | 高 | 白名单、SSRF 防护、条款评审、限流、内容隔离和紧急停用。 |
| 自动估值批量成本或审核积压失控 | 高 | 日预算、队列配额、canary、暂停开关、积压告警和分批回填。 |

## 10. Go/No-Go

出现以下任一情况应 No-Go 或立即停止扩大灰度：

- 无可验证数据库/JSONL 备份。
- 发现人工确认字段被静默覆盖。
- 同一来源重放持续产生重复线索。
- cursor 对账出现无法解释的漏数。
- 主体识别误合并超过确认阈值。
- 迁移导致长时间锁等待或关键接口明显退化。
- 评分/同步任务无法在重启后恢复。
- 生产仍使用公开默认内部密钥。
- POOL-009 转换接口去留未确认却准备直接删除。
- 本发布单元包含的标签、估值或布局口径尚未签字却准备上线。
- 自动估值可信来源、阈值或审核角色未确认。
- 发现融资金额误作估值、无来源具体数值、错误主体、非白名单访问或越权审核。
- 自动估值回填没有 dry-run/checkpoint/逆向数据，或来源成本和配额不可控。
