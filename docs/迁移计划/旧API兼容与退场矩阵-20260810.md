# 旧 API 兼容与退场矩阵

## 基线与原则

- 迁移前代码基线：`0a43c7d2d7eca0c55630a77c1ae29b02cf0d367d`。
- 基线中每个 Express 路由必须且只能归类为“保留”或“明确退场”。
- 保留不等于保留不安全的认证方式：所有业务 API 统一使用 HttpOnly 会话，写请求同时校验 CSRF 和 Origin。
- 保留路由由 `legacyApiCompatibilityAcceptance.ts` 直接从基线提取，与当前源码逐条比对；以下 8 个例外不得重新开放。

## 保留接口组

| 接口组 | 基线路径 | 兼容要求 |
| --- | --- | --- |
| 认证 | `/api/auth/*` | 保留登录、当前用户、退出路径和用户对象；不再返回 Bearer token |
| 项目与文件 | `/api/projects/*` | 保留列表分页、详情、阶段、评分、置顶和真实文件流路径 |
| 会议与待办 | `/api/meetings/*`、`/api/todos/*` | 保留 `list`，待办同时保留 `counts` |
| 风险 | `/api/risks/*` | 列表保留 `list` 和 `summary` |
| 元数据与线索 | `/api/users`、`/api/audit-logs`、`/api/templates`、`/api/leads/*`、`/api/ai-summaries` | 保留原分页和统计字段；管理数据加强系统管理员权限 |
| AI 任务 | `/api/ai/task-types`、`skills`、`templates/*`、`qa`、`tasks/*`、`artifacts/*` | 保留路径和列表形状，执行状态以 MySQL 为权威源 |
| 会话与工作区 | `/api/conversations/*`、`/api/workspace/*` | 保留路径，补强用户与项目隔离 |
| 材料与探针 | `/api/materials/generate`、`/api/materials/ai-cover`、`/api/llm-health` | 保留正式路径，材料产物改为登录用户私有访问 |

## 明确退场例外

| 方法与路径 | 退场原因 | 替代方式 |
| --- | --- | --- |
| `POST /api/materials/generate-internal` | 固定共享密钥可绕过用户会话 | 登录后调用 `/api/materials/generate` |
| `POST /api/internal/search-docs` | 依赖已退役 Flue localhost 回调 | 同进程项目知识工具 |
| `POST /api/internal/collect-intel` | 依赖已退役 Flue localhost 回调 | 同进程线索调研工具 |
| `POST /api/ai/project-summary` | 非权威摘要链路 | `/api/projects/:id/ai-summary` 或持久化 AI 任务 |
| `POST /api/ai/bp-parse` | 伪解析成功实现 | 真实文件上传和知识入库流程 |
| `GET /api/ai/jobs/:id` | 固定返回成功的伪任务 | `/api/ai/tasks/:id` |
| `POST /api/projects/files` | 只写元数据、不保存文件字节 | `/api/projects/files/upload` |
| `POST /api/projects/files/:id/parse-finish` | 固定伪解析完成 | 文件内容原子入库结果 |

## 发布门禁

`npm run accept:legacy-api-compatibility` 必须同时证明：

1. 基线路由全部被保留或列入上述 8 个退场例外；
2. 保留路由未认证访问返回统一 401；
3. 真实单服务中的登录、项目、会议、待办、风险、线索、管理和 AI 列表响应保留关键形状；
4. 8 个退场路由即使登录后访问也返回带 `requestId` 的统一 JSON 404；
5. 验收用户、项目、成员、会话和审计残留为 0，证据文件权限为 `0600`。
