# 单服务部署、启动与故障手册

适用对象：迁移后的投资中台。项目业务部署单元只有 `cybernaut-app.service`；MySQL、Nginx/Ingress 和 LLM Gateway 是外部基础设施，不计入项目业务服务，也不由应用自动启动。

## 1. 最终运行拓扑

| 类型 | 单元 | 常驻 | 端口/访问方式 | 处置 |
|---|---|---:|---|---|
| 项目业务服务 | `cybernaut-app.service` | 是，1 个 Node 主进程 | `127.0.0.1:3100` | 唯一启动单元 |
| JW Runtime、Socket、AI/评分 Worker、MySQL 调度器 | 主服务进程内组件 | 不新增进程 | 复用 3100/内部调用 | 随主服务启停 |
| Radar、Office/PDF/PPT 处理 | 受监督短时子进程 | 否 | 无监听端口 | 任务结束即退出，同一 cgroup 回收 |
| Flue | 无运行依赖 | 否 | 3584 必须关闭 | 只保留离线迁移恢复材料 |
| Radar FastAPI | 无常驻服务 | 否 | 8121 必须关闭 | 已被单次 Job 替代 |
| MySQL | 外部基础设施 | 是 | `.env` 的 `DB_HOST:DB_PORT` | 独立运维 |
| Nginx/Ingress | 外部基础设施 | 是 | TLS 443 | 只反代 3100 |
| LLM Gateway | 外部基础设施 | 按平台方案 | HTTPS API | AI 开启时必须可用 |

## 2. 启动前检查

1. `.env` 权限必须为 0600，数据库使用 `DB_HOST`、`DB_PORT`、`DB_DATABASE`、`DB_USERNAME`、`DB_PASSWORD`、`DB_FREFIX`；Runtime 账号只允许目标 Schema DML。
2. 先使用独立 Migration 凭据执行 `npm run db:migrate:separated`，再执行 `npm run audit:mysql-privileges` 和 `npm run check:mysql`。
3. 生产必须具备强会话/JWT 密钥、HTTPS Origin、Secure Cookie、模型凭据主密钥与模型网关主机白名单。
4. IM 启用时必须具备集成凭据主密钥；如需延期，设置 `IM_INTEGRATIONS_ENABLED=false`。能力扩展需延期时设置 `AI_CAPABILITIES_ENABLED=false`。
5. 文件根、Agent workspace、AI 产物目录和 Radar 工作目录必须挂载持久化且由 `cybernaut` 用户可写；代码和其他系统路径保持只读。

建议发布门禁：

```bash
npm run build:platform
npm run test:server
npm run check:platform
npm run check:mysql
npm run accept:single-service-runtime
```

> 发布连续性：`npm run build:platform` 现先在 `.runtime/build-candidates` 生成并校验成对的 `dist/server-dist`。3100 活跃时只保留候选指针，不删除或覆盖当前产物；`deploy.sh` 在唯一服务及旧进程停止后才运行 `npm run activate:build`。新版健康或投资文档 Skill 绑定失败时，脚本会停止失败版、执行 `npm run rollback:build`、恢复上一版 Skills 并尝试重启旧版。若产物回退本身失败，服务保持停止，不带病重启。

停服并激活候选产物后，`deploy.sh` 会在真正启动进程前自动执行：

```bash
NODE_ENV=production npm run check:single-service-prestart
```

该门禁不启动 Node 服务、不执行业务写入；它要求 3100/3584/8121 均无监听、`.env` 为 0600 常规文件、Web/后端产物成对且无符号链接、无待激活候选、生产配置通过，并以回滚窗口只读 MySQL 会话验证 3306 连接、最新迁移日志和必需表。失败时部署尝试恢复上一版产物与 Skills，但保持服务停止，避免用反复崩溃重启探测配置错误。它只写一份 0600 脱敏证据，不记录路径、数据库身份或配置值。

同一编译后门禁还被固定为 `cybernaut-app.service` 的 `ExecStartPre`，因此主机冷启动、人工 `systemctl start/restart` 和部署脚本都不能绕过。systemd 使用 `RestartPreventExitStatus=2 78` 阻止配置/安全拒绝退出进入重启环，并以 `StartLimitIntervalSec=300` / `StartLimitBurst=5` 约束其他连续启动失败。systemd 下的脱敏证据写入 `${APP_STATE_DIR}/prestart`，不要求业务用户写代码目录。

正式切换前先查看聚合结论，再执行严格门禁：

```bash
npm run audit:cutover-readiness
npm run check:cutover-readiness
```

`audit` 始终生成 0600 脱敏报告；`check` 在任一维度未就绪时退出 2。它同时聚合严格 MySQL 对账、弱密码、权威验收清单、当前单服务和 24 小时内的目标 Linux 现场证据，并单独拒绝“已勾选但明确不解除生产阻断”的延期 P0/安全冒烟、缺正式负责人/ISO 日期期限/批准人的例外、未完成生产冒烟以及未完成最终验收确认。这样缩减本批次范围或降低核心未完成数，都不会被误报为生产安全验收通过。所有数据库子检查强制使用回滚窗口只读会话；报告只保留维度布尔值、聚合计数和稳定阻断码，不包含账号、例外身份、路径、业务正文或密钥。

## 3. 启动、停止与验证

生产由部署脚本安装并启动唯一单元：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now cybernaut-app.service
sudo systemctl status cybernaut-app.service --no-pager
```

本地生产构建只运行：

```bash
npm run build:platform
npm run start:app
```

启动成功必须同时满足：

```bash
curl --fail http://127.0.0.1:3100/api/health
curl --fail http://127.0.0.1:3100/api/health/components
lsof -nP -iTCP:3100 -sTCP:LISTEN
lsof -nP -iTCP:3584 -iTCP:8121 -sTCP:LISTEN
```

预期：3100 只有统一应用监听；3584/8121 无输出。停止使用 `systemctl stop cybernaut-app.service`，不得单独保留 Worker、Radar 或文档子进程。`KillMode=control-group` 应回收同一 cgroup 内全部受监督子进程。

## 4. 独立扩展回滚

以下开关只接受 `true` 或 `false`，修改后重启唯一业务服务：

| 故障域 | 回滚配置 | 效果 |
|---|---|---|
| 能力扩展/作用域配置 | `AI_CAPABILITIES_ENABLED=false` | 关闭能力管理和会话选择；核心聊天降级为无 MCP、Skill、项目工具的最小互动 Agent，不回退旧 Flue |
| 全部 IM 集成 | `IM_INTEGRATIONS_ENABLED=false` | 同时关闭 Bot 管理、入站 Webhook、线索推送和 Outbox Job |
| 仅 IM 出站队列 | `IM_OUTBOX_ENABLED=false` | 保留配置但停止新一轮 Outbox 调度；已持久化任务不丢失 |
| 项目新建 JW 会话 | `JW_PROJECT_NEW_CONVERSATIONS_ENABLED=false` | 拒绝项目新会话，已有 MySQL 会话可继续读取 |
| 全局新建 JW 会话 | `JW_GLOBAL_NEW_CONVERSATIONS_ENABLED=false` | 拒绝全局新会话，不启动任何旧 Runtime |

恢复开关前必须先处理根因并执行对应专项验收，不能通过重新启动 Flue、Radar HTTP 或旧 localhost 回调绕过。

### 4.1 切换后的只读回滚观察窗

该模式不是普通维护模式，只允许在《PostgreSQL 增量 CDC 与切换手册》定义的最后安全回滚点之后、Point of No Return 之前使用：

```dotenv
MIGRATION_WRITE_FREEZE=true
MIGRATION_WRITE_FREEZE_MODE=rollback-window
```

通过以下受控命令预览和原子写入生产 `.env`，然后只重启 `cybernaut-app.service`：

```bash
npm run cutover:freeze-writes:preview -- --env-file /受控绝对路径/.env
npm run cutover:freeze-writes -- --env-file /受控绝对路径/.env
sudo systemctl restart cybernaut-app.service
```

健康响应必须包含 `writeMode=rollback-window` 和 `migration-write-freeze.ok=true`；Radar、周期 Job、线索/项目评分和 AI Task 组件必须为 `intentionally-disabled`。写 API 必须返回 `503/MIGRATION_WRITE_FROZEN`，MySQL Runtime 连接的 `@@SESSION.transaction_read_only` 必须为 1。

观察窗开始前先准备有效的多角色会话，因为登录本身会创建会话并被写冻结阻断。此时可以读取页面、权限、项目、线索、历史会话、既有 AI 任务状态和文件元数据，但不能上传、编辑、发消息、评分、生成材料或触发任务。17 个已批准永久缺失的项目原件按精确处置台账忽略，不要求在此窗口重新取得。

若六域写入增量均为 0 且达到批准的回滚阈值，可按手册回切读取流量；发现任何目标写入则停止流量和自动回切，交由数据负责人裁决。只有五类负责人签署 PONR 后，才可用 `cutover:cross-ponr:preview` 和 `cutover:cross-ponr` 配合 0600 审批 JSON 解除冻结并重启服务；此后只做 MySQL 前向修复。完整审批字段见 CDC 切换手册。

## 5. 故障处置

### 5.1 MySQL 不可用

- 现象：组件健康返回 MySQL/Job/会话组件失败，业务写入失败关闭。
- 操作：检查外部 MySQL 网络、最小权限账号 Host 绑定、连接容量和慢查询；不得临时改用 PostgreSQL/SQLite 或带 DDL/GRANT 的 DBA 账号运行应用。
- 恢复：MySQL 恢复后重启或等待连接池自动重连，检查租约恢复、队列积压和最近 `runtime_job_runs`；执行 `accept:mysql-resilience` 的同等现场步骤。

### 5.2 LLM Gateway 不可用或限流

- 核心非 AI CRUD 应继续可用；Agent/文档任务按有限重试、备用模型、超时、死信或可重试状态收口。
- 若影响持续，关闭项目/全局新会话或相关扩展开关；不得提高无界重试、预算或超时。
- 恢复后先做 Provider 连接测试，再做一条受控 Agent 和一类文档任务验收。

### 5.3 IM 渠道异常

- 先设置 `IM_INTEGRATIONS_ENABLED=false`，确认主项目、登录、Agent 和其他 Job 健康不受影响。
- 查看 Outbox、投递日志、重试次数和死信；不要删除历史投递或直接改密文。
- 轮换凭据后执行连接测试和受控单条发送，再恢复总开关。

### 5.4 Radar/文档子进程卡死

- 统一监督器应按超时终止整个子进程组，主 Node 继续运行。
- 核查 systemd cgroup 中是否存在孤儿；若有，保持服务停止并调查是否存在绕过监督器的调用。
- MySQL 租约到期后由恢复器重新排队或明确失败，禁止人工复制内存队列状态。

### 5.5 磁盘或文件根异常

- 立即暂停文件上传和文档任务，检查容量、权限、挂载和只读状态。
- 不允许用数据库路径猜测或重建缺失原件；使用 manifest、SHA-256 和迁移问题台账恢复。
- 恢复后抽样完成上传、解析、预览、下载及请求 ID 审计，并确认符号链接和跨用户读取仍被拒绝。

## 6. 不允许的临时修复

- 不启动 `cybernaut-flue`、Radar FastAPI、旧 API service、项目 cron 或 systemd timer。
- 不恢复 3584/8121 监听、Nginx `/ai/api` 或主服务对 localhost 业务回调。
- 不把 MySQL Runtime 账号升级为 DBA/DDL 账号，不将账号 Host 放宽为 `%`。
- 不跳过密码、生产源资产、文件 manifest、TLS、Aipin 排除或严格迁移对账门禁。
- 不在命令行、日志、文档、Git 或聊天中传递真实密钥。

## 7. 生产取证与交接

本地单服务验收不能替代生产证据。切换和观察期至少保存：部署 commit、systemd 单元与 cgroup、进程/端口、Nginx upstream、cron/timer、组件健康、MySQL 权限、CDC watermark、文件 manifest、队列/死信、登录与多角色冒烟、备份恢复、告警责任人和 Point of No Return 批准记录。

备份与恢复细节见 `MySQL备份恢复手册-20260809.md`，CDC/切换与前向修复见 `PostgreSQL增量CDC与切换手册.md`。严格全迁移对账未通过时，本手册只能用于演练，不能作为生产切换批准。
