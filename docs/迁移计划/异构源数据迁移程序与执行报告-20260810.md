# 异构源数据迁移程序与执行报告

## 1. 当前结论

PostgreSQL、PostgreSQL dump、JW SQLite 和 Flue SQLite 的迁移程序、来源白名单、幂等/断点/内容校验与机器报告均已交付。当前 checksum 锁定的 PostgreSQL dump 已完成 16 表、16,574 行基线对账；JW 批准业务投影为 0，37 个 Aipin 会话/2,168 条消息全部拒绝；两个 Flue 候选分别为空库和无业务归属的网关验收 fixture，业务写入均为 0。

这代表 `DEL-003` 的“程序和当前执行报告”可以交接，不代表生产全量迁移完成。在线 PostgreSQL 仍不可连接，生产部署机是否存在其他 PostgreSQL/JW/Flue 数据源尚未批准，真实 Flue 业务会话、文件附件和最终 CDC 追平也没有证据；严格全量对账当前必须保持 `fullMigrationReady=false`。

## 5. 生产执行顺序

1. 在维护窗口生成生产源资产清单，锁定 PostgreSQL URL 指纹/dump、全部 JW/Flue SQLite 和文件根；先审批，后迁移。
2. 对每个数据库/文件执行一致性备份和恢复抽样，保存大小、SHA-256、最大时间和停写水位。
3. 运行所有预览命令；Aipin 命中、未知表/来源、哈希漂移、归属缺失或文件引用缺失必须失败关闭。
4. PostgreSQL 保持唯一写入，先执行全量，再追平 CDC；SQLite 只对批准源应用，禁止扫描目录后自动纳入新库。
5. 执行目标完整性、全量来源对账、文件 manifest、业务抽样和单服务冒烟；严格全量对账非零时不得切流。
6. 完成业务、数据、安全和运维签字后才能记录 PONR；此前不得删除旧源或恢复材料。
