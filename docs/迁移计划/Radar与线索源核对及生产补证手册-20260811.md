## 3. 为什么 406 条空导入时间不回填

`imported=true`、正式线索映射和源序号是已存在的业务事实；具体导入时间不是。使用行创建时间、迁移执行时间或当前时间回填会把技术时间伪装成业务时间，破坏审计可信度。

本轮将空导入时间作为聚合指标公开，但不作为映射完整性的失败条件。若后续取得旧任务日志，可用独立、带来源哈希的修复迁移补充；在此之前保持 `NULL`。

## 4. 生产补证 manifest

生产补证时将一个不含正文和密钥的 JSON manifest 放在受控目录，并通过 `RADAR_PRODUCTION_ASSET_MANIFEST` 指向它。最低契约如下：

```json
{
  "schemaVersion": "1.0",
  "approved": true,
  "restoredAt": "2026-08-11T00:00:00.000Z",
  "ownerApprovedAt": "2026-08-11T00:00:00.000Z",
  "assets": [
    { "kind": "radar-jsonl", "records": 0, "sha256": "<64位小写SHA-256>", "restoredAt": "2026-08-11T00:00:00.000Z" },
    { "kind": "wechat-chat-originals", "records": 0, "sha256": "<64位小写SHA-256>", "restoredAt": "2026-08-11T00:00:00.000Z" },
    { "kind": "collector-state", "records": 0, "sha256": "<64位小写SHA-256>", "restoredAt": "2026-08-11T00:00:00.000Z" },
    { "kind": "wechat-accounts-xlsx", "records": 0, "sha256": "<64位小写SHA-256>", "restoredAt": "2026-08-11T00:00:00.000Z" }
  ]
}
```

四类资产必须全部存在有效计数、哈希和恢复时间，并有 manifest 级恢复时间与负责人批准时间，门禁才会把 `productionAssetReady` 置为 `true`。只提供空文件或口头确认不能替代源端数量核对、权限检查和恢复演练。

## 5. 切换前操作顺序

1. 在生产旧主机盘点四类原始资产，冻结源端写入或记录最终水位。
2. 生成内容哈希和记录数，不把正文、聊天内容、凭据或绝对路径写入证据。
3. 将资产复制到加密归档，按最小权限恢复到预生产隔离目录。
4. 抽样打开并核对记录数、哈希和采集状态；由资产负责人批准。
5. 配置 manifest 后重新运行本门禁，并确认 `productionAssetReady=true`。
6. 再执行迁移证据安全、业务不变量、单服务运行和最终切换门禁。

## 6. 未关闭风险

- 生产候选和群聊原文可能只存在于旧主机、个人目录或未纳管挂载点。
- 本机 Radar 候选为空，无法代表生产历史数据量。
- 97 条 `lead_reserve` 缺失详情尚未取得原内容。
- 406 条历史 imported 时间未知；除非取得可信旧日志，否则只能保留未知。
- 生产采集凭据、目录权限、保留期、恢复耗时和负责人签字仍待现场确认。
