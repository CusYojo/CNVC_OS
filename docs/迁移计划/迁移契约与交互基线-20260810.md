# 迁移契约与交互基线

日期：2026-08-10

本基线完成 `MIG-0020～0023`。它固定当前迁移目标的页面、REST、AI 助手和线索链路，不代表生产切流批准。机器报告和截图位于 `.runtime/migration-evidence/ui-contract-baseline/`；截图来自一次性隔离 MySQL Schema、随机合成管理员和空业务数据，禁止使用生产库页面代替。

## MIG-0020 页面路由与导航

保留路由为 `/`、`/login`、`/projects`、`/projects/:id`、`/sourcing`、`/ai`、`/meetings`、`/workflow`、`/risks`、`/knowledge`、`/system`、`/system/ai/models`、`/system/ai/capabilities`。`/materials` 永久转到 `/ai`，`/post-investment` 永久转到 `/projects`；未匹配路由进入 404 页面。

五张基线截图分别覆盖登录、首页完整导航、AI 助手、公共线索池和系统管理。导航明确只有首页、AI 助手、公共线索池、OA/项目流程、系统管理、模型设置和能力管理；IM 机器人、旧材料和投后工具没有伪造入口。

## MIG-0021 REST、错误与鉴权

统一 `/api` 下挂载 Auth、Projects、Meetings、Todos、Risks、Meta、OA、AI、JW Agent、Model Settings、Capabilities、Conversations 和 Workspace。每次基线命令动态统计全部 `GET/POST/PUT/PATCH/DELETE` 定义，并锁定路由源文件 checksum。

错误响应固定为 `code/message/details/requestId`，HTTP 响应头和正文请求编号必须一致；500 不返回内部原文。认证使用服务端 MySQL Session Cookie、CSRF/Origin 防护、角色守卫和项目访问复核，旧 Bearer/JWT 不作为登录旁路。

## MIG-0022 AI 助手交互

会话创建、改名、切换、删除、流式消息 Part、停止和恢复均以 MySQL 会话/消息表及 JW Runtime 为权威。项目会话绑定稳定项目 ID；文件走受控项目文件根和知识分块；六类任务卡统一进入 MySQL AI Task 租约；产物按用户/项目隔离并通过受权下载。无项目时页面明确提示先选择项目，不显示 `undefined` 或制造可执行状态。

真实模型多轮、项目工具、停止后无迟到写入、第二认证 Session 恢复和精确删除由 `accept:jw-multiturn-live` 及对应 0600 报告证明；这不替代生产浏览器域名的最终视觉验收。

## MIG-0023 线索全链路

统一链路为：不可变原始事件 → 主体审查 → 受控研究 → 初筛 → 人工复核（如需）→ 正式线索 → 评分 → 有来源补全 → 单事务转项目。Radar、公开情报和人工复核都使用 MySQL Pipeline；多主体或重复匹配不得自动选第一条或创建第三条。

来源原文、Run、Decision、Evidence、Review、评分输入和状态转换保留追加式审计。Flue Workflow、Radar HTTP 服务和直接 LLM HTTP 不属于活动写入链。

## 复验命令

`npm run capture:contract-baseline` 校验路由、API、错误/鉴权、AI/线索交互标记、五张隔离截图、已知问题 ID 和源文件 checksum，并重写仅所有者可读的机器报告。代码改动后必须重新构建并重新截图，不能沿用旧图宣称视觉一致。
