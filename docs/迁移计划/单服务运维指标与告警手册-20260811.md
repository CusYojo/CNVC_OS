# 单服务运维指标与告警手册

## 1. 目标和访问边界

统一应用通过 `GET /api/operations/metrics` 提供运维快照。接口位于现有 `cybernaut-app.service`、3100 端口和 HttpOnly 会话鉴权链内，只允许启用的系统管理员访问；未登录返回 401，普通用户由 `requireSystemAdmin` 拒绝。接口不创建第二个服务、端口、cron、timer 或子进程。

管理员也可进入“系统数据 → 迁移运维”查看同一接口的只读视图。页面集中显示 MySQL 连接池/运行线程/锁等待、四类 Worker 的健康/排队/运行/死信、Socket 连接/数据库并发/待重连、Agent 活跃会话/待交互、IM 待发/发送中/15 分钟投递/失败/死信，以及 CDC watermark/删除积压、Radar 候选与游标、`lead_reserve` 序号和原始事件覆盖、文件 manifest、生产源/Radar 原资产/全量对账结论；只能刷新，不能从页面批准、修改或删除任何迁移数据。

快照只输出汇总计数、延迟、资源和配置状态，不输出 URL 路径标签、项目/用户/文件名、数据库连接身份、凭据、业务正文或告警渠道实际值。外部监控采集器应使用独立最小权限系统管理员会话或由基础设施在受控网络增加专用适配层，不得把接口公开到互联网。

| 文档原生运行时 | 每 5 分钟无子进程探测 Python、LibreOffice、Poppler rasterizer/font audit、Tesseract、Fontconfig 是否可执行；macOS 的 Tesseract/Fontconfig 为可观测替代项，Linux 为必需项；不输出路径或版本 |
| CDC | 源数、不健康源、最大复制延迟、watermark gap、删除和级联删除累计数 |
| Radar | 候选/不可变原始事件数、采集状态数、来源数、同步状态/未完成回填、最新稳定游标、4 个 MySQL Runtime Job 及失败数 |
| 储备池 | 总数、已导入、缺原详情、待处理、最大 36氪 seq、原始事件缺失及历史 imported 时间未知数量 |
| 迁移证据 | 文件 manifest 可用性/根/文件/阻断/技术就绪/批准状态，生产源盘点批准，Radar 本地与生产资产就绪，目标结构/源对账/全量迁移就绪；只读取受控证据报告并输出白名单聚合，不返回路径、文件名、业务正文、审批人或凭据 |
| 单服务组件 | JW Runtime、Socket、AI Runtime 遥测、Runtime Job、评分 Worker、AI Task、受监督子进程、会话、Radar MySQL 事实源和迁移证据健康 |

所有数据库汇总由 `OperationalTelemetryRepository` 读取 MySQL；HTTP 和 Socket 只维护有界进程内计数。权威任务/租约/失败状态继续来自 MySQL，进程内计数不能覆盖数据库事实。

## 4. 采集和告警责任

- `OPS_ALERT_OWNER_ROLE` 记录责任角色，默认 `operations-on-call`。
- `OPS_ALERT_NOTIFICATION_CHANNEL_ID` 必须是已启用的 `im_bot_bindings.id` UUID；渠道凭据仍只保存在 AES-256-GCM 加密的 IM Bot 配置中。
- `OPS_ALERT_ESCALATION_POLICY_ID` 只记录不含密钥的外部升级策略标识；升级动作仍由目标渠道/值班制度执行。
- `OPS_ALERT_REMINDER_MINUTES` 控制同一告警集合的重复提醒，默认 60 分钟，允许 5～10080 分钟。
- API 只输出“是否配置”，绝不回显标识值。
- 告警评估复用唯一服务内现有 `im-outbox-dispatch` Job：活动告警、周期提醒和恢复通知写入同一 MySQL Outbox，继承租约、限速、有限重试、dead-letter 和投递日志；不增加第二个服务、端口、cron 或 timer。
- 告警 code/severity 集合形成稳定指纹；相同状态在提醒窗口内持久化去重，进程重启后仍有效。消息只含稳定 code、汇总指标值和阈值，不含用户、项目、文件、渠道标识或凭据。
- 当前本机未配置通知渠道和升级策略，`alertRoutingConfigured=false`；代码内投递闭环已经建立，但真实渠道、责任人、升级策略和外部实际收件尚未取证，因此 `OPS-010` 仍未关闭。
- 外部采集周期建议 60 秒；Critical 连续 5 分钟未恢复进入升级链。真实阈值、静默窗口、确认动作和责任人必须由运维/业务批准。

## 5. 当前已知告警

本机验收快照当前为 `warning`：

- `FILE_PARSE_FAILURE`：历史文件存在解析失败/缺原件处置项；不能通过隐藏记录消除告警。
- `LEAD_SOURCE_MISSING`：97 条 `lead_reserve` 缺少原始 `detail_json`，已隔离但尚未补源或获批永久缺失。
- `AI_TOKEN_USAGE_INCOMPLETE`：最近 24 小时线索 Agent Run 有输出 Token 和成本，但网关回传的输入 Token 为 0；解析器已覆盖 SDK 顶层 `usage`、按模型 `modelUsage`、蛇形/驼峰字段及缓存输入 Token，2026-08-11 非报告在线探针仍为输入 0、输出 202 Token，因此不得把 0 当作完整用量，也不得按成本反推。
- `LEAD_ENTITY_DUPLICATE_GROUPS`：当前线索名称 9 组/25 条、公司名称 33 组/82 条精确重复，合计 42 个字段级重复组；不得通过监控层隐藏、自动合并或删除。
- `MYSQL_DEADLOCK_OBSERVATION_UNAVAILABLE`：当前 MySQL `performance_schema=0`，Runtime 可读的 `SHOW GLOBAL STATUS` 不提供 `Innodb_deadlocks`；不能把缺失计数解释为没有死锁。
- `MYSQL_REPLICATION_OBSERVATION_UNAVAILABLE`：DML-only Runtime 账号无 `REPLICATION CLIENT`，`SHOW REPLICA STATUS` 被拒绝；保持最小权限，生产应由数据库监控账号或基础设施采集器提供复制状态。
- `FILE_STORAGE_GROWTH_BASELINE_UNAVAILABLE`：2026-08-11 已写入当前真实文件根的首条脱敏小时样本，但尚未经过 24 小时，暂时没有可用于跨日比较的同系列基线；此项会在连续采样满 24 小时后自动消失或转为真实增长率告警。

这七项与迁移问题台账一致。监控只能使问题可见，不能替代原始数据恢复、网关用量修复、重复实体业务裁决、MySQL 观测面补齐、跨日观察窗口或负责人批准。

```bash
npm run accept:operations-telemetry

```

生产文件 manifest 只有在严格扫描零阻断、明确指定生产环境和批准身份时才能记录批准；以下命令不会从页面自动执行：

```bash
npm run inventory:files -- --strict --environment production --approve --approved-by '<批准人身份>'
```

未带 `--strict`、非 production 或缺批准身份时会失败关闭。运维 API 只返回 `approvalRecorded` 布尔值，不返回批准人身份。

第一项只读核验真实 MySQL 汇总、HTTP 分位数、四十九类阈值告警、Radar/储备池游标与原始事件覆盖、文件/生产源/Radar 资产/全量对账的脱敏迁移证据摘要、任务和子进程失败/超时/重试/租约回收历史、文档原生运行时可执行状态、文件根容量、安全审计分类、敏感值排除、管理员路由和无额外服务/定时器；`accept:mysql-server-telemetry` 使用 `.env` 的 DML-only Runtime 账号核验慢查询、行锁和线程状态为真实单调计数，并确认死锁/复制不可观测时明确报告 unavailable、结果不含连接或复制身份；`accept:file-storage-capacity-history` 用随机临时根和两条隔离 MySQL 系统事件验证 25 小时基线、1 GiB 剩余空间下降、10 个百分点使用率增长、同小时幂等、安全字段白名单和精确清理零残留；`accept:auth-session-key-telemetry` 用随机用户和旧/新密钥验证历史 Cookie 命中每日幂等、续期切换当前密钥、四类轮换告警、安全系统事件及精确清理，事件不含密钥、Token、CSRF 或身份；`accept:ai-runtime-telemetry` 以 10 个纯内存调用验证 5 个真实 SDK 首 Token、5 个非流式 unavailable、成功/失败/取消、P95、覆盖率两类告警、内容/身份/密钥排除和清理零残留，不请求模型；`accept:document-runtime-dependencies` 只读取依赖 JSON、精确 Python 锁、SHA-256、安装和部署脚本，核对 Linux 原生依赖/OCR 语言/CJK 字体契约，不执行 Python、Office、Poppler、OCR 或字体命令；部署另运行 live 版本核验，但同样不读取或生成业务文件；`accept:target-single-service-evidence` 纯静态核对目标 Linux 取证契约，部署启动成功后另执行 live 只读取证，验证唯一 systemd 单元、cgroup 资源/端口归属、旧单元、timer/cron、Nginx TLS 和环境文件权限并输出 0600 脱敏报告；`accept:job-coordination-telemetry` 另以四条临时系统事件验证争抢、重复抑制、恢复和旧结果拒绝的持久化、SHA-256 目标保护、24 小时聚合及零残留；`accept:process-supervisor-telemetry` 真实覆盖成功、非零退出、超时强杀、取消、缓冲区超限和停机排空六条路径，验证退出历史精确增量、安全载荷和清理回基线；告警投递项用临时加密 IM Bot/绑定执行 16 项验收，覆盖配置拒绝、停用开关、活动告警、持久化去重、实际 Outbox 投递、投递日志、恢复通知、审计和零残留；最后一项真实启动唯一应用，确认运维接口未登录访问返回 401、业务仍只监听 3100，3584/8121 关闭。上述验收不创建 PPT、尽调、提案、Q&A 或合规性说明任务；日常原生运行时探测只做 `X_OK` 文件检查，文件容量探测只调用 `statfs`，均不启动 Office/Python/OCR；告警投递验收使用 `mock://success` 的安全适配器，不等于真实租户已收到消息。

## 7. 仍未关闭的生产工作

1. 配置真实告警 IM 绑定、责任人和升级策略，并在真实租户验证告警实际送达、确认、提醒和恢复通知。
2. 将专业文档所用非流式 Responses/视觉网关升级为能提供真实 delta 时间的受控流式接口，并把当前进程内 AI Runtime 窗口接入生产连续采集；现有实现已覆盖 JW 与五类线索 Agent 的真实首 Token，非流式入口保持 unavailable，不得用响应完成时间替代。
3. 在生产启用可审计的 `performance_schema` 死锁观测，并由数据库监控账号/基础设施采集器读取复制拓扑和延迟；不得为此给 DML-only Runtime 账号增加管理权限。慢查询累计数和行锁等待已由唯一服务采集。
4. 连续保留至少 24 小时真实文件容量样本并验证增长率告警实际收件；在生产 cgroup 中验证子进程资源序列、限额和真实退出趋势。
5. 在生产 PostgreSQL CDC、真实 IM 租户和 Radar 原始资产就位后验证对应指标非零路径。
6. 完成真实客户端 Socket 重连率和前端断线恢复指标；服务端当前记录连接、断开和鉴权失败。
7. 在目标 TLS 浏览器执行 CSRF/Origin 趋势观察和一次真实会话密钥轮换演练；本机当前历史密钥数 0、24 小时历史密钥命中 0，技术状态为 complete，但不替代生产操作取证。

Runtime Job 使用逐次运行表，因此 24 小时运行指标是精确事件计数；线索/项目评分和 AI Task 使用“每任务一条生命周期记录”，对应失败/重试指标表示最近 24 小时更新且发生过该状态的记录数。争抢、重复抑制、过期恢复和旧结果拒绝则统一追加到现有 `audit_logs`：系统 Actor、稳定模块/动作、仅保存 `domain:SHA-256(entityId)`，不保存任务参数、租约所有者、项目名或正文；争抢事件按同一目标一分钟去重，避免多实例空转制造高基数。事件写入失败只产生无标识错误日志，不反向破坏任务事务。

因此本手册关闭 HTTP 基础指标、AI Runtime 真实流式入口首 Token/总耗时/错误/取消及不可观测覆盖率、Worker/队列/租约/超时/重试技术采集、调度协调事件采集和受监督子进程退出历史的本地代码缺口，不把非流式模型入口、进程重启后的连续窗口或其他未取得生产证据的 `OPS-002～015` 和生产告警责任链描述为已完成。
