# 附属业务域迁移与退场报告

## 1. 结论

OA/流程、材料生成、模板、系统组织权限、数据字典和 Radar 结构化运行数据已有正式 MySQL 归属；旧投后页、通知已读和旧材料页继续退场。2026-08-11 的后续批准已撤销“组织/角色/字典编辑退场”结论，以编号迁移 `0036/0037` 和受审计管理 API 取代原浏览器内存实现。`lead_reserve` 的 10,000 行已保留，其中 9,903 行有详情并进入不可变事件边界，97 行缺少原始详情且处于 `source_missing` 隔离。

Radar FastAPI 8121、独立 service/timer 和运行时 Python Job 均已去除，采集能力迁入唯一 `cybernaut-app.service` 的 TypeScript 进程内采集器。当前本机 7 个文件根（包含 `project-discovery/data`）已做 249 文件、113,537,425 字节的确定性归档与隔离恢复；这不等于生产 Radar/群聊/公众号原资产已经盘点、授权和恢复。

本报告完成的是逐域迁移/退场裁决和证据交接，不关闭 `MIG-0719/0728`：生产原始资产、97 条详情和正式恢复/业务签字仍是 P0 门禁。

## 3. 删除与保留边界

可以从运行拓扑去除：旧材料页、旧投后页、通知入口、无契约组织/字典编辑、Radar FastAPI 8121、Flue 3584、旧 service/timer/cron 和 localhost 回调。

必须继续保留：

- OA、材料生成、模板、Radar 采集和 `lead_reserve` 的 MySQL 表、迁移台账与专项验收；
- `server/src/services/radarCollectorService.ts`、Node 网络依赖和 MySQL 调度契约；
- 当前与生产 Radar 原始文件、公众号 Excel、群聊原文、旧数据库/文件根备份，直到 manifest、恢复、保留期和销毁审批完成；
- 97 条 `source_missing` 原行及其 `migration_issues`，不得用空 JSON 或推测内容补齐；
- 旧材料/产物源文件恢复入口，直到缺失文件取得或批准处置。
