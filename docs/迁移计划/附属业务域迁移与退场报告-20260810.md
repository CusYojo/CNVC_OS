# 附属业务域迁移与退场报告

## 1. 结论

OA/流程、材料生成、模板、系统组织权限、数据字典和 Radar 运行能力已有正式 MySQL 归属；旧投后页、通知已读和旧材料页继续退场。2026-08-11 的后续批准已撤销“组织/角色/字典编辑退场”结论，以编号迁移 `0036/0037` 和受审计管理 API 取代原浏览器内存实现。`lead_reserve` 的 10,000 行已保留，其中 9,903 行有详情并进入不可变事件边界，97 行缺少原始详情且处于 `source_missing` 隔离。

Radar FastAPI 8121、独立 service/timer 和运行时 Python Job 均已从生产拓扑去除，采集能力迁入唯一 `cybernaut-app.service` 的 TypeScript 进程内采集器。2026-08-17 生产切换后，MySQL 当前保有 6,176 条候选、6,975 条原始事件和 1,312 个来源注册；微信群 Push 使用 HMAC-SHA256、300 秒时间窗和 MySQL 重放收据。原 `project-discovery/` 活动目录已删除，仅在服务器只读发布备份中保留回滚材料。

Radar 生产资产 manifest 已完成计数和 SHA-256 技术核验，但产品、研发、运维、数据四方稳定身份批准仍未完成；OpenAlex 生产实采、已暴露凭据轮换和截至 2026-08-24 20:39 的观察期也保持未关闭。本报告完成的是逐域迁移/退场裁决和证据交接，不单独关闭全局 `MIG-0719/0728`：97 条详情、其他历史文件原件和正式签字仍按主迁移清单处理。

必须继续保留：

- OA、材料生成、模板、Radar 采集和 `lead_reserve` 的 MySQL 表、迁移台账与专项验收；
- `server/src/services/radarCollectorService.ts`、Node 网络依赖和 MySQL 调度契约；
- 生产 Radar 原始文件、公众号 Excel、旧数据库/文件根和发布回滚备份，直到四方 manifest 批准、观察期、保留期和销毁审批完成；源端不存在的微信群原文按已签署缺失事实处理，不得伪造补齐；
- 97 条 `source_missing` 原行及其 `migration_issues`，不得用空 JSON 或推测内容补齐；
- 旧材料/产物源文件恢复入口，直到缺失文件取得或批准处置。
