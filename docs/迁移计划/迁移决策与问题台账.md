# 迁移决策与问题台账

更新时间：2026-08-11

本文件是迁移期决策和未关闭问题的索引。事实数量以机器证据和《单服务迁移期执行记录》最新一次结果为准；本文件不能替代生产负责人签字、真实源库验证或切流审批。

## 1. 已采用决策

| ID | 决策 | 状态 | 约束与证据 |
| --- | --- | --- | --- |
| ADR-001 | MySQL 是迁移后的业务权威数据库 | 已采用 | 生产运行代码只能使用 `DB_HOST/DB_PORT/DB_DATABASE/DB_USERNAME/DB_PASSWORD/DB_FREFIX`；PostgreSQL 只允许受控盘点、全量迁移、CDC 安装/应用和对账工具访问。 |
| ADR-002 | 生产业务进程收敛为 `cybernaut-app.service` | 已采用 | Web、API、Socket、JW Runtime、Radar 调度、评分和 AI Worker 在同一 Node 主进程；仅监听 3100。MySQL、Nginx/Ingress 和 LLM Gateway 是外部基础设施，不计入业务服务数。 |
| ADR-003 | Aipin 数据和能力不进入本次 JW 迁移 | 已采用 | 37 个 Aipin 会话和 2,168 条消息全部留在拒绝集；活动代码、环境变量名、迁移表白名单和目标 MySQL 均由严格排除门禁扫描。 |
| ADR-004 | 身份迁移使用稳定目标用户 ID 和显式映射 | 已采用 | 16,574 个 PostgreSQL dump 源实体均有目标映射；不能由证据唯一确定的身份必须进入问题台账，不生成虚构用户。 |
| ADR-005 | 不允许业务层分别向 PostgreSQL 和 MySQL 双写 | 已采用 | 切换前 PostgreSQL 是唯一写入所有者，前向 CDC 必须显式声明 `legacy-postgres-authoritative`；MySQL 接管后立即停止前向 CDC。 |
| ADR-006 | 缺失文件和缺失原始详情只隔离，不猜测恢复 | 已采用 | 缺失字节、正文或唯一归属时保留源键、基线哈希、问题和隔离状态；不得按相似文件名、路径或元数据制造内容。 |
| ADR-007 | 没有反向 CDC 时，Point of No Return 后只允许前向修复 | 已采用 | 切流前必须冻结未具备反向同步的业务域；越过 PONR 后不能宣称可无损回切 PostgreSQL。 |
| ADR-008 | 现有脏工作区按用户资产保护 | 已采用 | 当前全部改动保留在 `codex/mysql-migration`；基线脚本记录逐文件状态，但不推断历史改动归属，不自动清理、暂存或覆盖。 |
| ADR-009 | 迁移证据不得包含密钥或非必要业务正文 | 已采用 | 证据目录使用 0700、文件使用 0600；扫描当前配置密钥、通用凭据、敏感 JSON 字段、Markdown 正文、符号链接和权限。 |
| ADR-010 | 不新增与通用租约调度重复的专用 `lead_pipeline_jobs` | 已采用 | `lead_pipeline_items/transitions` 保存每个不可变事件的业务状态机与历史，`runtime_jobs/runtime_job_runs` 保存调度、租约、重试和运行记录；两层通过事件幂等键及 Run/Decision 链关联。迁移计划中的表清单是“建议新增或拆分”，复制一套未使用的 Job 表只会产生双权威源。 |
| ADR-011 | 旧 JWT 只允许有界迁移窗口，不作为生产长期认证方式 | 已采用 | 默认及生产均关闭；非生产迁移环境必须同时配置最长 30 天 UTC 截止时间和稳定用户 UUID 白名单。每次 REST/Socket 接受均审计，数据库单例失效水位和系统管理员命令可一次性吊销全部旧 Token；正式认证继续以 MySQL HttpOnly Session 为唯一长期路径。 |
| ADR-012 | 会话灰度不得重新引入 Flue 流量开关 | 已采用 | Flue 已从活动构建、入口、代理和端口退场，重新增加回退开关会制造双运行时和单服务回归风险。灰度只允许通过 `JW_GLOBAL_NEW_CONVERSATIONS_ENABLED` / `JW_PROJECT_NEW_CONVERSATIONS_ENABLED` 独立控制新建 JW 会话；已有 MySQL 会话不受影响，关闭范围失败关闭且没有备用 Runtime。需要回滚时回滚统一应用版本和数据切换步骤，不把新消息重新写回 Flue。 |
| ADR-013 | 计划中的领域前缀是概念分区，不复制现有物理表 | 已采用 | `iam_*`、`investment_*`、`knowledge_*`、`agent_*`、`ai_task_*`、`runtime_*`、`scheduler_*`、`audit_*` 映射到现有兼容表名；`DB_FREFIX` 负责实例前缀。禁止为满足命名形式再建无独立生命周期或调用方的表，避免双权威源。映射和机器门禁见《MySQL领域命名与约束裁决-20260811》。 |
| ADR-014 | PostgreSQL 部分唯一约束按业务条件选择 MySQL 等价 | 已采用 | OA 活动流程使用可空 `active_key` + 唯一索引；无条件唯一使用普通唯一索引；活动线索名目标为“条件生成可空列 + 唯一索引”，但 9 组/25 条同名线索未裁决前保持暂缓（另有 33 组/82 条公司名重复），不能用应用层预查冒充数据库约束。 |
| ADR-015 | Schema 只前进，回退使用迁移前备份恢复到隔离表前缀 | 已采用 | 发布顺序固定为当前前缀一致性备份→独立账号编号迁移→版本化种子→门禁。不得在活动前缀倒序执行未经验证的 DROP；回退把备份恢复到全新 `rollback_*_` 前缀并核对 DDL/行内容，审批后再切 `DB_FREFIX`。切流后有新写入且无反向 CDC 时仍受 PONR 约束。 |
