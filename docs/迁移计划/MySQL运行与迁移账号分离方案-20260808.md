# MySQL 运行与迁移账号分离方案（2026-08-08）

## 1. 结论

`.env` 中的 `DB_HOST`、`DB_PORT`、`DB_DATABASE`、`DB_USERNAME`、`DB_PASSWORD`、
`DB_FREFIX` 始终表示应用运行时 MySQL 连接。`DB_USERNAME` 不应拥有全局权限、
`GRANT OPTION`、`CREATE USER`、复制或服务器管理权限。

生产 Schema DDL 使用独立迁移账号，只在 `deploy.sh` 执行 `db:migrate` 时通过
root 所有的凭据文件注入，不写入应用 `.env`，也不会进入 systemd 服务环境。
生产 Node 启动只读核对迁移版本和必需表，不再自动执行 DDL。

## 2. 推荐授权

以下 SQL 中的库名、用户名、来源主机和密码必须由 DBA 替换，不应直接复制示例密码：

```sql
CREATE USER 'cybernaut_runtime'@'APP_HOST' IDENTIFIED BY 'ROTATED_RUNTIME_PASSWORD';
GRANT SELECT, INSERT, UPDATE, DELETE
  ON `TARGET_DATABASE`.* TO 'cybernaut_runtime'@'APP_HOST';

CREATE USER 'cybernaut_migrator'@'APP_HOST' IDENTIFIED BY 'ROTATED_MIGRATION_PASSWORD';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, DROP, INDEX, REFERENCES
  ON `TARGET_DATABASE`.* TO 'cybernaut_migrator'@'APP_HOST';
```

运行账号写入应用 `.env`：

```dotenv
DB_HOST=mysql.example.internal
DB_PORT=3306
DB_DATABASE=TARGET_DATABASE
DB_USERNAME=cybernaut_runtime
DB_PASSWORD=ROTATED_RUNTIME_PASSWORD
DB_FREFIX=sbl_
```

迁移账号只写入目标服务器 root 可读文件，例如
`/root/.cybernaut-mysql-migration.env`：

```dotenv
DB_MIGRATION_USERNAME=cybernaut_migrator
DB_MIGRATION_PASSWORD=ROTATED_MIGRATION_PASSWORD
```

```bash
chown root:root /root/.cybernaut-mysql-migration.env
chmod 0400 /root/.cybernaut-mysql-migration.env
DB_MIGRATION_ENV_FILE=/root/.cybernaut-mysql-migration.env bash deploy.sh update
```

## 3. 验证

```bash
npm run audit:mysql-privileges
NODE_ENV=production npm run start:app
```

权限审计必须返回 `ok:true`。生产启动日志必须出现
`schema verified read-only`，不能出现 `schema migrations ready`。

当前 `.env` 目标已于 2026-08-10 完成正式换号。Runtime 仅保留目标 Schema
`SELECT/INSERT/UPDATE/DELETE`，Migration 仅保留目标 Schema DML 与必要 DDL；两者精确
绑定当前应用来源，无全局或授权权限。`.env`、迁移凭据和回滚副本均为
0600，证据只保存主体 SHA-256 和权限集。`audit:mysql-privileges`、
`audit:mysql-account-cutover`、`db:migrate:separated`、生产只读 Schema 验证及单服务实启均通过。

2026-08-11 再次出现开发出口变化：安全预览确认当前精确 Host 绑定为 0、旧绑定为 2。
受控轮换先建立当前来源的两类同权限主体并分别实连，成功后才删除两个旧绑定；密码不变、
未使用 `%`。复验确认 Runtime 仍只有四项 DML，Migration 仍只有目标 Schema DML 与必要
DDL，82 张表、133 个外键、40 条迁移日志；唯一 3100 服务的 11 个组件曾恢复健康，当前服务保持停止并等待获准启动。
`audit:mysql-privileges` 的控制台结果已改为只保留主体 SHA-256，排除用户名和来源 Host。

本机回滚副本位于忽略的 `.runtime/secrets/`，只用于本次换号故障恢复。目标生产
部署仍须把 Migration 凭据放入 root-owned 0400/0600 文件，不能直接复制本机文件或
将本环境证据外推到其他环境。
