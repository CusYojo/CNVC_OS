# MySQL 领域命名与约束裁决

## 1. 结论

迁移计划中的 `iam_*`、`investment_*`、`knowledge_*`、`agent_*`、`ai_task_*`、`runtime_*`、`scheduler_*` 和 `audit_*` 是概念域及建议前缀，不要求把已经稳定运行的物理表再次复制或改名。目标 MySQL 继续以 `server/src/db/schema.ts` 和只前进的编号迁移为权威源，使用现有表名；`DB_FREFIX` 只负责实例级统一前缀。

本裁决关闭“表域设计不清楚”的缺口，不授权跳过生产源对账，也不把未完成的数据清洗描述为已经完成。特别是线索名 9 组/25 条、公司名 33 组/82 条重复（合计 42 组/107 条）仍由 `MIG-0125`/`ISSUE-006` 阻断，活动名称唯一约束只能在业务逐组裁决后新增。

## 2. 概念域到物理表映射

| 计划概念域 | 现有物理表 | 裁决 |
|---|---|---|
| `iam_*` | `users`、`auth_sessions`、`auth_legacy_bearer_policy`、`iam_user_mappings`、`identity_resolution_issues`、`project_members` | 用户角色和部门保存在 `users`，项目授权保存在稳定 ID 关系表；没有获批生命周期的通用组织树、角色编辑器和字典表不创建空壳。对应 `MIG-0110`。 |
| `investment_*` | `projects`、`leads`、`meetings`、`meeting_participants`、`todos`、`risks`、`oa_approval_*`、`oa_workflow_logs`、评分 Job | 保持现有 API/迁移兼容表名，审批、流程和评分都具有正式 MySQL 生命周期。对应 `MIG-0111`。 |
| `knowledge_*` | `project_files`、`project_file_versions`、`file_chunks`、`knowledge_chunks`、`ai_summaries` | 元数据、不可变文件版本、解析块和检索投影分层；磁盘字节仍受 manifest/恢复门禁约束。对应 `MIG-0112`。 |
| `agent_*` | `agent_conversations`、`agent_messages`、`agent_message_parts`、两张来源映射表 | 会话、消息、Part、工具状态和旧源映射均已持久化。对应 `MIG-0113`。 |
| `ai_task_*` | `ai_tasks`、`ai_artifacts`、`ai_task_sources`、`ai_task_templates`、`ai_custom_templates`、`ai_template_analysis_progress` | 任务、租约/重试、来源、产物、模板和分析进度形成一个事务域。对应 `MIG-0114`。 |
| `runtime_*` | `ai_model_providers`、`ai_models`、`ai_model_routes`、`ai_capabilities`、`ai_capability_bindings`、`ai_conversation_capabilities`、`im_*` | `ai_capabilities.kind` 统一承载 Skill、Agent、MCP、Plugin；Provider/Bot 凭据仅保存密文及掩码元数据；不再建重复的 `runtime_models` 或 `runtime_plugins`。对应 `MIG-0116`。 |
| `scheduler_*` | `runtime_jobs`、`runtime_job_runs` | 到期时间、租约所有者/过期时间、当前 Run、失败计数和不可丢失运行历史均已覆盖；不再建第二套 `scheduler_jobs`。对应 `MIG-0117`。 |
| `audit_*` | `audit_logs`、`migration_runs`、`migration_issues`、`migration_entity_mappings`、`migration_cdc_events`、`migration_cdc_checkpoints` | 操作、拒绝、认证安全事件写入追加式 `audit_logs`，迁移安全事件写入迁移控制面；生产运行路径不更新或删除审计记录。对应 `MIG-0118`。 |

### 身份权威源补充裁决

计划中的 `iam_users` 是 IAM 概念域名称，不要求物理表改名。现有 `users` 已由 46 条跨域外键、`IdentityRepository`、Cookie 会话、REST、Socket 和项目成员授权共同引用；新增同义 `iam_users` 会制造双写、双唯一键和身份漂移。因此 `MIG-0801` 的完成标准是“所有运行链只从物理 `users` 读取并按稳定 UUID 授权”，不是复制第二张表。`accept:identity-authority` 以只读实库、源码和浏览器 Store 三层验证该结论；旧 ID 只保存在 `iam_user_mappings`，不能成为认证源。

复制一套只满足前缀形式、却没有新的生命周期或调用方的表，会造成迁移脚本、Repository 和运维查询出现两个事实源，因此明确禁止。

## 3. PostgreSQL 部分唯一索引的 MySQL 等价

| 业务约束 | MySQL 等价 | 当前状态 |
|---|---|---|
| 一个项目最多一条活动 OA 流程 | 活动态将 `project_id` 写入可空 `active_key`，终态写 `NULL`；`uq_oa_active_project(active_key)` 利用 MySQL 允许多个 `NULL` 的唯一索引语义 | 已实现并由 OA 并发验收覆盖 |
| 用户邮箱全局唯一 | Drizzle 生成的普通唯一索引 `<DB_FREFIX>users_email_unique(email)` | 已实现；规范化冲突为 0 |
| 未转专属的活动线索名唯一 | 目标设计为“条件成立时生成规范化名称，否则为 `NULL`”的生成列加唯一索引 | 暂缓；历史基线迁移曾建立 `active_name`，迁移 `0002` 因真实重复数据删除。必须先关闭 `MIG-0125`/`ISSUE-006`，再用新的只前进迁移恢复，不能靠事务预查冒充唯一约束 |
| 其余无条件唯一键 | 普通唯一索引，例如 Provider 名称、Provider+Model Key、Capability 类型+Key、IM 入站外部消息和 Outbox 幂等键 | 已实现 |

这项裁决完成 `MIG-0120` 的设计要求；它不关闭线索去重和约束实际上线要求。

## 4. 事务、幂等与乐观锁规则

| 场景 | 事务边界 | 幂等/并发裁决 |
|---|---|---|
| 用户、权限、项目成员和会话失效 | 业务变更、稳定 ID 关系、活动会话撤销和审计同事务 | 用户邮箱唯一键最终裁决；管理员和目标用户行锁 |
| Agent 会话/消息/Part | 会话对、消息序号、Part 状态及中断同事务 | 外部消息 ID/Part 索引唯一键；终态不可被重放降级 |
| AI Task、产物、来源 | 主产物、预览、来源与完成态同事务 | 任务幂等键、租约 owner/expiry、状态条件更新；冲突整体回滚 |
| Provider、Model、Route、Capability | 配置写入与审计同事务 | `version` 乐观锁；默认模型域使用行锁串行化 |
| IM 配置与投递 | Bot/Binding/Rule 与审计同事务；投递日志与 Outbox 终态同事务 | Outbox 幂等键、入站外部消息唯一键、`FOR UPDATE SKIP LOCKED` 单领取、配置 `version` 乐观锁 |
| 通用周期任务 | Job 领取、Run 创建、心跳、成功/失败终态分别使用短事务 | 到期条件、lease owner/expiry、行锁和 Run ID 防止多实例重复完成 |
| OA 审批 | 请求、节点、记录、待办、项目阶段、流程日志和审计同事务 | `active_key` 唯一键、`lock_version` 乐观锁、节点顺序唯一键 |

Repository 的稳定错误映射、失败回滚和专项并发夹具继续以《MySQL Repository接口与事务规范》及五组真实 MySQL 验收为发布门禁。以上规则完成 `MIG-0137`，不改变 PostgreSQL CDC、生产切流和外部文件恢复的独立阻断状态。

## 5. 附属业务生命周期

`MIG-0126` 的逐域结论以《附属业务域迁移与退场报告-20260810》为准：OA/流程日志、AI 模板、材料生成能力和 Radar 结构化数据正式迁移；旧投后页、通知/已读、旧材料页以及无目标 Schema 的通用组织/字典编辑退场。页面退场不等于历史文件字节完成迁移，缺失原件继续按原清单阻断。

## 6. 机器验收

```bash
npm run accept:mysql-architecture-contract
```

该命令只读 `information_schema` 与代码/文档，验证领域表存在、重复权威表不存在、运行时配置密文列、配置唯一键/版本、调度租约/Run 外键、审计索引、部分唯一等价和事务实现，并输出不含连接身份或业务正文的 0600 证据。它不创建夹具，也不修改业务数据。
